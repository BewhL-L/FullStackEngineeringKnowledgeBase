# 设计模式知识点系统梳理（优化版）

> **文档说明**：系统梳理 23 种经典设计模式，重点讲解常用模式的结构、应用场景和 Java 实现，涵盖创建型、结构型、行为型三大类。

---

## 1. 概述

设计模式是软件开发中针对常见问题的**可复用解决方案**，是前人经验的总结。GoF（Gang of Four）提出了 23 种经典设计模式，分为三大类。

**设计模式六大原则（SOLID + 迪米特）**：
| 原则 | 简称 | 说明 |
|------|------|------|
| 单一职责 | SRP | 一个类只做一件事 |
| 开闭原则 | OCP | 对扩展开放，对修改关闭 |
| 里氏替换 | LSP | 子类可替换父类 |
| 接口隔离 | ISP | 接口要小而专，不要大而全 |
| 依赖倒置 | DIP | 依赖抽象，不依赖具体 |
| 迪米特法则 | LoD | 最少知识，降低耦合 |

## 2. 创建型模式（5种）

### 2.1 单例模式（Singleton）

**保证一个类只有一个实例，并提供全局访问点。**

```java
// 双重检查锁（DCL）
public class Singleton {
    private static volatile Singleton instance;
    private Singleton() {}
    public static Singleton getInstance() {
        if (instance == null) {
            synchronized (Singleton.class) {
                if (instance == null) {
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}

// 枚举单例（最安全，推荐）
public enum Singleton {
    INSTANCE;
    public void doSomething() {}
}
```

> 🔍 **知识点深度解析**
>
> **作用**：确保全局唯一实例，节省资源，常用于配置管理、连接池、日志对象。
>
> **原理**：构造方法私有，外部无法 new，通过静态方法获取唯一实例。DCL 双重检查保证线程安全且性能好，volatile 防止指令重排序（new 对象分三步：分配内存、初始化、引用赋值，重排序可能导致其他线程拿到未初始化对象）。枚举单例由 JVM 保证单例和线程安全，还能防止反射和序列化破坏。
>
> **用法要点**：① 优先用枚举实现单例；② DCL 必须加 volatile；③ 静态内部类也是线程安全的懒加载方案；④ 面试常考：单例实现方式、DCL 为什么要 volatile、枚举单例优势。

### 2.2 工厂方法模式（Factory Method）

**定义创建对象的接口，让子类决定实例化哪个类。**

```java
public interface Product { }
public class ProductA implements Product { }
public class ProductB implements Product { }

public interface Factory {
    Product createProduct();
}
public class FactoryA implements Factory {
    public Product createProduct() { return new ProductA(); }
}
```

### 2.3 抽象工厂模式（Abstract Factory）

**创建一系列相关或相互依赖的对象家族。**

```java
public interface AbstractFactory {
    Button createButton();
    Text createText();
}
public class WindowsFactory implements AbstractFactory {
    public Button createButton() { return new WindowsButton(); }
    public Text createText() { return new WindowsText(); }
}
```

### 2.4 建造者模式（Builder）

**将复杂对象的构建与表示分离，分步构建。**

```java
public class User {
    private String name;
    private int age;
    private String email;
    private User(Builder builder) {
        this.name = builder.name;
        this.age = builder.age;
        this.email = builder.email;
    }
    public static Builder builder() { return new Builder(); }
    public static class Builder {
        private String name;
        private int age;
        private String email;
        public Builder name(String name) { this.name = name; return this; }
        public Builder age(int age) { this.age = age; return this; }
        public Builder email(String email) { this.email = email; return this; }
        public User build() { return new User(this); }
    }
}
// 使用
User user = User.builder().name("Tom").age(20).email("tom@x.com").build();
```

### 2.5 原型模式（Prototype）

**通过复制现有对象创建新对象，避免复杂初始化。**

```java
public class Prototype implements Cloneable {
    private String name;
    @Override
    public Prototype clone() throws CloneNotSupportedException {
        return (Prototype) super.clone(); // 浅拷贝
    }
}
```

## 3. 结构型模式（7种）

### 3.1 代理模式（Proxy）

**为对象提供代理，控制对原对象的访问。**

```java
public interface Subject {
    void request();
}
public class RealSubject implements Subject {
    public void request() { /* 真实逻辑 */ }
}
public class Proxy implements Subject {
    private RealSubject real;
    public void request() {
        // 前置处理
        real.request();
        // 后置处理
    }
}
```

**动态代理**：JDK 动态代理（接口）、CGLIB（继承）。Spring AOP 基于动态代理。

> 🔍 **知识点深度解析**
>
> **作用**：在不修改原对象的前提下增强功能（日志、事务、权限、缓存）。
>
> **原理**：静态代理在编译期生成代理类，动态代理在运行时生成。JDK 动态代理通过 `Proxy.newProxyInstance` 生成实现目标接口的代理类，调用时走 `InvocationHandler.invoke`。CGLIB 通过 ASM 字节码框架生成目标类的子类，重写方法实现代理，不需要接口。Spring AOP 默认 JDK 动态代理（有接口时），无接口时用 CGLIB。
>
> **用法要点**：① JDK 代理需要接口，CGLIB 不需要（但不能代理 final 类/方法）；② Spring Boot 2.x 默认 CGLIB（spring.aop.proxy-target-class=true）；③ 同类内调用不触发代理（this 调用，需用 AopContext.currentProxy()）；④ 面试常考：JDK vs CGLIB、Spring AOP 原理、动态代理实现。

### 3.2 装饰器模式（Decorator）

**动态地给对象添加额外职责，比继承更灵活。**

```java
public interface Coffee {
    double cost();
    String desc();
}
public class SimpleCoffee implements Coffee {
    public double cost() { return 10; }
    public String desc() { return "咖啡"; }
}
public class MilkDecorator implements Coffee {
    private Coffee coffee;
    public MilkDecorator(Coffee coffee) { this.coffee = coffee; }
    public double cost() { return coffee.cost() + 2; }
    public String desc() { return coffee.desc() + "+牛奶"; }
}
// Java IO 流是装饰器经典应用：new BufferedInputStream(new FileInputStream(...))
```

### 3.3 适配器模式（Adapter）

**将不兼容的接口转换为客户端期望的接口。**

```java
public interface Target {
    void request();
}
public class Adaptee {
    public void specificRequest() {}
}
public class Adapter implements Target {
    private Adaptee adaptee;
    public void request() { adaptee.specificRequest(); }
}
```

### 3.4 桥接模式（Bridge）

**将抽象与实现分离，使两者可独立变化。**

### 3.5 外观模式（Facade）

**为子系统提供统一入口，简化调用。**

### 3.6 组合模式（Composite）

**将对象组合成树形结构，统一处理单个和组合对象。**

### 3.7 享元模式（Flyweight）

**共享细粒度对象，减少内存占用。**（String 常量池、数据库连接池）

## 4. 行为型模式（11种）

### 4.1 策略模式（Strategy）

**定义一系列算法，封装后可互换。**

```java
public interface PaymentStrategy {
    void pay(double amount);
}
public class AlipayStrategy implements PaymentStrategy {
    public void pay(double amount) { /* 支付宝支付 */ }
}
public class WechatPayStrategy implements PaymentStrategy {
    public void pay(double amount) { /* 微信支付 */ }
}
public class Order {
    private PaymentStrategy strategy;
    public void setStrategy(PaymentStrategy strategy) { this.strategy = strategy; }
    public void checkout(double amount) { strategy.pay(amount); }
}
```

### 4.2 观察者模式（Observer）

**一对多依赖，状态变化时通知所有观察者。**

```java
public interface Observer {
    void update(String msg);
}
public class Subject {
    private List<Observer> observers = new ArrayList<>();
    public void attach(Observer o) { observers.add(o); }
    public void notifyAll(String msg) {
        observers.forEach(o -> o.update(msg));
    }
}
// Spring Event、Guava EventBus 是观察者模式应用
```

### 4.3 模板方法模式（Template Method）

**定义算法骨架，子类实现具体步骤。**

```java
public abstract class Game {
    public final void play() { // final 防止重写骨架
        initialize();
        startPlay();
        endPlay();
    }
    abstract void initialize();
    abstract void startPlay();
    abstract void endPlay();
}
```

### 4.4 责任链模式（Chain of Responsibility）

**请求沿链传递，直到有对象处理。**（Servlet Filter、Spring Interceptor）

### 4.5 命令模式（Command）

**将请求封装为对象，支持撤销、排队。**（Runnable、Spring JdbcTemplate）

### 4.6 状态模式（State）

**对象内部状态改变时改变行为。**

### 4.7 迭代器模式（Iterator）

**顺序访问集合元素，不暴露内部结构。**（Java Iterator）

### 4.8 中介者模式（Mediator）

**用中介对象封装一组对象的交互。**（MVC 中的 Controller）

### 4.9 备忘录模式（Memento）

**保存和恢复对象状态。**（数据库事务回滚、编辑器撤销）

### 4.10 访问者模式（Visitor）

**在不改变元素类的前提下定义新操作。**

### 4.11 解释器模式（Interpreter）

**定义语言文法，解释句子。**（SQL 解析、正则表达式）

## 5. 面试高频考点

1. **单例模式**：DCL、volatile、枚举单例
2. **代理模式**：JDK vs CGLIB、Spring AOP
3. **装饰器模式**：与代理区别、Java IO
4. **策略模式**：与工厂模式区别、消除 if-else
5. **观察者模式**：Spring Event、发布订阅
6. **模板方法**：与策略模式区别
7. **责任链模式**：Filter/Interceptor 实现
8. **建造者模式**：链式调用、与工厂区别
9. **适配器模式**：类适配器 vs 对象适配器
10. **六大原则**：SOLID 理解和应用

## 📝 精简总结

- 创建型：单例、工厂方法、抽象工厂、建造者、原型 — 解决对象创建问题
- 结构型：代理、装饰器、适配器、桥接、外观、组合、享元 — 解决类/对象组合问题
- 行为型：策略、观察者、模板方法、责任链、命令等 11 种 — 解决对象交互问题
- 核心原则：开闭原则（对扩展开放）、依赖倒置（面向接口编程）
- 实际开发中最常用：单例、工厂、建造者、代理、策略、观察者、模板方法
