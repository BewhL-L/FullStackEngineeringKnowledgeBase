## 1.1props

props可以实现父子组件通信,在vue3中我们可以通过defineProps获取父组件传递的数据。且在组件内部不需要引入defineProps方法可以直接使用！

**父组件给子组件传递数据**

```
<Child info="我爱祖国" :money="money"></Child>
```

**子组件获取父组件传递数据:方式1**	

```
let props = defineProps({
  info:{
   type:String,//接受的数据类型
   default:'默认参数',//接受默认数据
  },
  money:{
   type:Number,
   default:0
}})
```

**子组件获取父组件传递数据:方式2**

```
let props = defineProps(["info",'money']);
```

子组件获取到props数据就可以在模板中使用了,但是切记props是只读的(只能读取，不能修改)


> 🔍 **知识点深度解析**
>
> **作用**：props是父传子的单向数据流，子组件只读不可改（需改用emit通知父）。
>
> **原理**：TS用defineProps<T>()泛型写法，withDefaults设默认值。
>
> **用法要点**：① props是父传子的单向数据流，子组件只读不可改（需改用emit通知父） ② 对象写法可指定类型type、默认值default、必填required、校验validator ③ 数组写法简洁但无校验 ④ TS用defineProps<T>()泛型写法，withDefaults设默认值

## 1.2自定义事件

在vue框架中事件分为两种:一种是原生的DOM事件，另外一种自定义事件。

原生DOM事件可以让用户与网页进行交互，比如click、dbclick、change、mouseenter、mouseleave....

自定义事件可以实现子组件给父组件传递数据

### 1.2.1原生DOM事件

代码如下:

```
 <pre @click="handler">
      我是祖国的老花骨朵
 </pre>
```


当前代码级给pre标签绑定原生DOM事件点击事件,默认会给事件回调注入event事件对象。当然点击事件想注入多个参数可以按照下图操作。但是切记注入的事件对象务必叫做$event.

```
  <div @click="handler1(1,2,3,$event)">我要传递多个参数</div>
```

在vue3框架click、dbclick、change(这类原生DOM事件),不管是在标签、自定义标签上(组件标签)都是原生DOM事件。

**<!--vue2中却不是这样的,在vue2中组件标签需要通过native修饰符才能变为原生DOM事件-->**

### 1.2.2自定义事件

自定义事件可以实现子组件给父组件传递数据.在项目中是比较常用的。

比如在父组件内部给子组件(Event2)绑定一个自定义事件

```
<Event2  @xxx="handler3"></Event2>
```

在Event2子组件内部触发这个自定义事件

```
<template>
  <div>
    <h1>我是子组件2</h1>
    <button @click="handler">点击我触发xxx自定义事件</button>
  </div>
</template>

<script setup lang="ts">
let $emit = defineEmits(["xxx"]);
const handler = () => {
  $emit("xxx", "法拉利", "茅台");
};
</script>
<style scoped>
</style>
```

我们会发现在script标签内部,使用了defineEmits方法，此方法是vue3提供的方法,不需要引入直接使用。defineEmits方法执行，传递一个数组，数组元素即为将来组件需要触发的自定义事件类型，此方执行会返回一个$emit方法用于触发自定义事件。

当点击按钮的时候，事件回调内部调用$emit方法去触发自定义事件,第一个参数为触发事件类型，第二个、三个、N个参数即为传递给父组件的数据。

需要注意的是:代码如下

```
<Event2  @xxx="handler3" @click="handler"></Event2>
```

正常说组件标签书写@click应该为原生DOM事件,但是如果子组件内部通过defineEmits定义就变为自定义事件了

```
let $emit = defineEmits(["xxx",'click']);
```




> 🔍 **知识点深度解析**
>
> **作用**：自定义事件是子传父的标准方式，defineEmits声明事件，$emit触发。
>
> **原理**：原生事件（click等）绑定到根元素，自定义事件需声明。
>
> **用法要点**：① 自定义事件是子传父的标准方式，defineEmits声明事件，$emit触发 ② 原生事件（click等）绑定到根元素，自定义事件需声明 ③ 事件名推荐kebab-case ④ v-model本质是:modelValue+@update:modelValue语法糖

## 1.3全局事件总线

全局事件总线可以实现任意组件通信，在vue2中可以根据VM与VC关系推出全局事件总线。

但是在vue3中没有Vue构造函数，也就没有Vue.prototype.以及组合式API写法没有this，

那么在Vue3想实现全局事件的总线功能就有点不现实啦，如果想在Vue3中使用全局事件总线功能

可以使用插件mitt实现。

**mitt:官网地址:https://www.npmjs.com/package/mitt**


> 🔍 **知识点深度解析**
>
> **作用**：全局事件总线（mitt库）实现任意组件间通信，$on监听/$emit触发/$off取消。
>
> **原理**：Vue3移除了$on/$off，需用mitt或tiny-emitter。
>
> **用法要点**：① 全局事件总线（mitt库）实现任意组件间通信，$on监听/$emit触发/$off取消 ② Vue3移除了$on/$off，需用mitt或tiny-emitter ③ 适用于兄弟/跨层级通信，但事件多了难维护，复杂状态优先用Pinia

## 1.4v-model

v-model指令可是收集表单数据(数据双向绑定)，除此之外它也可以实现父子组件数据同步。

而v-model实指利用props[modelValue]与自定义事件[update:modelValue]实现的。

下方代码:相当于给组件Child传递一个props(modelValue)与绑定一个自定义事件update:modelValue

实现父子组件数据同步

```
<Child v-model="msg"></Child>
```

在vue3中一个组件可以通过使用多个v-model,让父子组件多个数据同步,下方代码相当于给组件Child传递两个props分别是pageNo与pageSize，以及绑定两个自定义事件update:pageNo与update:pageSize实现父子数据同步

```
<Child v-model:pageNo="msg" v-model:pageSize="msg1"></Child>
```




> 🔍 **知识点深度解析**
>
> **作用**：v-model双向绑定，组件内需defineProps接收modelValue，defineEmits触发update:modelValue。
>
> **原理**：支持v-model:xxx多个绑定（替代Vue2的.sync）。
>
> **用法要点**：① v-model双向绑定，组件内需defineProps接收modelValue，defineEmits触发update:modelValue ② 支持v-model:xxx多个绑定（替代Vue2的.sync） ③ 修饰符通过modelModifiers prop接收 ④ 表单元素和自定义组件都可用

## 1.5useAttrs

在Vue3中可以利用useAttrs方法获取组件的属性与事件(包含:原生DOM事件或者自定义事件),次函数功能类似于Vue2框架中$attrs属性与$listeners方法。

比如:在父组件内部使用一个子组件my-button

```
<my-button type="success" size="small" title='标题' @click="handler"></my-button>
```

子组件内部可以通过useAttrs方法获取组件属性与事件.因此你也发现了，它类似于props,可以接受父组件传递过来的属性与属性值。需要注意如果defineProps接受了某一个属性，useAttrs方法返回的对象身上就没有相应属性与属性值。

```
<script setup lang="ts">
import {useAttrs} from 'vue';
let $attrs = useAttrs();
</script>
```




> 🔍 **知识点深度解析**
>
> **作用**：useAttrs获取未声明为props的属性（含class/style/事件监听器），自动继承到根元素。
>
> **原理**：inheritAttrs:false阻止自动继承。
>
> **用法要点**：① useAttrs获取未声明为props的属性（含class/style/事件监听器），自动继承到根元素 ② v-bind=attrs透传给子组件 ③ inheritAttrs:false阻止自动继承 ④ 封装高阶组件（包装el-input）时透传属性必备

## 1.6ref与$parent



ref,提及到ref可能会想到它可以获取元素的DOM或者获取子组件实例的VC。既然可以在父组件内部通过ref获取子组件实例VC，那么子组件内部的方法与响应式数据父组件可以使用的。

比如:在父组件挂载完毕获取组件实例

父组件内部代码:

```
<template>
  <div>
    <h1>ref与$parent</h1>
    <Son ref="son"></Son>
  </div>
</template>
<script setup lang="ts">
import Son from "./Son.vue";
import { onMounted, ref } from "vue";
const son = ref();
onMounted(() => {
  console.log(son.value);
});
</script>
```

但是需要注意，如果想让父组件获取子组件的数据或者方法需要通过defineExpose对外暴露,因为vue3中组件内部的数据对外“关闭的”，外部不能访问

```
<script setup lang="ts">
import { ref } from "vue";
//数据
let money = ref(1000);
//方法
const handler = ()=>{
}
defineExpose({
  money,
   handler
})
</script>
```

$parent可以获取某一个组件的父组件实例VC,因此可以使用父组件内部的数据与方法。必须子组件内部拥有一个按钮点击时候获取父组件实例，当然父组件的数据与方法需要通过defineExpose方法对外暴露

```
<button @click="handler($parent)">点击我获取父组件实例</button>
```


> 🔍 **知识点深度解析**
>
> **作用**：ref属性获取子组件实例，script setup中需defineExpose暴露。
>
> **原理**：$parent访问父组件实例（不推荐，耦合强）。
>
> **用法要点**：① ref属性获取子组件实例，script setup中需defineExpose暴露 ② $parent访问父组件实例（不推荐，耦合强） ③ 父调子方法用ref+expose，子调父用emit ④ TS中ref<InstanceType<typeof Comp>>()获取类型

## 1.7provide与inject

**provide[提供]**

**inject[注入]**

vue3提供两个方法provide与inject,可以实现隔辈组件传递参数

组件组件提供数据:

provide方法用于提供数据，此方法执需要传递两个参数,分别提供数据的key与提供数据value

```
<script setup lang="ts">
import {provide} from 'vue'
provide('token','admin_token');
</script>
```

后代组件可以通过inject方法获取数据,通过key获取存储的数值

```
<script setup lang="ts">
import {inject} from 'vue'
let token = inject('token');
</script>
```


> 🔍 **知识点深度解析**
>
> **作用**：provide/inject跨层级通信（祖到孙），不需逐层传props。
>
> **原理**：provide提供数据（可响应式），inject接收。
>
> **用法要点**：① provide/inject跨层级通信（祖到孙），不需逐层传props ② provide提供数据（可响应式），inject接收 ③ InjectionKey保证TS类型安全 ④ 适合主题/用户信息等全局数据，复杂状态用Pinia

## 1.9slot

插槽：默认插槽、具名插槽、作用域插槽可以实现父子组件通信.

**默认插槽:**

在子组件内部的模板中书写slot全局组件标签

```
<template>
  <div>
    <slot></slot>
  </div>
</template>
<script setup lang="ts">
</script>
<style scoped>
</style>
```

在父组件内部提供结构：Todo即为子组件,在父组件内部使用的时候，在双标签内部书写结构传递给子组件

注意开发项目的时候默认插槽一般只有一个

```
<Todo>
  <h1>我是默认插槽填充的结构</h1>
</Todo>
```

**具名插槽：**

顾名思义，此插槽带有名字在组件内部留多个指定名字的插槽。

下面是一个子组件内部,模板中留两个插槽

```
<template>
  <div>
    <h1>todo</h1>
    <slot name="a"></slot>
    <slot name="b"></slot>
  </div>
</template>
<script setup lang="ts">
</script>

<style scoped>
</style>
```

父组件内部向指定的具名插槽传递结构。需要注意v-slot：可以替换为#

```
<template>
  <div>
    <h1>slot</h1>
    <Todo>
      <template v-slot:a>  //可以用#a替换
        <div>填入组件A部分的结构</div>
      </template>
      <template v-slot:b>//可以用#b替换
        <div>填入组件B部分的结构</div>
      </template>
    </Todo>
  </div>
</template>

<script setup lang="ts">
import Todo from "./Todo.vue";
</script>
<style scoped>
</style>
```

**作用域插槽**

作用域插槽：可以理解为，子组件数据由父组件提供，但是子组件内部决定不了自身结构与外观(样式)

子组件Todo代码如下:

```
<template>
  <div>
    <h1>todo</h1>
    <ul>
     <!--组件内部遍历数组-->
      <li v-for="(item,index) in todos" :key="item.id">
         <!--作用域插槽将数据回传给父组件-->
         <slot :$row="item" :$index="index"></slot>
      </li>
    </ul>
  </div>
</template>
<script setup lang="ts">
defineProps(['todos']);//接受父组件传递过来的数据
</script>
<style scoped>
</style>
```

父组件内部代码如下:

```
<template>
  <div>
    <h1>slot</h1>
    <Todo :todos="todos">
      <template v-slot="{$row,$index}">
         <!--父组件决定子组件的结构与外观-->
         <span :style="{color:$row.done?'green':'red'}">{{$row.title}}</span>
      </template>
    </Todo>
  </div>
</template>

<script setup lang="ts">
import Todo from "./Todo.vue";
import { ref } from "vue";
//父组件内部数据
let todos = ref([
  { id: 1, title: "吃饭", done: true },
  { id: 2, title: "睡觉", done: false },
  { id: 3, title: "打豆豆", done: true },
]);
</script>
<style scoped>
</style>
```

### 额外发现的问题 ⚠️

| 问题                                                      | 说明                                                         |
| --------------------------------------------------------- | ------------------------------------------------------------ |
| `lodash` 和 `lodash-es` 重复                              | 两个都装了，建议只保留 `lodash-es`（支持 Tree Shaking，打包更小） |
| `moment` 和 `dayjs` 重复                                  | 两个都是日期库，建议只保留 `dayjs`（更轻量，Moment 已停止维护） |
| `sass` 和 `less` 同时存在                                 | CSS 预处理器二选一即可，除非项目同时用了 `.scss` 和 `.less` 文件 |
| `progress` 和 `nprogress` 不同                            | `nprogress` 是页面顶部进度条，`progress` 是终端进度条，不冲突 |
| `@typescript-eslint/*` 和 `@vue/eslint-config-typescript` | 已有 `typescript-eslint` 的情况下，`@vue/eslint-config-typescript` 可能多余，选其一即可 |

**最终建议**：精简掉重复的 `lodash`、`moment`，以及冲突的 ESLint 配置，能让你的 `node_modules` 更干净。

### 二、配置**prettier**

### 四、配置husky

在上面我们已经集成好了我们代码校验工具，但是需要每次手动的去执行命令才会格式化我们的代码。如果有人没有格式化就提交了远程仓库中，那这个规范就没什么用。所以我们需要强制让开发人员按照代码规范来提交。

要做到这件事情，就需要利用husky在代码提交之前触发git hook(git在客户端的钩子)，然后执行`pnpm run format`来自动的格式化我们的代码。

安装`husky`

```
pnpm install -D husky
```

执行

```
要先git init，创建git仓库
npx husky init
```

会在根目录下生成个一个.husky目录，在这个目录下面会有一个pre-commit文件，这个文件里面的命令在我们执行commit的时候就会执行

在`.husky/pre-commit`文件添加如下命令：

```
#!/usr/bin/env sh
. "$(dirname -- "$0")/_/husky.sh"
pnpm run format
```

当我们对代码进行commit操作的时候，就会执行命令，对代码进行格式化，然后再提交。

### 五、配置commitlint

对于我们的commit信息，也是有统一规范的，不能随便写,要让每个人都按照统一的标准来执行，我们可以利用**commitlint**来实现。

安装包

```
pnpm add @commitlint/config-conventional @commitlint/cli -D
```

添加配置文件，新建`commitlint.config.cjs`(注意是cjs)，然后添加下面的代码：

```
module.exports = {
  extends: ['@commitlint/config-conventional'],
  // 校验规则
  rules: {
    'type-enum': [
      2,
      'always',
      [
        'feat',
        'fix',
        'docs',
        'style',
        'refactor',
        'perf',
        'test',
        'chore',
        'revert',
        'build',
      ],
    ],
    'type-case': [0],
    'type-empty': [0],
    'scope-empty': [0],
    'scope-case': [0],
    'subject-full-stop': [0, 'never'],
    'subject-case': [0, 'never'],
    'header-max-length': [0, 'always', 72],
  },
}
```

在`package.json`中配置scripts命令

```
# 在scrips中添加下面的代码
{
"scripts": {
    "commitlint": "commitlint --config commitlint.config.cjs -e -V"
  },
}
```

配置结束，现在当我们填写`commit`信息的时候，前面就需要带着下面的`subject`

```
'feat',//新特性、新功能
'fix',//修改bug
'docs',//文档修改
'style',//代码格式修改, 注意不是 css 修改
'refactor',//代码重构
'perf',//优化相关，比如提升性能、体验
'test',//测试用例修改
'chore',//其他修改, 比如改变构建流程、或者增加依赖库、工具等
'revert',//回滚到上一个版本
'build',//编译相关的修改，例如发布版本、对项目构建或者依赖的改动
```

配置husky

```
npx husky add .husky/commit-msg （已被废弃）
********************************************************************************************************************************
直接手动进入 .husky 文件夹，新建文件 commit-msg，粘贴下面全部内容：
#!/usr/bin/env sh
. "$(dirname -- "$0")/_/husky.sh"

pnpm commitlint
```

在生成的commit-msg文件中添加下面的命令

```
#!/usr/bin/env sh
. "$(dirname -- "$0")/_/husky.sh"
pnpm commitlint
```

当我们 commit 提交信息时，就不能再随意写了，必须是 git commit -m 'fix: xxx' 符合类型的才可以，**需要注意的是类型的后面需要用英文的 :，并且冒号后面是需要空一格的，这个是不能省略的**

### 六、强制使用pnpm包管理器工具

团队开发项目的时候，需要统一包管理器工具,因为不同包管理器工具下载同一个依赖,可能版本不一样,

导致项目出现bug问题,因此包管理器工具需要统一管理！！！

在根目录创建`scritps/preinstall.js`文件，添加下面的内容

```
if (!/pnpm/.test(process.env.npm_execpath || '')) {
  console.warn(
    `\u001b[33mThis repository must using pnpm as the package manager ` +
    ` for scripts to work properly.\u001b[39m\n`,
  )
  process.exit(1)
}
```

配置命令

```
"scripts": {
	"preinstall": "node ./scripts/preinstall.js"
}
```

**当我们使用npm或者yarn来安装包的时候，就会报错了。原理就是在install的时候会触发preinstall（npm提供的生命周期钩子）这个文件里面的代码。**

## 3.7axios二次封装

在开发项目的时候避免不了与后端进行交互,因此我们需要使用axios插件实现发送网络请求。在开发项目的时候

我们经常会把axios进行二次封装。

目的:

1:使用请求拦截器，可以在请求拦截器中处理一些业务(开始进度条、请求头携带公共参数)

2:使用响应拦截器，可以在响应拦截器中处理一些业务(进度条结束、简化服务器返回的数据、处理http网络错误)

在根目录下创建utils/request.ts

```
import axios from "axios";
import { ElMessage } from "element-plus";
//创建axios实例
let request = axios.create({
    baseURL: import.meta.env.VITE_APP_BASE_API,
    timeout: 5000
})
//请求拦截器
request.interceptors.request.use(config => {
    return config;
});
//响应拦截器
request.interceptors.response.use((response) => {
    return response.data;
}, (error) => {
    //处理网络错误
    let msg = '';
    let status = error.response.status;
    switch (status) {
        case 401:
            msg = "token过期";
            break;
        case 403:
            msg = '无权访问';
            break;
        case 404:
            msg = "请求地址错误";
            break;
        case 500:
            msg = "服务器出现问题";
            break;
        default:
            msg = "无网络";

    }
    ElMessage({
        type: 'error',
        message: msg
    })
    return Promise.reject(error);
});
export default request;
```

>
> **作用**：Axios封装：create实例（baseURL/timeout），请求拦截器（加token/loading），响应拦截器（统一错误处理/解包data/刷新token）。
>
> **原理**：统一错误处理，业务代码不直接用axios。

## 全局组件的逐名词解释

```typescript
install(app: any) {
    Object.keys(allGlobalComponents).forEach((component: string) => {
        app.component(component, allGlobalComponents[component as keyof typeof allGlobalComponents])
    })
}
```

---

### 1. `install` — Vue 插件安装方法
- **类型**：方法名
- **作用**：这是 Vue 插件的**入口方法**。当你在 `main.ts` 中写 `app.use(插件)` 时，Vue 会**自动调用**这个 `install` 方法，并把 `app` 实例传进来。
- 没有 `install`，`app.use()` 就没法工作。

---

### 2. `app` — Vue 应用实例
- **类型**：参数（`any`）
- **作用**：代表整个 Vue 应用的根实例。它提供了全局 API，比如：
  - `app.component()` — 注册全局组件
  - `app.directive()` — 注册全局指令
  - `app.use()` — 安装插件

## 关于 Vite 环境变量的命名，答案分两种情况：

---

### 1. 想在客户端代码中使用（`import.meta.env.xxx`）

**不可以**，必须以 `VITE_` 开头。

Vite 出于**安全考虑**，默认只暴露以 `VITE_` 为前缀的环境变量给客户端代码。这是为了防止意外地将敏感的环境变量（如数据库密码、API 密钥等）泄露到浏览器端。

```typescript
// ✅ 可以访问

import.meta.env.APP_BASE_API
```

---

### 2. 只在 Vite 配置文件中使用（`vite.config.ts`）

**可以**，不需要 `VITE_` 前缀。

在 `vite.config.ts` 中，你可以通过 `loadEnv()` 或 `process.env` 直接访问所有环境变量，因为它们运行在 Node.js 服务端，不会暴露给浏览器：

```typescript
// vite.config.ts
import { defineConfig, loadEnv } from 'vite'

export default defineConfig(({ mode }) => {
  const env = loadEnv(mode, process.cwd())
  // 可以访问任意名称，不需要 VITE_ 前缀
  console.log(env.APP_BASE_API)  // 可以访问
})
```

作用：对原生 axios 做实例封装，统一处理请求头token、接口超时、响应数据简化、全局错误提示，项目所有接口都导入这个 `request` 发送请求，不用每个接口重复写基础配置。

\2. `import { ElMessage } from 'element-plus'`：导入ElementPlus消息提示组件，接口报错的时候弹出错误提示框给用户看
\3. `import useUserStore from '@/store/modules/user'`：导入Pinia用户仓库，用来拿到登录存储的token，请求的时候带给后端
\---
\## 1. 创建axios实例
\```typescript
//第一步:利用axios对象的create方法,去创建axios实例(其他的配置:基础路径、超时的时间)
const request = axios.create({
  //基础路径
  baseURL: import.meta.env.VITE_APP_BASE_API, //基础路径上会携带/api
  timeout: 5000, //超时的时间的设置

\```
\- `axios.create()`：创建一个独立axios实例，**不会修改全局axios**，可以自定义基础配置。
\- `baseURL`：接口基础地址。
  \- `import.meta.env.VITEAPPBASEAPI` 是Vite环境变量，一般 `.env` 文件配置为 `/api`
  \- 最终效果：调用接口 `/login`，真实请求地址拼接成 `/api/login`，配合vite代理转发后端接口。
\- `timeout:5000` 请求超时时间，单位毫秒。接口5秒没有返回结果，直接判定请求超时，触发错误回调。
\> 💡区别：直接`axios.get()`用的是全局实例；这里`request`是自定义实例，项目全部接口使用`request`。
\---
\## 2. 请求拦截器 `request.interceptors.request.use`
每次**发送请求之前自动执行**，统一处理请求头。
\```typescript
request.interceptors.request.use((config) => {
  //获取用户相关的小仓库:获取仓库内部token,登录成功以后携带给服务器
  const userStore = useUserStore()
  if (userStore.token) {
​    config.headers.token = userStore.token
  }
  //config配置对象,headers属性请求头,经常给服务器端携带公共参数
  //返回配置对象
  return config
})
\```
\- `config`：请求配置对象，包含请求url、method、headers请求头等信息，**必须return config，否则请求发不出去**。
\- `const userStore = useUserStore()` 获取pinia用户仓库实例。
\- 判断仓库存在token，把token放到请求头 `headers.token`，每一次接口请求自动带上身份凭证，后端用来识别登录用户。
\> ⚠️注意：后端约定token字段名，如果后端要 `Authorization`，就要改成 `config.headers.Authorization = `Bearer ${token}``。
\---
\## 3. 响应拦截器 `request.interceptors.response.use`
接口收到后端返回后，**统一处理返回结果和错误**，接收两个回调：
\1. 第一个回调：**http状态码2xx 成功**
\2. 第二个回调：**http状态码非2xx，网络错误、超时、断网都会进入error回调*
\```typescript
request.interceptors.response.use(
  (response) => {
​    //成功回调
​    //简化数据
​    return response.data
  },
\```
✅成功回调：
原生axios拿到的response是完整响应对象：`{status, headers, data:{后端返回真正数据}}`
`return response.data`：直接把后端返回的真实数据抛出去。
\> 使用的时候就不用每次写 `.data`：
\> `const res = await request.get('/xxx')` res直接就是后端返回的数据，而不是完整axios响应对象。
\### error失败回调（重点）
\```typescript
  (error) => {
​    //失败回调:处理http网络错误的
​    //定义一个变量:存储网络错误信息
​    let message = ''
​    //判断error.response是否存在,防止Cannot read properties of undefined
​    if (error.response) {
​      //http状态码
​      const status = error.response.status

​        case 401:
​          message = 'TOKEN过期'
​          break
​        case 403:
​          message = '无权访问'
​          break
​        case 404:
​          message = '请求地址错误'
​          break
​        case 500:
​          message = '服务器出现问题'
​          break
​        default:
​          message = '网络出现问题'
​          break
​      }
​    } else {
​      //error.response为undefined时(如网络断开、超时、后端服务不可达)
​      message = '网络连接失败,请检查网络或后端服务是否正常'
​    }
​    //提示错误信息
​    ElMessage({
​      type: 'error',
​      message,
​    })
​    return Promise.reject(error)
  },
)
\```
\- `error`：axios错误对象。
  \- ✅`error.response`存在：代表后端收到请求，返回http错误状态码（401/403/404/500）。
  \- ❌`error.response === undefined`：**没有收到后端响应**。场景：断网、超时、后端服务挂掉、跨域。
\- switch 根据HTTP状态码，给用户友好中文提示。
\- `ElMessage`弹出element-plus错误消息提示。
\- `return Promise.reject(error)`：**必须写！**
把错误继续向外抛出，业务页面中 `try catch` 才可以捕获接口异常；如果不写，页面会误以为接口成功。
\> 如果不写`Promise.reject(error)`，页面await请求不会抛异常，try{}catch(){}捕获不到错误。

## VITE_APP_BASE_API是什么

`VITE_APP_BASE_API` 是 **Vite 的环境变量**。
```js
baseURL: import.meta.env.VITE_APP_BASE_API
```
`import.meta.env` 是 Vite 专门用来读取环境变量的对象。

> ✅规则：Vite环境变量，**必须以 `VITE_` 开头**，否则读取不到。

### 1.写在哪里？
项目根目录新建环境文件：
- `.env`：所有环境都会读取
- `.env.development` 开发环境（npm run dev）
- `.env.production` 生产环境（npm run build打包）

示例 `.env.development`（开发环境）
```env
# .env.development
VITE_APP_BASE_API='/api'
```

`.env.production`（打包上线）
```env
# .env.production
VITE_APP_BASE_API='http://192.168.xxx:8080'
```

---

### 2.代码中发生了什么
当 `.env.development` 设置 `VITE_APP_BASE_API=/api`
```js
const request = axios.create({
  baseURL: import.meta.env.VITE_APP_BASE_API, //等价于 '/api'
  timeout:5000
})
```

假如调用接口：
```js
request.get('/user/list')
```
axios会自动拼接 baseURL，最终请求地址：`/api/user/list`

### 🧩开发环境配合Vite代理
前端浏览器实际访问 `/api/user/list`，前端本身没有这个接口，所以需要 vite.config.ts 配置代理，把 `/api`转发给真实后端地址：
```ts
//vite.config.ts
export default defineConfig({
  server:{
    proxy:{
      '/api':{
        target:'http://后端真实地址:8080',
        changeOrigin:true,
        rewrite:path=>path.replace(/^\/api/,'')
      }
    }
  }
})
```
流程：
1. 前端请求 `/api/user/list`
2. vite开发服务器代理拦截 `/api`
3. 去掉`/api`，转发给后端：`http://后端真实地址:8080/user/list`

> 开发环境用 `/api`，利用代理解决跨域问题。

### 生产环境
打包后没有vite代理，此时 `VITE_APP_BASE_API`直接填写后端完整域名地址，例如：
```env
VITE_APP_BASE_API='https://api.xxx.com'
```
接口请求就变成：`https://api.xxx.com/user/list`

1. 变量名**必须VITE_开头**，比如 `VITE_APP_BASE_API`，写 `APP_BASE_API`（没有VITE_）读取不到，值是`undefined`。

3. `import.meta.env` 只能在源码中使用，浏览器控制台打印看不到。

## import.meta 完整讲解

### 1、什么是 ES Module（ES模块）
现代 Vue3 + Vite 项目里所有 `.js/.ts` 文件都是 **ES模块**。
文件开头写 `import xxx from 'xxx'`、`export default xxx`，就是ES模块的标志。

> 在浏览器原生的 ES模块 中，每一个 js 模块，都自带一个特殊对象：**`import.meta`**
> ✅ `import.meta` 是 JS语言标准，不是Vite创造的。

### 原生JS自带属性：`import.meta.url`
新建一个js模块：
```js
// src/demo.js
console.log(import.meta)
console.log(import.meta.url)
```
运行打印：
```
{url: 'http://127.0.0.1:5173/src/demo.js'}
http://127.0.0.1:5173/src/demo.js
```
👉 `import.meta.url`：**获取当前这个js文件完整访问地址**。

原生JS里，`import.meta` 就**只有 url 这一个属性，没有 env！**

---

### 2、那 `import.meta.env` 哪里来的？
> ⚠️重点：**`.env` 是 Vite 给 `import.meta` 对象额外加上的属性！JS原生没有！**

#### Vite做了两件事：
1. 读取项目根目录下的环境文件：`.env`、`.env.development`、`.env.production`
2. 把所有以 `VITE_` 开头的变量，打包放到 `import.meta.env` 上。

举例子：
`.env.development`（根目录，和package.json同级）
```env
VITE_APP_BASE_API="/api"
VITE_APP_TITLE="后台管理系统"
```

Vite编译代码的时候，会把你的源码：
```js
baseURL: import.meta.env.VITE_APP_BASE_API
```
直接替换成字符串：
```js
baseURL: "/api"
```
> ✨注意：这是**编译期静态替换**，不是运行时读取对象。
> 所以浏览器控制台直接敲 `import.meta.env` 是看不到完整对象的。

#### Vite自带内置环境变量（不用自己写.env）
```ts
import.meta.env.MODE     // 字符串，当前环境：development / production
import.meta.env.DEV      // boolean，true=开发环境(npm run dev)
import.meta.env.PROD     // boolean，true=生产环境(npm run build)
import.meta.env.BASE_URL // 项目部署的基础路径
```

示例使用：
```ts
if(import.meta.env.DEV){
  console.log('✅现在是开发环境，可以打印调试日志')
}
if(import.meta.env.PROD){
  console.log('✅现在是打包后的生产环境，关闭调试')
}
```

### 3、对比老Vue2(webpack)的 process.env
Vue2 + webpack 项目写：
```js
process.env.VUE_APP_BASE_API
```
- `process` 是 Node.js 的全局变量，浏览器本身没有 `process`。
- webpack内部做模拟，把环境变量挂载到 `process.env`。

Vite 抛弃了 `process.env`，选择使用JS标准的 `import.meta`：
```js
import.meta.env.VITE_APP_BASE_API
```

| 技术 | 读取环境变量 | 变量前缀 |
|------|-------------|---------|
| Vue2+Webpack | `process.env.xxx` | `VUE_APP_` |
| Vue3+Vite | `import.meta.env.xxx` | `VITE_` |

> ❗不要在vite写 `process.env.VITE_APP_BASE_API`，拿不到值！

## Vite 到底是什么？

❌**不是编译器**。先分清几个名词：编译器、打包工具、开发服务器。

> Vite = **下一代前端构建工具**，由尤雨溪开发，专门给 Vue3 / React 等现代前端项目用。

它由两大部分组成：

1. **开发服务器（Dev Server）** → `npm run dev` 用
2. **构建打包工具（Build）** → `npm run build` 打包上线用

### 1. 先搞懂什么叫「编译器」

编译器：把A语言翻译成B语言。

- TS编译器 `tsc`：TypeScript → JavaScript
- Babel：高版本JS/ES6+ → 低版本ES5 JS

👉Vite**本身不是编译器**，它内部会调用 esbuild 做编译转译。

### 2. Vite开发模式：npm run dev（开发阶段）

老工具 Webpack：**启动时就把所有源码全部编译打包成一堆bundle文件**，再给浏览器使用。项目大的时候启动慢、热更新慢。

**Vite开发服务器核心：基于浏览器原生 ES Module（import/export）**

> 浏览器原生就支持 import 导入js文件！Vite开发服务器不提前打包全部代码。

1. 浏览器请求 `index.html`
2. html里面遇到 `import xxx from './xxx'`，浏览器直接发网络请求去请求这个js模块
3. Vite的开发服务器接收到浏览器的模块请求，**按需实时处理这个文件**：
   - `.ts/.vue` 文件：交给 `esbuild`（Go写的极速编译器）把ts/vue编译成浏览器能识别的js
   - `.css` 处理样式
4. 处理完直接返回给浏览器。

> 💡特点：**不用启动时打包全部代码**，启动飞快；改哪个文件就处理哪个，热更新速度极快。

> 你之前的 `import.meta.env`，就是 Vite Dev Server 在**请求模块的时候，把环境变量注入到代码里返回给浏览器**。

> ⚠️浏览器原生ES模块有短板：不能直接导入 `.vue`、`.ts`，浏览器不认识，所以中间必须有Vite服务做中转处理。

### 3. Vite打包模式：npm run build（生产打包）

浏览器原生ES Module不适合直接上线（会产生大量网络请求，性能差）。

所以打包阶段，Vite **内部调用 Rollup（真正的打包器）**，把所有源码、依赖全部打包压缩合并成少量 js/css 文件，输出 `dist` 文件夹，放到服务器部署。

> 总结：

> - 开发环境：Vite DevServer + esbuild（转译），**不打包全部代码，按需处理**

> - 生产打包：Vite 调用 Rollup 做打包构建

### 4. 角色对比表

|工具|角色|作用|

|---|---|---|

|esbuild|**编译器/转译器**|ts/vue → js，速度极快，Vite开发阶段用它|

|Rollup|**打包工具**|把零散模块合并压缩，Vite打包阶段底层用Rollup|

|Vite|**前端构建工具**|整合 esbuild + Rollup，提供dev服务、插件系统、环境变量处理、文件处理，给你一套完整项目工程化能力|

|Webpack|老牌构建工具|开发用webpack‑dev‑server，打包自己做；全部阶段都提前打包|

#### 通俗比喻

- esbuild：翻译官，把浏览器看不懂的ts/vue翻译成js。
- Rollup：打包工人，把一堆零散js文件压缩合并成上线包。
- **Vite：包工头**，把翻译官、打包工人组织起来，提供一套完整工作流程，处理环境变量、代理、插件、静态资源等杂活。

### 5. 回到你前面的代码串联理解

```js
baseURL: import.meta.env.VITE_APP_BASE_API
```

1. 运行 `npm run dev`，启动Vite开发服务器。
2. Vite读取根目录 `.env.development`。
3. 浏览器请求 `request.js` 文件，Vite捕获这个请求，把源码中 `import.meta.env.VITE_APP_BASE_API` 替换成字符串`"/api"`，再返回js代码给浏览器执行。
4. 浏览器拿到处理后的js运行。

当你执行 `npm run build`，Vite调用Rollup打包，同样做变量替换，输出dist文件夹。

### 容易混淆的几个概念小结

1. ✅**转译器（编译器）**：esbuild、babel、tsc，负责语法转换。
2. ✅**打包器**：rollup、webpack，负责把很多小文件合并成少量文件。
3. ✅**开发服务器**：提供本地http服务，处理浏览器的模块请求。
4. ✅**构建工具Vite**：整合上面三者，一套命令搞定开发、打包。

> Vite不是单纯编译器，也不是单纯打包器，它是**完整前端构建工具**。

### 补充小知识点
- 为什么Vite开发快？开发阶段不用一次性打包全部代码，浏览器需要哪个模块，Vite才处理哪个。
- webpack不管你用不用，启动就把全部代码打包一遍，项目越大启动越慢。

## 浏览器原生 ES Module（ESM）完整讲解

Vite 的核心魔力就建立在浏览器原生支持 ES Module 这个特性之上

### 1. 什么是 ES Module

以前浏览器引入 JS 只能用普通 `<script>`标签：

```html
<!-- 老式脚本，全局作用域，没有 import/export -->
<script src="a.js"></script>
```

这种脚本没有模块能力，变量全部泄露到全局，无法直接写 `import` / `export`。

后来浏览器实现了 **ES Module（ESM）**，只需要给 script 加上 `type="module"`：

```html
<!-- 浏览器原生ES模块 -->
<script type="module" src="/main.js"></script>
```

此时 `main.js` 就变成模块文件，就可以写：

```js
// main.js
import { foo } from './b.js'
console.log(foo)
export const num = 10
```

> ✔关键点：

1. 模块内部变量**不会泄露到window全局**，每个模块拥有独立作用域。
2. `import` 导入其他 js 文件，浏览器会**自动发送网络请求**去下载这个文件。
3. 浏览器原生只认识 js，**不认识 .ts、.vue 文件**。

#### 举个浏览器原生请求流程

index.html

```html
<script type="module" src="./main.js"></script>
```

main.js

```js
import { fn } from './utils.js'
fn()
```

浏览器加载流程：

1. 请求 `index.html`
2. 看到 `<script type="module" src="./main.js">`，发起请求下载 `main.js`
3. 解析 main.js，发现里面写了 `import './utils.js'`
4. **浏览器自动发出第二个网络请求，下载 utils.js**
5. 全部加载完成后执行代码。

👉每一个 `import`，都会产生一次浏览器网络请求。

这就是 **原生ESM的运行机制**。Vite开发服务器就是利用这套浏览器原生能力。

---

### 2. Vite 开发模式如何利用原生ESM（npm run dev）

> 注意：浏览器不能直接读取本地磁盘文件，必须要有 http 服务，Vite就提供这个http服务。

你的项目源码：

```
src/
 ├─main.ts
 └─utils/request.js
```

浏览器是看不懂 `.ts`、`.vue` 的。浏览器只认 JS。

**Vite Dev Server 充当中间服务器：**

1. 浏览器请求 `index.html`，里面引入 `<script type="module" src="/src/main.ts">`
2. 浏览器发起网络请求：`GET /src/main.ts`
3. 请求到达 Vite 开发服务器。Vite 在磁盘找到 `main.ts`。
4. 调用 **esbuild（转译器）**：把 ts 编译成浏览器可识别的 JS。
5. Vite 还做额外处理：把代码里的 `import.meta.env.VITE_APP_BASE_API`替换成实际字符串。
6. Vite把处理完的 JS 返回给浏览器。
7. 浏览器拿到 JS，解析代码，看到里面又有很多 `import xxx`，继续发新请求。
8. 每一个 import 都会触发一次请求，Vite按需处理对应的文件。

> 📌核心：**Vite开发环境不会一次性把所有文件打包合并。浏览器需要哪个文件，Vite就处理哪个。**

> 项目再大，启动速度几乎不受影响。

#### 对比 Webpack（老方案）

webpack‑dev‑server：启动项目的时候，**把项目所有源码全部打包编译成一大捆js**，再交给浏览器。

项目越大，文件越多，启动越慢，热更新也慢。

---

### 3. 但是原生ESM有很大缺点，所以上线不能直接用

开发环境可以用原生ESM，**生产打包不能直接这么跑**，原因：

假设你的项目有300个模块。

浏览器原生ESM运行，会触发**300次http请求**。

- 网络请求是昂贵的，大量小文件请求会造成网络开销，页面打开很慢。
- 没有压缩、没有Tree‑shaking优化，代码体积大。

👉所以执行 `npm run build` 的时候，Vite**放弃原生ESM模式**，调用底层的 **Rollup打包器**。

Rollup做的事情：

1. 把几百个零散模块合并、压缩、Tree‑shaking删除无用代码。
2. 输出少量压缩后的 js/css 文件到 dist 文件夹。
3. dist里面的代码是处理完成的静态资源，可以直接丢nginx部署。

> 简单记：

> - 🧑‍💻开发 `npm run dev`：浏览器原生ESM + Vite服务器 + esbuild按需转译

> - 🚀上线 `npm run build`：Rollup打包合并压缩，输出dist产物

---

### 4. 结合你axios封装的完整链路复盘

文件：`src/utils/request.js`

```js
const request = axios.create({
  baseURL: import.meta.env.VITE_APP_BASE_API,
  timeout:5000
})
```

#### 开发环境(npm run dev)

1. 浏览器请求某个页面，触发导入 `request.js`
2. http请求打到Vite开发服务器
3. Vite读取`.env.development`拿到`VITE_APP_BASE_API="/api"`
4. 把源码中 `import.meta.env.VITE_APP_BASE_API` 替换成字符串`"/api"`
5. 返回处理完成的JS给浏览器运行。

#### 打包环境(npm run build)

1. Vite调用Rollup，读取`.env.production`
2. Rollup编译阶段直接替换环境变量，压缩代码。
3. 输出dist，里面已经是替换完成的静态JS，不再需要Vite服务。

### 5. 几个容易混淆概念再总结一遍

1. **ES Module（ESM）**：浏览器原生模块标准，`import/export`，script要加`type="module"`。浏览器自己会发请求加载模块。
2. **esbuild**：Go语言写的高速转译器，ts/vue → js，Vite开发阶段用它。
3. **Vite Dev Server**：http服务，拦截浏览器ESM请求，交给esbuild处理源码，注入环境变量、代理接口。**开发阶段使用。**
4. **Rollup**：打包工具，把零散模块合并压缩，Vite打包底层依赖它。
5. **Vite**：构建工具，整合 dev服务 + esbuild + rollup，提供插件、环境变量、代理等整套工程能力。

## vite.config.ts 完整讲解（Vue3+Vite）

> 文件位置：项目根目录，和 `package.json`、`.env.development` 同级。
> 作用：Vite 的配置文件，控制开发服务器、代理、打包、插件、路径别名等。

### 完整常用模板
```ts
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import path from 'path'

// 
export default defineConfig({
  // 插件数组
  plugins: [vue()],

  // 开发服务器配置 npm run dev
  server: {
    host: '0.0.0.0', // 允许局域网访问，手机可以访问本机项目
    port: 5173,      // 本地端口
    open: true,      // 启动后自动打开浏览器
    proxy: {
      /**
       * /api 是请求前缀
       * 当前端请求 /api/xxx 就触发代理
       */
      '/api': {
        target: 'http://localhost:8080', // 后端真实接口地址
        changeOrigin: true, // 开启跨域，模拟后端来源
        rewrite: (path) => path.replace(/^\/api/, '')
        // rewrite：把请求路径开头的 /api 删掉
        // 前端：/api/login → 转发后端：http://localhost:8080/login
      }
    }
  },

  // 路径别名 @
  resolve: {
    alias: {
      '@': path.resolve(__dirname, './src')
      // @ 等价于 src文件夹，所以 import xxx from '@/utils/request'
    }
  },

  // 打包构建配置 npm run build
  build: {
    outDir: 'dist', // 输出文件夹名称，默认dist
    assetsDir: 'static', // js/css/img静态资源存放目录
  },

  // 环境变量相关不需要在这里写，交给 .env 文件
})
```

---

### 逐块拆解

#### 1. defineConfig
```ts
import { defineConfig } from 'vite'
export default defineConfig({ /*配置*/ })
```
- `defineConfig`：Vite提供工具函数，主要给TS提供类型提示，写配置的时候有代码提示。
- 你直接写对象也可以，但是没有类型提示，不推荐。

2. ### plugins 插件

```ts
import vue from '@vitejs/plugin-vue'
plugins: [vue()]
```
- `@vitejs/plugin-vue`：Vite识别`.vue`单文件组件的插件，**vue项目必须要有**。
没有这个插件Vite看不懂`.vue`文件。

> 其他插件例子：element-plus自动导入、svg图标插件等都写在这里。

#### 3. server → 开发服务器配置（npm run dev）
```ts
server: {
  host: '0.0.0.0',
  port: 5173,
  open: true,
  proxy: {
    '/api': {
      target: 'http://localhost:8080',
      changeOrigin: true,
      rewrite: (path) => path.replace(/^\/api/, '')
    }
  }
}
```
1. `host:'0.0.0.0'`
   默认localhost，只能本机访问。设置`0.0.0.0`，同一局域网其他设备（手机、别的电脑）可以通过你的电脑ip访问项目。
2. `port:5173`：本地启动端口，默认5173，如果端口被占用会自动换端口。
3. `open:true`：运行`npm run dev`自动打开浏览器。

#### ✨proxy代理（重点，和你axios封装强关联）

```ts
'/api': {
  target: 'http://localhost:8080',
  changeOrigin: true,
  rewrite: (path) => path.replace(/^\/api/, '')
}
```
结合你的axios：
```js
baseURL: import.meta.env.VITE_APP_BASE_API //值为 "/api"
```
业务调用：
```js
request.post('/login')
//axios拼接baseURL → 请求地址：/api/login
```

代理执行流程：
1. 浏览器发起请求：`http://localhost:5173/api/login`
2. Vite开发服务器拦截以`/api`开头的请求
3. `changeOrigin:true` 修改请求头来源，解决后端跨域校验问题，**几乎必开**
4. `rewrite`：正则把路径最开头的`/api`替换为空字符串
5. 转发给后端真实地址：`http://localhost:8080/login`

> ⚠️注意：**代理只在开发环境生效！打包之后(npm run build)proxy完全失效！**
打包后要在 `.env.production` 填写完整后端域名地址。

##### 两种常见后端接口情况

###### 情况1：后端接口本身不带/api（上面模板就是）
前端请求`/api/login`，转发后端`/login`，需要`rewrite`去掉/api。

###### 情况2：后端接口本身就带/api，后端地址 ``
那就不要rewrite，删掉rewrite这一行：
```ts
'/api': {
  target: 'http://localhost:8080',
  changeOrigin: true
  // 不写rewrite，/api会保留
  //前端/api/login → http://localhost:8080/api/login
}
```

#### 4. resolve 路径别名 alias
```ts
import path from 'path'
resolve: {
  alias: {
    '@': path.resolve(__dirname, './src')
  }
}
```
- `__dirname`：vite.config.ts文件所在目录（项目根目录）
- `path.resolve(__dirname,'./src')`拼接得到src文件夹绝对路径。
- `@`就映射到src文件夹。

所以你代码中：
```js
import useUserStore from '@/store/modules/user'
//等价于
import useUserStore from './src/store/modules/user'
```
> TS项目还需要在tsconfig.json配置paths，否则ts会报找不到模块。

#### 5. build 打包配置 `npm run build`
```ts
build: {
  outDir: 'dist',
  assetsDir: 'static'
}
```
- `outDir`：打包输出文件夹，默认dist。执行build生成dist文件夹。
- `assetsDir`：js、css、图片等资源放到dist/static下面。

打包完成后dist文件夹就是纯粹静态文件，**不需要Vite也可以运行**，丢Nginx部署。

### 🧩环境变量和vite.config关系
> ⚠️重要提醒：`vite.config.ts`里面**不能直接用`import.meta.env`！**
原因：
- vite.config.ts是Vite在node环境执行，属于Node.js代码。
- `import.meta.env`只存在浏览器源码环境。

vite.config.ts如果想读取.env变量，要用vite提供的`loadEnv`函数。
```ts
import { defineConfig, loadEnv } from 'vite'

export default defineConfig(({mode})=>{
  // mode 是 development / production
  const env = loadEnv(mode, process.cwd())
  console.log(env.VITE_APP_BASE_API)
  return {
    //配置写这里
  }
})
```
