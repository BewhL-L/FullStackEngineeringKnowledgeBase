# API 设计文档模板

## 一、概述
标准化API设计文档模板，确保接口设计清晰、完整、可追溯，是前后端协作和接口维护的基础。

## 二、模板结构
```markdown
# API设计文档：[模块名]

## 1. 概述
- 接口用途
- 调用方
- 版本：v1.0
- 基础URL：/api/v1/[module]

## 2. 接口列表
| 方法 | 路径 | 说明 | 鉴权 |
|------|------|------|------|

## 3. 接口详情
### 3.1 [接口名]
- 请求：POST /api/v1/[module]/[action]
- 请求头：Authorization: Bearer {token}
- 请求体：
\`\`\`json
{ "field": "类型", "description": "说明" }
\`\`\`
- 响应体：
\`\`\`json
{ "code": 200, "message": "success", "data": {} }
\`\`\`
- 错误码：400参数错误, 401未授权, 404不存在

## 4. 数据模型
## 5. 变更记录
```

## 三、实操示例
遵循RESTful规范：资源名用名词复数，HTTP方法对应CRUD，状态码语义正确，统一响应格式。

## 四、常见问题与排查
- 接口变更未通知 → 版本化+变更记录+通知机制
- 文档与实现不一致 → 从代码生成OpenAPI文档
- 缺少错误码定义 → 统一错误码表

## 五、进阶与最佳实践
- OpenAPI/Swagger规范，从文档生成代码
- Apifox管理：文档+Mock+测试一体化
- API变更评审：Breaking Change需审批
- 示例请求/响应：每个接口提供真实示例
