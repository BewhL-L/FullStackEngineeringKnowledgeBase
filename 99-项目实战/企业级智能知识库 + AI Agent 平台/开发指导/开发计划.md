代码工程已经**提前搭好完整骨架与大部分高级能力**，所以你不是「对着空白文件从零敲」，而是按下述方式学习：

**已在工程中落地的能力**（`产品/` 目录）：

- 基础 RAG 全链路 + Agentic RAG（Agent 自主检索、流式、限流 / 重试 / 缓存）
- **P0**：混合检索（BM25 + 向量 + RRF + Rerank + 查询改写）、上下文工程（记忆 / 压缩 / 预算）、RAG 评测体系（golden QA + 指标 + LLM 裁判 + RAGAS 接口）、MCP Server
- **P1**：Langfuse 可观测、LangGraph 三种编排、Redis / Celery / Postgres 生产化、Prompt 注入防护
- **P2**：A2A 协议、多模态解析（OCR / VLM / 表格）、微调脚本与选型文档
- 后端 47 个 pytest 全绿；前端按需构建、无体积警告

**仍然必须由你亲自完成的部分（AI 替代不了）**：

1. 逐行读懂上述模块，能白板手写 BM25、RRF、Hit@K / MRR、Agent 循环
2. 自己标注 / 扩充 golden QA，真实跑通「评测 → 定位问题 → 优化 → 指标提升」
3. 注册真实 LLM Key，把项目跑起来，用真实数据走查所有页面
4. 部署上线、写技术博客、按面试材料演练两版话术
5. 在骨架上做 1-2 个自主扩展（见下文每月任务与面试材料 Q10）

## 六、AI 使用指南

### AI 使用基本原则
**AI 辅助 + 自己理解，70% 自己写，30% 用 AI 提效**

完全手敲太慢，10个月做不完；完全靠 AI 面试一问就露馅。正确的姿势是：**AI 帮你省时间，但每一行代码你都要能讲清楚为什么这么写。**

### 可以放心用 AI 的部分（提效用）

| 场景 | 怎么用 | 为什么可以用 |
|------|--------|-------------|
| 写 CRUD 接口 | 让 AI 生成模板，你改字段 | 这种代码没技术含量，写多了浪费时间 |
| 写前端页面布局 | 让 AI 生成 Element Plus 页面 | 组件库用法查文档就行，不用背 |
| 查报错 | 把报错贴给 AI，让它分析 | 比自己搜快 10 倍 |
| 写正则、写工具函数 | 让 AI 生成，你看懂就行 | 这种东西用到再查，不用背 |
| 写 README、注释 | 让 AI 写初稿，你改 | 文档不是技术核心 |

### 必须自己理解、自己写的部分（面试要考）

| 场景 | 为什么必须自己来 |
|------|-----------------|
| **RAG 核心流程** | 检索、切片、拼接 Prompt、生成，这是项目灵魂，面试必问 |
| **数据库表设计** | 表结构、关系、索引，这是后端基本功 |
| **Prompt 设计** | 系统提示词怎么写、Few-shot 怎么加，这是 AI 应用的核心能力 |
| **流式输出实现** | SSE 原理、前后端怎么配合，这是高频考点 |
| **遇到 bug 的排查思路** | 面试一定会问"你遇到过什么最难的问题" |

### 正确的使用姿势

#### 错误姿势（别这么干）
```
❌ 让 AI 把整个项目写完
❌ 复制粘贴，不看代码
❌ 跑起来就不管了
❌ 面试讲不清楚自己写了什么
```

#### 正确姿势（这么干）
```
✅ 先自己想清楚要做什么
✅ 让 AI 给你思路和模板
✅ 自己敲一遍，边敲边理解
✅ 跑不通自己先调，调不出来再问 AI
✅ 每写完一个模块，用自己的话讲一遍
```

### 面试时怎么讲才不露馅？

**不要说：** "这个项目是我用 AI 写的"

**要说：** "这个项目是我独立开发的，开发过程中我用 AI 工具辅助提效，比如生成模板代码、排查报错，但核心的 RAG 流程、Prompt 设计、架构设计都是我自己思考和实现的。"

**面试官真正关心的是：**
1. 你能不能讲清楚原理？
2. 你遇到问题能不能解决？
3. 你来了能不能干活？

只要你能讲清楚，没人在乎你用没用 AI。现在所有公司都在用 AI 写代码，关键是你能不能驾驭它。

### 先自己想清楚要做什么是什么意思？

举个例子：你要做"文档上传"这个功能。

**❌ 错误做法（完全没想清楚就问 AI）**
- 直接问："帮我写一个文档上传功能"
- AI 给你一大段代码，你复制粘贴，跑起来就完事了
- 结果：你根本不知道这段代码干了什么，换个场景就不会了

**✅ 正确做法（先自己想清楚再问 AI）**
1. 你自己先想一遍：用户上传什么格式？存哪里？传完做什么？出错怎么办？
2. 把你想的整理成要求，问 AI 要模板
3. AI 给你代码，你一行一行看
4. 自己敲一遍，改一改，跑通

**总结：** 完全让 AI 写 = 啥也没学到；先自己想清楚再用 AI = 你知道了一个功能要怎么设计。

### 让 AI 给思路和模板是什么意思？

**打个比方：**
- 完全让 AI 写 = 去饭店直接吃别人做好的菜，永远学不会做饭
- 让 AI 给思路和模板 = 厨师教你菜谱，你自己动手炒，你能学会

**具体操作：**
1. **要思路不要代码**："XX 功能的整体流程是什么？分步骤讲一下"
2. **要模板不要完整实现**："给我一个函数模板，参数怎么设计，结构搭出来就行"
3. **自己填实现**：核心逻辑你自己写

### 为什么知识库需要垂直落地？

你以为的：知识库就是通用的，做一个通用的不就行了吗？

**不对。**

#### 通用知识库 = 没有竞争力
面试官会想："这东西谁都能做啊，不就是上传文档 + RAG 吗？我为什么要招你？"

#### 垂直场景 = 有故事可讲
同样是 RAG，你做"电商客服知识库"，面试官会想："哦，他懂电商场景，来了就能上手。"

#### 为什么垂直场景更好找工作？

| | 通用知识库 | 垂直场景知识库 |
|---|---|---|
| 面试官印象 | 哦，做了个玩具 | 哦，懂业务，来了就能用 |
| 可讲的东西 | 很少，就是 RAG | 很多，业务痛点、解决方案 |
| 匹配岗位 | 啥都能投，啥都不突出 | 精准匹配，一投一个准 |
| 竞争 | 一堆人都在做 | 做的人少，你脱颖而出 |

**所以你的项目怎么做？** 核心功能还是 RAG 问答，但包装成垂直场景：
- 投杭州 → 讲"电商客服知识库"
- 投上海 → 讲"企业内部知识助手"

**代码 90% 是一样的，只是面试讲故事不一样。**

### AI 使用黄金原则

**原则1：前期少用，后期多用**
- 前 3 个月打基础，少用 AI
- 后 7 个月做产品，大胆用 AI 提效

**原则2：核心自己写，边缘用 AI**
- 核心逻辑（RAG、Prompt、Agent、表设计）→ 自己写
- 边缘代码（CRUD、布局、样式、部署）→ 用 AI

**原则3：要思路，不要直接要代码**
- ❌ "帮我写个 XX 功能"
- ✅ "XX 功能的思路是什么？分步骤讲一下"

**原则4：AI 给的代码，一行一行看懂**
- 看不懂就继续问："这一行是什么意思？"
- 能讲清楚每一行干嘛的，才算学会了

## 八、风险预案（Plan B）

### 风险一：进度比预期慢
- **表现：** 某个月的任务没完成
- **应对：** 砍掉 P1、P2，先保 P0。核心功能做完，比什么都重要
- **不要做的事：** 不要因为进度慢就焦虑，然后疯狂赶进度，最后什么都没做扎实

### 风险二：找不到工作
- **表现：** 投了 100 家没有面试
- **应对：** 先投小公司、外包公司过渡，骑驴找马。先入行，再跳槽
- **不要做的事：** 不要考研逃避，不要在家蹲半年

### 风险三：技术迭代太快，学的东西过时了
- **表现：** 刚学完，技术栈变了
- **应对：** 学底层能力，不学表层框架。RAG 原理、Prompt 工程、全栈思维，这些不会过时
- **不要做的事：** 不要追新技术追得太累，把一个东西学透，比学十个半吊子强
