# 部署文档

本文档指导你把项目从零部署到云服务器，让项目有公网可访问的链接。

---

## 一、准备工作

### 1. 购买云服务器
- 阿里云 / 腾讯云轻量应用服务器
- 配置：2 核 4G 起步（向量库 + LLM 调用，模型在云端，本地不需要 GPU）
- 系统：Ubuntu 22.04 LTS
- 带宽：3M 以上

### 2. 购买域名（可选）
- 域名备案（国内服务器必须，约 1-2 周）
- 解析到服务器公网 IP

## 二、方式一：Docker 部署（推荐）

### 1. 安装 Docker

```bash
# 一键安装 Docker
curl -fsSL https://get.docker.com | bash

# 启动并设置开机自启
sudo systemctl start docker
sudo systemctl enable docker

# 安装 docker-compose（新版 Docker 自带，可用 docker compose 验证）
docker --version
docker compose version
```

### 2. 上传代码

```bash
# 方式 A：git 克隆
git clone <你的仓库地址> /opt/knowledge-base
cd /opt/knowledge-base/产品

# 方式 B：本地打包上传
scp -r 产品 root@服务器IP:/opt/knowledge-base
```

### 3. 配置环境变量

```bash
cd backend
cp .env.example .env
vi .env
```

修改关键配置：
```ini
# 必须改成随机字符串（生产环境）
SECRET_KEY=用openssl rand -hex 32生成
DEBUG=False

# 填入真实的 LLM API Key
LLM_API_KEY=你的key
LLM_BASE_URL=你的接口地址
LLM_MODEL=你的模型名
EMBEDDING_MODEL=你的向量模型名

# 允许的前端来源
CORS_ORIGINS=http://你的域名
```

### 4. 构建并启动

```bash
cd ..  # 回到 docker-compose.yml 所在目录
docker compose up -d --build
```

查看容器状态：
```bash
docker compose ps
docker compose logs -f backend
```

### 5. 验证
- 访问 `http://服务器IP` 看到前端页面
- 访问 `http://服务器IP/api/health` 返回 healthy

### 6. 常用运维命令

```bash
docker compose restart backend   # 重启后端
docker compose down              # 停止
docker compose up -d             # 启动
docker compose logs -f           # 查看日志
```

## 三、配置 HTTPS（域名 + 证书）

使用 certbot 免费申请 Let's Encrypt 证书：

```bash
sudo apt install certbot
# 先停掉占用 80 端口的服务
sudo certbot certonly --standalone -d your-domain.com
```

证书路径：
- 证书：`/etc/letsencrypt/live/your-domain.com/fullchain.pem`
- 私钥：`/etc/letsencrypt/live/your-domain.com/privkey.pem`

把 `docker/nginx.conf` 里的 HTTPS 配置打开，填入域名和证书路径，然后重启 Nginx。

## 四、方式二：手动部署（不用 Docker）

### 后端
```bash
cd backend
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env  # 编辑配置

# 用 systemd 或 nohup 常驻
nohup uvicorn app.main:app --host 0.0.0.0 --port 8000 > app.log 2>&1 &
```

### 前端
```bash
cd frontend
npm install
npm run build   # 产物在 dist/
```

把 `dist/` 交给 Nginx 托管，配置见 `frontend/nginx.conf`。

### Nginx 安装
```bash
sudo apt install nginx
sudo cp frontend/nginx.conf /etc/nginx/sites-available/knowledge-base
sudo ln -s /etc/nginx/sites-available/knowledge-base /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl restart nginx
```

## 五、数据备份

重要数据都在 `backend/` 下：
- `knowledge_base.db`：SQLite 数据库（用户、知识库、对话记录）
- `uploads/`：上传的原始文档
- `chroma_db/`：向量数据库

备份脚本（可加入 crontab）：
```bash
#!/bin/bash
DATE=$(date +%Y%m%d)
tar -czf /data/backup/kb_$DATE.tar.gz \
  /opt/knowledge-base/产品/backend/knowledge_base.db \
  /opt/knowledge-base/产品/backend/uploads \
  /opt/knowledge-base/产品/backend/chroma_db
```

## 六、常见问题排查

| 问题 | 排查方向 |
|------|---------|
| 前端能打开但接口报错 | 后端容器是否启动；Nginx 代理是否正确 |
| 上传文档后一直处理中 | 看后端日志；多半是 EMBEDDING API Key 没配 |
| 问答报 500 | 检查 LLM_API_KEY、模型名、接口地址是否正确 |
| 流式输出一次性返回 | Nginx 是否关闭了 `proxy_buffering` |
| 上传大文件失败 | Nginx `client_max_body_size`、后端 `MAX_FILE_SIZE_MB` |
| 跨域错误 | 检查 CORS_ORIGINS 配置 |

查看实时日志：
```bash
docker compose logs -f backend
```
