复查：三条债D E S I G N   R E V I E W

方向是对的，问题几乎都出在执行层的三笔债：可点性债、一致性债、可信度债。它们恰好都砸在「证据链」这个立论上——所以修起来优先，也最值。

概念与方向
4.5 / 5主张可记忆，与项目事实咬合
视觉执行
3.5 / 5气质成立，但红色通胀、层级扁平
可读性
3 / 5小字对比度不达标，9px 承载了真信息
交互完整性
3 / 5四处「看起来能点」其实点不动
一致性

评分为主观排序工具，不用于横向比较。共 18 项：P0 六项、P1 八项、P2 四项。

DEBT 01

可点性债

指标、实验行、写作条目、"看深潜"都长得像入口，但四个里三个点不动，一个跳错地方。

DEBT 02

一致性债

规范写「一屏最多三处朱砂」「禁止无限动效」「数字即入口」，原型三条全违反。

DEBT 03

可信度债

「60+ 接口」实际 52；「第 05 周」按 9/28 起算应是第 4 周。以证据为卖点的站，最不能出这种错。

先说成立的①「AI 负责快，我负责对」是能记住、且和 79 个测试强绑定的主张；②宋/等宽/黑三声音阶让页面有案卷感，和「证据链」同构，不是随便套的字体；③墨／纸双主题加朱砂印章，提供了少见的东方编辑气质，绕开了 AI 作品集的紫色模板脸。这三样别动。
01

视觉语言

VISUAL LANGUAGE

气质对了，配额失控了。

V1

朱砂通胀：一屏六处红，红色不再是信号

P0
现状

Work 首屏同时出现六处朱砂：W—01 编号、02 章节号、问题/我的动作/证据三个小标题、混合检索节点、看深潜链接，再加顶部进度线。

规范原文：一屏最多三处 · 配色配额 5%
影响与建议

红色从「行动信号」退化成「装饰色」，视线没有落点，最该被看见的证据链接反而被淹没。

建议：只保留三处——章节号、唯一主行动、印章。三个 h4 改 ink-3 加 2px 左红线；热节点改描边不填充；进度线改 ink。

预期：首屏视觉入口从 6 个收敛到 1 个，主行动可被一眼找到。

V2

整站最核心的「证据」，是视觉权重最低的元素

P0
现状

证据入口是 10px、--fg-3 灰、点状下划线、无内边距的按钮，高度约 17px；而纯装饰的技术 tag 反而更亮。

.ev-link{font-size:10px;color:var(--fg-3);padding:0}
影响与建议

概念说「每个数字都能点开」，视觉上却把它做成了脚注。用户不会点，概念就落空。

建议：证据条提到 11.5px / --fg-2，加左侧 1px 竖线与 8px 内边距；整个指标格变成可点区域，hover 时浮现「查看证据 ↗」。

预期：证据抽屉打开率是本站最该被观察的指标。

V3

小字对比度不达标：4.43:1 与 3.94:1

P1
现状

深色主题 #7C7770 on #0B0B0C = 4.43:1；纸白主题 #7B756B on #F2EEE6 = 3.94:1，均低于 4.5:1，且都用在 9–10px 的大写等宽标签上。

实测：4.43 / 3.94　目标：≥4.5（正文小字建议 ≥5）
影响与建议

能力剖面里的「13 视图 · 3.7k 行」、构建日志、页脚，在普通屏幕或强光下基本读不到；纸白主题更严重。

建议：深色 → #8C867C（5.4:1）；纸白 → #5E584C（6.1:1）；承载信息的小字不低于 11px，纯装饰的英文标签才允许 9px。

预期：axe 对比度告警归零，纸白主题可日常使用。

V4

四个指标等权，读者记不住任何一个

P1
现状

79 / 10 / 3 / 5 四格等宽、同字号、同字重。79（测试）是最强证据，却和 5（容器）平起平坐。

grid-template-columns:repeat(4,1fr)
影响与建议

扁平层级等于没有层级。3 秒测试里，读者一个数字都带不走。

建议：79 占 1.5 列或字号 ×1.4，其余降一级并缩小标签；或加第二个层次——「评测前后」一条对比。

预期：3 秒后能复述「79 个测试」这一个数字。

V5

等宽字体的中文回退，字重对不齐

P2
现状

--mono 栈里没有 CJK，流程节点「上传 / 解析 / 切片」与 tag 里的中文落到系统雅黑，比 JetBrains Mono 粗一档，宽度也不一致。

"JetBrains Mono", ui-monospace, Menlo, Consolas
影响与建议

同一行中英混排时笔画粗细跳变，精致感打折，放大到 200% 尤其明显。

建议：mono 栈追加 "Noto Sans SC"；或中文标签统一走 sans + letter-spacing: .02em，只让拉丁走等宽。

预期：中英混排视觉重量一致。

V6

首屏字体会「跳」一下，而且跳在最大的标题上

P0
现状

三个 Google Fonts 家族、两套 CJK，display=swap；首屏 104px 宋体的 fallback 是 SimSun。字体到达前用宋体替代，到达后字宽字重剧变。

Noto Serif SC + Noto Sans SC + JetBrains Mono
影响与建议

这是访客看到的第一个画面，却会出现一次明显重排——直接抵消「精心设计」的印象，也是 LCP 的主要成本。

建议：pyftsubset 只留页面用到的约 400 字，自托管 woff2（目标 <180KB），preload 首屏 serif，fallback 用 size-adjust 对齐字面。

预期：无可见字体跳变；LCP 进入 1.2s 预算；断网也能读。

V7

印章是装饰，但它是全站最好的入口

P2
现状

52px 红章「已评测」不可点、无解释，只带一个 aria-label；单独出现时读者不知道在评什么。

影响与建议

它本该是「可验证」的图腾，现在只是一个好看的贴纸。

建议：点击直接打开评测证据抽屉（79 用例 / golden QA / 报告）；hover 出现「查看评测记录」。

预期：装饰变入口，概念闭环。

02

交互体验

INTERACTION

最大的问题不是缺功能，是「长得很像能点」。

I1

四处假入口：指标、实验行、写作行、深潜链接

P0
现状

79/10/3/5 是 div，不可点；E1–E4 行尾写着「PROTOCOL ↗」但整行无链接；写作三行 href="#"；「看深潜」跳到 #method。

四个入口里：0 个真链接，1 个跳错，3 个死链
影响与建议

这是本站最伤的一类问题。访客点一次没反应，就不会再相信第二次——而「可验证」正是你的核心承诺。

建议：统一 data-ev 绑定，指标格、实验行、印章全部进抽屉；未上线内容用 disabled 态与「即将发布」标注，不要用 #；深潜指向真实页或页内展开区。

预期：页面上不存在「点了没反应」的元素。

I2

「看深潜」把读者送去了方法论

P0
现状

按钮文案是「看深潜 ↗」，href 指向 #method（我怎么 vibe coding），而读者期待的是这个项目的架构、决策与评测。

<a class="go-link" href="#method">看深潜</a>
影响与建议

期待与结果错位，是比死链更隐蔽的失望——读者会怀疑整个作品集只有表面。

建议：指向 /work/knowledge-base；页面未就绪前，改成页内展开的「三个关键决策」，文案改为「读完整复盘 →」。

预期：从项目卡到深潜的转化可被追踪。

I3

抽屉声明了 aria-modal，却没有焦点陷阱

P0
现状

打开抽屉后焦点移到容器，但 Tab 可以继续走进背后页面；背景没有 inert，屏幕阅读器仍可浏览。

role="dialog" aria-modal="true"　// 无 trap、无 inert
影响与建议

键盘与读屏用户体验断裂：以为在弹层里，实际在页面里乱走。面试官里只要有一个用键盘，就会记住这个。

建议：打开时给 main/header 加 inert，抽屉内做 focus trap，Esc 关闭并把焦点还给触发元素（已实现归还）。

预期：只用键盘可完成「打开证据 → 读完 → 关闭」。

I4

检索是「像 RAG」，但少了 RAG 最关键的两件事

P1
现状

命中词不高亮；结果不能 ↑↓ 选择；返回的是页面片段而不是结论。placeholder 问「你怎么防止大模型胡说？」，却只给三个段落标题。

3 CHUNKS · BM25 · 1MS　// 无 mark、无键盘导航
影响与建议

它被包装成「检索式导航」，操作却低于 command palette 的预期；用户不知道命中了什么，也不知道下一步。

建议：结果加 <mark> 高亮；↑↓ + Enter；顶部先给一句「最相关：评测闭环 · 命中 3 段」；空结果给三个建议词。

预期：从输入到抵达目标段落 ≤ 2 次按键。

I5

导航没有当前位置；1280 与手机上连章节入口都没有

P1
现状

顶部链接无 active 态；左侧 chunk 索引只在 ≥1400px 出现；≤760px 时 rail 与 nav links 同时消失，只剩三个按钮，其中还有一个桌面的「⌘K」。

@media(min-width:1400px){.rail{display:flex}}　// 1280 笔记本看不到
影响与建议

在最常见的 1280 笔记本与全部手机上，读者不知道自己在第几屏、也无法跳转；触屏用户看到一个用不了的快捷键。

建议：nav 复用同一个 IntersectionObserver 做 active；rail 下探到 1180；移动端给底部 sticky 章节条；⌘K 在触屏换成搜索图标。

预期：任何屏宽下都能一键到达 Work。

I6

触控目标：17px 高的证据链，点不中

P1
现状

证据链接高约 17px，chip 约 28px，分段控件约 30px。WCAG 2.5.8 的下限是 24px，iOS 建议 44px。

ev-link 17px · chip 28px · seg 30px　// 目标 ≥44px
影响与建议

手机上是「点了没反应」的高发区，误触还会触发相邻元素。

建议：证据链接 padding 10px 0、最小高度 44；chip 36；分段控件 34；相邻可点元素间距 ≥8px。

预期：移动端一次点中率 ≥95%（5 人测试）。

I7

切到「速览」，页面会跳走一屏

P1
现状

速览模式隐藏长段落，文档总高骤减，浏览器保留 scrollY，读者会被丢到别的章节。

display:none → 高度变化 → 滚动位置失效
影响与建议

看起来像页面出错，读者会怀疑自己点错了。

建议：切换前记录当前 section，切换后 scrollIntoView 复位；或只折叠卡片内部、不改整页高度。

预期：切换前后视线落在同一屏。

I8

五条无限循环的光点，和规范自相矛盾

P1
现状

数据流五个光点 infinite 循环；首屏 canvas 常驻 rAF；光标闪烁与状态点也在动。规范写的是「一屏最多两处主动效」「禁止无限」。

animation: travel 4.8s linear infinite　×5
影响与建议

阅读时余光被持续拉扯；笔记本上还会持续耗电，和「性能即证据」的主张相反。

建议：进视口播放一次，hover 重播；canvas 空闲 3 秒或指针离开后停；状态点只在首屏闪一次。

预期：静止时 CPU 接近 0，动效只在被注意时发生。

I9

写作三行是死链，点完毫无反馈

P2
现状

三行 href="#"；GitHub 与简历也是占位地址。视觉上它们是最像「可点」的整行。

影响与建议

一次点击没有反馈，用户会默认整站都是摆设。

建议：上线前替换；未发布则去掉下划线、加「即将发布」徽标并禁用 pointer。

预期：不存在无反馈的点击。

03

响应式

RESPONSIVE

390px 下，设计规范先崩了。

R1

设计文档的表格在手机上挤成竖排

P1
现状

390px 下三列表格每列约 110px，「理由」列变成每行 3–4 个字，7.1 选型表整整撑了二十多行。

390px / 3 列 ≈ 110px/列　// 中文 12.5px 每行 4 字
影响与建议

手机上完全不可读，读者只能横屏或放弃。

建议：表格统一包一层 overflow-x:auto + min-width:560px；或 <720px 转成卡片（dt/dd 纵向）。

预期：390px 下无需横向滚动即可读完任一表格。

R2

文档头部与 CTA 在 390px 换行错位

P2
现状

顶栏品牌名与版本号各换两行；封面 CTA 的标题被挤成两行、按钮贴到右边缘；eyebrow 的英文长句也折行。

影响与建议

文档第一屏就不像「被设计过」，与内容质量不匹配。

建议：≤720px 隐藏版本号与次级链接；CTA 改纵向排列；eyebrow 只保留短标签。

预期：移动端首屏无折行错位。

R3

768–1080 的 hero 丢掉了右栏，变成一条窄文本

P2
现状

≤1080px 直接 display:none 构建日志，hero 变单列；100svh 下上方空出近 200px，右侧完全留白。

影响与建议

平板上首屏显得空、且失去「正在构建」的活力证据。

建议：768–1080 把日志改成标题下方的一条横向 ticker，或放大 h1 填补右侧。

预期：平板首屏仍然是「有东西在看」的构图。

04

一致性与可信度

CONSISTENCY

最贵的问题：你说的和你做的不一样。

C1

三个数字经不起点开——这正是本站的立论

P0
现状

「60+ 接口」实际 52 个（13 个路由文件）；「第 05 周」按 9/28 起算应为第 4 周；「10-18 pytest 79 passed」这个日期在 README 里查不到。

grep -c @router.* = 52 9/28 → 10/22 = 24 天 ≈ 第 4 周
影响与建议

一个以「每个数字都能验证」为卖点的站，被抓到一个假数字，全站可信度归零——而且面试官恰恰是最会核的人。

建议：接口数改 52；周数在 PROFILE 里用起始日期动态计算；无法核实的日期直接删掉；1.1 万行统一为 1.17 万（含测试与脚本）。

预期：每个数字都能在 30 秒内被验证。

C2

规范与实现至少三处互相打脸

P1
现状

规范写「数字即入口」——未实现；「薄荷只表示通过」——流程光点是装饰性薄荷；「禁止无限动效」——五条无限循环；「一屏最多两处主动效」——hero 有三处。

影响与建议

懂行的人一对照就发现「说的 A 做的 B」，这比没有规范更伤：说明规范只是文案，不是约束。

建议：二选一，别两头都留。要么改实现，要么改规范并在文档里注明「v1 未实现」。优先改实现，因为这三条都指向体验。

预期：规范里每条规则都能在原型里被指认。

C3

术语、标点、精度不统一

P2
现状

「RAG 与 Agent」与「RAG/Agent」并存；「1.1 万行」与「1.17 万行」并存；日期写法 2026—2027 与 2026-10-22 混用；英文标签时而 Title Case 时而全大写。

影响与建议

单看都不是问题，累积起来会削弱「工程严谨」的印象——而这正是你想卖的。

建议：建 12 个高频词的 glossary（RAG / Agent / 评测 / 检索 / 深潜），统一大小写、空格与日期格式，写进内容规范。

预期：全站术语一致，改写时不再靠记忆。

07
