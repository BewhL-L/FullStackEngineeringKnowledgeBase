01

字体为什么糊

WHY TEXT LOOKS BLURRY

不是字体选错了，是渲染链路被三层东西破坏了。

浏览器只在文字所在层背景不透明、且不处于合成层时才启用 LCD 次像素抗锯齿（ClearType）；否则退化为灰度 AA。这套页面把最不该破的条件破了：最大的两块文字面——Work 卡片与构建日志——底色是 2% 白的 alpha，从第一行起就落在灰度 AA 里；再叠加一层全屏噪点、两处 backdrop-filter、300 字重与 9px 字号，细笔画就"糊成一团灰"。换字体解决不了，因为问题不在字形。

最小改动集（按顺序，约 90 分钟）

/* 1. 最大两块文字面：alpha → 实色（视觉零差异） */ --card-tint:#101011; /* paper: #F8F6F2 */ /* 2. 噪点从"盖在字上"移到背景层 */ body::after{ display:none } body{ background-image:url("data:image/svg+xml,...") } /* 3. 去掉会把文字关进合成层的模糊 */ .log{ backdrop-filter:none; background:var(--bg-1) } .nav.is-scrolled{ background:var(--bg); backdrop-filter:none } /* 4. 正文加粗；只改单条小字规则，不动 .mono 全局 */ body{ font-weight:400; font-synthesis-weight:none } /* 长写，别用简写 */ .metric span,.now-cell dt,.work-cols h4{ font-size:11px } /* 5. 标题停止负字距；印章去旋转 */ h1{ letter-spacing:0 } .seal{ transform:translateY(-8px) }

约 25 行。效果分平台：Windows（多数访客）约 80%；macOS 约 55%，且主因不同（噪点 > alpha），剩下的要靠 F7——把 reveal 从 850ms 提到 500–600ms，保留两属性，不要改成只动画 transform。注意 .mono 全局 11px 不要动，只改点名的单条规则。

字体链路剩下的 20% 严格按序：自建子集（3500 常用字 + 页专有词）→ 本地托管 → 才有资格 preload → 最后 size-adjust 对齐 fallback。请求可从 8 字重收敛到 5（净省体积≈0，省的是 3 组 @font-face 与规则数）：JetBrains+Mono:wght@400;500 & Noto+Sans+SC:wght@400 & Noto+Serif+SC:wght@400;500。mono 的 500 不能删，品牌字标在用。另把 --serif 里的 SimSun 去掉，避免子集缺字时回落到点阵宋体。

验收口径：Windows + deviceScaleFactor 1、同滚动位置、400% 放大汉字边缘截图——换位置会改变分数像素偏移，色边"时有时无"是误判主因。看有无红蓝色边——有色边说明 LCD 亚像素生效；纯灰边只说明"该机器上 card-tint 这条无效"，不否定字重/字号/噪点/字距。不要用 chrome://gpu，它看不到单段文字状态。P0-2c 的通过线写成：正常阅读速度滚动时，任一时刻处于过渡期的块 ≤ 2、单块暴露 ≤ 500ms；甩动不适用（甩动时 500ms 窗口必然超限，但内容本身不可读）。

02

整体设计缺陷

CONCEPTUAL

三个结构性错位，不是审美问题。

C1

「可点开」不等于「可验证」：抽屉里全是自述

P0
证据

十个抽屉的内容全是手写字符串：pytest 输出、ASCII 架构、文件树。全站唯一真实外链是页脚的「设计方案.html」。没有 commit、没有仓库、没有截图、没有可复现命令。

影响与改法

面试官点三次，看到三次"你说"，会把「每个数字都能点开」翻译成「点开是一段你自己写的字」。

改法：每个抽屉底部固定一条出处：repo/blob/<sha>/backend/tests/test_retrieval.py#L42。给不出外链的数字，降级为纯文本，别做成按钮。

C2

只有过程指标，没有业务结果

P1
证据

79 tests / 10 layers / 3 paths / 5 containers 全是"我怎么干活"。HR 折算不了，面试官容易归为练习项目。

影响与改法

没有一个人因为"5 个容器"决定面试你。

改法：至少补一个结果指标：谁在用、日均多少问、幻觉率从 x 到 y、客服工单降多少。给不出，就先别把容器数放首屏。

C3

用 RAG 的形做导航，却只"找"不"答"

P1
证据

输入问题 → 返回三个段落标题 → 跳到章节顶部。没有答案，没有引用，没有高亮。分数还恒为 1.00。

影响与改法

面试官必问"为什么不直接生成答案"，你只能答"这是静态页"——一分钟内从"懂 RAG"变成"没做 RAG"。

改法：结果区先给一句预生成结论 + 出处，或把入口改名为「按证据找」。别叫检索。

C4

双模式、双主题在服务设计者，不是读者

P1
证据

速览只减 5.8% 页高；折叠掉的恰好是"自建 golden QA""MCP/A2A"两条差异化证据；手机端直接隐藏该控件；唯一解释在 title 里。

影响与改法

读者点一次发现没变化，就不再碰任何开关——包括你真正想让他点的证据。

改法：改名「招聘速读 / 技术细读」，折叠解释句而非证据，切换时用 role=status 播报"已折叠 12 段"。

C5

首屏同时承担 6 个任务

P1
证据

主张、身份、状态、印章、检索、构建日志、滚动提示、左侧索引——首屏有 8 组视觉元素，其中 3 组在动。

影响与改法

3 秒测试里，读者记住的是"一块红的和一堆小字"，不是主张。

改法（结构性）：把 Now 四格并进 Hero 右栏替换日志，日志压成搜索框下一行 ticker。首屏只留：一句话 + 四个事实 + 一个入口。
