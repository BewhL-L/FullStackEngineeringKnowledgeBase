## 扩展① Agent 思考轨迹可视化

### 作用
让用户看到 Agent 内部"想了什么、调了什么工具、拿到什么结果"，这是 ReAct（Reason+Act）模式的可视化，也是面试讲"AI Agent 工作原理"的最佳素材。

### 原理
ReAct 循环长这样：

```
用户提问
  ↓
LLM 思考：要不要调工具？调哪个？
  ↓
调工具（get_current_time / calculator / search_knowledge_base）
  ↓
观察结果（Observation）
  ↓
再思考：信息够了吗？不够再调一次
  ↓
输出最终答案
```

后端有两个 Agent 入口，**返回结构不同，不要混**：
- `POST /api/agent/chat` → `agent_service.chat()`，只返回 `answer / sources`（单 Agent 工具调用，无轨迹）
- `POST /api/agent/multi-agent` → `native_multi_agent.run()`，返回 `steps`（planner / researcher / writer / supervisor 四角色状态机）

前端 `AgentDemo.vue` 调用的是**后者**，用 `el-timeline` 渲染 `steps`。

### 你要做什么
- [ ] 读 `backend/app/services/native_multi_agent.py` 的 `run()`，画出四个角色的执行顺序
- [ ] **亲手加一个字段**：给每个 `steps.append({...})` 加 `duration_ms`，用 `time.perf_counter()` 包住对应的 `_plan / retrieve / _write / _supervise` 调用
- [ ] 在 `AgentDemo.vue` 的时间线标题里显示 `s.duration_ms`（注意 `steps` 的 TS 类型要同步加字段）

### 验收标准
- 能口述：Agent 为什么要多轮调工具？一轮不够怎么办？
- 能讲清：tool_calls 是 LLM 返回的特殊消息格式，不是你主动调的

## 扩展② RBAC 协作权限（前端 UI 自己写）

### 作用
现在知识库只有"主人"一个人。加上 RBAC 后可以邀请同事进来，分三种角色：
- `owner`：完全控制（能删库、能邀请/移除成员）
- `editor`：能上传文档、能问答
- `viewer`：只能看和问答

### 原理
两张表配合：
- `users` 表加了 `role` 字段（系统级角色，默认 editor）
- 新建 `kb_members` 中间表（kb_id + user_id + role），解决**多对多关系**——一个用户在 A 库是 owner、在 B 库可能是 editor

权限判断逻辑在 `app/utils/deps.py` 的 `get_kb_role()` / `require_kb_role()`：
```python
if kb.user_id == user.id: return "owner"      # 创建者自动 owner，不查中间表
查 kb_members 表，返回该用户在这库的角色
都没有 → None → 403
```
`ROLE_LEVEL = {viewer:1, editor:2, owner:3}`，用 `>=` 比较，避免写一堆 if。

后端已实现的文件：`models/kb_member.py`、`utils/deps.py`、`routers/knowledge_bases.py`（列表接口已改为「我的 + 共享给我的」）。

### 你要做什么（前端 UI，亲手写）
**先读**：`frontend/src/api/knowledge.ts` 里已经写好的 `memberApi` 和 `KbMember` / `KbMemberList` 类型（调用接口的样板代码不用你重写，重点是页面逻辑）。

新建 `frontend/src/views/KbMembers.vue`：
1. 一个表格列出当前知识库的成员（调 `GET /api/kbs/{kb_id}/members`）
2. 一个"邀请成员"按钮 → 弹框（输入用户名 + 下拉选角色）→ 调 `POST /api/kbs/{kb_id}/members`
3. 每行一个"移除"按钮 → 调 `DELETE /api/kbs/{kb_id}/members/{member_id}`
4. **关键考点**：用接口返回的 `my_role` 控制按钮显隐——`viewer` 看不到邀请/移除按钮，`editor` 能上传但不能邀请
5. 把 `GET /api/kb` 列表里返回的 `role` 字段用在知识库卡片上（共享库打个「协作」标签）

### 接口清单
| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/kbs/{kb_id}/members` | 列出成员（需 viewer 及以上） |
| POST | `/api/kbs/{kb_id}/members` | 邀请成员（需 owner），body: `{username, role}` |
| DELETE | `/api/kbs/{kb_id}/members/{member_id}` | 移除成员（需 owner） |

### 验收标准
- 能讲清：为什么用中间表而不是在 users 表加 `kb_id` 字段？（答：多对多关系）
- 能写出来：角色等级判断怎么写（owner=3 > editor=2 > viewer=1）

## 扩展③ 结构化回答模板（前端渲染组件自己写）

### 作用
普通问答返回一大段文字。结构化回答让 LLM 按模板输出 JSON，前端根据模板类型渲染成：
- **bullets**：要点列表（适合总结）
- **comparison**：对比表格（适合"A 和 B 哪个好"）
- **timeline**：时间线（适合"项目流程"）

### 原理
后端 `POST /api/structured/generate` 接收 `{question, template, kb_id?}`，构造一个特殊 prompt，要求 LLM **只返回严格 JSON**（不要 markdown 包裹），解析后返回 `{template, result, raw, degraded}`。

解析在 `backend/app/services/structured_service.py`：
- `parse_structured()` 负责剥掉 ```json 包裹、截取 `{...}`、`json.loads`
- `normalize()` 负责补字段、对齐表格列数
- 任一步失败 → `fallback()` 降级成 bullets 并置 `degraded=true`，**接口永远 200**

前端 `src/utils/structured_parse.ts` 的 `normalizeStructured()` 再做一层容错：后端万一返回脏数据，组件不能崩。

### 你要做什么（前端渲染组件，亲手写）
**先读**：`frontend/src/utils/structured_parse.ts` 的类型定义与 `normalizeStructured()`，以及 `frontend/src/api/structured.ts` 里已写好的 `structuredApi`。

新建 `frontend/src/components/StructuredAnswer.vue`：
1. props 接收后端返回的整包响应，第一行先 `normalizeStructured(props.data)` 拿到联合类型
2. 根据 `result.template` 分支（TS 会自动收窄类型）：
   - `bullets` → 用 `el-list` 渲染要点
   - `comparison` → 用 `el-table` 渲染对比表（headers 当列，rows 当数据）
   - `timeline` → 用 `el-timeline` 渲染时间线
3. 加一个"切换模板"的下拉框，同一个问题用三种模板各问一次，对比效果

### 验收标准
- 能讲清：为什么 LLM 输出 JSON 容易出错？怎么容错？
- 能写出来：TypeScript 联合类型怎么定义三种模板的字段（`type Result = Bullets | Comparison | Timeline`）

## 扩展④ 前端测试（Vitest）

### 作用
后端有 85 个 pytest，前端之前一个测试都没有。加上 Vitest 后，关键纯函数有测试保护，重构时不心慌。

### 原理
测试分两种：
- **纯函数测试**：输入确定，输出就该确定。比如 `normalizeStructured(null)` 永远该返回空 bullets
- **组件测试**：要 mock DOM，复杂，学习阶段先不写

已经写好的 5 个 case 覆盖：空输入、bullets、comparison（行不齐）、timeline（混入脏数据）、未知模板回退。

### 你要做什么
- [ ] 读 `frontend/tests/structured_parse.test.ts`，看 `describe / it / expect` 怎么写
- [ ] **亲手加 2 个测试 case**：例如「comparison 的 rows 不是数组时怎么容错」「timeline 的 events 全是空对象时是否回退」
- [ ] 跑 `npm run test` 确认 7 个测试全过

### 验收标准
- 能讲清：为什么要测"错误输入"而不只是"正确输入"？
- 知道命令：`npm run test`（一次性跑）/ `npm run test:watch`（监听模式）
