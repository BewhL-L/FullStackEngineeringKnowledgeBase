# 数据库小镇 · 立牌演出系统 · 完整提示词 v3

**定位**：检索不是一个 loading，是一次「出门取资料」的演出。两只动物是立牌，小镇是索引。
**与 v32 评审包的关系**：P1 视觉系统、P2 装饰系统、P3 版式重排 **全部保留**；**本文档替换原 P4（3D 宠物）这一整段**，并连带重写 P5 的素材部分。

## 第一部分 · 为什么立牌比 3D 对

这不是降级，是换了一种更准的语言。四条依据：

1. **主动的"假"胜过失败的"真"。** 立牌承认自己是纸片，观众接受这个约定；现在 `assets3d` 里那批灰色素模（球体 + 圆柱 + 断开的尾巴）是"想真但没做到"，观感直接崩。判断成立的标准是观众的预期是否被满足，不是多边形数量。
2. **物质世界一致。** 页面已经在用手账语言：纸、胶布、便利贴、打孔、印章。立牌是**同一种材料**的延续——它就该是纸。3D 的塑料高光和这个世界没有交集。
3. **动效逻辑更简单且更可爱。** 立牌没有骨骼，行走只能靠**整体刚体摆动**，也就是你说的"摇摇晃晃"。这不是妥协：恰恰是它最有记忆点的地方。真实四足行走反而需要骨骼动画，成本高且容易恐怖谷。
4. **成本量级差两位。** 4 张立牌贴图（2 动物 × 2 姿态）vs 建模 + 贴图 + 绑定 + 动画 + 性能预算。前者一下午能跑通整条链路。

**代价要说清**：立牌永远是正面/镜像，不能四分之三转身；动作只有"整块摆动"，没有关节联动。作为 portfolio 的演出层够用，作为角色展示不够。

## 第二部分 · 数据库小镇（场景）

### 2.1 视觉规格（对齐参照图）

| 项 | 规格 |
|---|---|
| 投影 | 2:1 等距（≈30°），所有建筑共用同一套等距网格，禁止透视 |
| 描边 | 1.5–2px，深墨 `#2E2A26`，线条平直不抖，转角略圆 |
| 填充 | 平涂，零渐变、零纹理、零投影光晕 |
| 调色 | 纸白 `#FBF8F0` / 薄荷 `#CFE7DA` / 草绿 `#A8CF9A` / 蜂蜜 `#F3C77A` / 珊瑚 `#E8745B` / 天蓝 `#9FC8DD` / 墨 `#2E2A26` |
| 尺度 | 人 18–24px 高；建筑 120–260px；树 30–50px；角色立牌 96–120px |
| 道路 | 浅米 `#F0E7D6` 带 2px 白边，宽 26–34px，路口用圆角 |
| 细节 | 窗户为简单矩形、门为单色块、屋顶不做瓦纹；一切造型用 3–5 个几何体拼 |

### 2.2 建筑清单（每栋 = 一个数据源）

| 编号 | 建筑 | 对应能力 | 造型 |
|---|---|---|---|
| 00 | 检索大厅 | 用户提问 / 入口 | 中央广场，圆形台阶 + 旗杆 |
| 01 | 关系库 | 结构化表 | 带排架的仓库，卷帘门 |
| 02 | 向量库 | 语义召回 | 圆顶 + 雷达天线 + 一圈环带 |
| 03 | 图库 | 关系/图谱 | 三间相连小屋 + 空中连线 |
| 04 | 文档库 | 全文检索 | 两层书店，外墙上排满书脊 |
| 05 | 缓存亭 | 命中缓存 | 报刊亭 + 闪电牌 |
| 06 | 归档塔 | 冷数据 | 水塔 + 钟楼 |

每栋门口有一个 **门牌色块**（40×24，分区色 400 档 + 2px 墨线 + 编号），这是唯一允许出现文字的地方，字号 10px。

### 2.3 布局

- 一处中心广场（占比 22%）+ 六条放射路 + 外圈六栋。
- 角色默认站在广场中央，背对大厅。
- 视口 1440 宽时，小镇呈 1000×620 的横构图，右上角留 180×140 的空给"查询气泡"。

## 第三部分 · 立牌角色

### 3.1 资产清单

| 文件 | 内容 | 用途 |
|---|---|---|
| `cat-sit.png` | 三花猫坐姿，朝右 | 待机 / 抵达 |
| `cat-run.png` | 三花猫奔跑，朝右 | 移动 |
| `dog-sit.png` | 长毛腊肠犬坐姿，朝右 | 待机 / 抵达 |
| `dog-run.png` | 长毛腊肠犬奔跑，朝右 | 移动 |
| （可选）`*-found.png` | 叼着资料卡的变体 | 返回时 |

- 朝向只画右，朝左用 `scaleX(-1)`。
- 交付：透明 PNG，高 2000px，模切白边已包含在图内。
- 姿态要求：**奔跑姿态的轮廓必须能一眼读出**——四肢分开、身体前倾、耳朵或尾巴向后飘。

### 3.2 立牌的物质性（这是"像立牌"的关键，五项缺一不可）

1. **模切白边** 6px，沿轮廓外扩，边缘略不平整（0.5px 抖动）。
2. **卡纸厚度**：底部一条 5px 浅灰阶 `#E6DED0`，只在底边出现，营造纸的厚度。
3. **底座**：椭圆 44×10，深一号 `#D9CFBE`，居中贴底。
4. **投影**：椭圆，宽为底座的 1.6 倍，`blur 6px`，`opacity .18`，位于底座正下。
5. **纸面反光**：一条 8% 白、斜 20° 的窄带掠过身体，`mix-blend-mode: soft-light`，随场景光轻微移动。

### 3.3 动效参数（直接给数值）

| 动作 | 参数 |
|---|---|
| 待机呼吸 | `scaleY 1.012`，周期 2.6s，`ease-in-out` |
| 待机摆头 | 每 6–9s 随机一次，`rotate ±1.5°`，180ms 进出 |
| 起步预备 | 90ms 下蹲 `scaleY .96`，同时完成转向 |
| **奔跑摇晃** | `rotate -3.4° ↔ +3.4°`，0.26s 交替；`translateY ±2px`，0.13s（双频）；底座阴影 `scaleX .92 ↔ 1.06` 同步 |
| 转向翻转 | 220ms，`scaleX` 经过 0（中点挤压到 92%），中点额外 `translateY -6px`，落地回弹一次 |
| 刹车抵达 | 120ms 内 `rotate -6°` 回正，`translateX` 超出目标 8px 再退回 |
| 坐下 | 180ms，`scaleY 1.06 → 1`，同步底座阴影收窄 |
| 找到资料 | 头顶弹出资料卡，`translateY -18px` + `opacity 0→1`，220ms，卡片轻微旋转后回正 |

**关键**：所有变换的 `transform-origin` 必须是 `50% 100%`（立牌底部钉在地上），否则会像在飘。

### 3.4 状态机

```
idle ──(查询触发)──> turn ──> run ──> arrive ──> sit ──> deliver ──> idle
                     ↑                                            │
                     └──────────────(下一次查询)───────────────────┘
```

- 同一时刻只有一只角色在主路线移动；另一只在广场待机（可做轻微延迟的呼吸错相）。
- 动作不可被新查询硬打断：新查询进入队列，等当前 `deliver` 结束再执行。

## 第四部分 · 演出与检索逻辑的绑定

一次真实检索被拆成四拍，每一拍都能被页面看到：

| 拍 | 检索阶段 | 演出 | 时长 |
|---|---|---|---|
| 1 | 接收查询 | 广场旗杆升旗 + 查询气泡浮出 | 200ms |
| 2 | 三路召回 | 依次跑向 02 / 03 / 04，房子亮灯，门口浮出「命中 N 条」 | 每站 900–1200ms |
| 3 | 融合与重排 | 回到广场，头顶转圈的三张资料卡合并为一张 | 600ms |
| 4 | 生成答案 | 坐姿 → 资料卡飞入右侧引用区 → 打字机输出 | — |

边界情况：
- **0 命中**：跑到最近一栋，摇头两次，回来，气泡显示「没找到」，房子灯灭。
- **命中缓存**：直接跑到 05 缓存亭，路程缩短 60%，演出时间减半——**这条本身就在展示系统能力**。
- **降级**：`prefers-reduced-motion: reduce` 时，取消路径移动，改为"角色淡出 → 在目标房前淡入"，其余状态保持。

### P4 · 立牌动效与状态机（代码助手）

```
为 <DbTown> 实现立牌的移动与姿态演出。不做骨骼动画、不做逐帧精灵图，
用"整体刚体摆动"模拟奔跑——这是这套设计的核心观感。

【资产】
每个角色两张：{name}-sit、{name}-run，均朝右。朝左时对容器加 transform: scaleX(-1)。
每个立牌由三层嵌套构成：
  .pet-path   —— 由 offset-path 控制位置
  .pet-flip   —— 控制左右翻转（scaleX）
  .pet-body   —— 控制摇晃、呼吸、下蹲（rotate / scaleY / translateY）
  transform-origin 全部为 50% 100%（底部中心），立牌必须"钉在地上"。
  .pet-base   —— 底座椭圆与投影，独立元素，不随 body 摇晃，只做 scaleX 同步。

【状态机】
idle → turn → run → arrive → sit → deliver → idle
- 状态用 data-state 属性驱动，CSS 负责表现，JS 只负责推进状态与时序。
- 新查询进入队列（最多 2 条），当前 deliver 结束后才消费；禁止跨状态硬切换。

【关键动效数值】
待机：body { animation: breathe 2.6s ease-in-out infinite }  keyframes: scaleY(1)→scaleY(1.012)
起步：90ms 内 scaleY .96，同时执行转向
奔跑：body { animation: waddle .26s ease-in-out infinite alternate }
      keyframes: rotate(-3.4deg) → rotate(3.4deg)
      叠加 translateY: bob .13s ease-in-out infinite alternate（0 → -2px）
      base:  waddleShadow .26s 同步 scaleX(.92) ↔ scaleX(1.06)，opacity .18↔.13
转向：flip 元素 220ms，scaleX 由 1 → |-0.92| → -1，中点额外 translateY(-6px)，结束回弹
抵达：120ms 内 rotate(-6deg) 归零，位移超出目标 8px 后回退
坐下：180ms 内 body scaleY 1.06 → 1，切换为 sit 贴图
找到资料：资料卡 translateY(-18px) + opacity 0→1，220ms，初始 rotate(6deg) 回正

【路径】
- 每条路在场景中以 SVG <path> 定义，角色用 CSS offset-path: path("...") + offset-rotate: 0deg 沿路移动。
- 移动用 offset-distance 0% → 100%，时长按路程 / 220px 每秒计算，ease-in-out。
- 不支持 offset-path 的浏览器：降级为直线插值（requestAnimationFrame 线性补间），可接受。

【可访问性】
- 立牌为装饰层：aria-hidden="true"，不进入 tab 顺序。
- 演出状态通过 aria-live="polite" 的区域播报文字（如"正在检索向量库，命中 12 条"），
  供读屏用户获得同等信息。
- prefers-reduced-motion: reduce 时：不位移，改为在目标房前淡入（180ms），姿态直接切 sit，
  并跳过摇晃与起步预备。
```

### P5 · 与检索逻辑联动（代码助手）

```
把 <DbTown> 接到真实检索流程上，让演出成为检索状态的可视化，而不是纯装饰。

【映射】
- 查询提交 → 旗杆升起 + 查询气泡浮出（200ms）。
- 三路召回 → 依次访问向量库(02)、图库(03)、文档库(04)：
  每次抵达时该建筑亮灯（描边换成 400 色 + 门口浮出"命中 N 条"），停留 400ms 后离开。
- 命中缓存 → 只跑 05 缓存亭，路程缩短 60%，演出时间减半（这条本身展示系统能力）。
- 融合 → 回广场，头顶三张资料卡收拢为一张。
- 生成 → 坐姿，资料卡飞入右侧引用区，随后开始流式输出。
- 0 命中 → 跑到最近一栋，摇头两次，返回，气泡显示"没找到"，建筑灯灭。

【数据接口】
onRetrieve(query) 返回 { stages: [{source:'vector', hits:12, ms:180}, ...], cached:bool }
组件只消费这个结构，不关心实现；没有真实后端时用 mock 数组驱动，保证演出可独立演示。

【错误与慢响应】
- 单站超过 2.5s 未返回：该建筑门牌变成闪烁的虚线，角色在门口做一次"等待"摆头。
- 整个检索超时：角色返回广场，气泡显示"超时"，并提供重试按钮。

【埋点与调试】
```
