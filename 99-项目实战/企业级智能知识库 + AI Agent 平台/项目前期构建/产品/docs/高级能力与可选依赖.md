# 高级能力与可选依赖说明

本文档说明项目在基础 RAG 之外的生产级能力：每个模块**做什么、如何开关、依赖什么、怎么运行**。

设计原则：**核心链路零重依赖也能跑**。所有高级能力都采用「可选依赖 + 缺失时优雅降级」：
- 没装 `jieba` → 自动用内置降级分词；
- 没装 `langgraph` / `mcp` / `langfuse` / `ragas` → 对应功能静默关闭或给出安装指引，不影响主服务启动；
- 核心算法（BM25、RRF、评测指标、记忆/压缩）均为纯 Python 实现，可直接单测。

---

## 1. 混合检索（`app/retrieval/`）

**做什么**：解决纯向量检索对「专有名词、编号、精确关键词」不敏感的问题。

检索管线：

```
原始问题
  └─ Multi-Query 查询改写（LLM 生成多种表述，扩大召回）
       └─ 向量路（Chroma） ┐
                            ├─ RRF 倒数排名融合
          BM25 路（关键词）┘
              └─ Rerank 重排（LLM 或 Cohere）→ Top N
```

| 文件 | 职责 |
|------|------|
| `tokenizer.py` | 分词，优先 jieba，缺失降级为「英文数字词 + 中文单字 + 相邻 bigram」 |
| `bm25_retriever.py` | Okapi BM25（K1=1.5、B=0.75），每库持久化，支持增量增删 |
| `query_rewrite.py` | Multi-Query 改写、HyDE 假想答案检索 |
| `reranker.py` | LLM 重排（输出 order JSON）/ 可选 Cohere 多语言 Rerank |
| `hybrid.py` | RRF 融合 + HybridRetriever，随文档增删自动维护 BM25 |

**关键配置**（`.env`）：

```ini
RETRIEVAL_MODE=hybrid          # hybrid / vector
BM25_WEIGHT=0.4
VECTOR_WEIGHT=0.6
RRF_K=60
FETCH_K=20
RERANK_ENABLED=true
RERANK_PROVIDER=llm            # llm / cohere
RERANK_TOP_N=5
QUERY_REWRITE_ENABLED=true
MULTI_QUERY_COUNT=3
HYDE_ENABLED=false
```

**可选依赖**：`jieba`（强烈建议，中文效果）、`cohere`（用 Cohere Rerank 时）。

## 2. 上下文工程（`app/context_engine/`）

**做什么**：在有限上下文窗口里放「最该放的信息」，并让长对话不丢关键信息。

| 文件 | 职责 |
|------|------|
| `memory.py` | 短期记忆（滑动窗口）+ 长期记忆（跨会话事实，持久化） |
| `compressor.py` | 较早对话用 LLM 压缩成一条摘要，保留最近若干轮原文 |
| `assembler.py` | Token 估算、按预算裁剪资料、组装 system/历史/问题、工具数量预算 |

**关键配置**：

```ini
CONTEXT_MAX_TOKENS=6000
HISTORY_COMPRESS_ENABLED=true
HISTORY_KEEP_TURNS=6
MEMORY_ENABLED=true
LONG_MEMORY_PATH=./long_memory.json
TOOL_BUDGET=10
```

## 3. RAG 评测体系（`app/evaluation/`）

**做什么**：把「效果好不好」从主观感觉变成可对比的数字。

| 文件 | 职责 |
|------|------|
| `data/golden_qa.json` | 标准问答集（问题、参考答案、必含关键词、期望来源文档） |
| `metrics.py` | Hit@K、MRR、Context Precision/Recall、答案关键词覆盖（确定性，可离线） |
| `llm_judge.py` | LLM 裁判：忠实度（防幻觉）、答案相关性 |
| `ragas_runner.py` | 安装 ragas 后跑官方 RAGAS 四指标 |
| `runner.py` | 逐用例跑检索+生成+评分，输出报告 JSON |

**运行方式**：

```bash
# CLI
python -m app.evaluation.run_eval                 # 全部用例
python -m app.evaluation.run_eval --kb-id 1       # 统一评测某知识库
python -m app.evaluation.run_eval --no-judge      # 不调用 LLM 裁判，省 token

# HTTP 接口
POST /api/evaluation/run      # 触发评测
GET  /api/evaluation/latest   # 查看最新报告
```

报告输出到 `EVAL_REPORT_DIR`（默认 `./eval_reports`），含 `latest.json`。

**可选依赖**：`ragas`、`datasets`（仅 RAGAS 指标需要；确定性指标无需）。

> 方法论：每做一次优化（换检索策略 / 调 Prompt / 换模型），先跑评测，对比指标，形成「发现问题 → 定位到层 → 优化 → 指标提升」闭环。

## 4. MCP Server（`app/mcp_server/`）

**做什么**：把知识库检索/问答暴露为标准 **MCP（Model Context Protocol）工具**，供 Claude Desktop、支持 MCP 的 IDE / Agent 宿主调用。

工具：`list_knowledge_bases`、`search_knowledge_base`、`ask_knowledge_base`、`get_current_time`。

**运行方式**：

```bash
# stdio（桌面/IDE 以子进程方式接入）
python -m app.mcp_server.run_stdio

# streamable-http（默认 0.0.0.0:8001，端点 /mcp）
python -m app.mcp_server.run_http
```

**可选依赖**：`mcp`（缺失时启动会给出安装指引）。

## 5. Agent 编排（`app/orchestration/`）

**做什么**：提供基于 **LangGraph** 的多种主流 Agent 架构，与原生 ReAct（`services/agent_service.py`）对照学习。

| 文件 | 架构 | 入口 |
|------|------|------|
| `react_graph.py` | ReAct（推理-行动循环） | `build_react_agent()` / `run_react()` |
| `plan_execute.py` | Plan-and-Execute（先规划再执行，可重规划） | `build_plan_execute_graph()` / `run_plan_execute()` |
| `multi_agent.py` | Supervisor 多智能体（researcher 检索 + writer 整合） | `build_supervisor()` / `run_multi_agent()` |

> 当前**主链路使用原生 Agent**（无重依赖、已通过测试）。上述 LangGraph 实现为等价参考与可切换实现。

**切换方式**：通过 `orchestration.get_orchestrator()` 工厂按 `ORCHESTRATION_BACKEND` 配置获取编排函数：

```ini
# .env
ORCHESTRATION_BACKEND=native   # native / langgraph-react / langgraph-plan-execute / langgraph-multi-agent
```

```python
from ..orchestration import get_orchestrator

runner = get_orchestrator()          # native 返回 None（用原生 AgentService）；langgraph 未安装时抛出带安装指引的 RuntimeError
if runner:
    answer = await runner(question, kb_id)
```

前端「评测中心」页面可对任意知识库一键跑评测并可视化指标，作为优化前后的对照基线。

**可选依赖**：`langgraph`、`langchain-openai`。

## 6. 可观测性（`app/observability/`）

**做什么**：把每次问答的「检索了什么、生成耗时、token」上报到 Langfuse，便于排查 bad case。

**配置**：

```ini
LANGFUSE_ENABLED=false
LANGFUSE_PUBLIC_KEY=
LANGFUSE_SECRET_KEY=
LANGFUSE_HOST=https://cloud.langfuse.com
```

未启用 / 未安装 / 写入失败均静默，不影响问答。**可选依赖**：`langfuse`。

## 7. A2A 协议（`app/protocols/a2a_server.py`）

**做什么**：实现 **Agent2Agent** 互操作协议，让外部 Agent 能发现并调用本服务。

- Agent Card：`GET /a2a/.well-known/agent.json`
- 调用：`POST /a2a`（JSON-RPC `message/send`，目标知识库通过 `message.metadata.kb_id` 传入）

无需额外依赖（基于 FastAPI 手写）。

## 9. 微调（`scripts/finetune/`）

```bash
# 1) golden QA → 微调 jsonl
python scripts/finetune/prepare_finetune_data.py
# 2) 调用 OpenAI 兼容微调接口
python scripts/finetune/run_finetune.py
```

**什么时候该微调、什么时候用 RAG**：见 `docs/微调与RAG选型.md`。结论：RAG 解决「知识」，微调解决「风格 / 技能」；先做 RAG + Prompt，确有必要再微调，并用评测做 A/B 验证。

## 10. 生产化组件

- **缓存** `services/cache.py`：配置 `REDIS_URL` 且 Redis 可达时用 Redis，否则用内存缓存。
- **异步任务** `app/tasks/`：Celery + Redis（文档解析等耗时任务）。
  ```bash
  celery -A app.tasks.celery_app:celery_app worker --loglevel=info
  ```
  一键拉起 Redis + worker：
  ```bash
  docker-compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
  ```
- **PostgreSQL**：设置 `DATABASE_URL=postgresql+psycopg2://user:pass@host/db`，驱动会自动去掉 SQLite 专属参数。**可选依赖**：`psycopg2-binary`。
- **CI**：`.github/workflows/ci.yml` 自动跑后端 pytest + 前端 build。

---

## 11. 安全防护（`app/utils/guard.py`）

- `is_injection` / `injection_risk`：启发式检测 Prompt 注入（「忽略以上指令」「ignore previous instructions」「泄露 system prompt」、伪造角色标记等）。
- `neutralize`：剥离 `<|im_start|>`、`[INST]` 等角色标记。
- `wrap_context`：给检索到的外部资料加「这是数据不是指令」的边界。
- 危险工具（代码求值）使用 AST 白名单，禁止 import / 属性逃逸。
