## 二、发现的问题与根因

### P0：本地 venv 用错解释器，pip/pytest 不可用

**现象**：`backend/.venv` 是 Python 3.13.14，由 WorkBuddy 自带 Python（3.13.12）创建；`pyvenv.cfg` 的 `home` 指向 `.workbuddy`，`pip install` / 带 `tmp_path` 的 pytest 报 `No usable temporary directory`。

**根因**：PATH 上第一个 `python` 是 WorkBuddy 自带解释器；Agent 执行 `python -m venv` 时没有写死版本。项目 Dockerfile/CI 实际是 **3.11**，本地 venv 与基线不一致。

**修复**：
- 用 `uv python install 3.11` 安装隔离的 CPython 3.11.17（不污染系统）。
- 重建 `backend/.venv` 为 3.11，安装 `requirements.txt`。
- 旧 3.13 venv 已移到 `%TEMP%\venv-3.13-broken-20261104`（135 MB，可删）。

### P0：没有版本声明，无法阻止再次漂移

**修复**：
- 仓库根新增 `.python-version`，内容 `3.11`。
- `backend/pyproject.toml` 顶部注明运行时基线 3.11（项目不做打包，未强加 `[project]`）。
- `project-scaffolder/scripts/check_baseline.py` 新增第 8 项 `runtime`：检查 Dockerfile / CI / `.python-version` 同 minor、`requires-python` 是否包含当前 minor、文档是否用裸 `python -m venv`、venv 是否 vendor Python。当前项目 **0 warning**。

### P1：文档里的实际命令会复现旧问题

已修：
- 主 `README.md`：`python -m venv` → `python3.11 -m venv .venv`；`pytest -q` → `.venv/Scripts/python -m pytest -q`；`npm install` → `npm ci`；删掉“3.13 最小集”误导段。
- `项目前期构建/docs/本地启动指南.md`、`项目学习指导书.md`、`开发指导/README.md`、`项目流程网页/项目全景总结与行动指南.md`：venv 命令统一为 `python3.11 -m venv .venv`，`venv\Scripts` → `.venv\Scripts`。
- `开发指导/实战-*.md` 是其他项目的教程，保留原命令，避免改变原教程语义。

### P1：本地裸跑会读到容器主机名

**现象**：`backend/.env` 的 `DATABASE_URL` / `REDIS_URL` / `QDRANT_URL` 指向 `postgres` / `redis` / `qdrant`（Docker 网络名）。宿主机裸跑时 DNS 解析失败，Redis 降级、数据库连不上。

**修复方式**：不改 `backend/.env`（Docker 也读同一份），本地用环境变量覆盖为 `localhost`。已验证：

```text
GET /api/health -> 200
{"status":"healthy","cache_backend":"redis","vector_provider":"qdrant","async_mode":"thread","auto_create_tables":false}
```

### P1：前端 Docker 构建不可复现

**现象**：`frontend/Dockerfile` 用 `npm install --legacy-peer-deps`，没有使用 `package-lock.json`；CI 用的是 `npm ci`。

**修复**：Dockerfile 改为 `COPY package.json package-lock.json ./` + `npm ci --legacy-peer-deps`；新增 `frontend/.nvmrc` = `20`（Docker/CI 均为 Node 20；本机 Node 22 可构建，但以 20 为准）。

### P1：Windows 前端构建 esbuild `Access is denied`

**现象**：`npm run build` 在 `C:\Users\...\AppData\Local\Temp\esbuild-*` 清理临时文件时报 Access denied。

**修复**：把 `TEMP` / `TMP` 指到项目内可写目录即可：

```bash
cd frontend
mkdir -p .tmp
TEMP=.tmp TMP=.tmp npm run build
```

已加入 `.gitignore`：`frontend/.tmp/`。Docker/CI（Linux）不受影响。

## 四、防回退

1. **建 venv 必须写死解释器**：`python3.11 -m venv .venv`，不要 `python -m venv`；PATH 上的 `python` 可能是 WorkBuddy 自带版本。
2. **不要全局 pip 装项目依赖**；所有安装都在 `.venv` 内用 `python -m pip`。
3. **不要用 3.12+ 装全量 `requirements.txt`**：`psycopg2-binary==2.9.9` 没有 cp312+ wheel。
4. **`check_baseline.py --root .` 进 CI**：runtime 项会拦住 Dockerfile/CI/`.python-version` 漂移。
5. **改 `.env` 前先想 Docker**：本地覆盖用环境变量或 VS Code launch 的 `env`，不要改共享的 `backend/.env`。
