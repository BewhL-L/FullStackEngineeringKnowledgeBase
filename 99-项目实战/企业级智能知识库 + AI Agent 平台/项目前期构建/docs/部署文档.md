# 部署文档

把项目部署到云服务器，得到一个公网可访问的地址。

> **路径约定（2026-10-26 起）**：代码是独立仓库，仓库根目录就是 `docker-compose.yml` 所在目录。
> 本文所有命令都从**仓库根**执行，除非特别注明 `cd backend`。

---

## 一、准备工作

### 1. 云服务器
- 阿里云 / 腾讯云轻量应用服务器
- 2 核 4G 起步（模型在云端，本地不需要 GPU）
- Ubuntu 22.04 LTS，带宽 3M 以上

### 2. 域名（可选）
- 国内服务器需备案（1-2 周）
- 解析到服务器公网 IP

## 二、Docker 部署（推荐）

### 1. 安装 Docker

```bash
curl -fsSL https://get.docker.com | bash
sudo systemctl enable --now docker
docker --version && docker compose version
```

### 2. 拉代码

```bash
git clone <你的仓库地址> /opt/kb-platform
cd /opt/kb-platform
```

### 3. 配置环境变量

```bash
cd backend
cp .env.example .env
vi .env
```

必改项：

```ini
# 生产必须换掉，生成方法：openssl rand -hex 32
SECRET_KEY=<随机串>
DEBUG=false

LLM_API_KEY=<你的 key>
LLM_BASE_URL=<OpenAI 兼容地址>
LLM_MODEL=<模型名>
EMBEDDING_MODEL=<向量模型名>

CORS_ORIGINS=https://你的域名

# schema 由 Alembic 管理，应用不再自动建表
AUTO_CREATE_TABLES=false
```

### 4. 启动（两种编排，选一种）

```bash
# A. 基础编排：postgres + redis + qdrant + backend + frontend（5 个）
docker compose up -d --build

# B. 叠加生产 overlay：多一个 Celery worker（6 个）
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
```

数据库不用手动初始化：backend 的启动命令里已经带了 `python scripts/db_bootstrap.py`，
它会自动判断「空库建全 / 老库 stamp / 已纳管升级」。

### 5. 验证

```bash
docker compose ps                        # 全部 Up（backend 应为 healthy）
curl -s http://localhost:8000/api/health # {"status":"healthy"}
curl -s -o /dev/null -w "%{http_code}\n" http://localhost/   # 200
```

### 6. 常用运维

```bash
docker compose logs -f backend
docker compose restart backend
docker compose down
docker compose exec backend alembic current      # 当前数据库版本
docker compose exec backend python scripts/db_bootstrap.py   # 手动升级
```

> [!danger] 生产编排三条铁律
> 1. **overlay 不能重写 `DATABASE_URL` / `VECTOR_PROVIDER` / `QDRANT_URL`**——一旦重写，backend 与 worker 会各自连到容器内的 SQLite / Chroma，表现为「文档永远 processing + 检索结果为空」，且日志无报错。
> 2. `ASYNC_MODE=celery` 必须在 overlay 里设置，否则 worker 拿不到任务。
> 3. worker 与 backend 必须挂同一个 `/app/data`（BM25 索引、Embedding 缓存、长期记忆），否则 worker 建的索引 API 读不到。

## 三、HTTPS

```bash
sudo apt install certbot
sudo systemctl stop nginx || true          # 若 80 被占用先停
sudo certbot certonly --standalone -d your-domain.com
```

证书路径：
- `/etc/letsencrypt/live/your-domain.com/fullchain.pem`
- `/etc/letsencrypt/live/your-domain.com/privkey.pem`

打开 `docker/nginx.conf` 里的 HTTPS 段，填域名与证书路径；或在前端容器外层再挂一层 Nginx 做 TLS 终止。
**注意保留 `/api/` 的 `proxy_buffering off`**，否则 SSE 流式会一次性返回。

## 四、手动部署（不用 Docker）

```bash
cd backend
python3.11 -m venv .venv && source .venv/bin/activate   # 必须 3.11，3.13 装不上 jieba
pip install -r requirements.txt
cp .env.example .env        # 编辑配置

python scripts/db_bootstrap.py     # 建表 / 升级
nohup uvicorn app.main:app --host 0.0.0.0 --port 8000 > app.log 2>&1 &
```

前端：

```bash
cd frontend
npm ci --legacy-peer-deps
npm run build               # 产物在 dist/
```

`dist/` 交给 Nginx 托管，配置参考 `frontend/nginx.conf`（`try_files` 回退 + `/api` 反代 + SSE 免缓冲）。

## 五、数据备份

Docker 部署下数据在四个地方，缺一不可：

| 数据 | 位置 | 备份方式 |
|---|---|---|
| 业务库 | `postgres_data` 卷 | `docker compose exec -T postgres pg_dump -U postgres knowledge_base > kb.sql` |
| 向量 | `qdrant_data` 卷 | 停容器后打包卷，或用 Qdrant snapshot API |
| 原始文件 | `backend/uploads` | `tar -czf uploads.tar.gz backend/uploads` |
| 运行期状态 | `backend/data` | `tar -czf data.tar.gz backend/data`（BM25 索引 / 缓存 / 长期记忆，可重建但备份更省事） |

示例脚本（crontab 每日）：

```bash
#!/bin/bash
DATE=$(date +%Y%m%d)
mkdir -p /data/backup
docker compose exec -T postgres pg_dump -U postgres knowledge_base > /data/backup/kb_$DATE.sql
tar -czf /data/backup/files_$DATE.tar.gz backend/uploads backend/data
find /data/backup -name "*.sql" -mtime +14 -delete
find /data/backup -name "*.tar.gz" -mtime +14 -delete
```

> 手动部署（SQLite）时，改为备份 `backend/knowledge_base.db` + `backend/uploads` + `backend/chroma_db`。

## 六、常见问题排查

| 现象 | 原因 | 排查方向 |
|---|---|---|
| 前端能打开但接口 502 | 后端未就绪 | `docker compose ps` 看 backend 是否 healthy |
| 接口报 `no such column` | 没跑迁移 | `docker compose exec backend alembic current` / `db_bootstrap.py` |
| 文档一直 processing | worker 连错库（overlay 覆盖了 DATABASE_URL） | `docker compose config` 看两边 DATABASE_URL 是否一致 |
| 处理成功但检索为空 | worker 写 Chroma、API 读 Qdrant | 两边 `VECTOR_PROVIDER` / `QDRANT_URL` 必须一致 |
| 问答 500 | Key / Base URL / 模型名 | 用 curl 直接打模型接口验证 |
| 流式一次性返回 | Nginx 开了缓冲 | `proxy_buffering off` + `X-Accel-Buffering: no` |
| 上传大文件失败 | Nginx / 后端限制 | `client_max_body_size` 与 `MAX_FILE_SIZE_MB` |
| 跨域错误 | CORS 白名单 | `CORS_ORIGINS` 只填域名，不要带路径 |
| 改了 `.env` 不生效 | 没重启 | `docker compose restart backend` |
| 容器反复重启 | 迁移失败或端口冲突 | `docker compose logs backend` 看第一屏报错 |

实时日志：`docker compose logs -f backend`
