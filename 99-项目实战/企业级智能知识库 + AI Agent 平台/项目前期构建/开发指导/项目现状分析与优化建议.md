## 二、任务分工：你的核心任务 vs AI 代劳

### 2.1 你必须亲自动手完成的部分（AI 替代不了）

这些是面试的「命根子」——面试官考的是你脑子里的东西，不是仓库里的东西：

1. **配好真实环境跑起来**：注册豆包/DeepSeek Key，填 `.env`，启动前后端，上传真实文档走查全部页面。这是后面一切的前提。
2. **逐行读懂核心模块并白板手写**（能脱稿复现才算过关）：
   - BM25 打分公式、RRF 融合（`retrieval/`）
   - Hit@K / MRR 计算（`evaluation/metrics.py`）
   - Agent ReAct 循环 + Function Calling 消息协议（`services/agent_service.py`）
   - SSE 流式前后端配合（`routers/chat.py` + `src/api/chat.ts`）
3. **扩充 golden QA 并跑通优化闭环**：把 10 条示例扩到 30-50 条覆盖你上传的真实文档，亲自做一轮「跑评测 → 发现 Hit@K 低的用例 → 定位是切片还是检索还是 Prompt 的问题 → 优化 → 指标提升」。这条闭环故事是面试最大杀手锏。
4. **自主扩展 1-2 个功能**：在骨架上做属于你自己的功能（建议方向见第四节），并能讲清楚设计取舍。
5. **部署上线**：买服务器、域名、HTTPS、Nginx——流程必须亲手走一遍，踩坑经历本身就是面试素材。
6. **求职材料**：技术博客、3 分钟 / 10 分钟两版项目话术、简历量化成果（用评测报告的真实数字）。

### 2.2 AI 可以代劳的部分（本次已实现 + 后续可继续委托）

- ✅ **修 Bug**：`.env.example` JWT 算法拼写（已修）

## 四、优化建议与拓展方向（按价值 × 优先级排序）

结合 2025-2026 全栈 AI 工程的主流方向（评测驱动开发、Agent 可靠性、多模态、可观测、LLM 安全），按「面试价值 ÷ 实现成本」排序：

### P0 —— 直接决定 offer 的事

**1. 评测驱动优化闭环（价值 ★★★★★）**
你已有全套评测基建，但缺的是「数据 + 过程」。用真实文档扩 golden QA 到 30-50 条，跑出基线报告，做至少 2 轮有记录的优化（如：调整 CHUNK_SIZE 对比 Hit@K、开/关 Rerank 对比 MRR），把前后报告留档。**理由**：这是中小 AI 公司最看重的能力——「能不能把效果调上去」；也是你简历上唯一能量化的数字来源。成本：3-5 天，纯你自己的活。

**2. 真实数据走查 + bad case 日记（价值 ★★★★★）**
用 5-10 份真实业务文档跑通所有页面，把回答不好的 case 记成清单（问题、检索到了什么、答案差在哪、归因到切片/检索/生成哪一层）。**理由**：面试必问「遇到过什么最难的问题」，没有真实踩坑故事的项目讲不活。成本：2-3 天。

### P1 —— 高性价比扩展（1-2 周内可完成）

**3. Agentic RAG 可视化（价值 ★★★★）**
评测中心这次补上了「效果可视化」，下一步把 Agent 的思考轨迹可视化：在 AgentDemo 页展示每轮检索的关键词、工具调用链、token 消耗（后端已有 trace 数据，缺前端时间线组件）。**理由**：Agent 可解释性是当前行业热点，演示效果炸裂；且复用现有数据，AI 可代劳大半。

**4. 用户权限管理 RBAC（价值 ★★★★，计划 P1 未实现）**
加 `role` 字段（admin/member）+ 知识库协作成员表，admin 可管理公共库。**理由**：补齐计划书里唯一缺失的 P1 功能；「多租户权限设计」是企业服务公司高频面试题。建议：先由 AI 出设计稿，表结构变更你自己拍板（表设计是面试基本功）。

**5. 前端测试脚手架（价值 ★★★）**
Vitest + 2-3 个关键组件测试（chat 流式解析、评测页分数着色）。**理由**：面试聊「工程质量」时前端零测试是短板；成本半天。

### P2 —— 拔高亮点（有余力再做）

**6. GraphRAG 轻量版（价值 ★★★☆）**
对知识库构建实体-关系抽取（LLM 抽取三元组入 SQLite），检索时图谱扩展一跳邻居。**理由**：GraphRAG 是当前 RAG 演进最热方向，能讲出「什么时候该上图谱、什么时候向量够了」就是差异化；但完整实现成本高，做轻量版+文档即可。
**7. 结构化输出 + 深度问答模式（价值 ★★★）**
利用 LLM 结构化输出（JSON Schema）做「对比表 / 时间线 / 要点摘要」三种回答模板，用户可切换。**理由**：Structured Output 是 2025 年后 LLM 应用的标配能力，成本低、演示直观。
**8. 本地开源模型接入（价值 ★★☆）**
通过 Ollama 接入 Qwen 等本地模型作为可选 provider。**理由**：能聊「私有化部署与成本权衡」；优先级低是因为对求职故事增量有限。

### 不建议现在做的

- 微调实战（有选型文档即可，中小公司岗位极少要求真微调过）
- 更多协议（已有 MCP/A2A 够讲，再加是堆砌）
- 换 Postgres/K8s 等重型生产化（面试问原理即可，简历上「用过」比「真部署过 K8s」性价比高）
