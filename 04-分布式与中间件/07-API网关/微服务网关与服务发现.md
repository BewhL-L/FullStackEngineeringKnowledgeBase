# 微服务网关与服务发现

> 微服务架构下，服务数量众多，如何让服务之间互相发现、如何统一管理入口流量，是微服务基础设施的核心。服务发现（注册中心）解决"服务在哪"的问题，API网关解决"统一入口"的问题。本文从原理到实战，完整讲解微服务网关与服务发现。
>
> **核心组件**：注册中心（Nacos/Eureka/Consul）+ 网关（Spring Cloud Gateway/Kong/APISIX）。

---

## 一、概述：微服务基础设施

### 1.1 为什么需要服务发现

| 单体架构 | 微服务架构 |
|---------|-----------|
| 服务在同一进程，直接方法调用 | 服务分布在不同节点，需要网络调用 |
| 地址固定（localhost） | 服务动态扩缩，IP/端口变化 |
| 无需注册发现 | 需要注册中心管理服务地址 |

### 1.2 服务发现核心概念

```text
服务提供者（Provider）：启动时向注册中心注册自己的地址
服务消费者（Consumer）：从注册中心获取提供者地址列表，然后调用
注册中心（Registry）：维护服务名 → 地址列表的映射，支持健康检查

调用流程：
1. Provider启动 → 注册到Registry（IP+端口+服务名）
2. Consumer启动 → 从Registry订阅服务
3. Registry推送Provider地址列表给Consumer
4. Consumer通过负载均衡选择一个Provider调用
5. Provider宕机 → Registry健康检查剔除 → 通知Consumer更新
```

### 1.3 API网关核心概念

```text
API网关 = 微服务的统一入口
所有外部请求先到网关，网关负责路由、认证、限流、监控等

核心功能：
- 路由转发：根据路径/规则转发到对应服务
- 认证授权：统一登录校验、权限检查
- 限流熔断：保护后端服务不被打垮
- 协议转换：HTTP → gRPC、REST → GraphQL
- 日志监控：统一访问日志、链路追踪
- 灰度发布：按规则分流到不同版本
```

## 二、底层原理：注册中心与网关

### 2.1 注册中心对比

| 特性 | Nacos | Eureka | Consul | ZooKeeper |
|------|-------|--------|--------|-----------|
| 开发语言 | Java | Java | Go | Java |
| CAP模型 | AP/CP可切换 | AP | CP | CP |
| 健康检查 | 客户端心跳+TCP/HTTP | 客户端心跳 | Agent+TCP/HTTP | 会话保持 |
| 配置中心 | 支持 | 不支持 | 支持（KV） | 支持（ZK节点） |
| 控制台 | 完善 | 基础 | 完善 | 第三方 |
| 性能 | 高 | 高 | 中 | 中 |
| 生态 | Spring Cloud Alibaba | Spring Cloud Netflix | HashiCorp生态 | Hadoop生态 |
| 推荐度 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐（已停更） | ⭐⭐⭐⭐ | ⭐⭐⭐ |

### 2.2 Nacos架构原理

```text
Nacos Server
├── 服务注册（Naming）
│   ├── 临时实例（AP）：客户端心跳，不健康自动剔除
│   └── 持久实例（CP）：健康检查，不健康不剔除但标记
├── 配置管理（Config）
│   ├── 配置发布/订阅
│   ├── 版本管理（灰度回滚）
│   └── 监听推送（长轮询）
└── 集群管理
    ├── 节点间数据同步（Distro协议 for AP / Raft for CP）
    └── 选主（CP模式下Raft选主）
```

### 2.3 API网关对比

| 特性 | Spring Cloud Gateway | Kong | APISIX | Nginx+Lua |
|------|---------------------|------|--------|-----------|
| 开发语言 | Java | Lua/Go | Lua | Lua |
| 性能 | 中 | 高 | 极高 | 极高 |
| 插件生态 | Spring生态 | 丰富 | 丰富 | 需自研 |
| 动态路由 | 支持 | 支持（DB） | 支持（etcd） | 需reload |
| 配置方式 | Java代码/YAML | 管理界面/API | 管理界面/API | 配置文件 |
| 适用场景 | Java技术栈 | 通用、企业级 | 云原生、高性能 | 已有Nginx技术栈 |

### 2.4 Spring Cloud Gateway原理

```text
请求 → Gateway Handler Mapping（路由匹配）
     → Gateway Web Handler（过滤器链）
     → 代理转发（Netty HttpClient）
     → 后端服务

过滤器链：
GlobalFilter（全局） + GatewayFilter（路由级）
顺序：pre过滤器（请求前）→ 代理 → post过滤器（响应后）

核心过滤器：
- 路由过滤器：Path、Host、Header、Cookie匹配
- 过滤器工厂：StripPrefix、AddRequestHeader、RequestRateLimiter
- 全局过滤器：LoadBalancer（负载均衡）、NettyRouting（转发）
```

### 3.4 Spring Cloud Gateway网关配置

```xml
<!-- gateway-service pom.xml -->
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-gateway</artifactId>
</dependency>
<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-nacos-discovery</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.cloud</groupId>

```

```yaml
# gateway-service application.yml
server:
  port: 9000

spring:
  application:
    name: gateway-service
  cloud:
    nacos:
      discovery:
        server-addr: localhost:8848
    gateway:
      discovery:
        locator:
          enabled: true  # 开启服务发现路由（自动按服务名路由）
          lower-case-service-id: true
      routes:
        # 用户服务路由
        - id: user-service-route
          uri: lb://user-service  # lb:// 表示负载均衡
          predicates:
            - Path=/api/user/**
          filters:
            - StripPrefix=1  # 去掉/api前缀
            - name: RequestRateLimiter  # 限流
              args:
                redis-rate-limiter.replenishRate: 100
                redis-rate-limiter.burstCapacity: 200
                key-resolver: "#{@ipKeyResolver}"
        # 订单服务路由
        - id: order-service-route
          uri: lb://order-service
          predicates:
            - Path=/api/order/**
          filters:
            - StripPrefix=1
      # 全局跨域配置
      globalcors:
        cors-configurations:
          '[/**]':
            allowed-origins: "*"
            allowed-methods: "*"
            allowed-headers: "*"
            allow-credentials: true
```

### 3.5 网关自定义过滤器

```java
// 全局认证过滤器
@Component
public class AuthGlobalFilter implements GlobalFilter, Ordered {

    @Autowired
    private RedisTemplate<String, String> redisTemplate;

    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        ServerHttpRequest request = exchange.getRequest();
        String path = request.getURI().getPath();

        // 白名单路径直接放行
        if (isWhitelist(path)) {
            return chain.filter(exchange);
        }

        // 校验Token
        String token = request.getHeaders().getFirst("Authorization");
        if (token == null || !token.startsWith("Bearer ")) {
            return unauthorized(exchange, "缺少Token");
        }

        String userId = redisTemplate.opsForValue().get("token:" + token.substring(7));
        if (userId == null) {
            return unauthorized(exchange, "Token无效或已过期");
        }

        // 将用户ID传递给下游服务
        ServerHttpRequest modifiedRequest = request.mutate()
            .header("X-User-Id", userId)
            .build();

        return chain.filter(exchange.mutate().request(modifiedRequest).build());
    }

    private boolean isWhitelist(String path) {
        return path.startsWith("/api/user/login") ||
               path.startsWith("/api/user/register") ||
               path.startsWith("/actuator");
    }

    private Mono<Void> unauthorized(ServerWebExchange exchange, String message) {
        exchange.getResponse().setStatusCode(HttpStatus.UNAUTHORIZED);
        exchange.getResponse().getHeaders().add("Content-Type", "application/json");
        String body = "{"code":401,"message":"" + message + ""}";
        DataBuffer buffer = exchange.getResponse().bufferFactory().wrap(body.getBytes());
        return exchange.getResponse().writeWith(Mono.just(buffer));
    }

    @Override
    public int getOrder() {
        return -100;  // 优先级，数字越小越先执行
    }
}
```

### 3.6 服务间调用（OpenFeign）

```xml
<!-- order-service pom.xml -->
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-openfeign</artifactId>
</dependency>
```

```java
// Feign客户端
@FeignClient(name = "user-service", path = "/user")
public interface UserClient {

    @GetMapping("/{id}")
    Result<User> getUserById(@PathVariable("id") Long id);

    @PostMapping("/batch")
    Result<List<User>> getUsersByIds(@RequestBody List<Long> ids);
}

// 使用
@Service
public class OrderService {

    @Autowired
    private UserClient userClient;

    public OrderDetail getOrderDetail(Long orderId) {
        Order order = orderMapper.selectById(orderId);
        // 调用用户服务获取用户信息
        Result<User> userResult = userClient.getUserById(order.getUserId());
        User user = userResult.getData();
        return new OrderDetail(order, user);
    }
}
```

## 四、常见问题与排查

### 4.1 服务注册发现问题

| 问题 | 原因 | 解决 |
|------|------|------|
| 服务注册不上 | Nacos地址错误、网络不通 | 检查server-addr配置、防火墙、Nacos状态 |
| 服务已注册但调用不到 | 服务名不一致、命名空间不同 | 检查spring.application.name、namespace配置 |
| 服务下线不及时 | 心跳间隔长、不健康剔除慢 | 调整lease-renewal-interval、health-check |
| 调用负载不均 | 权重配置、区域亲和 | 检查Nacos权重配置、负载均衡策略 |
| 多环境混淆 | namespace/group配置错误 | 严格按环境隔离namespace |

### 4.2 网关问题排查

```bash
# 1. 查看网关路由
curl http://localhost:9000/actuator/gateway/routes

# 2. 查看网关过滤器
curl http://localhost:9000/actuator/gateway/globalfilters

# 3. 开启网关调试日志
logging:
  level:
    org.springframework.cloud.gateway: DEBUG
    reactor.netty: DEBUG

# 4. 检查服务注册状态
# Nacos控制台 → 服务管理 → 服务列表 → 查看实例数和健康状态
```

### 4.3 常见错误

| 错误 | 原因 | 解决 |
|------|------|------|
| 503 Service Unavailable | 服务未注册或全部不健康 | 检查Nacos服务实例状态 |
| 404 Not Found | 路由规则不匹配 | 检查Path断言、StripPrefix配置 |
| 连接超时 | 后端服务慢或网络问题 | 调整超时时间、检查后端性能 |
| 循环调用 | 路由配置错误，网关转发给自己 | 检查uri配置，避免lb://gateway-service |
| CORS错误 | 跨域配置不生效 | 检查globalcors配置、预检请求处理 |

### 5.2 网关限流方案

| 限流维度 | 实现方式 | 适用场景 |
|---------|---------|---------|
| IP限流 | RequestRateLimiter + IP KeyResolver | 防爬虫、防攻击 |
| 用户限流 | 按用户ID限流 | 防止单个用户滥用 |
| 接口限流 | 按路由路径限流 | 保护特定接口 |
| 全局限流 | 网关总QPS限制 | 保护整体系统 |
| 分布式限流 | Redis+Lua | 多网关实例统一限流 |

### 5.3 最佳实践清单

- [ ] 注册中心集群部署（至少3节点）
- [ ] 服务名规范（业务-模块-服务）
- [ ] 命名空间按环境隔离（dev/test/prod）
- [ ] 网关统一入口，外部不直连后端服务
- [ ] 网关做认证、限流、日志、监控
- [ ] 服务间调用使用OpenFeign + 负载均衡
- [ ] 配置中心管理配置，支持动态刷新
- [ ] 服务健康检查配置合理（心跳+就绪探针）
- [ ] 优雅上下线（避免调用失败）
- [ ] 网关超时配置合理（连接超时+读取超时）
- [ ] 链路追踪集成（Sleuth+Zipkin / SkyWalking）
- [ ] 网关限流降级保护后端
- [ ] 定期清理无效服务实例
