# 前端工程化与构建工具

> 前端工程化的完整体系：模块化、构建工具、代码规范、自动化测试、CI/CD、性能优化。

## 概述

前端工程化是指用软件工程的方法和工具来管理前端开发流程，提高开发效率、代码质量和可维护性。它不是某个具体工具，而是一套完整的开发体系。

**前端工程化的核心目标**：
- 提高开发效率（热更新、自动构建、脚手架）
- 保证代码质量（Lint、格式化、类型检查、测试）
- 降低维护成本（模块化、组件化、文档）
- 自动化重复工作（构建、部署、测试）
- 团队协作规范（代码风格、Git工作流、Code Review）

**前端工程化的发展历程**：
```text
手工时代 → 模块化时代 → 构建工具时代 → 工程化体系时代
  ↓            ↓              ↓                ↓
直接写JS    SeaJS/RequireJS  Grunt/Gulp      Webpack/Vite
手动引入    浏览器端模块化    任务流自动化    全链路工程化
```

## 原理

### 前端工程化的六大支柱

```text
┌─────────────────────────────────────────────────┐
│                  前端工程化体系                    │
├──────────┬──────────┬──────────┬────────────────┤
│  模块化   │  构建工具 │ 代码规范  │  自动化测试    │
│  组件化   │  打包优化 │ 类型检查  │  单元/E2E     │
├──────────┼──────────┼──────────┼────────────────┤

└──────────┴──────────┴──────────┴────────────────┘
```

### 1. 模块化与组件化

**模块化的演进**：
- **IIFE**：立即执行函数，避免全局变量污染
- **CommonJS**：Node.js 模块规范，`require/module.exports`，同步加载
- **AMD**：浏览器端异步模块，`define/require`，RequireJS
- **CMD**：Common Module Definition，SeaJS，按需加载
- **ESM**：ES6 Module，`import/export`，静态分析，浏览器原生支持

**组件化**：
- UI 组件：按钮、表单、弹窗等可复用 UI 单元
- 业务组件：登录框、搜索栏等业务相关组件
- 页面组件：完整页面级组件
- 组件库：Element Plus、Ant Design、Vuetify

### 2. 构建工具核心原理

**构建工具做什么**：
```text
源代码（ES6+/TS/JSX/Vue/SCSS）
    ↓
转换（Babel/TS编译器 → ES5）
    ↓
打包（分析依赖图 → 合并模块）
    ↓
优化（压缩/Tree Shaking/代码分割）
    ↓
产物（JS/CSS/HTML/静态资源）
```

**Webpack 核心概念**：
- **Entry**：入口，构建的起点
- **Output**：输出，产物的位置和命名
- **Loader**：模块转换器，处理非 JS 文件（CSS、图片、TS）
- **Plugin**：插件，执行更广泛的任务（压缩、提取CSS、生成HTML）
- **Mode**：模式，development/production，自动启用对应优化
- **DevServer**：开发服务器，热更新、代理

**Vite 核心概念**（详见 [[Vite构建工具原理]]）：
- 开发时：原生 ESM + esbuild 预构建
- 构建时：Rollup 打包
- HMR：基于 ESM 的精确热更新

**Babel 原理**：
```text
源代码 → Parse（解析成AST）→ Transform（转换AST）→ Generate（生成代码）
```
- Preset：预设，一组插件的集合（@babel/preset-env、@babel/preset-react、@babel/preset-typescript）
- Plugin：单个转换功能
- Polyfill：为旧浏览器提供新 API 的实现（core-js）

### 3. 代码规范与质量

**ESLint**：代码质量检查，发现潜在错误和不规范写法
**Prettier**：代码格式化，统一代码风格
**TypeScript**：静态类型检查，在编译时发现类型错误
**Stylelint**：CSS 代码检查
**Commitlint**：Git 提交信息规范检查

**常见配置组合**：
```text
ESLint + Prettier + TypeScript + Husky + lint-staged
    ↓
提交代码时自动检查和格式化
```

### 4. 自动化测试

- **单元测试**：测试单个函数/组件（Vitest、Jest）
- **组件测试**：测试 Vue/React 组件（Vue Test Utils、Testing Library）
- **E2E 测试**：端到端测试，模拟用户操作（Cypress、Playwright）
- **快照测试**：对比 UI 渲染结果的快照

### 5. CI/CD

- **持续集成（CI）**：代码提交后自动构建、测试、检查
- **持续部署（CD）**：通过测试后自动部署到生产环境
- 常见平台：GitHub Actions、GitLab CI、Jenkins、Vercel、Netlify

### 6. 性能优化

- **构建优化**：分包、Tree Shaking、压缩、缓存
- **加载优化**：懒加载、预加载、CDN、HTTP缓存
- **运行时优化**：虚拟列表、防抖节流、Web Worker

## 实操

### 1. 从零搭建前端工程化项目

```bash
# 1. 初始化项目
mkdir my-project && cd my-project
npm init -y

# 2. 安装 Vite + Vue + TS
npm create vite@latest . -- --template vue-ts

# 3. 安装 ESLint + Prettier
npm install -D eslint prettier eslint-plugin-vue @typescript-eslint/parser @typescript-eslint/eslint-plugin eslint-config-prettier

# 4. 安装 Husky + lint-staged（提交时自动检查）
npm install -D husky lint-staged
npx husky install
npx husky add .husky/pre-commit "npx lint-staged"

# 5. 安装测试框架
npm install -D vitest @vue/test-utils jsdom

# 6. 项目结构
my-project/
├── .husky/              # Git hooks
├── public/              # 静态资源
├── src/
│   ├── assets/          # 资源文件
│   ├── components/      # 通用组件
│   ├── views/           # 页面组件
│   ├── stores/          # 状态管理
│   ├── router/          # 路由
│   ├── utils/           # 工具函数
│   ├── api/             # API 接口
│   ├── types/           # TypeScript 类型
│   ├── styles/          # 全局样式
│   ├── App.vue
│   └── main.ts
├── tests/               # 测试文件
├── .eslintrc.cjs        # ESLint 配置
├── .prettierrc          # Prettier 配置
├── vite.config.ts       # Vite 配置
├── tsconfig.json        # TypeScript 配置
└── package.json
```

### 2. ESLint + Prettier 配置

```javascript
// .eslintrc.cjs
module.exports = {
  root: true,
  env: { browser: true, es2020: true, node: true },
  extends: [
    'eslint:recommended',
    'plugin:@typescript-eslint/recommended',
    'plugin:vue/vue3-recommended',
    'prettier' // 必须在最后，覆盖其他规则的格式部分
  ],
  parser: 'vue-eslint-parser',
  parserOptions: {
    parser: '@typescript-eslint/parser',
    ecmaVersion: 'latest',
    sourceType: 'module'
  },
  rules: {
    'vue/multi-word-component-names': 'off',
    '@typescript-eslint/no-unused-vars': ['warn', { argsIgnorePattern: '^_' }],
    'no-console': ['warn', { allow: ['warn', 'error'] }]
  }
}
```

### 3. package.json 脚本

```json
{
  "scripts": {
    "dev": "vite",
    "build": "vue-tsc --noEmit && vite build",
    "preview": "vite preview",
    "lint": "eslint . --ext .vue,.js,.ts --fix",
    "format": "prettier --write \"src/**/*.{vue,js,ts,json,css,scss}\"",
    "test": "vitest",
    "test:coverage": "vitest --coverage",
    "type-check": "vue-tsc --noEmit",
    "prepare": "husky install"
  },
  "lint-staged": {
    "*.{vue,js,ts}": ["eslint --fix", "prettier --write"],
    "*.{json,css,scss,md}": ["prettier --write"]
  }
}
```

### 4. GitHub Actions CI 配置

```yaml
# .github/workflows/ci.yml
name: CI

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  build-and-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
      - run: npm ci
      - run: npm run lint
      - run: npm run type-check
      - run: npm run test
      - run: npm run build
```

## 问题

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| ESLint和Prettier冲突 | 规则重叠，格式化标准不一致 | 用eslint-config-prettier关闭ESLint的格式规则 / Prettier只管格式，ESLint管质量 |
| 构建慢 | 项目大 / 依赖多 / 未用缓存 | 用Vite替代Webpack / 配置构建缓存 / 并行构建 / 升级Node版本 |
| 打包体积大 | 未分包 / 全量引入库 / 未Tree Shaking | 配置manualChunks / 按需引入 / 检查依赖 / 用rollup-plugin-visualizer分析 |
| 类型检查不通过 | TS配置错误 / 类型定义缺失 / any滥用 | 检查tsconfig / 安装@types包 / 逐步替换any / 用vue-tsc |
| HMR不生效 | 组件命名问题 / 文件路径大小写 / 缓存 | 组件用多词命名 / 检查路径大小写 / 清除缓存重启 / 检查import路径 |
| 依赖版本冲突 | 多个包依赖同一库的不同版本 | 用npm overrides / pnpm overrides / 升级或降级统一版本 / 检查peerDependencies |
| CI环境构建失败 | 本地能构建CI失败 / 环境差异 | 锁定依赖版本(package-lock.json) / 用npm ci / 检查Node版本 / 配置环境变量 |
| 样式穿透不生效 | CSS scoped / 预处理器嵌套 / 选择器优先级 | 用:deep() / ::v-deep / 检查选择器 / 提高优先级 / 用全局样式 |
| 代理不生效 | proxy配置错误 / 路径重写 / 后端跨域 | 检查target / 配置rewrite / 用changeOrigin / 后端配置CORS |
| 内存溢出(OOM) | 项目太大 / 构建时内存不足 | 增加Node内存(--max-old-space-size=4096) / 优化构建配置 / 分包构建 |
