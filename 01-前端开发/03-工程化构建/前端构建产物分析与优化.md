## 一、概述

### 1. 为什么需要分析构建产物

```text
构建产物的重要性：
- 直接影响首屏加载时间（JS/CSS 体积越大，加载越慢）
- 影响用户流量消耗（移动端尤其重要）
- 影响缓存效率（合理的文件分割提升缓存命中率）
- 影响构建速度（产物越大，构建越慢）

常见问题：
- 打包体积过大（单个 JS > 500KB）
- 依赖冗余（引入了未使用的代码）
- 重复打包（多个 chunk 包含相同代码）
- 不合理的代码分割（首屏加载了非首屏代码）
- 缓存失效（文件名没有 hash，每次发布都失效）

优化目标：
- 首屏 JS < 200KB（gzip 后）
- 首屏 CSS < 50KB（gzip 后）
- 单个 chunk < 200KB（便于并行加载和缓存）
- 第三方依赖单独打包（vendor chunk）
- 长期缓存（文件名带 content hash）
```

### 2. 构建产物组成

```text
典型前端构建产物：

dist/
├── index.html              # HTML 入口
├── assets/
│   ├── index-abc123.js     # 主 JS chunk
│   ├── index-def456.css    # 主 CSS chunk
│   ├── vendor-ghi789.js    # 第三方依赖 chunk
│   ├── router-jkl012.js    # 路由级异步 chunk
│   ├── component-mno345.js # 组件级异步 chunk
│   ├── logo-pqr678.svg     # 静态资源
│   ├── hero-stu901.webp    # 图片
│   └── Inter-vwx234.woff2  # 字体
├── favicon.ico
└── manifest.json            # PWA manifest

产物分类：
1. HTML：入口文件，通常很小
2. JS：业务代码 + 第三方依赖，通常最大
3. CSS：样式文件
4. 静态资源：图片、字体、SVG、媒体文件
5. 其他：source map、manifest、service worker

关键指标：
- 原始大小（Raw size）：未压缩
- Gzip 大小：Gzip 压缩后
- Brotli 大小：Brotli 压缩后（通常比 Gzip 小 15-25%）
- 解析/执行时间：JS 解析和执行耗时
```

## 三、体积优化

### 1. Tree Shaking

```text
Tree Shaking（摇树优化）：
- 移除未使用的代码（dead code elimination）
- 基于 ES Module 的静态分析（import/export）
- 生产构建时自动启用

Tree Shaking 生效条件：
1. 使用 ES Module（import/export），不能用 CommonJS（require）
2. package.json 中设置 "sideEffects": false 或指定副作用文件
3. 生产模式构建（mode: 'production'）
4. 不要动态 import 整个模块（import * as）

常见问题：
- 整个包被引入（import _ from 'lodash'）→ 用按需引入
- CSS 被 Tree Shaking 移除 → 在 sideEffects 中声明 CSS
- 副作用代码被移除 → 正确配置 sideEffects
```

```javascript
// package.json
{
  "name": "my-package",
  "sideEffects": [
    "*.css",
    "*.scss",
    "src/polyfill.js"
  ]
  // false 表示没有副作用，可以安全 Tree Shaking
  // 数组列出有副作用的文件
}

// ❌ 不好：引入整个库
import _ from 'lodash'
import { debounce, throttle } from 'lodash'  // 仍然可能引入整个包

// ✅ 好：按需引入
import debounce from 'lodash/debounce'
import throttle from 'lodash/throttle'

// 或用 lodash-es（ES Module 版本，支持 Tree Shaking）
import { debounce, throttle } from 'lodash-es'

// ❌ 不好：引入整个组件库
import ElementPlus from 'element-plus'
app.use(ElementPlus)

// ✅ 好：按需引入（配合 unplugin-vue-components）
// vite.config.js
import Components from 'unplugin-vue-components/vite'
import { ElementPlusResolver } from 'unplugin-vue-components/resolvers'

export default {
  plugins: [
    Components({
      resolvers: [ElementPlusResolver()]
    })
  ]
}
```

### 2. 代码分割（Code Splitting）

```text
代码分割策略：

1. 入口分割（Entry Points）
   - 多页面应用，每个页面一个入口
   - 单页面应用通常只有一个入口

2. 防止重复（Split Chunks）
   - 公共依赖提取到单独 chunk
   - 避免重复打包

3. 动态导入（Dynamic Import）
   - 路由级分割：每个路由一个 chunk
   - 组件级分割：大组件异步加载
   - 功能级分割：特定功能按需加载

4. 第三方依赖分割（Vendor）
   - node_modules 单独打包
   - 变化频率低，适合长期缓存
```

```javascript
// Webpack 配置
module.exports = {
  optimization: {
    splitChunks: {
      chunks: 'all',  // 同步和异步都分割
      cacheGroups: {
        // Vue 生态
        vue: {
          name: 'vue-vendor',
          test: /[\\/]node_modules[\\/](vue|vue-router|pinia)[\\/]/,
          priority: 20,
        },
        // UI 库
        ui: {
          name: 'ui-vendor',
          test: /[\\/]node_modules[\\/](element-plus|ant-design-vue)[\\/]/,
          priority: 20,
        },
        // 工具库
        utils: {
          name: 'utils-vendor',
          test: /[\\/]node_modules[\\/](lodash|dayjs|axios)[\\/]/,
          priority: 10,
        },
        // 其他第三方
        vendor: {
          name: 'vendor',
          test: /[\\/]node_modules[\\/]/,
          priority: 5,
          minChunks: 2,  // 至少被 2 个 chunk 引用才提取
        },
        // 公共代码
        common: {
          name: 'common',
          minChunks: 2,
          priority: 1,
          reuseExistingChunk: true,
        }
      }
    },
    // 运行时代码单独提取
    runtimeChunk: {
      name: 'runtime'
    }
  }
}
```

```javascript
// Vite 配置（Rollup 选项）
// vite.config.js
export default defineConfig({
  build: {
    rollupOptions: {
      output: {
        // 手动分包
        manualChunks: {
          'vue-vendor': ['vue', 'vue-router', 'pinia'],
          'ui-vendor': ['element-plus'],
          'utils-vendor': ['lodash-es', 'dayjs', 'axios'],
          'chart-vendor': ['echarts'],
        },
        // 或用函数动态分包
        manualChunks(id) {
          if (id.includes('node_modules')) {
            if (id.includes('vue')) return 'vue-vendor'
            if (id.includes('element-plus')) return 'ui-vendor'
            if (id.includes('echarts')) return 'chart-vendor'
            return 'vendor'
          }
        },
        // chunk 文件名
        chunkFileNames: 'assets/js/[name]-[hash].js',
        entryFileNames: 'assets/js/[name]-[hash].js',
        assetFileNames: 'assets/[ext]/[name]-[hash].[ext]',
      }
    }
  }
})
```

```javascript
// 路由级代码分割（Vue Router）
const routes = [
  {
    path: '/',
    name: 'Home',
    // 首屏页面可以直接导入
    component: () => import('@/views/Home.vue')
  },
  {
    path: '/about',
    name: 'About',
    // 非首屏页面动态导入
    component: () => import(/* webpackChunkName: "about" */ '@/views/About.vue')
  },
  {
    path: '/dashboard',
    name: 'Dashboard',
    // 分组：同一组的 chunk 一起加载

  },
  {
    path: '/admin/users',
    name: 'AdminUsers',
    component: () => import(/* webpackChunkName: "admin" */ '@/views/admin/Users.vue')
  }
]

// 组件级代码分割
const HeavyComponent = defineAsyncComponent(() =>
  import('@/components/HeavyComponent.vue')
)

// 带加载状态和错误状态
const HeavyComponent = defineAsyncComponent({
  loader: () => import('@/components/HeavyComponent.vue'),
  loadingComponent: LoadingSpinner,
  errorComponent: ErrorDisplay,
  delay: 200,
  timeout: 10000,
})
```

### 2. 替换轻量库

```text
常见库的轻量替代：

| 原库 | 大小(gzip) | 替代方案 | 大小(gzip) | 说明 |
|------|-----------|---------|-----------|------|
| lodash | ~24KB | lodash-es（按需）/ 原生方法 | ~2-5KB | 现代 JS 已支持很多方法 |
| moment.js | ~17KB | dayjs / date-fns | ~2-3KB | API 兼容，体积小很多 |
| axios | ~13KB | fetch / ky / ofetch | ~0-5KB | 现代浏览器原生 fetch |
| jquery | ~30KB | 原生 JS / cash | ~0-3KB | 现代项目不需要 |
| echarts | ~100KB | chart.js / apexcharts | ~30-50KB | 按需引入 echarts 模块 |
| xlsx | ~150KB | exceljs / sheetjs（按需） | ~50-100KB | 只在需要时动态导入 |
| markdown-it | ~40KB | marked / micromark | ~10-20KB | 按需选择 |
| crypto-js | ~20KB | Web Crypto API | ~0KB | 浏览器原生支持 |

原则：
- 能用原生 API 就不用库
- 能按需引入就不引入整个库
- 功能简单就用轻量库
- 大型库动态导入（只在需要时加载）
```

```javascript
// ❌ 不好：引入整个 echarts
import * as echarts from 'echarts'

// ✅ 好：按需引入 echarts 模块
import * as echarts from 'echarts/core'
import { BarChart, LineChart } from 'echarts/charts'
import {
  TitleComponent, TooltipComponent, GridComponent, LegendComponent
} from 'echarts/components'
import { CanvasRenderer } from 'echarts/renderers'

echarts.use([
  BarChart, LineChart,
  TitleComponent, TooltipComponent, GridComponent, LegendComponent,
  CanvasRenderer
])

// ❌ 不好：全局引入 xlsx
import XLSX from 'xlsx'

// ✅ 好：动态导入（只在用户点击导出时加载）
async function exportExcel() {
  const XLSX = await import('xlsx')
  // ...
}
```

## 五、缓存优化

### 1. 文件名 Hash

```javascript
// Vite 默认配置（生产构建自动加 hash）
// vite.config.js
export default defineConfig({
  build: {
    rollupOptions: {
      output: {
        // JS 文件：name-hash.js
        entryFileNames: 'assets/js/[name]-[hash].js',
        chunkFileNames: 'assets/js/[name]-[hash].js',
        // CSS 文件
        assetFileNames: (assetInfo) => {
          const ext = assetInfo.name.split('.').pop()
          if (ext === 'css') return 'assets/css/[name]-[hash].[ext]'
          if (['png', 'jpg', 'svg', 'webp'].includes(ext))
            return 'assets/images/[name]-[hash].[ext]'
          if (['woff2', 'woff', 'ttf'].includes(ext))
            return 'assets/fonts/[name]-[hash].[ext]'
          return 'assets/[ext]/[name]-[hash].[ext]'
        }
      }
    }
  }
})

// 构建产物示例：
// assets/js/index-a1b2c3d4.js
// assets/js/vendor-e5f6g7h8.js
// assets/css/index-i9j0k1l2.css
// assets/images/logo-m3n4o5p6.svg
```

### 2. HTTP 缓存策略

```nginx
# Nginx 缓存配置

# HTML：不缓存（每次都获取最新）
location ~* \.html$ {
    add_header Cache-Control "no-cache, no-store, must-revalidate";
    add_header Pragma "no-cache";
    expires 0;
}

# 带 hash 的静态资源：长期缓存（1年）
location ~* \.(js|css|png|jpg|jpeg|gif|svg|ico|woff2|woff|ttf)$ {
    add_header Cache-Control "public, max-age=31536000, immutable";
    expires 1y;
    # 提供预压缩文件
    gzip_static on;
    brotli_static on;
}

# 不带 hash 的资源：协商缓存
location ~* \.(json|xml|txt)$ {
    add_header Cache-Control "public, max-age=0, must-revalidate";
    expires 0;
}
```

```text
缓存策略原则：

1. HTML（入口文件）
   - no-cache：每次都验证
   - 因为 HTML 引用的 JS/CSS 文件名带 hash
   - HTML 本身很小，验证成本低

2. 带 hash 的静态资源（JS/CSS/图片/字体）
   - max-age=31536000, immutable
   - 内容变化时 hash 变化，文件名变化
   - 旧文件名的资源可以永久缓存
   - 这是长期缓存的关键

3. 不带 hash 的资源
   - 协商缓存（ETag / Last-Modified）
   - 或 max-age=0, must-revalidate

4. Service Worker（PWA）
   - 可以更精细地控制缓存
   - 离线可用
   - 但需要谨慎处理更新
```

## 六、构建速度优化

### 1. Vite 构建优化

```javascript
// vite.config.js
export default defineConfig({
  build: {
    // 目标浏览器
    target: 'es2015',  // 现代浏览器，不需要转译太多

    // 用 esbuild 压缩（默认，比 terser 快 10-100 倍）
    minify: 'esbuild',

    // 禁用 source map（生产环境）
    sourcemap: false,

    // 增大 chunk 大小警告（避免不必要的警告）
    chunkSizeWarningLimit: 1500,

    // 依赖预构建（开发模式）
    // optimizeDeps 配置
  },

  // 依赖预构建（开发模式加速）
  optimizeDeps: {
    include: ['vue', 'vue-router', 'pinia', 'axios'],
    exclude: ['some-local-package'],
  },

  // 插件优化
  plugins: [
    vue(),
    // 按需引入组件（减少打包体积）
    Components({ resolvers: [ElementPlusResolver()] }),
    AutoImport({ imports: ['vue', 'vue-router', 'pinia'] }),
  ]
})
```

### 2. 通用构建优化

```text
构建速度优化方法：

1. 升级工具版本
   - 最新版本的 Vite/Webpack 通常更快
   - Node.js 升级到最新 LTS

2. 并行处理
   - Vite 原生支持并行
   - Webpack 用 thread-loader / HappyPack
   - 压缩用并行压缩

3. 缓存
   - Vite 有依赖预构建缓存
   - Webpack 用 cache-loader / 持久化缓存
   - CI 中缓存 node_modules 和构建缓存

4. 减少处理范围
   - exclude 不需要处理的文件
   - include 只处理需要的文件
   - 不要用 babel 处理 node_modules

5. 增量构建
   - 开发模式用 HMR
   - 生产构建用缓存

6. 硬件升级
   - SSD（比 HDD 快很多）
   - 多核 CPU
   - 大内存

7. CI 优化
   - 缓存 node_modules
   - 并行构建
   - 只构建变更的部分
```

## 七、最佳实践

### 1. 分析优先

- [ ] **先分析再优化**：用 bundle analyzer 定位大模块
- [ ] **定期审计**：每月检查依赖和产物大小
- [ ] **设置预算**：CI 中设置体积预算，超过则失败
- [ ] **对比基线**：每次发布对比产物大小变化
- [ ] **关注 gzip 大小**：用户实际下载的是压缩后的大小

### 2. 体积优化

- [ ] **Tree Shaking**：用 ES Module，配置 sideEffects
- [ ] **按需引入**：UI 库、工具库按需引入
- [ ] **代码分割**：路由级、组件级、功能级分割
- [ ] **第三方分包**：node_modules 单独打包，便于缓存
- [ ] **压缩**：Gzip/Brotli 预压缩
- [ ] **移除 console**：生产环境移除 console.log
- [ ] **替换轻量库**：用 dayjs 替代 moment，用 fetch 替代 axios
- [ ] **动态导入大库**：echarts/xlsx 等只在需要时加载
- [ ] **图片优化**：WebP/AVIF、压缩、响应式图片
- [ ] **字体优化**：只加载用到的字重，font-display: swap

### 3. 缓存优化

- [ ] **文件名带 hash**：content hash，内容变化才变
- [ ] **HTML 不缓存**：每次验证，获取最新引用
- [ ] **静态资源长期缓存**：max-age=1年，immutable
- [ ] **第三方依赖单独 chunk**：变化频率低，缓存命中率高
- [ ] **合理的 chunk 大小**：单个 chunk 100-200KB，便于并行加载
- [ ] **CDN 加速**：静态资源用 CDN

### 4. 构建优化

- [ ] **用现代工具**：Vite > Webpack（新项目优先 Vite）
- [ ] **esbuild 压缩**：比 terser 快很多
- [ ] **禁用生产 source map**：减小产物，加快构建
- [ ] **目标现代浏览器**：减少转译开销
- [ ] **CI 缓存**：缓存 node_modules 和构建缓存
- [ ] **并行构建**：多核并行处理

### 5. 监控与维护

- [ ] **构建产物报告**：每次构建生成 analyzer 报告
- [ ] **体积趋势图**：跟踪产物大小变化
- [ ] **依赖更新**：定期更新依赖，获取体积优化
- [ ] **移除未使用依赖**：depcheck 检查并清理
- [ ] **代码审查关注体积**：PR 中检查是否引入了大依赖

## 八、常见问题与排查

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| **打包体积过大** | 引入了大库/未按需引入/未Tree Shaking | 用 analyzer 分析、按需引入、Tree Shaking、代码分割 |
| **单个 JS > 1MB** | 所有代码打包在一起/大库未分割 | splitChunks 分包、路由级分割、动态导入 |
| **Tree Shaking 不生效** | 用了 CommonJS/sideEffects 配置错/动态import | 用 ES Module、配置 sideEffects、避免 import * |
| **CSS 被移除** | sideEffects 未声明 CSS | 在 sideEffects 中列出 CSS 文件 |
| **重复打包** | splitChunks 配置不当/公共依赖未提取 | 配置 splitChunks、minChunks、cacheGroups |
| **首屏加载慢** | 首屏 JS 太大/加载了非首屏代码 | 路由级分割、首屏关键代码内联、预加载 |
| **缓存命中率低** | 文件名无hash/HTML缓存了 | 文件名带 content hash、HTML 不缓存 |
| **每次发布所有缓存失效** | 文件名用了构建时间/版本号而非hash | 用 content hash，内容不变文件名不变 |
| **构建速度慢** | 处理文件太多/压缩慢/未缓存 | 用 esbuild、exclude 不必要文件、CI缓存、升级硬件 |
| **source map 泄露** | 生产环境开启了 source map | 生产环境禁用 source map，或上传到错误监控平台 |
| **依赖版本冲突** | 多个版本的同一包 | npm dedupe、overrides 强制统一版本 |
| **引入了未使用的依赖** | 历史遗留/误添加 | depcheck 检查、移除未使用依赖 |
| **图片体积大** | 未压缩/格式旧 | 压缩图片、WebP/AVIF、响应式图片、图片CDN |
| **字体文件大** | 引入了完整字体/多字重 | 只加载用到的字重、字体子集化、font-display:swap |
| **第三方脚本阻塞** | 同步加载第三方脚本 | 异步加载、延迟加载、defer/async |
| **chunk 太多** | 过度分割 | 调整 splitChunks 配置、合并小 chunk |
| **chunk 太少** | 未分割 | 配置 splitChunks、路由级动态导入 |
| **gzip 未生效** | 服务器未配置/未预压缩 | Nginx 配置 gzip、预生成 .gz 文件 |
| **Brotli 未生效** | 服务器不支持/浏览器不支持 | 配置 Brotli、提供 gzip 降级 |
| **CI 构建慢** | 未缓存/全量构建 | 缓存 node_modules、增量构建、并行任务 |
| **分析工具不显示** | 未生成 stats.json/路径错 | 检查插件配置、确认报告文件生成 |
| **Vite 依赖预构建慢** | 依赖多/未缓存 | 配置 optimizeDeps.include、缓存预构建结果 |
| **生产构建和开发不一致** | 环境变量/插件配置不同 | 检查 mode 配置、统一环境变量、用 production 模式测试 |
