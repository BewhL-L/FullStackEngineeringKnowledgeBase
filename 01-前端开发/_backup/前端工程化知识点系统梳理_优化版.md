# 前端工程化知识点系统梳理（优化版）

> **文档说明**：系统梳理前端工程化体系，涵盖构建工具（Vite/Webpack）、代码规范（ESLint/Prettier）、Git 钩子（Husky/Commitlint）、CI/CD、性能优化、模块化等核心内容。

---

## 1. 概述

前端工程化是将软件工程的方法和工具应用到前端开发中，通过**规范化、自动化、模块化**提升开发效率和代码质量。

**工程化四大支柱**：
- **模块化**：代码组织与复用
- **规范化**：编码规范、提交规范、目录规范
- **自动化**：构建、测试、部署自动化
- **性能化**：构建性能、运行性能优化

## 2. 模块化

### 2.1 模块化方案演进

| 方案 | 特点 | 环境 |
|------|------|------|
| IIFE | 立即执行函数，避免全局污染 | 浏览器 |
| CommonJS | `require/module.exports`，同步加载 | Node.js |
| AMD | `define/require`，异步加载 | 浏览器（RequireJS） |
| CMD | 类似 AMD，依赖就近 | 浏览器（SeaJS） |
| ES Module | `import/export`，静态分析，官方标准 | 浏览器 + Node.js |

### 2.2 ES Module 详解

```javascript
// 导出
export const name = 'Tom';
export function say() {}
export default { }; // 默认导出

// 导入
import { name, say } from './module';
import defaultExport from './module';
import * as all from './module'; // 命名空间导入
import { name as userName } from './module'; // 重命名

// 动态导入（返回 Promise）
const module = await import('./module.js');
```

> 🔍 **知识点深度解析**
>
> **作用**：模块化是工程化的基础，ES Module 是当前标准。
>
> **原理**：ES Module 是静态的，import/export 必须在顶层，不能在条件语句中。这使得构建工具可以进行 Tree Shaking（移除未使用的代码）。CommonJS 是动态的，require 可以在任何地方调用，无法静态分析。ESM 在浏览器中通过 `<script type="module">` 加载，默认延迟执行（defer），CORS 限制。Node.js 12+ 原生支持 ESM（.mjs 或 package.json 中 "type": "module"）。
>
> **用法要点**：① 新项目统一用 ES Module；② `export default` 一个模块只能有一个；③ 具名导出用 `{}` 接收，默认导出直接命名；④ 循环依赖：ESM 支持但需注意导出值是绑定（实时更新），CommonJS 是值拷贝；⑤ 面试常考：ESM 与 CommonJS 区别、Tree Shaking 原理、循环依赖。

## 3. 构建工具

### 3.1 Vite（推荐）

**核心特性**：
- 开发时基于原生 ESM，无需打包，秒级启动
- 生产构建用 Rollup，Tree Shaking 优秀
- 开箱即用：TS、JSX、CSS 预处理器、HMR

```bash
# 创建项目
npm create vite@latest my-app -- --template vue-ts

# 常用命令
npm run dev      # 开发服务器
npm run build    # 生产构建
npm run preview  # 预览构建结果
```

```javascript
// vite.config.ts
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';
import path from 'path';

export default defineConfig({
  plugins: [vue()],
  resolve: {
    alias: { '@': path.resolve(__dirname, 'src') }
  },
  server: {
    port: 3000,
    proxy: {
      '/api': { target: 'http://localhost:8080', changeOrigin: true }
    }
  },
  build: {
    outDir: 'dist',
    sourcemap: false,
    rollupOptions: {
      output: {
        manualChunks: { vue: ['vue', 'vue-router', 'pinia'] }
      }
    }
  }
});
```

### 3.2 Webpack（传统大型项目）

**核心概念**：入口（entry）、输出（output）、loader、plugin、mode

```javascript
// webpack.config.js
const path = require('path');
const HtmlWebpackPlugin = require('html-webpack-plugin');

module.exports = {
  entry: './src/index.js',
  output: { path: path.resolve(__dirname, 'dist'), filename: '[name].[contenthash].js' },
  module: {
    rules: [
      { test: /\.js$/, use: 'babel-loader', exclude: /node_modules/ },
      { test: /\.css$/, use: ['style-loader', 'css-loader'] }
    ]
  },
  plugins: [new HtmlWebpackPlugin({ template: './index.html' })],
  optimization: { splitChunks: { chunks: 'all' } }
};
```

> 🔍 **知识点深度解析**
>
> **作用**：构建工具是工程化的核心，负责代码编译、打包、优化。
>
> **原理**：Vite 开发时利用浏览器原生 ESM，只在请求时编译对应文件（按需编译），启动极快；HMR（热模块替换）在 ESM 基础上精准更新变更模块。生产构建用 Rollup，比 Webpack 的 Tree Shaking 更彻底（因为 ESM 静态分析）。Webpack 是全量打包，启动时需要构建整个依赖图，项目大了启动慢，但生态成熟、插件丰富。Vite 的 `optimizeDeps` 预构建 CommonJS 依赖（esbuild 转 ESM），解决浏览器不能直接加载 CommonJS 的问题。
>
> **用法要点**：① 新项目优先 Vite，老项目维护用 Webpack；② Vite 配置 alias 必须用 path.resolve，不要用相对路径；③ 代理配置 changeOrigin: true 修改 Host 头；④ 生产构建分包：manualChunks 分离第三方库；⑤ 环境变量用 import.meta.env（Vite）或 process.env（Webpack）；⑥ 面试常考：Vite 原理、与 Webpack 区别、HMR 实现、Tree Shaking。

## 4. 代码规范

### 4.1 ESLint

```bash
# 安装
npm install eslint -D
npx eslint --init

# 检查和修复
npx eslint src/**/*.js
npx eslint src/**/*.js --fix
```

```javascript
// .eslintrc.cjs
module.exports = {
  env: { browser: true, es2021: true, node: true },
  extends: ['eslint:recommended', 'plugin:vue/vue3-recommended'],
  parser: 'vue-eslint-parser',
  parserOptions: { ecmaVersion: 'latest', sourceType: 'module' },
  rules: {
    'no-unused-vars': 'warn',
    'no-console': process.env.NODE_ENV === 'production' ? 'warn' : 'off',
    'vue/multi-word-component-names': 'off'
  }
};
```

### 4.3 Stylelint

```bash
npm install stylelint stylelint-config-standard -D
```

```json
// .stylelintrc.json
{
  "extends": ["stylelint-config-standard"],
  "rules": {
    "color-hex-length": "short"
  }
}
```

> 🔍 **知识点深度解析**
>
> **作用**：代码规范保证团队代码风格一致，减少低级错误，提升可维护性。
>
> **原理**：ESLint 通过 AST（抽象语法树）分析代码，根据规则检测问题，部分问题可自动修复。Prettier 是代码格式化工具，不检测逻辑错误，只统一格式（缩进、引号、分号等）。两者配合：ESLint 管代码质量，Prettier 管代码格式。`eslint-config-prettier` 关闭 ESLint 中与 Prettier 冲突的格式规则，`eslint-plugin-prettier` 让 Prettier 规则作为 ESLint 规则运行。
>
> **用法要点**：① ESLint + Prettier 配合使用，不要让两者冲突；② VSCode 安装 ESLint 和 Prettier 插件，设置保存时自动格式化；③ 规则级别：off(0)/warn(1)/error(2)；④ 团队项目统一配置，提交到 Git；⑤ 面试常考：ESLint 与 Prettier 区别、配置方式、保存自动格式化。

## 5. Git 钩子与提交规范

### 5.1 Husky

```bash
# 安装
npm install husky -D
npx husky install
npm set-script prepare "husky install"

# 添加 pre-commit 钩子
npx husky add .husky/pre-commit "npx lint-staged"
```

### 5.2 lint-staged

```json
// package.json
{
  "lint-staged": {
    "*.{js,ts,vue}": ["eslint --fix", "prettier --write"],
    "*.{css,scss}": ["stylelint --fix", "prettier --write"],
    "*.md": ["prettier --write"]
  }
}
```

### 5.3 Commitlint + Conventional Commits

```bash
npm install @commitlint/cli @commitlint/config-conventional -D
npx husky add .husky/commit-msg "npx commitlint --edit $1"
```

```javascript
// commitlint.config.cjs
module.exports = { extends: ['@commitlint/config-conventional'] };
```

**提交格式**：
```
<type>(<scope>): <subject>

feat(auth): 添加登录功能
fix(api): 修复用户列表分页错误
docs(readme): 更新安装说明
style: 格式化代码
refactor: 重构请求模块
perf: 优化列表渲染性能
test: 添加单元测试
chore: 更新依赖
build: 修改构建配置
ci: 修改 CI 配置
revert: 回滚提交
```

> 🔍 **知识点深度解析**
>
> **作用**：Git 钩子在提交时自动检查代码，提交规范让 Git 历史清晰可读，可自动生成 CHANGELOG。
>
> **原理**：Husky 是 Git 钩子工具，在 `.husky/` 目录创建钩子脚本，Git 事件触发时执行。`pre-commit` 在提交前执行（可拦截提交），`commit-msg` 在写入提交信息后执行（校验格式）。lint-staged 只对暂存区（git add 的文件）执行检查，比全量检查快很多。Commitlint 校验提交信息是否符合 Conventional Commits 规范，不符合则拒绝提交。
>
> **用法要点**：① pre-commit 用 lint-staged 只检查暂存文件，提升速度；② commit-msg 用 commitlint 校验提交格式；③ type 必须是规定类型，subject 首字母小写、不加句号；④ 可配合 commitizen 交互式生成提交信息；⑤ 面试常考：Husky 原理、Conventional Commits 格式、lint-staged 作用。

## 6. CI/CD

### 6.1 GitHub Actions 示例

```yaml
# .github/workflows/ci.yml
name: CI
on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
      - run: npm ci
      - run: npm run lint
      - run: npm run test
      - run: npm run build
      - uses: actions/upload-artifact@v4
        with:
          name: dist
          path: dist
```

### 6.2 自动化部署

- **Vercel / Netlify**：前端项目一键部署，自动 HTTPS、CDN
- **GitHub Pages**：静态站点免费托管
- **Docker + Nginx**：容器化部署到自有服务器
- **OSS + CDN**：上传到阿里云/腾讯云对象存储

> 🔍 **知识点深度解析**
>
> **作用**：CI/CD 实现代码提交后自动测试、构建、部署，减少人工操作，提升交付效率。
>
> **原理**：CI（持续集成）在代码提交后自动运行测试和构建，确保代码质量。CD（持续部署/交付）在 CI 通过后自动部署到生产/预发环境。GitHub Actions 通过 YAML 配置工作流，触发事件（push/pr）后在虚拟机（runner）中执行步骤。缓存 node_modules 加速安装，`npm ci` 比 `npm install` 更严格（按 lockfile 精确安装）。
>
> **用法要点**：① CI 必须包含：安装依赖 → 代码检查 → 测试 → 构建；② 用 actions/cache 缓存依赖，提升速度；③ 生产构建禁用 sourcemap，开启 gzip/br 压缩；④ 部署用 hash 文件名（contenthash）利用浏览器缓存；⑤ 面试常考：CI/CD 概念、GitHub Actions 配置、部署方案。

## 7. 性能优化

### 7.1 构建性能

- Vite 天然快，Webpack 用 cache-loader、thread-loader、DLL
- 合理配置 alias，减少模块搜索
- 排除不必要的依赖（externals）

### 7.2 加载性能

| 优化手段 | 说明 |
|----------|------|
| 代码分割 | 路由懒加载、第三方库分包 |
|  Tree Shaking | 移除未使用代码（ESM） |
| 图片优化 | WebP/AVIF、懒加载、响应式图片 |
| 压缩 | Gzip/Brotli、HTML/CSS/JS 压缩 |
| CDN | 静态资源 CDN 加速 |
| 缓存 | HTTP 强缓存+协商缓存、Service Worker |
| 预加载 | `<link rel="preload">`、`prefetch` |

### 7.3 运行性能

- 虚拟列表（大数据量渲染）
- 防抖节流（频繁事件）
- requestAnimationFrame（动画）
- 避免强制同步布局（layout thrashing）
- Web Worker（耗时计算）

```javascript
// 路由懒加载
const Home = () => import('@/views/Home.vue');

// 图片懒加载
<img loading="lazy" src="image.jpg" alt="">

// 防抖
function debounce(fn, delay = 300) {
  let timer;
  return (...args) => {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}
```

> 🔍 **知识点深度解析**
>
> **作用**：性能优化提升用户体验，是前端高级能力的体现。
>
> **原理**：加载性能核心是减少请求数和请求体积。代码分割按需加载（路由懒加载），首屏只加载必要代码。Tree Shaking 依赖 ESM 静态分析，移除未引用的导出。图片用现代格式（WebP 比 JPG 小 25-35%，AVIF 更小），`loading="lazy"` 原生懒加载。HTTP 缓存：强缓存（Cache-Control: max-age）不发请求，协商缓存（ETag/Last-Modified）发请求验证。运行性能核心是减少 JS 执行时间和避免重排重绘。
>
> **用法要点**：① 首屏加载时间（FCP/LCP）是核心指标；② 路由懒加载是最有效的代码分割；③ 大图片必须压缩，用 WebP 格式；④ 列表超过 100 条考虑虚拟列表；⑤ 滚动/输入事件用防抖节流；⑥ 面试常考：性能优化方案、懒加载实现、缓存策略、首屏优化。

## 8. 测试
