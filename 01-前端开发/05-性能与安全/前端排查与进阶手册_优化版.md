## 一、useEffect 死循环排查

### 1.1 现象 → 根因 → 修复
| 现象 | 根因 | 修复 |
|------|------|------|
| 无限请求 | 依赖里放了新对象/数组字面量 | 用 `useMemo` 固定引用 |
| setState 触发重渲染 | effect 内 setState 未加依赖守卫 | 用 ref/守卫条件 |
| lint 关闭导致 | `eslint-disable` 掩盖依赖缺失 | 补齐依赖而非禁用 |

### 1.2 代码
```jsx
// ❌ 每次渲染新建对象 → 依赖变化 → 再渲染 → 死循环
useEffect(() => { fetchData(opts) }, [opts]);   // opts = {a:1} 字面量
// ✅ 固定引用
const opts = useMemo(() => ({ a: 1 }), []);
useEffect(() => { fetchData(opts) }, [opts]);
```

💡 **深度讲解**：React 用 `Object.is` 比较依赖；每次渲染生成的新对象引用必不相等，effect 反复触发。用 `useMemo`/`useCallback` 固定引用是根治。
📝 **精简总结**：依赖放字面量必死循环；用 memo 固定；别用 `eslint-disable` 掩盖；effect 内 setState 需守卫。
🔍 **知识点深度解析**：作用=消除无限渲染；原理=依赖引用比较；要点=引用稳定 + 依赖准确。

## 二、SSR 水合不匹配

### 2.1 现象 → 根因 → 修复
| 现象 | 根因 | 修复 |
|------|------|------|
| Warning: text mismatch | 服务端/客户端渲染不一致 | 用 `suppressHydrationWarning` 局部 |
| 随机值差异 | `Math.random`/Date 在两端不同 | 客户端 effect 内赋值 |
| 时区/环境差 | 服务端 UTC vs 浏览器本地 | 统一或延后渲染 |

### 2.2 代码
```jsx
function Clock(){
  const [t, setT] = useState(null);          // 初始 null 两端一致
  useEffect(() => { setT(new Date().toISOString()); }, []);
  return <span>{t ?? "..."}</span>;          // 避开水合不一致
}
```

💡 **深度讲解**：SSR 时服务端先渲染 HTML，客户端 React 拿同样结构「水合」。一旦两者文本不同，React 只得丢弃重渲染并报警。动态值延到 effect 是最稳做法。
📝 **精简总结**：动态/随机/时间值延后到客户端 effect；不稳定处用 `suppressHydrationWarning`；确保首屏 HTML 两端一致。
🔍 **知识点深度解析**：作用=消除水合告警与闪烁；原理=双端结构比对；要点=首屏确定性。

## 三、CORS 跨域实战排查

### 3.1 现象 → 根因 → 修复
| 现象 | 根因 | 修复 |
|------|------|------|
| No 'Access-Control-Allow-Origin' | 服务端未回头 | 服务端加 CORS 头 |
| 预检 405 | 未处理 OPTIONS | 后端允许 OPTIONS |
| 带 cookie 仍拦 | 缺 `Allow-Credentials` | 头 + `withCredentials` 配对 |

### 3.2 代码
```js
// 服务端(Express)正确配置
app.use((req,res,next)=>{
  res.setHeader("Access-Control-Allow-Origin", "https://app.example.com");
  res.setHeader("Access-Control-Allow-Credentials", "true");
  res.setHeader("Access-Control-Allow-Headers", "Content-Type,Authorization");
  if (req.method === "OPTIONS") return res.sendStatus(204);  // 预检直返
  next();
});
```

💡 **深度讲解**：CORS 是「浏览器」的同源策略，报错在服务端缺头。简单请求直接发；带自定义头/凭证触发 OPTIONS 预检，后端必须正确响应。
📝 **精简总结**：服务端与 `withCredentials` 配对；预检 OPTIONS 直返 204；`Allow-Origin` 勿用 `*` 配凭证；代理(Nginx)也常更简。
🔍 **知识点深度解析**：作用=安全跨域；原理=浏览器同源策略；要点=预检 + 凭证一致性。

## 四、内存泄漏定位

### 4.1 现象 → 根因 → 修复
| 现象 | 根因 | 修复 |
|------|------|------|
| 标签页越用越卡 | 事件/定时器未清理 | effect 返回清理函数 |
| 堆只增不减 | 全局缓存无上限 | LRU + 弱引用 |
| 闭包持大对象 | 变量被长期引用 | 及时解引用 |

### 4.2 代码
```jsx
useEffect(() => {
  const id = setInterval(poll, 5000);
  window.addEventListener("resize", onResize);
  return () => {                 // 清理！
    clearInterval(id);
    window.removeEventListener("resize", onResize);
  };
}, []);
```

💡 **深度讲解**：SPA 中 effect 注册的监听/定时器若不清理，组件卸载后仍存活→泄漏。Chrome DevTools Memory 快照对比「堆只增不减」即确诊。
📝 **精简总结**：effect 必返回清理函数；全局缓存加 LRU；用 Memory 面板对比快照；长列表虚拟滚动态。
🔍 **知识点深度解析**：作用=稳定性；原理=可达性垃圾回收；要点=及时解引用 + 清理。

## 五、Web Vitals 性能调优（进阶）

### 5.1 核心指标
| 指标 | 含义 | 优秀线 |
|------|------|--------|
| LCP | 最大内容绘制 | < 2.5s |
| CLS | 累积布局偏移 | < 0.1 |
| INP | 交互到响应 | < 200ms |
| TTFB | 首字节 | < 0.8s |

### 5.2 调优
💡 **深度讲解**：LCP 看「首屏最大元素加载」——图片懒加载/预加载关键资源；CLS 看「布局抖动」——给图片/广告位预留尺寸；INP 取代 FID 测真实交互。
📝 **精简总结**：图片 `width/height` 防 CLS；关键资源 `preload`；代码分割降主线程阻塞；用 RUM 看真实用户指标。
🔍 **知识点深度解析**：作用=用户体验量化；原理=渲染关键路径；要点=真实字段(RUM) > 实验室。

## 六、构建产物体积分析（进阶）

### 6.1 步骤
```bash
# Vite/Webpack 体积分析
npx vite-bundle-visualizer
# 或 rollup-plugin-visualizer 生成 treemap
```
| 问题 | 优化 |
|------|------|
| 单包过大 | 路由级代码分割 `import()` |
| 重复依赖 | `dedupe` + 锁定版本 |
| 全量引入 | 改按需引入(如 antd es) |

💡 **深度讲解**：体积 = 下载 + 解析 + 执行开销。treemap 定位「胖依赖」；按需引入与 tree-shaking 常砍掉过半体积。
📝 **精简总结**：用可视化找胖依赖；路由分割；按需引入；`manualChunks` 拆vendor；Gzip/Brotli 压缩。
🔍 **知识点深度解析**：作用=提速首屏；原理=传输与解析成本；要点=分割 + 压缩。

## 七、微前端与 Monorepo（进阶）

### 7.1 模式
| 方案 | 特点 | 适用 |
|------|------|------|
| qiankun/Module Federation | 独立部署子应用 | 多团队 |
| Monorepo(pnpm/nx) | 单仓多包共享 | 统一基建 |

### 7.2 要点
💡 **深度讲解**：微前端解「巨石应用 + 多团队发布冲突」，但引入样式/状态隔离复杂度；Monorepo 用 pnpm workspace 共享依赖与工具链，提升复用。
📝 **精简总结**：按团队边界选型；隔离靠 sandbox/沙箱；Monorepo 用 pnpm + changesets 管版本；共享设计系统降重复。
🔍 **知识点深度解析**：作用=规模化协作；原理=运行时/构建时集成；要点=隔离 + 契约。
