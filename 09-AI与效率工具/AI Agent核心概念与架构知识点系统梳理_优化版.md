# AI Agent 核心概念与架构知识点系统梳理（优化版）

> **优化版说明**：本文档在原有内容基础上，为每个三级标题知识点补充了「🔍 深度解析」（作用+原理+用法要点），所有原有内容完整保留，未做任何修改。


> **文档说明**：系统梳理 AI Agent（智能体）的核心概念、架构模式、关键能力（规划/记忆/工具调用）、Multi-Agent 协作与应用场景。

---

## 1. 概述

AI Agent（人工智能智能体）是能够**自主感知环境、做出决策并执行行动**以完成目标的 AI 系统。与传统 LLM 只能"对话"不同，Agent 能调用工具、访问外部信息、执行多步骤任务，是 LLM 从"聊天机器人"向"智能助手"演进的关键形态。

**Agent vs 普通 LLM 对话**：

| 维度 | 普通 LLM 对话 | AI Agent |
|------|--------------|----------|
| 能力 | 文本生成 | 文本 + 工具调用 + 自主决策 |
| 任务 | 单轮问答 | 多步骤复杂任务 |
| 外部交互 | 无 | 搜索、代码执行、API 调用 |
| 自主性 | 被动回答 | 主动规划和执行 |
| 记忆 | 对话历史 | 短期 + 长期记忆 |

## 2. Agent 核心架构

### 2.1 感知-决策-执行循环

```
┌─────────────────────────────────────┐
│           AI Agent 循环              │
│                                     │
│  感知（Perception）                 │
│    ↓ 接收用户目标、环境信息          │
│  规划（Planning）                   │
│    ↓ 拆解任务、制定步骤              │
│  决策（Decision）                   │
│    ↓ 选择行动/工具                   │
│  执行（Action）                     │
│    ↓ 调用工具、执行代码              │
│  观察（Observation）                │
│    ↓ 获取执行结果                    │
│  反思（Reflection）                 │
│    ↓ 评估结果，调整策略              │
│    ↓ 循环直到任务完成                │
└─────────────────────────────────────┘
```


> 🔍 **知识点深度解析**
>
> **作用**：Agent 通过感知环境输入、LLM 决策规划、执行工具调用并观察结果的循环，自主完成多步骤任务。
>
> **原理**：循环从接收用户目标开始：感知模块收集环境信息（用户输入、工具返回、上下文），LLM 作为决策核心进行推理（Thought）选择行动（Action），执行器调用工具获取观察结果（Observation），结果反馈给 LLM 继续推理，直到任务完成或达到终止条件。这个循环本质是 ReAct 范式的工程化，每轮 LLM 调用都是一次无状态推理，状态由外部消息历史维护。
>
> **用法要点**：① 循环由 LLM 推理驱动，每轮包含 Thought→Action→Observation  ② 需要设置最大循环次数和终止条件，防止无限循环  ③ 工具返回结果过长时需截断或摘要，避免上下文爆炸  ④ 可在循环中加入人工确认节点（Human-in-the-loop）  ⑤ 面试常考：Agent 循环流程、ReAct 模式、终止条件设计、状态管理

### 2.2 三大核心组件

#### 1. 规划（Planning）

将复杂目标拆解为可执行的子任务。

- **任务分解**：LLM 将大目标拆为小步骤
- **反思与修正**：根据执行结果调整计划
- **树状规划**：探索多条路径，选择最优


> 🔍 **知识点深度解析**
>
> **作用**：规划是 Agent 的决策核心，将复杂目标分解为可执行子任务并动态调整策略。
>
> **原理**：规划能力来自 LLM 的推理能力：任务分解（将大目标拆为小步骤）、反思修正（根据执行结果调整计划）、多路径探索（ToT 思维树评估多条路径）。规划方法包括 ReAct（边想边做）、Plan-and-Execute（先规划后执行）、Reflexion（反思迭代）。规划质量取决于 LLM 推理能力、任务可分解性和反馈准确性。
>
> **用法要点**：① 任务分解：大目标→子任务→可执行步骤  ② 反思修正：执行失败后重新规划  ③ ToT 探索多条路径并评估选择  ④ 简单任务不需要复杂规划，ReAct 即可  ⑤ 面试常考：规划方法、任务分解、ReAct vs Plan-Execute

#### 2. 记忆（Memory）

- **短期记忆**：当前对话上下文（Context Window）
- **长期记忆**：外部存储（向量数据库），持久化知识
- **工作记忆**：Agent 当前任务的状态和中间结果


> 🔍 **知识点深度解析**
>
> **作用**：记忆让 Agent 跨会话保留信息，分为短期工作记忆和长期持久记忆。
>
> **原理**：短期记忆即上下文窗口中的对话历史和中间状态，容量受 token 限制，需摘要压缩。长期记忆用向量数据库持久化（对话历史、用户偏好、执行经验），通过 RAG 语义检索按需召回。记忆管理包括写入策略（重要性判断）、遗忘机制（TTL/低频归档）和摘要压缩（旧记忆合并）。
>
> **用法要点**：① 短期记忆=上下文窗口，容量有限  ② 长期记忆=向量数据库，RAG 检索召回  ③ 记忆写入需判断重要性，避免噪声  ④ 摘要压缩释放上下文空间  ⑤ 面试常考：短期 vs 长期记忆、记忆管理、RAG 记忆

#### 3. 工具调用（Tool Use / Function Calling）

Agent 调用外部工具扩展能力：
- 搜索引擎（Google/Bing）
- 代码执行（Python REPL）
- API 调用（天气、数据库、第三方服务）
- 文件读写
- 浏览器操作

> 🔍 **知识点深度解析**
>
> **作用**：理解 Agent 的三大核心组件是构建 Agent 系统的基础。
>
> **原理**：Agent 的本质是 LLM + 工具 + 循环。LLM 作为"大脑"负责理解和决策，工具作为"手脚"扩展能力，循环让 Agent 能自主完成多步骤任务。规划能力来自 LLM 的推理能力（CoT/ToT），将复杂目标拆解。记忆分为短期（上下文窗口，有限）和长期（向量数据库，通过 RAG 检索），解决 LLM 上下文有限和无持久化的问题。工具调用通过 Function Calling 实现：LLM 输出结构化的工具调用指令（JSON），系统执行后将结果返回给 LLM，LLM 根据结果决定下一步。ReAct 模式将推理（Reasoning）和行动（Acting）交替进行，是 Agent 的经典范式。
>
> **用法要点**：① Agent 适合多步骤、需要外部信息、需要执行操作的任务；② 简单问答不需要 Agent，直接用 LLM 更高效；③ 工具描述要清晰准确，LLM 才能正确选择和使用；④ 面试常考：Agent 定义、三大组件、ReAct 模式、规划/记忆/工具调用原理、Agent vs LLM。

## 3. 经典 Agent 范式

### 3.1 ReAct（Reasoning + Acting）

```
问题：北京今天适合出门吗？
思考：我需要知道北京今天的天气，应该调用天气查询工具。
行动：weather_api("北京")
观察：北京今天晴，25-32度，空气质量良，无降水。
思考：天气晴好，温度适宜，适合出门。需要提醒防晒。
回答：北京今天晴，25-32度，空气质量良，适合出门，注意防晒。
```

**特点**：推理和行动交替，每步思考后执行一个动作，根据观察结果继续推理。


> 🔍 **知识点深度解析**
>
> **作用**：ReAct 将推理（Thought）和行动（Action）交替进行，让 LLM 边思考边调用工具，是 Agent 最经典的范式。
>
> **原理**：ReAct 提示 LLM 按 Thought→Action→Observation 格式输出：Thought 分析当前状态和下一步计划，Action 输出工具调用（JSON），系统执行工具返回 Observation，LLM 据此继续 Thought。这种交错模式让 LLM 的推理链与外部信息交互，比纯推理（CoT）更准确（能获取实时信息），比纯行动更可控（有显式推理链可追溯）。
>
> **用法要点**：① Thought→Action→Observation 循环，推理链可追溯  ② 比纯 CoT 更准确：可获取外部信息纠正推理  ③ Action 必须是结构化工具调用，系统解析后执行  ④ Observation 是工具返回结果，拼接到上下文供下轮推理  ⑤ 面试常考：ReAct 原理、与 CoT 区别、提示词格式、ReAct 优缺点

### 3.2 Plan-and-Execute

```
1. 规划阶段：一次性制定完整计划
   计划：[搜索资料 → 整理大纲 → 撰写文章 → 校对润色]
2. 执行阶段：按计划逐步执行
3. 反思阶段：检查结果，必要时重新规划
```

**特点**：先规划后执行，适合目标明确的复杂任务。


> 🔍 **知识点深度解析**
>
> **作用**：先由 Planner 一次性制定完整执行计划，再由 Executor 逐步执行，适合目标明确的复杂任务。
>
> **原理**：Plan-and-Execute 将规划和执行分离：Planner LLM 接收目标后生成有序步骤列表（Plan），Executor 逐个执行每个步骤（可调用工具或子 Agent），执行完后可由 Replanner 检查结果并调整剩余计划。这种模式减少了 LLM 调用次数（不需要每步都重新规划），但灵活性不如 ReAct，适合步骤明确的工作流。
>
> **用法要点**：① Planner 生成步骤列表，Executor 逐步执行，Replanner 检查调整  ② 比 ReAct 减少 LLM 调用次数，Token 成本更低  ③ 计划可能因环境变化而失效，需要重规划机制  ④ 适合报告生成、数据处理等步骤明确的任务  ⑤ 面试常考：Plan-and-Execute vs ReAct、规划执行分离、重规划

### 3.3 Reflexion（反思型 Agent）

- 执行任务后进行自我反思
- 将反思结果存入记忆
- 下次类似任务时参考历史经验
- 持续迭代提升表现

---


> 🔍 **知识点深度解析**
>
> **作用**：Agent 执行任务后进行自我反思，将经验教训存入记忆，在后续尝试中改进，实现迭代提升。
>
> **原理**：Reflexion 在 Actor（执行）基础上增加 Evaluator（评估结果）和 Self-Reflection（反思失败原因）：执行失败后，LLM 分析失败原因生成反思文本，存入长期记忆。下次尝试时将历史反思作为上下文，避免重复犯错。反思内容是自然语言（而非参数更新），相当于让 LLM 从经验中学习。
>
> **用法要点**：① Actor 执行→Evaluator 评估→Self-Reflection 反思→记忆→重试  ② 反思是自然语言经验，不更新模型参数  ③ 适合代码调试、数学推理等可验证对错的任务  ④ 反思记忆需控制数量，避免上下文过长  ⑤ 面试常考：Reflexion 机制、与微调区别、反思记忆、迭代提升

## 4. 工具调用（Function Calling）

### 4.1 原理

LLM 输出结构化的工具调用请求，系统执行后返回结果。

```python

> 🔍 **知识点深度解析**
>
> **作用**：Function Calling 让 LLM 输出结构化的工具调用请求，系统执行后将结果返回 LLM，实现 LLM 与外部世界的交互。
>
> **原理**：开发者在 API 请求中提供 tools 定义（name/description/parameters JSON Schema），LLM 训练时学会在需要时输出 tool_calls 结构（函数名+参数 JSON），而非自然语言。应用解析 tool_calls 执行对应函数，将结果以 role=tool 消息返回，LLM 根据结果继续生成。这本质是 LLM 做了参数提取和路由决策，实际执行由应用代码完成。
>
> **用法要点**：① tools 定义包含 name/description/parameters（JSON Schema）  ② LLM 输出 tool_calls，应用解析执行后返回 role=tool 消息  ③ description 质量直接影响 LLM 选择工具的准确性  ④ 并行工具调用：一次返回多个 tool_calls  ⑤ 面试常考：Function Calling 原理、工具定义、执行流程、与 RAG 区别

# 工具定义
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "查询指定城市的天气",
            "parameters": {
                "type": "object",
                "properties": {
                    "city": {"type": "string", "description": "城市名称"}
                },
                "required": ["city"]
            }
        }
    }
]

# LLM 返回工具调用
{
    "tool_calls": [{
        "function": {
            "name": "get_weather",
            "arguments": "{\"city\": \"北京\"}"
        }
    }]
}

# 执行工具，将结果返回给 LLM
```

### 4.2 常用工具类型

| 工具类型 | 示例 | 用途 |
|----------|------|------|
| 搜索 | Google Search、Tavily | 获取实时信息 |
| 代码执行 | Python REPL、Jupyter | 计算、数据处理 |
| API 调用 | 天气、股票、数据库 | 获取结构化数据 |
| 文件操作 | 读写文件 | 文档处理 |
| 浏览器 | Playwright、Selenium | 网页操作 |
| 数据库 | SQL 查询 | 数据检索 |
| 向量检索 | RAG | 知识库问答 |

---


> 🔍 **知识点深度解析**
>
> **作用**：Agent 可调用搜索、代码执行、API、文件操作、浏览器、数据库、向量检索等工具扩展能力边界。
>
> **原理**：搜索工具获取实时信息（弥补知识截止），代码执行工具进行精确计算和数据处理（Python REPL），API 工具调用外部服务（天气/支付/CRM），文件工具读写文档，浏览器工具操作网页（Playwright），数据库工具执行 SQL，向量检索工具实现 RAG。工具设计原则：描述清晰、参数明确、粒度适中、错误信息友好。
>
> **用法要点**：① 搜索工具解决知识截止和实时信息问题  ② 代码执行工具解决 LLM 数学计算不可靠问题  ③ 工具粒度适中：太粗 LLM 不会用，太细调用次数多  ④ 每个工具应有清晰的 description 和参数说明  ⑤ 面试常考：工具类型、工具设计原则、RAG 检索工具、代码执行沙箱

## 5. 记忆系统

### 5.1 记忆层级

```
感觉记忆（瞬时）→ 短期记忆（上下文）→ 长期记忆（向量库）
```


> 🔍 **知识点深度解析**
>
> **作用**：Agent 记忆分为感觉记忆、短期工作记忆和长期记忆，对应人类认知架构，解决上下文有限和知识持久化问题。
>
> **原理**：感觉记忆是原始输入（用户消息、工具结果），短期记忆是当前上下文窗口中的对话历史和中间状态（容量有限，受 token 限制），长期记忆是外部持久化存储（向量数据库），通过语义检索按需召回。工作记忆是当前任务的临时状态（变量、步骤进度）。记忆管理需要摘要压缩（旧对话压缩为摘要）、重要性评分和遗忘机制。
>
> **用法要点**：① 短期记忆=上下文窗口，容量有限，需管理 token 预算  ② 长期记忆=向量数据库，通过 RAG 语义检索召回  ③ 摘要压缩：将旧对话压缩为摘要释放上下文空间  ④ 记忆写入需判断重要性，避免噪声污染记忆库  ⑤ 面试常考：记忆层级、短期 vs 长期、摘要压缩、记忆管理

### 5.2 长期记忆实现

- **向量数据库**：Pinecone、Chroma、Milvus、Weaviate
- **存储内容**：对话历史、用户偏好、知识库文档、执行经验
- **检索方式**：语义相似度检索（RAG）
- **记忆管理**：重要性评分、遗忘机制、摘要压缩


> 🔍 **知识点深度解析**
>
> **作用**：通过向量数据库持久化存储对话历史、用户偏好和知识，用 embedding 语义检索实现按需召回。
>
> **原理**：实现流程：记忆内容经 embedding 模型转为向量存入向量库（Pinecone/Milvus/Chroma），检索时将当前查询向量化，用余弦相似度检索 top-k 相关记忆，拼接到 LLM 上下文。记忆管理包括：重要性评分（LLM 打分决定是否存储）、时效性（TTL 过期）、摘要（多条记忆合并）、遗忘（低频记忆归档）。
>
> **用法要点**：① embedding 向量化 + 余弦相似度检索是核心  ② 记忆类型：情景记忆（事件）、语义记忆（知识）、程序性记忆（技能）  ③ 重要性评分过滤低价值记忆，减少噪声  ④ 用户偏好记忆可实现个性化（记住用户习惯）  ⑤ 面试常考：向量检索原理、记忆 CRUD、重要性评分、记忆与 RAG 关系

### 5.3 RAG（检索增强生成）

```
用户问题 → 向量化 → 向量库检索相关文档 → 拼接上下文 → LLM 生成回答
```

RAG 是 Agent 长期记忆和知识增强的核心技术，解决 LLM 知识过时和幻觉问题。

---


> 🔍 **知识点深度解析**
>
> **作用**：RAG 通过检索外部知识库并将相关文档拼入提示词，让 LLM 基于准确信息生成回答，减少幻觉。
>
> **原理**：RAG 流程：文档切分为 chunk → embedding 向量化存入向量库 → 用户问题向量化 → 相似度检索 top-k chunks → 将 chunks 拼入 prompt 作为上下文 → LLM 基于上下文生成回答并引用来源。高级 RAG 包括查询改写、混合检索（向量+关键词）、重排序（reranker）、多跳检索。RAG 解决知识截止、私有数据问答和幻觉问题。
>
> **用法要点**：① 文档切分策略：固定长度/语义切分/递归切分，重叠避免断句  ② 检索质量决定回答质量：chunk 大小、top-k、embedding 模型都影响  ③ 混合检索（向量+BM25）+ reranker 提升召回准确率  ④ 必须引用来源，让用户可验证  ⑤ 面试常考：RAG 完整流程、chunk 策略、混合检索、reranker、RAG vs 微调

## 6. Multi-Agent（多智能体）

### 6.1 概念

多个 Agent 协作完成复杂任务，每个 Agent 有专门角色和能力。


> 🔍 **知识点深度解析**
>
> **作用**：Multi-Agent 系统由多个专业化 Agent 协作完成单 Agent 难以胜任的复杂任务，通过分工提升可靠性和质量。
>
> **原理**：多 Agent 系统中每个 Agent 有独立角色（规划者/执行者/审查者）、工具集和记忆，通过消息传递协作。相比单 Agent，多 Agent 可并行处理子任务、互相校验（辩论/审查减少错误）、专业化分工（每个 Agent prompt 更聚焦）。但增加了 Token 成本、协调复杂度和调试难度。
>
> **用法要点**：① 角色专业化：每个 Agent 有明确职责和系统提示  ② 消息传递是 Agent 间通信方式（共享对话或定向消息）  ③ 适合复杂任务：代码开发（架构师+程序员+测试）、研究报告  ④ 成本和延迟随 Agent 数量增加，需权衡  ⑤ 面试常考：Multi-Agent vs 单 Agent、协作模式、通信机制、适用场景

### 6.2 协作模式

| 模式 | 说明 | 示例 |
|------|------|------|
| **顺序协作** | Agent A 输出 → Agent B 输入 | 研究员→撰稿人→编辑 |
| **并行协作** | 多个 Agent 同时工作，结果汇总 | 多搜索引擎并行查询 |
| **辩论模式** | Agent 之间讨论，达成共识 | 多模型辩论提升准确性 |
| **层级管理** | Manager Agent 分配任务给 Worker | 项目经理→开发者 |
| **自主协作** | Agent 自主决定何时与谁协作 | AutoGen 群聊 |


> 🔍 **知识点深度解析**
>
> **作用**：多 Agent 协作有顺序流水线、并行、辩论、层级管理和自主协作等模式，按任务特点选择。
>
> **原理**：顺序协作（流水线）：A→B→C 依次处理，前一个输出是后一个输入（研究→写作→校对）。并行协作：多个 Agent 同时处理后汇总（多源搜索）。辩论模式：多 Agent 互相质疑达成共识（提升准确性）。层级模式：Manager 分配任务给 Worker 并汇总。自主协作：Agent 自主决定与谁通信（AutoGen 群聊）。
>
> **用法要点**：① 顺序模式适合有明确阶段的任务（内容创作流水线）  ② 并行模式适合可独立的子任务（多源信息收集）  ③ 辩论模式适合需要准确性的决策（多视角审查）  ④ 层级模式适合复杂项目管理（Manager-Worker）  ⑤ 面试常考：协作模式对比、CrewAI/AutoGen、消息路由、成本控制

### 6.3 典型架构（CrewAI）

```
项目经理（规划）→ 研究员（搜索）→ 撰稿人（写作）→ 编辑（校对）
```

---


> 🔍 **知识点深度解析**
>
> **作用**：CrewAI 等框架用角色化 Agent + 任务编排实现多 Agent 协作，定义 Agent 角色、目标和任务依赖。
>
> **原理**：CrewAI 中定义 Agent（role/goal/backstory/tools）、Task（description/expected_output/agent）、Crew（agents/tasks/process）。Process 支持 sequential（顺序执行）和 hierarchical（层级管理，自动分配 Manager）。任务间可通过 context 传递输出。框架处理消息路由、工具调用和结果汇总，开发者只需定义角色和任务。
>
> **用法要点**：① Agent 定义：role（角色）、goal（目标）、backstory（背景）、tools  ② Task 定义：描述、期望输出、负责 Agent、依赖的上游 Task  ③ sequential 顺序执行，hierarchical 自动选 Manager 分配  ④ 任务输出可作为下游任务的 context  ⑤ 面试常考：CrewAI 架构、Agent/Task/Crew 关系、sequential vs hierarchical

## 8. Agent 的挑战

- **可靠性**：Agent 可能在循环中卡住或偏离目标
- **成本**：多轮 LLM 调用，Token 消耗大
- **延迟**：多步骤执行，响应时间长
- **安全性**：工具调用可能执行危险操作，需权限控制
- **评估**：Agent 行为复杂，难以量化评估
- **幻觉**：LLM 幻觉会导致 Agent 做出错误决策

---

## 8.1 Agent 类型分类

| 类型 | 特点 | 示例 |
|------|------|------|
| **反射型** | 直接根据感知行动，无内部状态 | 简单规则机器人 |
| **基于模型** | 维护内部状态模型 | 有记忆的助手 |
| **基于目标** | 以目标为导向规划行动 | 任务执行 Agent |
| **基于效用** | 评估多个目标的效用，选最优 | 多目标决策 Agent |
| **理性 Agent** | 追求期望效用最大化 | 理论最优模型 |

---


> 🔍 **知识点深度解析**
>
> **作用**：按智能水平从低到高分为反射型、基于模型、基于目标、基于效用和理性 Agent，体现 Agent 能力演进。
>
> **原理**：反射型 Agent 直接根据感知做反应（无状态，类似 if-else）。基于模型的 Agent 维护内部世界状态模型。基于目标的 Agent 朝目标规划行动。基于效用的 Agent 在多个目标间评估效用选最优。理性 Agent 追求期望效用最大化（理论框架）。实际 LLM Agent 多为基于目标+效用的混合体。
>
> **用法要点**：① 反射型最简单但无记忆，基于模型型维护内部状态  ② 基于目标型能规划，基于效用型能权衡多目标  ③ LLM Agent 通常是目标导向 + 工具调用 + 记忆的组合  ④ 分类来自 Russell & Norvig《人工智能》教材  ⑤ 面试常考：Agent 类型分类、各类型特点、LLM Agent 属于哪种

## 8.2 规划算法

- **HTN**（层次任务网络）：将任务递归分解为子任务
- **MCTS**（蒙特卡洛树搜索）：搜索决策树，选最优行动
- **ToT**（思维树）：LLM 探索多条推理路径，评估后选择
- **规划与执行分离**：Planner 制定计划，Executor 执行

---


> 🔍 **知识点深度解析**
>
> **作用**：Agent 规划算法包括 HTN 层次任务网络、MCTS 蒙特卡洛树搜索、ToT 思维树等，决定任务分解和路径选择策略。
>
> **原理**：HTN 将复杂任务递归分解为子任务直到可执行。MCTS 通过选择-扩展-模拟-回传搜索决策树，在巨大空间中找最优行动。ToT 让 LLM 生成多个推理分支并评估，探索多条路径后选最优（比单链 CoT 更全面）。规划与执行分离：Planner 生成计划，Executor 执行并反馈。
>
> **用法要点**：① HTN 递归分解任务，适合结构化领域  ② MCTS 四步：选择→扩展→模拟→回传，平衡探索与利用  ③ ToT 思维树：多分支推理+评估+剪枝，适合复杂推理  ④ 规划质量取决于 LLM 推理能力和任务可分解性  ⑤ 面试常考：HTN/MCTS/ToT 原理、ToT vs CoT、规划执行分离

## 8.3 记忆类型详解

| 记忆类型 | 内容 | 存储 |
|----------|------|------|
| **情景记忆**（Episodic） | 具体事件、对话历史 | 向量数据库 |
| **语义记忆**（Semantic） | 事实知识、概念 | 知识库/RAG |
| **程序性记忆**（Procedural） | 技能、操作流程 | 工具/代码 |
| **工作记忆**（Working） | 当前任务状态、中间结果 | 上下文窗口 |

---


> 🔍 **知识点深度解析**
>
> **作用**：Agent 记忆按内容分为情景记忆、语义记忆、程序性记忆和工作记忆，各有不同的存储和检索方式。
>
> **原理**：情景记忆存储具体事件和对话历史（时序化，向量检索）。语义记忆存储事实知识和概念（结构化知识库/RAG）。程序性记忆存储技能和操作流程（工具使用方法、代码模板）。工作记忆是当前任务的临时状态（上下文窗口中的变量和中间结果）。不同记忆类型有不同的写入策略、检索方式和生命周期。
>
> **用法要点**：① 情景记忆：事件/对话，向量库，时序检索  ② 语义记忆：事实/概念，知识图谱/RAG，语义检索  ③ 程序性记忆：技能/流程，工具定义/代码模板，模式匹配  ④ 工作记忆：当前状态，上下文窗口，容量有限  ⑤ 面试常考：四种记忆类型、存储方式、检索策略、记忆协作

## 8.4 MCP（Model Context Protocol）

Anthropic 提出的工具调用标准化协议：
- **Server/Client 架构**：工具以 MCP Server 形式提供
- **标准化接入**：任何支持 MCP 的 Agent 都能使用
- **资源/工具/提示词**三种暴露类型
- 目标：解决工具接入碎片化问题

---


> 🔍 **知识点深度解析**
>
> **作用**：MCP 是 Anthropic 提出的工具调用标准化协议，让工具以 MCP Server 形式提供，任何支持 MCP 的 Client 都能即插即用。
>
> **原理**：MCP 采用 Client-Server 架构：MCP Server 暴露 Resources（资源/数据）、Tools（可执行函数）、Prompts（提示词模板）三种能力，MCP Client（如 Claude Desktop、IDE）通过 stdio/SSE 连接 Server。协议基于 JSON-RPC 2.0，定义了工具发现、调用、流式响应等标准消息。目标是解决 N×M 工具集成问题（每个 Agent 接每个工具），变为 N+M（Agent 接 MCP，工具实现 MCP）。
>
> **用法要点**：① 三种能力：Resources（只读数据）、Tools（可执行）、Prompts（模板）  ② 基于 JSON-RPC 2.0，支持 stdio 本地和 SSE 远程传输  ③ 解决工具碎片化：一次实现 MCP Server，所有 MCP Client 可用  ④ 类似 LSP（语言服务器协议）之于编辑器，MCP 之于 AI Agent  ⑤ 面试常考：MCP 架构、三种能力类型、与 Function Calling 关系、解决什么问题

## 8.5 Agent 评估基准

| 基准 | 评测内容 |
|------|----------|
| **AgentBench** | 多环境 Agent 能力（8个环境） |
| **WebArena** | 真实网页操作任务 |
| **SWE-bench** | 真实 GitHub Issue 修复 |
| **GAIA** | 通用 AI 助手任务（需多步推理+工具） |

---


> 🔍 **知识点深度解析**
>
> **作用**：AgentBench/WebArena/SWE-bench/GAIA 等基准从不同维度评估 Agent 的多步推理、工具使用和任务完成能力。
>
> **原理**：AgentBench 在 8 个环境（操作系统、数据库、知识图谱等）评估 Agent。WebArena 在真实网站上执行复杂任务（购物、表单填写）。SWE-bench 让 Agent 修复真实 GitHub Issue（评估代码能力）。GAIA 设计需要多步推理+工具使用的通用助手任务。评估指标通常是任务成功率，而非 BLEU 等文本相似度。
>
> **用法要点**：① SWE-bench：真实 GitHub Issue 修复，考验代码理解和编辑能力  ② WebArena：真实网页操作，考验浏览器工具使用  ③ GAIA：通用助手任务，考验多步推理+工具组合  ④ 评估核心是任务成功率（端到端），不是单轮文本质量  ⑤ 面试常考：主流 Agent 基准、评估指标、Agent 评估难点

## 8.6 Agent 安全与对齐

- **工具滥用**：限制工具权限，敏感操作需人工确认
- **权限边界**：最小权限原则，沙箱执行
- **目标漂移**（Goal Misgeneralization）：Agent 偏离原始目标
- **可中断性**：随时可停止，避免无限循环
- **红队测试**：模拟攻击测试 Agent 安全性

---


> 🔍 **知识点深度解析**
>
> **作用**：Agent 安全关注工具滥用、权限边界、目标漂移和可中断性，确保 Agent 行为在可控范围内。
>
> **原理**：工具滥用防护：敏感操作（删除/支付/发邮件）需人工确认，工具权限最小化。沙箱执行：代码执行在隔离容器中，限制网络和文件访问。目标漂移：Agent 在多步执行中偏离原始目标，需监控和目标对齐。Prompt 注入：恶意输入诱导 Agent 执行非预期操作，需输入过滤和指令优先级。可中断性：随时可停止 Agent，设置最大步数和预算。
>
> **用法要点**：① 敏感工具调用需 Human-in-the-loop 确认  ② 代码执行用沙箱（Docker/微虚拟机）隔离  ③ Prompt 注入防护：系统指令与用户输入分离，输入消毒  ④ 设置最大循环次数、Token 预算和超时，防止失控  ⑤ 面试常考：Agent 安全风险、Prompt 注入、最小权限、沙箱、目标漂移

- 记忆：RAG 检索增强，向量数据库存储长期记忆
