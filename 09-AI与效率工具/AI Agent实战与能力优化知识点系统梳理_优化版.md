# AI Agent 实战与能力优化知识点系统梳理（优化版）

> **文档说明**：系统梳理 AI Agent 实战开发中的关键技术与优化方法，涵盖 RAG 实战、Agent 评估、幻觉控制、工具调用优化、安全边界、性能优化等。

---

## 1. 概述

AI Agent 从 Demo 到生产需要解决诸多工程问题：检索质量、幻觉控制、工具可靠性、成本控制、安全边界、效果评估。本文梳理实战中的核心技术和最佳实践。

## 2. RAG 实战优化

### 2.1 RAG 完整流程

```
文档加载 → 文档清洗 → 文本切分 → 向量化 → 向量库存储
                                          ↓
用户查询 → 查询改写 → 向量检索 → 重排序 → 上下文拼接 → LLM 生成 → 引用标注
```

### 2.2 文本切分优化

| 切分策略 | 说明 | 适用场景 |
|----------|------|----------|
| 固定长度 | 按字符数切分，重叠窗口 | 通用 |
| 语义切分 | 按语义段落切分 | 结构化文档 |
| 递归切分 | 按标题/段落/句子递归 | Markdown/HTML |
| 结构化切分 | 按文档结构（标题层级） | 技术文档、论文 |

**要点**：
- 切分大小 256-1024 Token，重叠 10-20%
- 保留元数据（标题、来源、页码）
- 代码块不要切散

### 2.3 检索优化

- **混合检索**：向量检索 + 关键词检索（BM25），互补优势
- **查询改写**：LLM 将用户问题改写为更适合检索的查询
- **多路召回**：多种检索方式召回，合并去重
- **重排序（Rerank）**：用 Cross-Encoder 对召回结果精排，提升 Top-K 质量
- **查询分解**：复杂问题拆为多个子问题，分别检索

### 2.4 向量化模型选择

| 模型 | 特点 |
|------|------|
| text-embedding-3 | OpenAI，效果好，需 API |
| bge-large-zh | 中文效果好，开源可本地 |
| m3e | 中文多粒度，开源 |
| Cohere Embed | 多语言，效果好 |

> 🔍 **知识点深度解析**
>
> **作用**：RAG 是 Agent 知识增强的核心，检索质量直接决定回答质量。
>
> **原理**：RAG（检索增强生成）通过外部知识库补充 LLM 的知识，解决知识过时和幻觉问题。检索分召回（Recall）和排序（Rerank）两阶段：召回用向量相似度快速取回 Top-N（如50条），重排序用更精确的 Cross-Encoder 模型精排取 Top-K（如5条）。混合检索结合向量语义检索和 BM25 关键词检索，向量擅长语义匹配，BM25 擅长精确关键词匹配（如专有名词、错误码），两者互补。查询改写用 LLM 将口语化问题转为规范查询，提升召回率。切分质量影响检索粒度，太大引入噪声，太小丢失上下文。
>
> **用法要点**：① 评估 RAG 用召回率（相关文档是否被召回）和准确率（Top-K 中相关比例）；② 中文场景用 bge/m3e 等中文优化的 embedding 模型；③ 必须加 Rerank，显著提升质量；④ 面试常考：RAG 流程、切分策略、混合检索、Rerank、查询改写、RAG 评估。

## 3. 幻觉控制

### 3.1 幻觉类型

- **事实性幻觉**：编造不存在的事实
- **忠实性幻觉**：回答与提供的上下文不符
- **指令性幻觉**：不遵循指令要求

### 3.2 控制方法

| 方法 | 说明 |
|------|------|
| **RAG** | 提供外部知识，让模型基于事实回答 |
| **Prompt 约束** | "只根据提供的上下文回答，不知道就说不知道" |
| **引用标注** | 要求回答标注信息来源，便于验证 |
| **自我验证** | 模型生成后自我检查是否与上下文一致 |
| **事实核查** | 用工具或另一个模型核查关键事实 |
| **降低温度** | temperature=0 减少随机性 |
| **结构化输出** | JSON Schema 约束输出格式 |

### 3.3 幻觉评估

- **忠实度（Faithfulness）**：回答是否与上下文一致
- **答案相关性（Answer Relevance）**：回答是否切题
- **上下文精度（Context Precision）**：检索的上下文是否相关
- 人工抽检 + 自动化评估（LLM-as-Judge）

## 4. 工具调用优化

### 4.1 工具设计原则

1. **单一职责**：每个工具做一件事
2. **清晰描述**：name + description + parameters 要准确
3. **参数简单**：尽量用基本类型，避免复杂嵌套
4. **错误处理**：工具返回清晰的错误信息
5. **幂等性**：重复调用结果一致（写操作需注意）

### 4.2 工具选择优化

- **工具数量控制**：太多工具 LLM 选择困难，5-10 个为宜
- **工具分组**：按场景分组，动态加载相关工具
- **工具描述优化**：用清晰的自然语言描述用途和参数
- **示例引导**：在 Prompt 中提供工具使用示例

### 4.3 工具执行安全

- 危险操作（删除、支付）需人工确认
- 沙箱执行代码，限制资源访问
- API 调用限制权限范围
- 超时控制，防止工具卡住 Agent

## 5. Agent 评估

### 5.1 评估维度

| 维度 | 指标 | 方法 |
|------|------|------|
| **任务完成率** | 成功完成任务的比例 | 标准测试集 |
| **步骤效率** | 完成任务的平均步数 | 日志统计 |
| **工具使用准确率** | 工具调用是否正确 | 人工/自动标注 |
| **回答质量** | 准确性、相关性、完整性 | LLM-as-Judge |
| **幻觉率** | 编造信息的比例 | 事实核查 |
| **成本** | 平均 Token 消耗 | 用量统计 |
| **延迟** | 平均响应时间 | 性能测试 |

### 5.2 评估方法

- **离线评估**：固定测试集，自动化运行
- **在线评估**：生产环境 A/B 测试
- **人工评估**：专家打分
- **LLM-as-Judge**：用强模型评估弱模型输出
- **LangSmith / W&B**：专业评估平台

### 5.3 测试集构建

- 覆盖典型任务和边界情况
- 包含成功和失败案例
- 标注期望结果
- 定期更新

## 6. 成本与性能优化

### 6.1 成本优化

- **模型分级**：简单任务用小模型（GPT-3.5/Haiku），复杂任务用大模型
- **缓存**：相同查询缓存结果，减少 LLM 调用
- **Prompt 压缩**：精简上下文，去除无关信息
- **批量处理**：合并多个请求
- **早期终止**：任务完成立即停止，不要多余循环

### 6.2 性能优化

- **流式输出**：提升用户体验
- **并行工具调用**：独立工具同时调用
- **异步执行**：异步 I/O 提升并发
- **向量检索优化**：ANN 索引（HNSW）、量化
- **本地模型**：简单任务用本地小模型，降低延迟

## 7. 安全边界

### 7.1 Prompt 注入防护

- 系统提示与用户输入隔离
- 工具调用前验证指令合法性
- 输入过滤和清洗
- 最小权限原则

### 7.2 数据安全

- 敏感数据不上传云端 LLM（用本地模型）
- 输出过滤敏感信息
- 数据脱敏
- 访问控制和审计日志

### 7.3 操作安全

- 写操作需确认
- 代码沙箱执行
- API 权限最小化
- 速率限制防滥用

## 8. 典型 Agent 实战案例

### 8.1 知识库问答 Agent

```
用户提问 → 查询改写 → 混合检索 → Rerank → 上下文拼接
→ LLM 生成（带引用）→ 自我验证 → 输出答案+来源
```

### 8.2 数据分析 Agent

```
用户问题 → 理解需求 → 生成 SQL/Python → 执行代码
→ 检查结果 → 生成图表 → 撰写分析报告
```

### 8.3 编程 Agent

```
需求描述 → 任务规划 → 阅读代码库 → 编写代码
→ 运行测试 → 调试修复 → 提交 PR
```

## 8.4 Agent 监控与可观测性

- **执行 Trace**：记录每一步 LLM 调用、工具调用、输入输出
- **Token 消耗监控**：按 Agent/任务/模型统计成本
- **延迟监控**：端到端响应时间、各步骤耗时
- **错误率统计**：工具调用失败率、LLM 调用失败率
- **平台**：LangSmith、Langfuse、Helicone、自建 Prometheus+Grafana

## 8.5 错误恢复与重试

| 策略 | 说明 |
|------|------|
| **指数退避重试** | 工具/LLM 调用失败，等待时间递增后重试 |
| **降级策略** | 工具不可用时切换备用方案或跳过 |
| **死循环检测** | 超过最大步数或重复调用同一工具时强制终止 |
| **超时控制** | 每个工具调用设置超时，防止卡住 |
| **状态回滚** | 失败时回滚到上一个稳定状态 |

## 8.6 人机协作（Human-in-the-loop）

- **审批节点**：敏感操作（删除、支付、发布）暂停等待人工确认
- **人工介入**：Agent 遇到无法解决的问题时请求人工帮助
- **反馈学习**：人工修正 Agent 的输出，用于后续优化
- **实现**：LangGraph 的 interrupt 机制、自定义审批队列

## 8.7 Agent 安全沙箱

- **代码执行沙箱**：隔离环境执行 LLM 生成的代码（Docker/E2B）
- **文件系统隔离**：限制 Agent 可访问的目录范围
- **网络限制**：白名单域名，禁止访问内网
- **权限最小化**：API Key 只授予必要权限
- **资源限制**：CPU/内存/执行时间上限

## 8.8 成本监控与预算控制

- **Per-Agent 预算**：每个 Agent 设置 Token 消耗上限
- **模型分级**：简单任务用小模型（Haiku/GPT-4o-mini），复杂用大模型
- **缓存优化**：相同查询缓存结果，Embedding 结果缓存
- **Prompt 精简**：去除冗余上下文，压缩历史对话
- **告警**：成本超阈值时告警或自动降级
