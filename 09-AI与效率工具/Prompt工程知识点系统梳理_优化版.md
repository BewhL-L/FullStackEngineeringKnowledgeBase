# Prompt 工程知识点系统梳理（优化版）

> **优化版说明**：本文档在原有内容基础上，为每个三级标题知识点补充了「🔍 深度解析」（作用+原理+用法要点），所有原有内容完整保留，未做任何修改。


> **文档说明**：系统梳理 Prompt 工程（提示词工程）的核心原则、结构化方法、高级技巧、常见模式与最佳实践，帮助高效使用大语言模型。

---

## 1. 概述

Prompt 工程是通过设计输入提示词来引导大语言模型（LLM）输出高质量结果的技术。LLM 是"预测下一个词"的概率模型，好的 Prompt 能显著提升输出质量，是使用 AI 的核心技能。

**Prompt 工程的价值**：
- 无需微调即可提升模型表现
- 降低幻觉，提高准确性
- 控制输出格式和风格
- 适用于所有 LLM，可迁移

## 2. 核心原则

### 2.1 清晰明确

```
❌ 模糊：写一篇关于AI的文章
✅ 明确：写一篇800字的科普文章，主题是"生成式AI如何改变内容创作"，
        面向普通读者，语言通俗易懂，包含3个具体案例，分3个小标题。
```


> 🔍 **知识点深度解析**
>
> **作用**：清晰明确是 Prompt 工程第一原则：指令具体、无歧义、提供上下文和约束，让 LLM 准确理解任务。
>
> **原理**：LLM 没有读心能力，模糊指令产生模糊输出。清晰 Prompt 包含：角色设定（你是...）、具体任务（做什么）、上下文（背景信息）、格式要求（输出结构）、约束条件（不要做什么）。策略：写指令像给新员工写任务说明，包含足够细节；用分隔符区分指令和数据；提供示例说明期望格式。
>
> **用法要点**：① 包含角色+任务+上下文+格式+约束五要素  ② 用分隔符（```/---/<tag>）区分指令和输入数据  ③ 避免'帮我写点东西'这类模糊指令  ④ 指定输出格式（Markdown/JSON/表格）  ⑤ 面试常考：清晰 Prompt 要素、分隔符作用、指令设计原则

### 2.2 提供上下文

- 说明背景信息、目标受众、使用场景
- 提供相关数据、文档、代码片段


> 🔍 **知识点深度解析**
>
> **作用**：在 Prompt 中提供充分背景信息（项目情况、约束条件、相关数据），让 LLM 给出贴合实际的回答。
>
> **原理**：LLM 不知道你的项目背景，必须在 Prompt 中提供：技术栈版本、业务场景、已有代码、错误信息、约束条件。上下文越具体，回答越精准。技巧：用分隔符区分背景和任务、提供相关代码片段而非描述、给出数据样例、说明已尝试的方案。长上下文需注意 Token 预算，只提供相关信息。
>
> **用法要点**：① 提供技术栈、版本、业务场景等背景  ② 粘贴错误信息和相关代码，而非口头描述  ③ 用分隔符（```/---）区分背景和指令  ④ 说明已尝试的方案和结果，避免重复建议  ⑤ 上下文质量决定回答质量，垃圾进垃圾出

### 2.3 指定角色

```
你是一位有10年经验的前端架构师，精通Vue3和TypeScript。
请审查以下代码，指出潜在问题并给出优化建议：
```


> 🔍 **知识点深度解析**
>
> **作用**：角色设定让 LLM 以特定专家身份和视角回答，提升专业领域输出质量。
>
> **原理**：在 Prompt 开头指定角色：'你是资深 Java 架构师'、'你是有 10 年经验的前端工程师'、'你是技术文档翻译专家'。角色设定影响 LLM 的词汇选择、深度和关注点。可组合角色+技能+经验年限。配合系统提示（System Prompt）持久化角色设定。角色越具体（领域+经验+风格），输出越专业。
>
> **用法要点**：① '你是 XX 专家'赋予专业视角  ② 角色+经验年限+技能组合更精确  ③ System Prompt 中固化角色，对话全程生效  ④ 可要求角色用特定思维框架思考  ⑤ 适合专业领域：代码审查、架构设计、医学/法律咨询

### 2.4 设定输出格式

```
请按以下JSON格式输出：
{
  "title": "文章标题",
  "summary": "200字摘要",
  "keywords": ["关键词1", "关键词2"]
}
```


> 🔍 **知识点深度解析**
>
> **作用**：明确指定输出格式（Markdown/JSON/表格/代码），让 LLM 输出可直接使用的结构化结果。
>
> **原理**：指定格式：'用 Markdown 表格输出'、'返回 JSON，字段为...'、'先给代码再给解释'。提供格式示例或模板效果更好。JSON 输出可指定 Schema（字段名/类型/必填）。复杂格式可给 few-shot 示例。结构化输出便于程序解析（API 场景用 JSON mode 或 Function Calling）。
>
> **用法要点**：① 明确格式：Markdown/JSON/表格/代码块  ② JSON 输出指定字段名和类型，API 场景用 JSON mode  ③ 提供格式模板或示例，比文字描述更准确  ④ 代码输出指定语言和注释要求  ⑤ 结构化输出可直接被程序消费，减少后处理

### 2.5 分步引导

- 复杂任务拆分为多个步骤
- 让模型先思考再回答

> 🔍 **知识点深度解析**
>
> **作用**：Prompt 工程是与 LLM 高效沟通的核心技能，掌握原则能大幅提升输出质量。
>
> **原理**：LLM 通过上下文窗口中的所有信息来"预测下一个词"，Prompt 就是给模型的全部上下文。模型没有记忆（每次对话独立，除非系统保留历史），所以需要在 Prompt 中提供所有必要信息。角色设定（Role Prompting）通过设定专业身份，让模型从该角色的知识和视角回答，提升专业性和准确性。明确的格式要求让模型输出结构化结果，便于后续处理。模糊的 Prompt 会让模型"猜测"意图，导致输出偏离预期。
>
> **用法要点**：① Prompt 要包含：角色 + 任务 + 上下文 + 格式 + 约束；② 先写清楚再优化，不要一上来就追求完美；③ 用迭代法：先跑一版，根据输出调整 Prompt；④ 面试常考：Prompt 设计原则、角色设定、Few-shot、CoT、结构化输出。

## 3. 结构化 Prompt 模板

### 3.1 CRISPE 框架

| 要素 | 说明 | 示例 |
|------|------|------|
| **C**apacity（角色） | 设定模型身份 | "你是资深Python后端工程师" |
| **R**ole（任务） | 具体任务 | "优化以下代码的性能" |
| **I**nsight（背景） | 上下文信息 | "这是一个高并发API，当前QPS 1000" |
| **S**tatement（要求） | 具体要求 | "输出优化后的代码和性能分析" |
| **P**ersonality（风格） | 输出风格 | "简洁专业，代码注释清晰" |
| **E**xperiment（实验） | 提供多个方案 | "给出2种优化方案并对比" |


> 🔍 **知识点深度解析**
>
> **作用**：CRISPE 是一个系统化 Prompt 框架：Capacity/Role（角色）、Insight（背景）、Statement（任务）、Personality（风格）、Experiment（要求多方案）。
>
> **原理**：C-Capacity/Role：设定 LLM 角色（你是资深 Java 架构师）。I-Insight：提供背景信息（项目规模/技术栈）。S-Statement：具体任务描述。P-Personality：输出风格（专业/简洁/幽默）。E-Experiment：要求给出多个方案供选择。CRISPE 比简单指令更全面，适合复杂任务的 Prompt 设计。
>
> **用法要点**：① C：角色设定赋予专业视角  ② R：背景洞察让回答贴合实际场景  ③ S：明确任务声明  ④ P：风格控制输出语气和详略  ⑤ E：多方案输出便于比较选择

### 3.2 RTF 框架（Role-Task-Format）

```
【角色】你是一位专业的技术文档撰写者。
【任务】将以下技术笔记整理为结构化的Markdown文档。
【格式】

> 🔍 **知识点深度解析**
>
> **作用**：RTF 是最简洁的 Prompt 框架：Role（角色）、Task（任务）、Format（格式），适合日常快速使用。
>
> **原理**：Role 设定角色身份（你是前端专家），Task 描述具体任务（重构这段代码并说明优化点），Format 指定输出格式（用 Markdown，先给代码再给说明）。RTF 是 CRISPE 的精简版，三要素覆盖了最关键信息，适合 80% 的日常场景。复杂任务再增加上下文和约束。
>
> **用法要点**：① Role：你是 XX 专家  ② Task：具体做什么  ③ Format：输出什么格式  ④ RTF 是最小可用框架，日常够用  ⑤ 复杂任务在 RTF 基础上加上下文/示例/约束

## 4. Few-shot（少样本提示）

### 4.1 原理

在 Prompt 中提供几个输入-输出示例，让模型学习模式，无需微调即可完成任务。


> 🔍 **知识点深度解析**
>
> **作用**：Zero-shot（零样本）不提供示例直接让 LLM 完成任务，依赖 LLM 的预训练知识和指令遵循能力。
>
> **原理**：Zero-shot Prompt 只给指令不给示例，LLM 根据指令理解任务并直接输出。现代 LLM（GPT-3.5/4/Claude）经指令微调后 zero-shot 能力很强，能理解'将以下句子翻译为英文'这类指令。Zero-shot 适合简单明确的任务，但复杂任务或特定格式要求时可能不稳定，需要 few-shot 引导。
>
> **用法要点**：① 不给示例，纯指令驱动  ② 依赖指令微调后的能力，现代 LLM zero-shot 很强  ③ 适合简单任务：翻译/摘要/分类/改写  ④ 复杂格式或专业领域 zero-shot 可能不稳定  ⑤ 面试常考：zero-shot 原理、适用场景、与 few-shot 区别

### 4.2 示例

```
将以下评论分类为正面/负面/中性：

评论："这个产品质量很好，物流也快"
分类：正面

评论："客服态度差，退货麻烦"
分类：负面

评论："价格一般，东西还行"
分类：中性

评论："用了一周就坏了，不推荐"
分类：
```


> 🔍 **知识点深度解析**
>
> **作用**：Few-shot（少样本）在 Prompt 中提供几个输入-输出示例，让 LLM 通过示例学习任务模式。
>
> **原理**：Few-shot Prompt 在指令后给出 2-5 个示例（输入→输出对），LLM 通过 in-context learning 从示例中推断任务模式、格式和风格，然后处理新输入。示例选择要多样化（覆盖不同情况）、格式一致、按难度递进。示例数量不是越多越好，2-5 个通常足够，太多浪费 Token 且可能导致过拟合到示例模式。
>
> **用法要点**：① 提供 2-5 个输入→输出示例  ② 示例覆盖典型情况和边界情况  ③ 格式一致，让 LLM 学习输出模式  ④ 示例顺序：从简单到复杂  ⑤ 面试常考：few-shot 原理、示例选择、in-context learning

### 4.3 要点

- 示例要多样化，覆盖不同情况
- 示例格式与目标输出一致
- 3-5 个示例通常足够
- 示例顺序可能影响结果，可调整

---


> 🔍 **知识点深度解析**
>
> **作用**：Few-shot 的关键要点包括示例选择、格式一致性、示例数量和示例顺序。
>
> **原理**：示例应与真实输入分布一致（随机划分而非刻意挑选），包含正例和边界情况。所有示例格式必须一致（否则 LLM 困惑）。示例中的标签/输出必须准确（错误示例会误导 LLM）。通常 2-5 个示例最佳，过多增加 Token 成本且收益递减。示例顺序可影响输出，困难示例放前面或随机排列。
>
> **用法要点**：① 示例分布要代表真实场景  ② 格式必须一致，标签必须准确  ③ 2-5 个示例性价比最高  ④ 包含边界情况和困难案例  ⑤ Few-shot 不是万能：示例间冲突会降低质量

## 5. 思维链（Chain of Thought, CoT）

### 5.1 原理

让模型分步推理，而不是直接给答案，显著提升复杂问题（数学、逻辑）的准确率。


> 🔍 **知识点深度解析**
>
> **作用**：思维链（CoT）让 LLM 逐步推理而非直接给答案，显著提升数学、逻辑和多步推理任务准确率。
>
> **原理**：CoT Prompt 在指令中加入'让我们一步步思考'或提供含推理过程的 few-shot 示例，引导 LLM 生成中间推理步骤。原理：LLM 是自回归生成，每步生成的 token 成为下一步的上下文，显式推理链为后续推理提供了中间结果（相当于工作记忆），避免跳步导致的错误。CoT 对小模型（<10B）效果有限，主要在大模型上有效。
>
> **用法要点**：① 核心：'Let's think step by step' 或含推理的 few-shot  ② 中间推理步骤为后续生成提供上下文（工作记忆）  ③ 对数学/逻辑/多步推理提升显著，简单任务无需 CoT  ④ 主要在大模型（≥10B）上有效，小模型 CoT 可能产生错误链  ⑤ 面试常考：CoT 原理、为什么逐步推理更准、适用场景

### 5.2 方法

```
❌ 直接问：15个球，拿走3个，剩下的平分给4个人，每人几个？

✅ CoT：15个球，拿走3个，剩下的平分给4个人，每人几个？
请一步步思考：
第一步：原来有15个球
第二步：拿走3个，剩下 15-3=12个
第三步：平分给4个人，12÷4=3
答案：每人3个
```


> 🔍 **知识点深度解析**
>
> **作用**：CoT 的主要方法包括 Zero-shot CoT、Few-shot CoT 和手动推理链示范。
>
> **原理**：Zero-shot CoT：加一句'Let's think step by step'，最简单。Few-shot CoT：提供含详细推理步骤的示例，引导 LLM 模仿推理格式。手动 CoT：在 Prompt 中明确要求分步骤（第一步...第二步...）。推理链可以是：列出已知条件→分析问题→选择方法→逐步计算→验证结果。不同任务设计不同推理结构。
>
> **用法要点**：① Zero-shot CoT：加'一步步思考'，零成本  ② Few-shot CoT：给推理示例，更可控  ③ 手动指定推理步骤结构（分析→方案→验证）  ④ 推理链后可加'因此最终答案是...'提取结论  ⑤ CoT 增加 Token 消耗，简单任务不必使用

### 5.3 Zero-shot CoT

```
简单添加："让我们一步步思考。"
```


> 🔍 **知识点深度解析**
>
> **作用**：Zero-shot CoT 仅通过一句'让我们一步步思考'激活 LLM 的逐步推理能力，无需示例。
>
> **原理**：Kojima et al. 2022 发现，在 Prompt 末尾加'Let's think step by step'就能大幅提升 MultiArith/GSM8K 等推理基准准确率。原理：这句话作为触发器，让 LLM 进入推理模式生成中间步骤。两阶段提示法：第一阶段生成推理链，第二阶段用'因此答案是'提取最终答案。中文可用'请一步步分析'。
>
> **用法要点**：① 一句魔法咒语：'Let's think step by step'  ② 无需示例，零成本提升推理能力  ③ 两阶段：先生成推理，再提取答案  ④ 对大模型效果明显，小模型不稳定  ⑤ 是最简单有效的推理增强技术

### 5.4 进阶：Self-Consistency

- 多次采样不同的推理路径
- 投票选择最常见的答案
- 进一步提升准确率

---


> 🔍 **知识点深度解析**
>
> **作用**：Self-Consistency 通过采样多条推理链并投票选最一致答案，降低单条推理链出错概率。
>
> **原理**：方法：对同一问题用 temperature>0 独立采样多条（5-20 条）CoT 推理链，每条链可能走不同推理路径，最终选出现次数最多的答案（多数投票）。原理：正确答案通常只有一个，不同推理路径会收敛到同一答案；错误路径方向多样，投票分散。Self-Consistency 以更多 Token 消耗换取更高准确率。
>
> **用法要点**：① 采样多条 CoT 链（temperature 0.5-0.7）  ② 多数投票选最频繁答案  ③ 正确推理收敛，错误推理分散  ④ Token 成本×N 倍，适合高准确率要求场景  ⑤ 面试常考：Self-Consistency 原理、投票机制、与 CoT 关系

## 6. 高级技巧

### 6.1 自我批判（Self-Critique）

```
请完成以下任务，然后：
1. 检查你的回答是否有事实错误
2. 检查逻辑是否严密
3. 如果有问题，修正后给出最终答案
```


> 🔍 **知识点深度解析**
>
> **作用**：Self-Critique 让 LLM 先生成初稿再自我审查和修正，通过自我批评提升输出质量。
>
> **原理**：流程：① LLM 生成初始回答 ② 用批判 Prompt 让 LLM 审查自己的回答（找出错误/遗漏/不一致）③ LLM 根据批判修正回答。可迭代多轮。变体：Constitutional AI（用一组原则审查）、Self-Refine（生成→反馈→ refined 循环）。关键：批判 Prompt 要具体（检查事实准确性/逻辑完整性/格式规范），而非泛泛的'改进这个回答'。
>
> **用法要点**：① 生成→批判→修正，可迭代多轮  ② 批判 Prompt 要具体：检查事实/逻辑/格式/遗漏  ③ Constitutional AI 用原则列表指导审查  ④ 适合代码审查、文章润色、数学验证  ⑤ 面试常考：Self-Critique 流程、与 Reflexion 关系、批判 Prompt 设计

### 6.2 知识生成（Generated Knowledge）

```
先列出关于"Transformer注意力机制"的5个关键知识点，
然后基于这些知识回答问题。
```


> 🔍 **知识点深度解析**
>
> **作用**：知识生成让 LLM 先生成相关背景知识，再基于这些知识回答问题，提升事实性准确率。
>
> **原理**：流程：① 让 LLM 生成与问题相关的事实/知识（'关于 X 你知道什么？'）② 将生成的知识作为上下文，让 LLM 重新回答原问题。原理：先激活 LLM 的相关知识（类似回忆），再基于激活的知识推理，比直接回答更准确。风险：生成的知识本身可能有幻觉，需要验证。
>
> **用法要点**：① 两阶段：先生成背景知识，再基于知识回答  ② 类似人类'先回忆相关知识再答题'  ③ 生成的知识可能含幻觉，关键事实需验证  ④ 适合常识推理和事实性问题  ⑤ 面试常考：Generated Knowledge 原理、两阶段提示、幻觉风险

### 6.3 树状思维（Tree of Thoughts）

- 探索多个推理路径
- 评估每条路径
- 选择最优路径继续
- 适合复杂规划和决策


> 🔍 **知识点深度解析**
>
> **作用**：ToT 让 LLM 在推理树中探索多条路径，评估并剪枝，选择最优推理链，解决需要全局规划的问题。
>
> **原理**：CoT 是单链推理（一条路走到黑），ToT 维护思维树：每步生成多个候选思路（分支），用 LLM 评估每个思路的前景（价值打分），剪枝低分路径，沿高分路径继续探索。支持回溯（走不通回到分叉点）。适合 24 点游戏、填字游戏、创意写作等需要探索多条路径的任务。代价是 Token 消耗大（多次 LLM 调用）。
>
> **用法要点**：① 思维树：分支生成→评估→剪枝→探索→回溯  ② 比 CoT 单链更全面，适合需要探索的任务  ③ LLM 同时充当生成器和评估器  ④ Token 成本高，适合复杂推理而非日常任务  ⑤ 面试常考：ToT vs CoT、树搜索、评估剪枝、适用场景

### 6.4 ReAct（推理+行动）

```
问题：北京今天天气怎么样？
思考：我需要查询实时天气，这需要调用工具。
行动：调用 weather_api("北京")
观察：北京今天晴，25-32度，空气质量良。
思考：有了天气信息，可以回答了。
回答：北京今天晴，气温25-32度...
```


> 🔍 **知识点深度解析**
>
> **作用**：ReAct 交替生成推理链和工具调用，让 LLM 边思考边获取外部信息，是 Agent 的基础范式。
>
> **原理**：ReAct = Reasoning + Acting：Thought（分析当前状态）→ Action（调用工具/搜索）→ Observation（工具返回）→ Thought（分析结果）→ ... 循环直到得出答案。相比纯 CoT（无法获取实时信息），ReAct 可通过搜索/计算工具获取外部信息纠正推理。相比纯行动（无推理链），ReAct 有显式思考过程可追溯。
>
> **用法要点**：① Thought→Action→Observation 循环  ② 可调用搜索/计算器/API 获取外部信息  ③ 推理链可追溯，便于调试  ④ 是 AI Agent 的核心范式  ⑤ 面试常考：ReAct 模式、与 CoT 区别、Agent 基础

### 6.5 提示词链（Prompt Chaining）

将复杂任务拆分为多个子任务，前一个输出作为后一个输入：
1. 提取要点 → 2. 组织结构 → 3. 撰写初稿 → 4. 润色优化

---


> 🔍 **知识点深度解析**
>
> **作用**：提示词链将复杂任务拆分为多个子任务，每个子任务用专门 Prompt，前一步输出作为下一步输入。
>
> **原理**：链式拆解：任务 A 的输出→任务 B 的输入→任务 C 的输入→最终输出。例如写文章：①生成大纲 ②根据大纲逐段写 ③润色修改。每步 Prompt 专注单一职责，比一个大 Prompt 质量更高更可控。可并行化（无依赖的分支）和条件分支（根据中间结果选择路径）。LangChain LCEL 和 LangGraph 是实现链式编排的工具。
>
> **用法要点**：① 复杂任务拆分为多步，每步单一职责  ② 前一步输出作为下一步输入  ③ 比单一大 Prompt 质量高、可控、可调试  ④ 可并行无依赖步骤，条件分支选择路径  ⑤ 面试常考：Prompt Chaining 优势、任务拆分、与 LangChain 关系

### 7.1 代码审查

```
角色：资深代码审查专家
任务：审查以下代码，从以下维度分析：
1. 功能正确性
2. 性能问题
3. 安全漏洞
4. 代码风格
5. 可维护性

代码：
```
{code}
```

输出格式：
| 维度 | 问题 | 严重程度 | 修复建议 |
```


> 🔍 **知识点深度解析**
>
> **作用**：用 LLM 做代码审查时，Prompt 需指定审查维度、输出格式和项目上下文。
>
> **原理**：有效 Prompt：角色（资深代码审查员）+ 审查维度（安全/性能/可读性/错误处理/命名）+ 输出格式（问题列表：文件:行号/严重级别/问题描述/修改建议）+ 代码上下文（语言/框架/编码规范）。可要求按严重级别分类（Blocker/Major/Minor），给出具体修改代码而非泛泛建议。增量审查可只给 diff。
>
> **用法要点**：① 指定审查维度：安全/性能/可读性/最佳实践  ② 输出结构化：位置/级别/问题/建议/修改代码  ③ 提供语言/框架/规范上下文  ④ 要求给出可直接应用的修改代码  ⑤ 可结合 System Prompt 固化审查标准

### 7.2 文档总结

```
请总结以下文档，要求：
1. 不超过300字
2. 提取3-5个核心要点
3. 用列表形式呈现
4. 保留关键数据和结论

文档：
{document}
```


> 🔍 **知识点深度解析**
>
> **作用**：文档总结 Prompt 需指定总结目的、长度、结构和重点，避免泛泛的摘要。
>
> **原理**：指定：总结目的（快速了解/决策参考/学习笔记）、目标读者（技术/管理/新手）、长度（3 句话/500 字/3 个要点）、结构（要点列表/执行摘要/问答对）、重点关注（技术方案/风险/数据）。长文档需分块总结再合并（map-reduce）。可要求保留关键数据和引用。
>
> **用法要点**：① 明确目的和读者决定总结风格  ② 指定长度和结构（要点/摘要/问答）  ③ 长文档分块总结再合并（map-reduce）  ④ 要求保留关键数据和来源引用  ⑤ 结构化输出：核心观点/关键数据/行动建议

### 7.3 翻译

```
请将以下英文翻译为中文，要求：
1. 专业术语保留英文并在括号中注明中文
2. 符合中文技术文档表达习惯
3. 不改变原文结构和格式

原文：
{text}
```


> 🔍 **知识点深度解析**
>
> **作用**：翻译 Prompt 需指定源语言/目标语言、风格领域和术语处理，保证翻译质量和一致性。
>
> **原理**：指定：源语言和目标语言、领域（技术/法律/文学）、风格（正式/口语化）、术语表（特定术语固定译法）、保留格式（Markdown/代码不译）。技术翻译要求：代码块不翻译、专有名词保留英文或加括号注释、保持 Markdown 格式。可给 few-shot 示例说明风格。长文本分块翻译保持术语一致。
>
> **用法要点**：① 指定语言对、领域、风格  ② 术语表：专业术语固定译法，保持一致性  ③ 代码块/命令/URL 不翻译  ④ 保持 Markdown 格式和结构  ⑤ 可要求先列出术语对照表再翻译

### 7.4 头脑风暴

```
角色：创意总监
任务：为"AI编程工具"产品命名，要求：
1. 10个候选名称
2. 每个名称说明含义和定位
3. 风格：科技感、易记、可注册商标
4. 避免与现有知名品牌重名
```

---


> 🔍 **知识点深度解析**
>
> **作用**：头脑风暴 Prompt 让 LLM 生成大量创意，需指定数量、视角、约束和评价标准。
>
> **原理**：技巧：指定数量（生成 20 个想法）、多视角（从用户/开发者/商业角度）、设约束（在 X 预算内/不用 Y 技术）、鼓励发散（不要评价，先量后质）、组合创新（将 A 和 B 结合）。可分两轮：第一轮发散生成，第二轮评估筛选。温度设高（0.8-1.0）增加多样性。
>
> **用法要点**：① 指定数量（≥10 个），先量后质  ② 多视角：用户/技术/商业/竞品  ③ 设约束条件激发创造力  ④ 高 temperature 增加多样性  ⑤ 两轮：发散→评估筛选

## 8. 避坑指南

1. **不要一次塞太多任务**：一个 Prompt 专注一个目标
2. **不要假设模型知道上下文**：必要信息都要提供
3. **不要用模糊词**："好一点""差不多"要量化
4. **不要忽略迭代**：第一版 Prompt 很少完美，根据输出调整
5. **不要轻信模型**：重要信息要验证，模型会幻觉
6. **注意 Token 限制**：超长 Prompt 会截断或超预算

---

## 8.1 Prompt 安全

| 攻击类型 | 说明 | 防护 |
|----------|------|------|
| **提示词注入** | 用户输入覆盖系统指令 | 输入过滤、指令隔离、输出校验 |
| **越狱攻击** | 诱导模型绕过安全限制 | 安全训练、输出审核、关键词过滤 |
| **系统提示泄露** | 诱导模型输出系统提示 | 不要在系统提示中存敏感信息 |
| **间接注入** | 通过检索文档/RAG注入 | 检索内容标记、来源验证 |

---


> 🔍 **知识点深度解析**
>
> **作用**：Prompt 安全关注 Prompt 注入、敏感信息泄露和越狱攻击，需在系统设计层面防护。
>
> **原理**：Prompt 注入：用户输入覆盖系统指令。防护：系统指令与用户输入用分隔符隔离、输入消毒、指令优先级声明。越狱（Jailbreak）：通过角色扮演/编码/多轮诱导绕过安全限制。敏感信息：系统 Prompt 中不写密码/密钥，防止通过注入提取。数据泄露：日志脱敏、不将敏感数据发给不可信模型。
>
> **用法要点**：① 分隔符隔离系统指令和用户输入  ② 系统 Prompt 中不包含密钥/密码等硬编码秘密  ③ 输入消毒和输出过滤  ④ 敏感操作需外部验证，不依赖 LLM 自律  ⑤ 面试常考：Prompt 注入、越狱、信息泄露、防护策略

## 8.2 上下文窗口管理

- **重要信息置顶**：系统提示和关键约束放最前面
- **滑动窗口**：保留最近 N 轮对话，旧对话摘要压缩
- **对话摘要**：定期用 LLM 总结历史对话，替换原始记录
- **Token 计数**：tiktoken 等工具精确计算，避免超窗
- **检索增强**：长文档用 RAG 检索相关片段，不全部塞入

---


> 🔍 **知识点深度解析**
>
> **作用**：上下文窗口有限，需通过摘要、裁剪、检索和分段策略管理 Token 预算，避免信息丢失或超限。
>
> **原理**：策略：对话历史摘要压缩（旧消息总结为摘要）、滑动窗口（只保留最近 N 轮）、RAG 检索（只注入相关文档而非全量）、分段处理（长文档 map-reduce）、工具结果裁剪（只返回必要字段）。优先级：系统指令 > 当前任务上下文 > 相关历史 > 旧历史。Token 计数预估，超限时自动压缩。
>
> **用法要点**：① 摘要压缩：旧对话→摘要，释放空间  ② 滑动窗口：保留最近 N 轮+摘要  ③ RAG：按需注入相关上下文而非全量  ④ 工具返回结果精简，避免大 JSON 占满窗口  ⑤ 面试常考：上下文限制、摘要策略、Token 预算、长文档处理

## 8.3 自动 Prompt 优化

| 方法 | 原理 |
|------|------|
| **APE**（自动提示词工程） | 用 LLM 生成和评估候选 Prompt |
| **OPRO** | 元提示词优化，用 LLM 作为优化器 |
| **Promptbreeder** | 进化算法迭代优化 Prompt 种群 |

---


> 🔍 **知识点深度解析**
>
> **作用**：自动 Prompt 优化（APE/OPRO/DSPy）用算法自动搜索和优化 Prompt，减少人工调参。
>
> **原理**：APE（Automatic Prompt Engineer）：让 LLM 生成多个候选 Prompt，在训练集上评估选最优。OPRO：LLM 作为优化器，根据评估结果迭代生成更好的 Prompt。DSPy：将 Prompt 编写变为编程（Signature 声明输入输出，Optimizer 自动优化）。这些方法用评估集量化 Prompt 质量，自动化'试错-评估-改进'循环。
>
> **用法要点**：① APE：生成候选 Prompt→评估→选最优  ② OPRO：LLM 自身作为优化器迭代 Prompt  ③ DSPy：编程式 Prompt，自动优化编译  ④ 需要评估集量化 Prompt 效果  ⑤ 面试常考：自动 Prompt 优化、APE、DSPy、评估驱动

## 8.4 系统提示设计最佳实践

系统提示（System Prompt）是给模型的全局指令，结构应包含：
1. **角色设定**：你是谁，专业背景
2. **任务描述**：核心职责是什么
3. **约束条件**：不能做什么，必须遵守什么
4. **输出格式**：结构化要求
5. **示例**：Few-shot 示例（可选）
6. **长度控制**：简洁，避免冗余

---


> 🔍 **知识点深度解析**
>
> **作用**：系统提示（System Prompt）设计需结构化、模块化、可维护，是 AI 应用质量的基石。
>
> **原理**：最佳实践：用 XML 标签结构化（<role>/<context>/<constraints>/<output_format>）；指令用肯定句（说要做什么而非不要做什么）；输出格式用 JSON Schema 或模板明确；示例放在指令后；将长系统提示拆为可复用模块（角色/规则/工具说明）；版本管理（系统提示变更影响大，需 A/B 测试）；将易变信息（数据/日期）与稳定指令分离。
>
> **用法要点**：① XML 标签结构化：<role>/<rules>/<format>  ② 肯定句指令，输出格式用 JSON Schema 明确  ③ 模块化：角色/规则/工具/格式分离，可复用  ④ 版本管理+A/B 测试，系统提示变更影响大  ⑤ 易变数据与稳定指令分离，用变量注入

## 📝 精简总结

- Prompt 工程：通过设计提示词引导 LLM 高质量输出，无需微调
- 核心原则：清晰明确、提供上下文、指定角色、设定格式、分步引导
- 结构化框架：CRISPE（角色/任务/背景/要求/风格/实验）、RTF
- Few-shot：提供示例让模型学习模式，3-5个示例效果好
- 思维链 CoT：让模型分步推理，"让我们一步步思考"即可触发，Self-Consistency 投票提升
- 高级技巧：自我批判、知识生成、树状思维、ReAct、提示词链
- 系统提示：角色+任务+约束+格式+示例，全局生效，重要信息置顶
- 上下文管理：滑动窗口、对话摘要压缩、Token计数、RAG检索相关片段
- Prompt 安全：防注入（输入过滤/指令隔离）、防越狱（安全训练/输出审核）、防间接注入（来源标记）
- 自动优化：APE/OPRO/Promptbreeder，用AI优化AI提示词
- 常见模板：代码审查、文档总结、翻译、头脑风暴
- 避坑：一次一个任务、提供全部上下文、量化要求、迭代优化、验证输出
