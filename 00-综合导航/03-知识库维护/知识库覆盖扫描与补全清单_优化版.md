## 一、扫描方法与范围

### 1. 扫描方法

```text
扫描流程：
1. 全量遍历：遍历知识库根目录下所有 **/*.md 文件
2. 分类识别：按一级目录归类，区分"内容型文档"与"导航/模板/规则型文档"
3. 质量评估：按《知识库文档统一编写标准v2》四维标准评估每篇文档
   - 内容丰富度：是否覆盖定义/原理/用法/问题/最佳实践
   - 结构合理性：是否遵循六段式结构
   - 解析细致程度：原理是否讲透、代码是否有注释
   - 视觉美观性：是否有图示/表格/代码块
4. 覆盖度分析：按知识体系框架检查每个主题是否有对应文档
5. 盲区识别：标记"完全缺失"、"仅有MOC无内容"、"内容薄弱"三类盲区
6. 优先级排序：按 P0（核心缺失）、P1（重要增强）、P2（体系优化）分级
```

### 2. 扫描范围

| 范围 | 包含内容 | 说明 |
|------|---------|------|
| **一级板块** | 00-综合导航 ~ 09-AI与效率工具 | 10 个一级目录 |
| **二级目录** | 各板块下的子分类 | 如 01-前端开发/01-基础语言 |
| **原子笔记** | 具体知识点文档 | 内容型专文 |
| **MOC/枢纽** | 各板块的导航/索引文档 | 导航型文档 |
| **模板/规范** | 编写标准、模板、规则 | 规范型文档 |
| **维护文档** | 健康度、覆盖扫描、维护报告 | 维护型文档 |

### 3. 文档分类判定标准

| 类型 | 判定标准 | 示例 |
|------|---------|------|
| **内容型专文** | 具备多章节、代码示例、表格、深度解析，字数 > 3000 | `RAG检索增强生成.md`、`Java-多线程与并发.md` |
| **MOC/枢纽** | 以链接列表为主，是板块导航入口 | `MOC-前端开发.md`、`MOC-AI与效率工具.md` |
| **模板/规范** | 规定格式、标准、规则的文档 | `知识库文档统一编写标准v2.md`、`标签命名规范.md` |
| **维护型** | 扫描、评估、报告类文档 | 本文档、`知识库健康度评估指标.md` |
| **内容薄弱** | 有标题但内容 < 3000 字，或缺核心章节 | 需重写的薄文档 |
| **内容空白** | 仅有 MOC 目录，无对应内容型专文 | 缺失领域 |

## 六、质量验收标准

### 1. 单篇文档验收（按《编写标准v2》四维）

| 维度 | 验收标准 | 检查方法 |
|------|---------|---------|
| **内容丰富度** | ① 六模块齐全 ② 代码示例 ≥ 3 个 ③ 常见问题 ≥ 8 个 ④ 关联笔记 ≥ 8 篇 | 章节完整性检查、计数 |
| **结构合理性** | ① 严格六段式 ② 标题层级 ≤ 4 级 ③ 每节有深度讲解+总结 ④ 核心知识点有三位一体解析 | 结构对照模板 |
| **解析细致程度** | ① 原理讲透"为什么" ② 代码注释率 ≥ 30% ③ 问题有"现象→原因→方案" ④ 复杂概念有图示 | 抽查深度、注释率 |
| **视觉美观性** | ① ≥ 1 个内联 HTML 动画图 ② ≥ 1 个 Mermaid 图 ③ 对比用表格 ④ 代码有语言标注 | 图示计数、格式检查 |

**验收结论**：
- 四维全部达标 → ✅ 内容已完善
- 三维达标、一维有不足 → 🟡 待优化
- 两维及以上不达标 → 🔄 需重写

### 3. 版本管理与备份

```text
版本管理：
- 使用 Git 管理知识库（推荐）
- 每次重大更新提交 commit，写清晰的 commit message
- 定期推送到远程仓库（GitHub/Gitee）
- 重要节点打 tag（如 v1.0-框架完成、v2.0-全集补齐）

备份策略：
- 本地：工作目录实时保存
- 云端：Git 远程仓库 + 云盘同步（OneDrive/iCloud）
- 定期：每周自动备份到外部存储
- 导出：每月导出一次完整知识库 zip 包

回滚机制：
- 内容误删/误改：Git revert 回滚
- 大规模损坏：从最近备份恢复
- 单篇文档问题：从 Git history 恢复历史版本
```
