## 三、定期维护工作流

### 3.1 周度小维护（每周日，30分钟）

```text
周度维护清单：
- [ ] 检查本周新增文档的 Frontmatter 完整性
- [ ] 检查新增文档是否符合《编写标准v2》六段式结构
- [ ] 检查新增文档难度标注是否合理
- [ ] 为新增文档补充双向链接（至少5个）
- [ ] 将新增文档登记到对应 MOC
- [ ] 运行死链检查，修复本周新增死链
- [ ] 更新学习进度追踪看板
- [ ] 处理 Inbox 积压（如有）
- [ ] 记录本周维护日志
```

### 3.2 月度大维护（每月1号，2-3小时）

```text
月度维护清单：
- [ ] 运行完整健康度评估（六大维度评分）
- [ ] 生成月度健康度报告（更新本文档）
- [ ] 运行全库死链扫描，批量修复
- [ ] 统计标签使用频率，审计低频标签（<3次），合并或删除
- [ ] 检查 MOC 完整性，补充缺失的 MOC
- [ ] 抽查 10% 文档的质量（按四维标准评分）
- [ ] 统计薄文档（<3000字），更新重写队列
- [ ] 统计 3 个月/6 个月未更新文档，标记过时
- [ ] 推进一批薄文档深度重写（7-10篇）
- [ ] 检查知识缺口，对照学习路线识别盲区
- [ ] 分析链接网络，识别孤岛笔记并补链
- [ ] 更新下月维护计划
```

### 3.3 季度重构（每季度首月，半天）

```text
季度维护清单：
- [ ] 全面健康度评估，与上季度对比趋势
- [ ] 分类结构评估：当前目录结构是否合理，是否需要新增/合并/拆分目录
- [ ] 过时知识清理：标记或删除已过时的内容，更新版本标注
- [ ] 体系重构建议：是否需要调整知识体系框架
- [ ] 学习路径更新：根据知识增长和行业趋势更新学习顺序
- [ ] 工具与流程评估：当前维护工具和流程是否高效
- [ ] 年度目标对齐：检查知识库建设是否对齐年度学习目标
- [ ] 大规模重复检测，合并内容重叠的笔记
- [ ] 全面更新所有 MOC 导航
- [ ] 备份知识库（Git 提交 + 云盘同步）
```

### 3.4 年度盘点（每年12月，1天）

```text
年度维护清单：
- [ ] 全面复核所有笔记难度标注
- [ ] 技术内容大规模更新（框架新版本、新工具、行业趋势）
```

### 4.2 自动化脚本

```text
维护脚本清单（存放于知识库 _scripts 目录）：

1. kb_health_check.ps1 — 健康度检查
   - 统计文档数、平均字数、薄文档比例
   - 检查 Frontmatter 完整率
   - 统计标签使用频率
   - 输出健康度评分

2. kb_broken_links.ps1 — 死链扫描
   - 扫描所有 [[]] 链接
   - 检查目标文件是否存在
   - 输出死链列表和引用来源
   - 支持批量修复（映射到现有笔记）

3. kb_quality_check.ps1 — 质量校验
   - 检查六段式结构完整性
   - 检查代码块语言标注
   - 检查双向链接数量
   - 输出单篇质量评分

4. kb_orphan_notes.ps1 — 孤岛笔记检测
   - 查找零入链零出链的笔记
   - 按板块分组
   - 推荐相关笔记用于补链

5. kb_tag_audit.ps1 — 标签审计
   - 统计所有标签使用频率
   - 识别低频标签（<3次）
   - 识别同义词标签
   - 输出合并建议

6. kb_rewrite_queue.ps1 — 重写队列生成
   - 按文件大小从小到大排序
   - 排除 MOC/模板/规范/备份类文档
   - 筛选 3-15KB 薄文档
   - 输出每批 7 篇的重写队列
```

### 4.3 Git 版本管理

```bash
Git 维护规范：
- 提交频率：每周至少提交一次，重大变更立即提交
- Commit Message 格式：
  - feat: 新增文档/功能
  - fix: 修复死链/错误
  - refactor: 重写/重构文档
  - docs: 更新规范/维护报告
  - chore: 清理备份/调整结构
- 分支策略：main 分支保持稳定，重大调整用 feature 分支
- 远程仓库：同步到 GitHub/Gitee 私有仓库
- 标签：重要节点打 tag（v1.0-框架完成、v2.0-全集补齐、v3.0-质量深化）
```
