# 🏷️ 标签命名规范

> 本规则定义知识库的标签体系、命名规则和使用标准。统一的标签体系是知识聚合、图谱可视化和智能检索的基础。

---

## 1. 标签层级体系

### 1.1 四级标签结构

```
一级：领域标签（11个，固定）
  #前端 #后端 #数据库 #分布式 #云原生 #计算机基础 #通用工具 #Python全栈 #AI与效率工具 #项目实战 #综合导航

二级：技术标签（动态增长，具体技术名）
  #Vue3 #TypeScript #SpringBoot #MySQL #Redis #Docker #K8s #Python #Django #FastAPI #LangChain #SpringAI #AIGC #AIAgent ...

三级：类型标签（8个，固定）
  #概念 #原理 #实战 #面试 #速查 #对比 #架构 #踩坑

四级：状态标签（5个，固定）
  #草稿 #待完善 #已审核 #精品 #过时
```

### 1.2 标签使用组合

每个笔记的标签 = **1个领域 + 1-3个技术 + 1个类型 + 0-1个状态**

```
示例：
  RAG 检索增强生成.md → #AI与效率工具 #AIAgent #RAG #概念 #已审核
  Spring AI ChatClient高级API.md → #后端 #SpringAI #AIAgent #实战 #已审核
  Vue3 useChat 钩子.md → #前端 #Vue3 #AIAgent #速查 #已审核
  面试高频考点汇总.md → #前端 #后端 #面试 #速查
```

## 2. 命名规则

### 2.1 通用规则

| 规则 | 说明 | 示例 |
|------|------|------|
| **英文优先** | 技术术语用英文，保持与业界一致 | `#Vue3` 而非 `#视图框架` |
| **驼峰命名** | 多词技术名用驼峰或连字符 | `#SpringAI` / `#Spring-AI`（统一用驼峰） |
| **不用空格** | 标签中不使用空格 | `#FunctionCalling` 而非 `#Function Calling` |
| **不用复数** | 统一用单数形式 | `#设计模式` 而非 `#设计模式们` |
| **版本号** | 大版本可加在技术名后 | `#Vue3` `#SpringBoot3` |
| **缩写** | 业界通用缩写可直接用 | `#RAG` `#AIGC` `#LLM` `#JVM` |

### 2.2 中文标签规则

- 领域标签用中文：`#前端` `#后端` `#数据库`
- 非技术概念用中文：`#面试` `#速查` `#对比` `#踩坑`
- 技术名有通用中文译法且更常用时可用中文：`#并发编程` `#分布式事务`
- 中英文不混用：`#SpringAI` 或 `#Spring人工智能`，不写 `#SpringAI框架`

### 2.3 禁止创建的标签

- ❌ 只使用一次的标签（如 `#2026年8月学到的东西`）
- ❌ 与已有标签重复的近义词（已有 `#Vue3` 就不再创建 `#Vue.js`）
- ❌ 过于宽泛的标签（`#技术` `#编程` `#知识`）
- ❌ 情绪化标签（`#好难` `#重点` `#必考` → 用 `#面试` 替代）

## 4. 技术标签管理

### 4.1 标签生命周期

```
新标签创建 → 使用≥3次 → 纳入正式标签体系
     ↓
使用<3次且超过30天 → 建议合并到已有标签或删除
     ↓
技术过时 → 标记 `#过时`，保留但不再新增
```

### 4.2 标签合并规则

当出现以下情况时合并标签：
- 同义词：`#SpringBoot` 和 `#Spring-Boot` → 统一为 `#SpringBoot`
- 包含关系：`#Vue3组件` 是 `#Vue3` 的子集 → 合并到 `#Vue3`，用内容区分
- 中英文重复：`#向量数据库` 和 `#VectorDatabase` → 统一为 `#向量数据库`（中文更常用）

### 4.3 标签使用统计（月度审计）

每月生成标签使用报告：

```
📊 标签使用统计 - 2026-08

【Top 10 高频标签】
1. #Vue3 (24篇)
2. #TypeScript (18篇)
3. #SpringBoot (15篇)
...

【低频标签（<3次）】- 建议合并或删除
- #WebLLM (1次) → 合并到 #浏览器端AI
- #可灵 (1次) → 合并到 #视频生成
...

【新增标签】
```

## 5. 标签与图谱颜色的对应

关系图谱中，标签和目录共同决定节点颜色：

| 匹配优先级 | 规则 | 颜色 | 说明 |
|-----------|------|------|------|
| 1 | `file:Home` | 亮白 | 首页特殊色 |
| 2 | `tag:MOC` | 金色 | 所有索引页 |
| 3-13 | `path:目录` | 各领域色 | 按目录分色（主规则） |
| 14 | `tag:面试` | 深红 | 面试类文档覆盖色 |

**注意**：图谱颜色主要按目录（path）区分，标签用于筛选和聚合，不直接决定颜色。如需为特定技术标签分配颜色，可在 `graph.json` 中新增 `tag:技术名` 规则（优先级需在 path 规则之前才会生效）。

## 6. 标签查询技巧

在 Obsidian 中：

```
#前端 #面试          → 同时包含两个标签的笔记
#前端 OR #后端       → 包含任一标签的笔记
#Vue3 -#面试         → 包含Vue3但不包含面试的笔记
tag:#AIAgent         → 搜索标签（精确匹配）
```

在 AI 工具中检索时：

```
请帮我找出所有 #后端 #AIAgent 标签的笔记，按创建时间排序
请统计 #RAG 标签的笔记数量，并列出标题
```
