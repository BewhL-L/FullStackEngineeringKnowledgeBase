# ✅ 质量校验规则

> 本规则定义知识库笔记的质量标准和校验流程。AI 工具生成/修改笔记后必须自动校验，不通过的标记「需人工审核」。

---

## 1. 校验维度与标准

### 1.1 结构完整性

| 检查项 | 标准 | 严重程度 |
|--------|------|----------|
| front matter | 必须包含 title/tags/created/source | 🔴 必须 |
| 一句话定义 | 必须有 blockquote 形式的定义 | 🔴 必须 |
| 核心要点 | 3-5条，覆盖关键信息 | 🟡 建议 |
| 深入理解 | 有原理说明和代码示例 | 🟡 建议 |
| 关联知识 | 至少2个双向链接 | 🔴 必须 |
| 来源标注 | 可追溯到原始出处 | 🔴 必须 |
| 返回导航 | 末尾有 MOC 和 Home 链接 | 🟢 可选 |

### 1.2 内容质量

| 检查项 | 标准 | 严重程度 |
|--------|------|----------|
| 原子化 | 一个笔记只讲一个概念 | 🔴 必须 |
| 独立理解 | 不依赖上下文能读懂核心 | 🟡 建议 |
| 准确性 | 技术事实正确，无明显错误 | 🔴 必须 |
| 时效性 | 标注适用版本，过时内容标记 | 🟡 建议 |
| 无冗余 | 不与已有笔记大面积重复 | 🟡 建议 |
| 有深度 | 不止于表面定义，有原理/误区 | 🟢 加分 |

### 1.3 链接质量

| 检查项 | 标准 | 严重程度 |
|--------|------|----------|
| 出向链接 | 至少2个，指向真实存在的笔记 | 🔴 必须 |
| 链接精准 | 链接与内容相关，不凑数 | 🟡 建议 |
| 无死链 | 链接指向的文件存在 | 🔴 必须 |
| 关系标注 | 关联知识部分标注关系类型 | 🟢 加分 |

### 1.4 格式规范

| 检查项 | 标准 | 严重程度 |
|--------|------|----------|
| 标题层级 | # 标题 → ## 章节 → ### 子节，不跳级 | 🟡 建议 |
| 代码块 | 有语言标注（```java / ```ts） | 🟡 建议 |
| 表格 | 对比类内容优先用表格 | 🟢 加分 |
| 中英文间距 | 中英文之间有空格 | 🟢 加分 |
| 无 HTML 标签 | 不使用 <br> <div> 等 | 🟡 建议 |

## 2. 自动校验流程（AI 执行）

```
输入：新生成/修改的笔记

步骤1：结构校验
  - 检查 front matter 字段完整性
  - 检查必备章节是否存在
  - 检查返回导航链接
  → 不通过：补充缺失部分，或标记「需人工审核」

步骤2：原子化校验
  - 分析标题和内容是否只讲一个概念
  - 如果包含多个独立概念 → 建议拆分
  → 不通过：标记「需拆分」，生成拆分建议

步骤3：链接校验
  - 统计出向链接数量（需≥2）
  - 检查每个链接的目标文件是否存在
  - 检查链接与内容的相关性
  → 不通过：自动补充关联链接，或标记「需人工审核」

步骤4：重复校验
  - 与全库笔记做语义相似度比对
  - 相似度 > 80% → 标记「可能重复」，列出候选
  → 不通过：标记「待合并」，附相似笔记列表

步骤5：格式校验
  - 检查标题层级、代码块语言、表格使用
  → 不通过：自动修复格式问题

步骤6：生成校验报告
  - 通过/不通过项清单
  - 自动修复的内容
  - 需人工审核的内容
  - 建议操作（拆分/合并/补充）
```

---

## 3. 校验结果处理

| 校验结果 | 处理方式 |
|----------|----------|
| ✅ 全部通过 | 自动归档到对应分类，更新 MOC |
| ⚠️ 建议项未通过 | 自动修复后归档，记录修复内容 |
| 🔴 必须项未通过 | 存入 `Inbox/_草稿/`，标记「需人工审核」 |
| 🔀 可能重复 | 归档但标记「待合并」，在周度重构中处理 |
| ✂️ 需拆分 | 不归档，生成拆分建议，人工确认后拆分 |

## 4. 定期审计规则

### 4.1 周度审计（每周日）

AI 自动扫描全库，生成审计报告：

```
📊 周度知识库审计报告 - 2026-W33

【健康度】85/100

【问题清单】
1. 孤儿笔记（0入向0出向）：3篇
   - [[概念A]] [[概念B]] [[概念C]]
2. 待合并笔记（相似度>80%）：2组
   - [[概念D]] vs [[概念E]] (相似度87%)
3. 链接不足（<2个出向链接）：5篇
   - [[概念F]] ...
4. 过时风险（>6个月未更新且涉及快速变化技术）：8篇
5. Inbox 积压：12条待处理

【建议操作】
- 优先处理 Inbox 积压
- 合并2组重复笔记
- 为3篇孤儿笔记添加关联
```

### 4.2 月度审计（每月1号）

- MOC 完整性检查：每个分类的文档是否都在 MOC 中
- 标签使用统计：识别低频标签（使用<3次），建议合并或删除
- 知识缺口分析：哪些领域文档偏少，建议补充
- 链接网络分析：识别知识孤岛，建议建立关联

### 4.3 季度审计（每季度首月）

- 分类结构评估：当前目录结构是否合理
- 过时知识清理：标记或删除已过时的内容
- 体系重构建议：是否需要新增/合并/拆分分类
- 学习路径更新：根据知识增长更新学习顺序

## 5. 笔记成熟度等级

根据质量校验结果，笔记分为5个等级：

| 等级 | 标签 | 标准 | 占比目标 |
|------|------|------|----------|
| 🌱 草稿 | #草稿 | 刚从 Inbox 提取，未校验 | <10% |
| 🌿 待完善 | #待完善 | 结构完整但内容较浅 | 20-30% |
| 🌳 已审核 | #已审核 | 通过全部校验，内容充实 | 50-60% |
| 🏆 精品 | #精品 | 深度+示例+关联+对比，可作范本 | 10-20% |
| 📦 过时 | #过时 | 技术已过时，保留供参考 | <5% |

**升级路径**：草稿 → 待完善（补充内容）→ 已审核（通过校验）→ 精品（深度打磨）

---

## 6. 校验命令模板（给 AI 工具）

```
请对以下笔记执行质量校验：
1. 按「质量校验规则」的4个维度逐项检查
2. 自动修复格式和结构问题
3. 补充缺失的关联链接（从全库中寻找相关笔记）
4. 检查是否与已有笔记重复
5. 生成校验报告，标注通过/不通过/需人工审核项
6. 如果全部通过，归档到对应分类并更新 MOC

笔记内容：
<粘贴笔记>
```
