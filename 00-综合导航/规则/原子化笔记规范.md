# ⚛️ 原子化笔记规范

> 本规则定义原子化笔记的结构、粒度、命名和写作要求。AI 工具从 Inbox 拆解知识时必须遵守本规范。

---

## 1. 什么是原子化笔记

**原子化笔记 = 一个笔记只讲一个概念，可独立理解、可独立引用、可独立演化。**

```
❌ 非原子化（一个笔记讲多个概念）：
  "Spring AI 核心概念：ChatModel、Prompt、Advisor、VectorStore"

✅ 原子化（每个概念一个笔记）：
  "ChatModel - Spring AI 对话模型统一接口"
  "Prompt - Spring AI 提示词封装"
  "Advisor - Spring AI 调用拦截器"
  "VectorStore - Spring AI 向量存储接口"
```

### 1.1 原子化的三个标准

| 标准 | 说明 | 检验方法 |
|------|------|----------|
| **单一概念** | 标题能用一个名词短语概括 | 标题含"和/与/及"→ 可能不够原子 |
| **独立理解** | 不依赖其他笔记就能读懂核心内容 | 新读者只看这一篇能理解吗？ |
| **独立引用** | 其他笔记可以只引用这个概念 | 能被 `[[]]` 单独链接吗？ |

---

## 2. 笔记粒度判断

### 2.1 合适的粒度

```
太粗（需拆分）：
  "前端工程化" → 拆成：Vite / ESLint / Husky / CI-CD / 性能优化

合适（原子化）：
  "Vite 依赖预构建机制"
  "ESLint flat config 配置方式"
  "Husky pre-commit 钩子原理"

太细（需合并）：
  "useChat 的 messages 属性" → 合并到 "Vercel AI SDK useChat 钩子"
```

### 2.2 粒度判断决策树

```
这个笔记的标题能用一个概念名词概括吗？
  ├─ 不能 → 拆分
  └─ 能 → 这个概念能再拆成两个独立子概念吗？
       ├─ 能且子概念都有独立价值 → 拆分
       └─ 不能或子概念无独立价值 → 粒度合适
```

## 3. 原子化笔记结构

### 3.1 标准模板

```markdown
---
title: <概念名> - <一句话说明>
tags: [<领域>, <技术栈>, <概念类型>, 面试?]
created: YYYY-MM-DD
updated: YYYY-MM-DD
source: <来源，如 Inbox/2026-08-13-xxx>
related:
  - [[相关概念1]]
  - [[相关概念2]]
---

# <概念名>

> 一句话定义：这个概念是什么，解决什么问题。

## 核心要点
- 要点1
- 要点2
- 要点3

## 深入理解
### 原理/机制
<底层原理、工作机制>

### 用法示例
```<语言>
<代码示例>
```

### 常见误区
- 误区1：<说明>
- 误区2：<说明>

## 关联知识
- 前置知识：[[概念A]]（学习本概念前需要了解）
- 后续延伸：[[概念B]]（学完本概念后可以学）
- 相似对比：[[概念C]] vs [[概念D]]

## 来源
- [[Inbox/原始笔记]]
- <外部链接>
```

### 3.2 各部分写作要求

| 部分 | 要求 | 字数建议 |
|------|------|----------|
| **一句话定义** | 用"是什么+解决什么"的句式，不超过50字 | 30-50字 |
| **核心要点** | 3-5条，每条一句话，覆盖最关键信息 | 100-200字 |
| **深入理解** | 原理+示例+误区，是笔记的主体 | 300-800字 |
| **关联知识** | 至少2个双向链接，标注关系类型 | 2-5个链接 |
| **来源** | 标注原始出处，可追溯 | 必填 |

## 4. 命名规范

### 4.1 文件命名

```
格式：<概念名> <修饰说明>.md

示例：
  ChatModel 统一接口.md
  Function Calling 工具调用.md
  RAG 检索增强生成.md
  Vercel AI SDK useChat 钩子.md
  Spring AI ChatClient 高级API.md
```

**规则**：
- 用中文或英文概念名，保持与领域习惯一致
- 技术术语保留英文（如 RAG、Function Calling）
- 不使用"知识点梳理""大全""完整版"等模糊词
- 不添加日期（日期在 front matter 里）

### 4.2 标题命名

```
# <概念名>

副标题（blockquote）：<一句话定义>
```

## 5. 双向链接规范

### 5.1 必须添加链接的场景

- 提到另一个已存在的概念 → `[[概念名]]`
- 提到一个尚未创建但重要的概念 → `[[新概念]]`（创建空链接，后续填充）
- 对比两个概念 → `[[A]] vs [[B]]`
- 引用系统化文档的某部分 → `[[文档名#章节]]`

### 5.2 链接关系标注

在「关联知识」部分标注关系类型：

```markdown
## 关联知识
- 前置依赖：[[Embedding 向量嵌入]]（RAG 的基础）
- 同类对比：[[关键词检索 BM25]] vs [[向量检索]]
- 上层应用：[[AI Agent 开发]]（RAG 是 Agent 的知识来源）
- 实现细节：[[VectorStore 向量存储接口]]
```

### 5.3 链接质量标准

- 每个原子笔记至少有 **2 个** 出向链接（指向其他笔记）
- 每个重要概念至少被 **3 个** 笔记引用（入向链接）
- 避免"孤儿笔记"（0 个入向链接也 0 个出向链接）
- 链接要精准，不要为了凑数添加无关链接

## 6. 标签规范

### 6.1 标签层级

```
领域标签：#前端 #后端 #数据库 #分布式 #云原生 #计算机基础 #AI
技术标签：#Vue3 #TypeScript #SpringAI #LangChain #RAG #AIGC
类型标签：#概念 #原理 #实战 #面试 #速查 #对比
状态标签：#草稿 #待完善 #已审核 #过时
```

### 6.2 标签使用规则

- 每个笔记 3-6 个标签
- 必须包含 1 个领域标签
- 技术标签用具体技术名，不用模糊词（如 #框架 → #Vue3）
- 状态标签可选，用于标记笔记成熟度
- 不创建只使用一次的标签

## 7. 原子化拆解操作指南（AI 执行）

### 7.1 拆解步骤

```
输入：一篇 Inbox 原始笔记

步骤1：概念提取
  - 识别笔记中的所有核心概念
  - 每个概念判断是否需要独立成笔记
  - 输出：概念列表

步骤2：粒度调整
  - 对每个概念判断粒度是否合适
  - 过粗的拆分，过细的合并
  - 输出：最终原子概念列表

步骤3：生成笔记
  - 对每个概念按模板生成原子笔记
  - 自动添加 front matter、关联链接、标签
  - 输出：原子笔记草稿集合

步骤4：关联建链
  - 扫描所有新笔记，识别概念间的关联
  - 为高关联度的概念对添加双向链接
  - 扫描全库，为新笔记添加入向链接（被已有笔记引用）
  - 输出：带完整链接的笔记

步骤5：质量自检
  - 对照「质量校验规则」逐条检查
  - 不通过的标记「需人工审核」
  - 输出：处理报告
```

### 7.2 拆解示例

**输入**：一篇关于 Spring AI RAG 的博客笔记

**输出原子笔记**：
1. `RAG 检索增强生成.md`（总览概念）
2. `文档切分策略.md`（TextSplitter）
3. `Embedding 向量嵌入.md`（向量化）
4. `VectorStore 向量存储接口.md`（存储）
5. `相似度检索 Top-K.md`（检索）
6. `QuestionAnswerAdvisor 检索增强器.md`（Spring AI 实现）

每篇笔记之间互相链接，形成 RAG 主题的知识网络。
