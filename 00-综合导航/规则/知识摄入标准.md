# 📥 知识摄入标准

> 本规则定义什么知识值得进入知识库、如何进入 Inbox、以及原始笔记的最低格式要求。AI 工具处理 Inbox 时必须遵守本标准。

---

## 1. 值得摄入的知识类型

| 类型 | 示例 | 优先级 |
|------|------|--------|
| **新概念** | 第一次接触的技术、算法、设计模式 | ⭐⭐⭐ 高 |
| **深入理解** | 对已知概念的新角度、底层原理、踩坑经验 | ⭐⭐⭐ 高 |
| **实战经验** | 项目中遇到的问题、解决方案、最佳实践 | ⭐⭐⭐ 高 |
| **结构化梳理** | 某领域的系统总结、对比分析、知识地图 | ⭐⭐ 中 |
| **灵感记录** | 突发想法、待研究课题、学习计划 | ⭐⭐ 中 |
| **资讯动态** | 技术新闻、版本更新、行业趋势 | ⭐ 低（定期清理） |

**不摄入**：纯情绪发泄、无信息量的转发、临时待办（用任务管理工具）、已完全掌握且无新角度的基础概念。

---

## 2. Inbox 命名规范

```
格式：YYYY-MM-DD-来源-简短主题.md

示例：
  2026-08-13-博客-SpringAI函数调用原理.md
  2026-08-13-会议-项目架构评审.md
  2026-08-13-书籍-设计模式之禅第3章.md
  2026-08-13-灵感-Agent多轮对话优化思路.md
```

**来源标签**：博客 / 论文 / 书籍 / 课程 / 会议 / 项目 / 灵感 / 视频 / 对话 / 其他

---

## 3. 原始笔记最低格式

存入 Inbox 的笔记必须包含以下内容（AI 处理时依赖这些元数据）：

```markdown
---
title: <原始笔记标题>
source: <来源，如 https://... 或 "项目实战">
type: <博客/论文/书籍/会议/灵感/...>
created: YYYY-MM-DD
status: 待处理
tags: [Inbox]
---

# <标题>

## 原始内容
<粘贴或记录的原始内容，保持原样，不用整理>

## 个人批注（可选）
> 你的即时想法、疑问、关联记忆

## 待提取概念（可选）
- [ ] 概念1
- [ ] 概念2
```

**关键要求**：
- `status: 待处理` 是必须字段，AI 靠它筛选待处理笔记
- 原始内容保持原样，不要提前整理（LLM 处理效果更好）
- 个人批注很重要，它区分了"别人的知识"和"你的理解"

## 4. 摄入渠道

### 4.1 手动摄入（主要方式）

1. **Obsidian 快速笔记**：Ctrl+N 新建，存入 Inbox，套用「每日笔记模板」
2. **网页剪藏**：浏览器插件（如 Obsidian Web Clipper）剪藏到 Inbox
3. **移动端**：Obsidian 移动端快速记录，同步到 Inbox
4. **语音转文字**：会议/灵感用录音转文字后存入 Inbox

### 4.2 半自动摄入

1. **RSS 订阅**：技术博客 RSS → 定期筛选 → 存入 Inbox
2. **GitHub Trending**：每周扫描 → 感兴趣的项目 → 存入 Inbox
3. **论文追踪**：arXiv / Papers with Code → 相关论文 → 存入 Inbox

### 4.3 AI 辅助摄入

向 AI 工具（Claude Code / Codex / 豆包）发送内容时，指令模板：

```
请将以下内容作为知识摄入存入 Inbox：
- 来源：<说明来源>
- 类型：<博客/论文/...>
- 内容：<粘贴内容>
- 我的批注：<可选>

按照「知识摄入标准」生成 Inbox 笔记。
```

---

## 5. Inbox 容量管理

| 指标 | 阈值 | 处理方式 |
|------|------|----------|
| 待处理笔记数 | > 20 | 优先处理，暂停新摄入 |
| 单条笔记存在时间 | > 7 天 | 标记「需人工审核」或直接归档 |
| 重复内容 | 发现重复 | 合并到一条，删除重复 |
| 低价值内容 | 判定无价值 | 移入 `Inbox/_归档/` 或删除 |

**目标**：Inbox 始终保持「日清周结」，不积压超过 20 条待处理笔记。

---

## 6. 摄入质量自检（3 问）

存入 Inbox 前，快速问自己：

1. **这条知识 3 个月后还有用吗？** → 没有则不摄入
2. **它和我已有的知识有什么不同？** → 完全重复则不摄入
3. **我能用一句话说清它的核心价值吗？** → 说不清则先想清楚再摄入
