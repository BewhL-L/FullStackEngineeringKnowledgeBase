## 一、大模型基础

### Q1: Transformer的核心结构？自注意力机制原理？

**考察点**：深度学习基础、模型架构

**答案**：
- **Transformer结构**：Encoder-Decoder架构，Encoder由多层（自注意力+前馈网络）组成，Decoder额外加交叉注意力
- **自注意力**：Q（查询）、K（键）、V（值）三个矩阵，计算Attention(Q,K,V)=softmax(QK^T/√d_k)V
- **多头注意力**：多组Q/K/V并行计算，捕捉不同子空间的关系
- **位置编码**：Transformer无顺序概念，通过位置编码注入位置信息（正弦编码/可学习编码/RoPE）
- **前馈网络**：两层全连接，中间激活函数（GELU）
- **LayerNorm+残差连接**：每子层后都有，稳定训练

### Q2: 大模型训练的三个阶段？

**答案**：
1. **预训练（PT）**：海量无标注数据，自监督学习（下一词预测），获得通用能力
2. **监督微调（SFT）**：高质量标注数据，学习人类指令格式和回答风格
3. **人类反馈强化学习（RLHF）**：
   - 奖励模型训练：人类标注偏好数据，训练Reward Model
   - PPO强化学习：用奖励模型指导LLM优化，对齐人类偏好
4. **DPO**（替代RLHF）：直接偏好优化，无需奖励模型，直接用偏好对训练

### Q3: 什么是Tokenization？常见方案？

**答案**：
- 将文本切分为Token的过程，是模型输入的基础
- **BPE**（Byte Pair Encoding）：迭代合并高频字节对，GPT/LLaMA使用
- **WordPiece**：基于似然度合并，BERT使用
- **SentencePiece**：无空格语言友好，支持子词
- **关键参数**：词表大小（通常32K-128K）、特殊Token（[BOS]/[EOS]/[PAD]/[UNK]）
- **影响**：词表太小→单Token信息少，序列长；太大→稀疏，参数多

### Q4: 模型量化的原理和方法？

**答案**：
- **目的**：降低显存占用、加速推理、降低成本
- **原理**：将高精度（FP16/BF16）权重映射到低精度（INT8/INT4）
- **方法**：
  - PTQ（训练后量化）：校准集统计范围，直接量化（GPTQ/AWQ）
  - QAT（量化感知训练）：训练中模拟量化误差，精度更高
  - GGUF：llama.cpp格式，支持CPU推理
- **精度影响**：INT8精度损失小，INT4有损失但显存减半
- **KV Cache量化**：推理时KV缓存也可量化，进一步省显存

## 二、RAG

### Q5: RAG的完整流程？各环节的优化点？

**考察点**：RAG架构、工程实践

**答案**：
```text
文档加载 → 文本分块 → 向量化(Embedding) → 存入向量库
                                              ↓
用户问题 → 问题向量化 → 向量检索 → 重排序 → 拼接Prompt → LLM生成 → 答案
```

**各环节优化**：
| 环节 | 优化方法 |
|------|---------|
| 文档加载 | 格式解析（PDF/Word/HTML）、OCR、表格提取 |
| 文本分块 | 固定大小/语义分块/递归分块/父子分块，重叠策略 |
| Embedding | 选择合适模型（bge/m3e/text-embedding-3）、维度选择 |
| 检索 | 混合检索（向量+关键词BM25）、多路召回、查询改写 |
| 重排序 | Cross-Encoder（bge-reranker）、LLM重排 |
| Prompt | 引用标注、指令优化、上下文压缩 |
| 生成 | 流式输出、引用溯源、拒答策略 |

### Q6: RAG效果不好如何排查？

**答案**：
1. **召回率低**：检查分块大小、Embedding模型、检索方式（加混合检索）
2. **召回不准**：加查询改写、HyDE（假设文档嵌入）、重排序
3. **生成幻觉**：加强Prompt约束、引用标注、加拒答策略
4. **上下文太长**：上下文压缩、选择最相关的Top-K
5. **评估体系**：建立RAG评估指标（召回率/答案相关性/忠实度），用RAGAS/TruLens

### Q7: 向量数据库选型？

| 数据库 | 特点 | 适用场景 |
|--------|------|---------|
| Chroma | 轻量、嵌入式、Python友好 | 原型开发、小规模 |
| PgVector | PostgreSQL扩展、SQL查询 | 已有PG、数据量中等 |
| Milvus | 分布式、高性能、云原生 | 大规模生产 |
| Qdrant | Rust实现、过滤强、高性能 | 生产环境、过滤多 |
| Weaviate | 模块化、向量化器内置 | 快速开发 |
| Elasticsearch | 全文+向量混合检索 | 已有ES、混合检索 |

## 三、Agent

### Q8: Agent的核心组件？ReAct原理？

**答案**：
- **核心组件**：
  1. 规划（Planning）：任务分解、推理（ReAct/Chain of Thought）
  2. 记忆（Memory）：短期记忆（对话历史）、长期记忆（向量库）
  3. 工具调用（Tool Use）：Function Calling、MCP协议
  4. 执行（Action）：调用工具获取结果
- **ReAct**：Reasoning+Acting交替
  ```text
  Thought: 我需要先查天气
  Action: weather_api(city="北京")
  Observation: 北京今天晴，25度
  Thought: 现在可以回答了
  Final Answer: 北京今天晴天，25度
  ```

### Q9: Function Calling的原理？

**答案**：
- 模型输出结构化的工具调用指令（JSON格式：工具名+参数）
- 训练时：用工具调用的示例微调，让模型学会输出特定格式
- 推理时：系统提示中定义工具schema，模型输出符合schema的JSON
- 应用层：解析模型输出，执行工具，将结果返回模型继续推理
- 关键：严格的JSON输出、参数校验、错误处理、多工具调用编排

### Q10: 多Agent协作模式？

| 模式 | 说明 | 适用 |
|------|------|------|
| 主从模式 | 一个Manager分配任务给Worker | 任务可分解 |
| 辩论模式 | 多个Agent辩论，最后综合 | 决策类任务 |
| 流水线模式 | Agent按顺序处理，前一个输出是后一个输入 | 流程化任务 |
| 群聊模式 | Agent自由对话，协调完成 | 开放式任务 |

## 四、Prompt工程

### Q11: 高质量Prompt的要素？

**答案**：
1. **角色设定**：明确AI扮演什么角色（"你是资深后端架构师"）
2. **任务描述**：清晰说明要做什么
3. **上下文**：提供相关背景信息
4. **输入格式**：明确输入数据的格式
5. **输出格式**：指定输出格式（JSON/Markdown/表格）
6. **约束条件**：字数、风格、禁止事项
7. **示例**：Few-shot示例（1-3个最佳）
8. **思考链**：要求"一步步思考"（CoT）

### Q12: Prompt优化技巧？

- **Few-shot**：给示例比纯指令效果好
- **CoT**：复杂推理任务要求"一步步思考"
- **结构化输出**：指定JSON schema，减少解析错误
- **分隔符**：用```或---分隔指令和输入
- **迭代优化**：测试→分析失败案例→调整Prompt
- **版本管理**：Prompt版本化，A/B测试效果

## 五、模型部署与推理

### Q13: vLLM的核心优化PagedAttention？

**答案**：
- **问题**：传统KV Cache管理低效，内存碎片严重，利用率低
- **PagedAttention**：借鉴操作系统虚拟内存分页
  - KV Cache分成固定大小的Block（如16个Token）
  - 逻辑连续，物理上可以不连续（Block Table映射）
  - 按需分配，共享前缀（Prefix Caching）
- **效果**：显存利用率从40%提升到90%+，吞吐量提升2-4倍
- **其他优化**：连续批处理（Continuous Batching）、投机解码

### Q14: 推理优化技术？

| 技术 | 原理 | 效果 |
|------|------|------|
| KV Cache | 缓存历史Key/Value，避免重复计算 | 解码阶段加速 |
| 连续批处理 | 请求动态加入/离开批次 | 提升吞吐量 |
| 投机解码 | 小模型草稿+大模型验证 | 加速2-3倍 |
| 量化 | INT8/INT4权重和KV | 省显存+加速 |
| PagedAttention | 分页管理KV Cache | 高显存利用率 |
| FlashAttention | IO感知的注意力计算 | 加速训练/推理 |
| TensorRT | 算子融合+精度校准 | GPU加速 |

### Q15: 模型服务化的关键设计？

- **OpenAI兼容API**：统一接口，降低接入成本
- **多模型路由**：按任务/成本/延迟路由到不同模型
- **流式输出**：SSE/WebSocket，首Token延迟低
- **限流降级**：Token限流、并发控制、降级策略
- **负载均衡**：多实例部署、请求分发
- **可观测性**：Token消耗、延迟、成功率监控
- **成本控制**：缓存、模型降级、批处理

## 六、AI工程化

### Q16: AI应用的可观测性？

- **Trace**：记录完整调用链（Prompt→模型→工具→输出）
- **指标**：Token消耗、延迟、成功率、成本
- **评估**：输出质量评估（人工/自动）
- **工具**：Langfuse、LangSmith、Helicone、自建
- **关键**：每个请求都有Trace ID，可回溯完整过程

### Q17: Prompt注入攻击与防护？

**答案**：
- **攻击类型**：
  - 直接注入：用户输入中包含恶意指令
  - 间接注入：外部数据（网页/文档）中包含恶意指令
- **防护措施**：
  1. 输入过滤：检测和移除可疑指令
  2. 指令分层：系统指令优先级高于用户输入
  3. 输出校验：检查输出是否符合预期
  4. 工具权限控制：最小权限原则
  5. 沙箱执行：工具调用在沙箱中执行
  6. 监控告警：异常行为检测

### Q18: AI网关的作用？

- **统一入口**：所有AI请求经过网关
- **多模型路由**：按策略路由到不同模型/供应商
- **限流熔断**：保护后端模型服务
- **成本控制**：Token统计、预算控制、缓存
- **安全防护**：API Key管理、输入过滤、审计
- **可观测**：统一日志、监控、Trace
- **协议转换**：统一OpenAI格式，适配不同模型

## 七、系统设计题

### Q19: 设计一个企业级RAG问答系统？

**要点**：
- **文档处理**：多格式解析、分块策略、增量更新
- **检索层**：向量库+ES混合检索、重排序、查询改写
- **生成层**：多模型路由、流式输出、引用溯源
- **管理后台**：文档管理、知识库管理、效果评估
- **非功能**：权限控制、审计日志、高可用、成本优化

### Q20: 设计一个AI Agent平台？

**要点**：
- **Agent编排**：可视化工作流、ReAct/Plan-and-Execute
- **工具市场**：工具注册、版本管理、权限控制
- **记忆系统**：短期对话记忆、长期知识库记忆
- **模型管理**：多模型接入、路由、降级
- **可观测**：完整Trace、评估、成本统计
- **安全**：沙箱执行、输入过滤、权限隔离
