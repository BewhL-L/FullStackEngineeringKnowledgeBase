# 技术简历模板与写作指南

> **文档说明**：技术简历写作指南，包含简历结构、内容优化、项目描述技巧、常见错误和完整模板。帮助开发者写出能通过ATS筛选、吸引面试官的专业简历。
>
> **适用人群**：求职中的开发者、应届生、跳槽工程师
>
> **核心原则**：量化成果、突出技术深度、匹配岗位需求、一页纸原则

---

## 一、简历核心原则

### 1.1 黄金法则

| 原则 | 说明 |
|------|------|
| **一页纸** | 3年以下经验一页，5年以上最多两页 |
| **量化成果** | 用数字说话：性能提升X%、用户量X万、节省X小时 |
| **STAR法则** | Situation情境→Task任务→Action行动→Result结果 |
| **岗位匹配** | 根据JD调整关键词，通过ATS筛选 |
| **技术深度** | 写清楚用了什么技术、解决了什么问题、效果如何 |
| **无废话** | 删除"负责日常开发"这类无信息量描述 |

### 1.2 ATS（自动筛选系统）要点

- 使用标准标题（工作经历、教育背景、技能）
- 避免图片、表格、特殊符号
- 关键词匹配JD中的技术栈
- 导出为PDF，文件名规范（姓名-岗位-年限.pdf）
- 字体用标准字体（宋体/微软雅黑/Arial）

## 二、简历结构

### 2.1 推荐结构

```text
1. 个人信息（姓名、电话、邮箱、求职意向、GitHub/博客）
2. 个人简介（2-3句话，突出核心优势）
3. 专业技能（分类列出，标注熟练度）
4. 工作经历（倒序，公司-职位-时间-项目）
5. 项目经历（2-4个核心项目，STAR描述）
6. 教育背景（学校-专业-学历-时间）
7. 加分项（开源贡献、技术博客、证书、竞赛）
```

### 2.2 各部分要点

**个人信息**：
- 必写：姓名、电话、邮箱、求职岗位
- 选写：GitHub链接（有优质项目）、技术博客、所在地
- 不写：年龄、性别、婚育状况（除非岗位要求）、照片

**个人简介**（2-3句）：
- 第一句：X年经验+核心技术栈+岗位
- 第二句：核心优势/亮点（如"主导过日活百万级系统设计"）
- 第三句：求职意向/职业目标

**专业技能**：
- 分类：编程语言、框架、数据库、中间件、运维工具
- 标注熟练度：精通/熟练/了解（慎用"精通"）
- 与JD匹配，JD要求的关键词必须出现

## 三、项目描述模板

### 3.1 STAR法则

```text
【项目名称】 | 项目时间 | 担任角色

项目背景：
  一句话说明项目是什么、解决什么问题、规模多大。

技术栈：
  Java / SpringBoot / MySQL / Redis / Kafka / Docker

个人职责：
  • 负责XXX模块的设计与开发（具体做了什么）
  • 优化XXX，将响应时间从500ms降至80ms（量化成果）
  • 设计XXX方案，支持日增100万数据（技术深度）

项目成果：
  • 系统上线后稳定运行，日活用户达XX万
  • 通过缓存优化，数据库QPS降低60%
  • 代码评审中被评为团队最佳实践
```

### 3.2 动词库

| 类别 | 动词 |
|------|------|
| 设计 | 设计、架构、规划、制定 |
| 开发 | 开发、实现、构建、重构、封装 |
| 优化 | 优化、提升、降低、减少、加速 |
| 解决 | 解决、排查、修复、攻克 |
| 带领 | 主导、负责、带领、协调 |
| 成果 | 上线、交付、达成、获得 |

### 3.3 量化表达模板

```text
❌ 负责系统性能优化
✅ 通过引入Redis缓存和SQL优化，将接口平均响应时间从800ms降至120ms，QPS提升5倍

❌ 开发了用户模块
✅ 基于SpringBoot+MyBatis-Plus开发用户中心，支持500万用户，日均登录请求200万次

❌ 参与微服务改造
✅ 主导单体应用拆分为8个微服务，使用SpringCloud Alibaba，部署到K8s，发布频率从周级提升到日级
```

## 五、常见错误

| 错误 | 问题 | 修改建议 |
|------|------|---------|
| 写"负责日常开发" | 无信息量 | 具体写做了什么模块 |
| 罗列技术栈不写用法 | 不知道深度 | 写用技术解决了什么问题 |
| 项目描述无量化 | 无法评估价值 | 加数字：性能/用户量/效率 |
| 简历超过2页 | HR没时间看 | 精简到1-2页 |
| 技能写"精通"太多 | 面试容易被问倒 | 精通≤2项，其余熟练/了解 |
| 错别字/格式混乱 | 不专业 | 仔细检查，PDF导出 |
| 虚假项目 | 面试穿帮 | 真实项目，能讲清楚细节 |
| 不写GitHub | 无法验证能力 | 有优质项目一定写 |
| 写无关信息 | 占空间 | 只写与岗位相关的 |

## 六、不同经验阶段重点

### 应届生（0经验）
- 突出：教育背景、GPA、竞赛、实习、项目（课程项目/毕设）
- 技能：基础扎实（数据结构/算法/计算机基础）
- 项目：写清楚技术选型和个人贡献

```text
### 初级（1-3年）
```
- 突出：项目经验、技术广度、学习能力
- 技能：主流框架使用、基础扎实
- 项目：参与的模块、具体实现

```text
### 中级（3-5年）
```
- 突出：独立负责模块、技术深度、性能优化
- 技能：架构设计、问题排查、技术选型
- 项目：主导的模块、量化成果

### 高级（5年+）
- 突出：架构设计、团队带领、技术决策、业务价值
- 技能：系统设计、分布式、团队管理
- 项目：从0到1的系统、架构演进、团队成果

---

## 七、面试准备关联

- 简历中每个项目都要能讲清楚：背景、方案、难点、成果
- 技术栈中每个"熟练"以上的都要能深入回答
- 准备3个最有代表性的项目，能讲5-10分钟
- 量化数据要真实，面试会追问细节
