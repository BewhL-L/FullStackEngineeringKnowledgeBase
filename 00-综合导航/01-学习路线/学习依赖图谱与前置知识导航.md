# 学习依赖图谱与前置知识导航

> **文档说明**：梳理各知识点之间的前置依赖关系，帮助学习者明确"学A之前必须先学B"，避免因基础不足导致学习卡壳。按学习阶段组织依赖链，每条依赖链标注难度递进。
>
> **使用方法**：学习某个知识点前，先检查其前置知识是否已掌握。如果前置知识标为🟩已掌握，可以开始学习；如果是🟥未开始，先补前置。

## 五、学习顺序检查清单

学习任何新知识点前，回答以下问题：

### 5.1 前置知识检查

- [ ] 该知识点的必须前置是否已掌握（🟩状态）？
- [ ] 如果前置未掌握，是否安排了先补前置的时间？
- [ ] 是否有足够的基础概念理解该知识点的术语？
- [ ] 是否有对应的实操环境可以验证？

### 5.2 学习准备检查

- [ ] 已阅读该笔记的「概述」和「底层原理」
- [ ] 已查看「关联笔记」中的前置知识
- [ ] 已准备好开发环境
- [ ] 已规划好学习时间（建议1-2小时/次）

### 5.3 学习完成检查

- [ ] 能独立复现实操示例中的代码
- [ ] 能不看笔记解释核心原理
- [ ] 能回答「常见问题与排查」中的问题
- [ ] 已更新笔记状态为🟨复习中或🟩已掌握
- [ ] 已在学习日志中记录

## 六、常见学习顺序错误

| 错误顺序 | 问题 | 正确顺序 |
|---------|------|---------|
| 直接学SpringCloud | 不懂SpringBoot基础，无法理解微服务 | SpringBoot → 微服务概念 → SpringCloud |
| 直接学RAG | 不懂Embedding和向量检索 | AI API → Embedding → 向量库 → RAG |
| 直接学K8s | 不懂Docker和Linux | Linux → Docker → K8s |
| 直接学Vue3源码 | 不懂JavaScript和Vue3使用 | JS → Vue3使用 → 响应式原理 → 源码 |
| 直接学模型微调 | 不懂Transformer和训练基础 | Transformer → 推理部署 → SFT → LoRA |
| 直接学分布式事务 | 不懂数据库事务和微服务 | 数据库事务 → 微服务 → 分布式事务 |

## 七、按阶段的依赖检查点

### 入门期（0-4月）检查点
- [ ] 计算机基础：命令行、Git、网络、HTTP
- [ ] 编程语言：语法、OOP、集合、异常
- [ ] 前端：HTML/CSS/JS基础
- [ ] 数据库：SQL、基本概念
- [ ] AI：概念、API调用

### 进阶期（4-9月）检查点
- [ ] 框架：Vue3 + SpringBoot/FastAPI 熟练使用
- [ ] 缓存：Redis数据结构和常用场景
- [ ] 消息队列：基本使用
- [ ] AI：Prompt工程 + RAG全流程
- [ ] 工程化：Docker部署、CI/CD基础

### 高级期（9-15月）检查点
- [ ] 微服务：注册中心、网关、服务调用
- [ ] 分布式：事务、锁、一致性
- [ ] AI：Agent框架、模型部署、AI网关
- [ ] 云原生：K8s、监控、日志
- [ ] 架构：高可用、高并发设计

### 专家期（15-24月）检查点
- [ ] 源码级理解：至少一个框架
- [ ] 模型训练：SFT/LoRA/DPO
- [ ] 架构设计：复杂系统设计能力
- [ ] 技术领导力：团队管理、技术选型
- [ ] 技术输出：博客、开源、分享
