## 一、质量分级体系

### 1.1 三级质量分级

| 级别 | 标记 | Frontmatter | 含义 | 学习要求 | 时间占比 |
|------|------|------------|------|---------|---------|
| ⭐ **核心必读** | `priority: 核心` | 该领域最关键的知识，面试/工作必考，是知识体系的骨架 | 必须精读 + 实操 + 通过自检 + 能讲给别人听 | 60% |
| 📌 **重要** | `priority: 重要` | 常用知识，需要掌握但不必深入源码 | 通读 + 理解 + 会用 + 知道原理 | 30% |
| 📖 **扩展** | `priority: 扩展` | 进阶/冷门/特定场景知识，拓宽视野 | 了解即可，需要时再深入 | 10% |

### 1.2 分级判断标准

**⭐ 核心必读的判断标准**（满足 3 条以上）：
1. 该技术领域的**基础和核心**，不掌握就无法继续学习后续内容
2. **面试高频考点**，80% 的技术面试会涉及
3. **工作中每天都在用**，是日常开发的基础工具
4. 理解它能**举一反三**，带动相关知识的理解
5. 是知识体系的**关键节点**，连接多个知识点

**📌 重要的判断标准**（满足 2 条以上）：
1. 工作中**经常使用**，但不是每天
2. 面试中**可能问到**，但不是必考题
3. 理解它能**提升开发效率**或代码质量
4. 是某个核心技术的**延伸或配套**知识

**📖 扩展的判断标准**：
1. 特定场景才需要（如特定行业、特定规模）
2. 比较冷门或新兴，尚未普及
3. 深入源码或底层原理，非架构师不需要
4. 工具/插件类，会用即可，不需要深入

### 6.2 每周学习计划模板

```text
每周学习计划（建议 10-15 小时/周）：
├── 精读核心必读（6-8 小时）
│   ├── 阅读笔记（3-4 小时）
│   ├── 动手实操（2-3 小时）
│   └── 整理笔记/输出（1 小时）
├── 项目实战（3-5 小时）
│   └── 将所学应用到个人项目
├── 复习和回顾（1-2 小时）
│   └── 间隔重复复习已学内容
└── 扩展阅读（可选，1 小时）
    └── 浏览重要/扩展笔记
```

### 6.3 学习方法建议

| 方法 | 说明 | 效果 |
|------|------|------|
| **费曼学习法** | 学完后用自己的话讲给别人听（或写出来） | 检验是否真正理解 |
| **间隔重复** | 1天/3天/7天/14天/30天 复习 | 对抗遗忘曲线 |
| **项目驱动** | 每学一个技术就用在项目中 | 从「知道」到「会用」 |
| **主题阅读** | 同一主题读多篇笔记，交叉验证 | 建立完整知识网络 |
| **输出倒逼输入** | 写博客/做分享/回答问题 | 深化理解，发现知识盲区 |
| **代码实操** | 每个核心概念都手写代码验证 | 编程是实践学科，不动手等于没学 |

### 7.2 Dataview 自动筛选

在 Obsidian 中使用 Dataview 插件自动筛选核心必读笔记：

````markdown
## 所有核心必读笔记

```
TABLE difficulty AS "难度", category AS "分类", file.mtime AS "更新时间"
FROM "全栈工程MarkDown文档"
WHERE priority = "核心"
SORT difficulty ASC, file.mtime DESC
```

## 按阶段筛选核心必读

```
TABLE difficulty AS "难度", priority AS "级别"
FROM "02-后端开发"
WHERE priority = "核心" AND contains(file.tags, "微服务")
SORT file.name ASC
```

## 本周学习清单（未完成的核心必读）

```
TABLE difficulty AS "难度", category AS "分类"
FROM "全栈工程MarkDown文档"
WHERE priority = "核心" AND !contains(file.tags, "已掌握")
SORT difficulty ASC
LIMIT 10
```
````
