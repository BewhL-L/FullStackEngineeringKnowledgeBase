# 🌱 自增长知识库架构说明

> 基于 Andrej Karpathy「LLM as Wiki Maintainer」理念设计，让 LLM 成为知识库的一等公民维护者，实现知识的自动摄入、原子化拆解、智能关联与持续迭代生长。

---

## 1. 核心理念：Karpathy LLM Wiki

### 1.1 传统知识库 vs LLM 自增长知识库

| 维度 | 传统知识库 | LLM 自增长知识库 |
|------|-----------|-----------------|
| **维护者** | 人手动整理、分类、链接 | LLM 自动维护，人在回路确认 |
| **知识单元** | 大而全的长文档 | 原子化笔记（一概念一笔记） |
| **关联方式** | 手动添加双向链接 | LLM 自动发现概念关联并建链 |
| **增长方式** | 线性增长，写完即静态 | 持续重构，随使用演化生长 |
| **检索方式** | 文件夹 + 搜索 | 图谱导航 + 语义检索 + MOC 聚合 |
| **质量保障** | 靠人自觉 | 规则文件 + LLM 校验 + 定期审计 |

### 1.2 四条核心原则

```
┌─────────────────────────────────────────────────────────┐
│  原则一：原子化（Atomicity）                              │
│  每个笔记只讲一个概念，可独立理解、可独立引用、可独立演化  │
├─────────────────────────────────────────────────────────┤
│  原则二：收件箱驱动（Inbox-Driven）                       │
│  所有原始输入先进入 Inbox，由 LLM 处理后再归档            │
├─────────────────────────────────────────────────────────┤
│  原则三：自动关联（Auto-Linking）                         │
│  LLM 扫描新笔记，自动发现与已有知识的关联并建立双向链接    │
├─────────────────────────────────────────────────────────┤
│  原则四：持续重构（Continuous Refactoring）               │
│  定期合并重复、拆分过大、更新索引，知识库越用越好          │
└─────────────────────────────────────────────────────────┘
```

### 2.2 三层流转模型

```
        摄入层                    处理层                    归档层
     ┌──────────┐            ┌──────────────┐          ┌──────────────┐
     │  Inbox   │───LLM处理──▶│  原子化拆解   │──归档──▶│  分类目录     │
     │ 原始输入  │            │  打标签+建链  │          │  01~09       │
     └──────────┘            └──────────────┘          └──────────────┘
          ▲                        │                        │
          │                        ▼                        ▼
     人工输入                 质量校验规则              MOC 自动更新
     (阅读/会议/灵感)          (规则文件约束)           (索引页维护)
```

## 3. 自动化流转机制

### 3.1 知识摄入流水线（5 步）

```
步骤1：原始摄入
  来源：阅读笔记 / 网页剪藏 / 会议纪要 / 灵感记录 / 代码片段
  动作：存入 Inbox/，文件名格式 YYYY-MM-DD-来源-主题.md
  状态：标记为「待处理」

步骤2：LLM 原子化拆解
  输入：Inbox 中的原始笔记
  动作：
    - 提取核心概念（每个概念一个原子笔记）
    - 为每个概念生成标题、摘要、正文
    - 自动添加 front matter（tags/created/source）
    - 识别概念间的关联，添加双向链接
  输出：多个原子化笔记草稿（存 Inbox/_草稿/）

步骤3：质量校验
  规则：对照「质量校验规则.md」自动检查
    - 是否符合原子化规范（一概念一笔记）
    - 标签是否符合命名规范
    - 是否有足够的双向链接（至少2个）
    - 是否标注了来源
  不通过：退回重新处理，或标记为「需人工审核」

步骤4：归档入库
  动作：
    - 根据标签和内容自动归类到 01~09 对应目录
    - 更新对应分类的 MOC（添加新笔记链接）
    - 在原 Inbox 笔记中添加「已归档」标记
  状态：Inbox 笔记标记为「已处理」，原子笔记进入归档区

步骤5：关联增强（异步）
  动作：
    - 扫描新笔记与全库的语义关联
    - 为高关联度的笔记对添加双向链接
    - 检查是否有重复概念，标记待合并
    - 更新关系图谱（自动，Obsidian 实时渲染）
```

### 3.2 持续重构周期

| 周期 | 任务 | 执行者 | 产出 |
|------|------|--------|------|
| **每日** | 处理当日 Inbox | LLM + 人工确认 | 原子化笔记入库 |
| **每周** | 周度重构：合并重复、拆分过大笔记、补全链接 | LLM 提议 + 人工确认 | 重构报告 + 更新后的笔记 |
| **每月** | MOC 审计：检查索引完整性、更新学习路径 | LLM + 人工 | 更新后的 MOC + 知识缺口报告 |
| **每季度** | 体系重构：调整分类结构、淘汰过时知识 | 人工主导 + LLM 辅助 | 新目录结构 + 迁移记录 |

### 3.3 LLM 维护者的工作边界

```
LLM 自动执行（无需确认）：
  ✅ 提取概念、生成摘要、打标签
  ✅ 发现关联、添加双向链接
  ✅ 格式规范化（front matter、标题层级）
  ✅ 质量校验（对照规则文件）
  ✅ MOC 索引更新（添加新链接）

LLM 提议 + 人工确认：
  ⚠️ 合并重复笔记
  ⚠️ 拆分过大笔记
  ⚠️ 修改已有笔记的核心内容
  ⚠️ 调整分类目录归属
  ⚠️ 删除过时知识

人工主导（LLM 不参与）：
  🚫 最终知识正确性判断
  🚫 个人经验和观点的写入
  🚫 知识库整体架构的重大调整
```

## 4. 与现有知识库的兼容方案

### 4.1 存量文档的定位

现有 60 份知识文档属于**「系统化梳理文档」**，不是原子化笔记。它们的价值在于：
- 作为领域的**全景地图**和**速查手册**
- 作为原子化笔记的**上层聚合**和**索引入口**
- 作为 LLM 拆解新知识时的**参考上下文**

**不做的事**：不强行把现有长文档拆成原子笔记（成本高、收益低）

**要做的事**：
1. 为现有文档补充 `source`、`related` 等元数据
2. 在现有文档中添加指向关键概念的双向链接
3. 新摄入的知识按原子化规范处理，逐步与现有文档形成互补
4. 长期：从现有文档中「生长」出原子化概念卡片（按需提取，不批量拆）

### 4.2 双轨制知识体系

```
┌──────────────────────────────────────────────────────┐
│  轨道A：系统化文档（现有 60 份）                       │
│  特点：大而全、结构化、面试导向、速查手册              │
│  增长：低频更新，主要靠人工补充和修订                  │
│  用途：系统学习、面试复习、快速查阅某领域全貌          │
├──────────────────────────────────────────────────────┤
│  轨道B：原子化笔记（自增长，从 Inbox 生长）            │
│  特点：一概念一笔记、自动关联、持续演化、随用随长      │
│  增长：高频增长，LLM 自动处理 Inbox                    │
│  用途：深度理解、概念关联、知识图谱、灵感沉淀          │
├──────────────────────────────────────────────────────┤
│  连接层：MOC + 双向链接                                │
│  系统化文档中引用原子笔记，原子笔记中链接系统化文档     │
│  两者通过 MOC 和关系图谱形成统一的知识网络             │
└──────────────────────────────────────────────────────┘
```

## 5. 快速开始

### 5.1 启用自增长的 3 个动作

1. **配置规则文件**：阅读 `00-综合导航/规则/` 下的 4 份规则，根据个人习惯调整
2. **配置 AI 工具**：按照 `00-综合导航/规则/AI工具对接指南.md` 配置 Claude Code / Codex / 豆包
3. **开始使用 Inbox**：任何新知识先存入 `Inbox/`，不要直接归档

### 5.2 日常使用流程

```
1. 学到新知识 → 存入 Inbox/2026-08-13-来源-主题.md
2. （可选）当天或周末让 LLM 处理 Inbox
3. LLM 生成原子化笔记草稿 → 人工快速审核
4. 确认后自动归档到对应分类 + 更新 MOC
5. 定期（每周）运行重构工作流，保持知识库健康
```

## 📝 精简总结

- Karpathy LLM Wiki 核心理念：LLM 是知识库的一等维护者，不是辅助工具
- 四条原则：原子化、收件箱驱动、自动关联、持续重构
- 三层架构：Inbox（摄入）→ LLM处理（原子化+校验）→ 分类目录（归档）+ MOC（索引）
- 五步流水线：原始摄入 → 原子化拆解 → 质量校验 → 归档入库 → 关联增强
- 双轨制兼容：现有系统化文档（速查手册）+ 新增原子化笔记（概念网络），通过 MOC 和双向链接统一
- 人的角色：知识正确性的最终判断者，LLM 负责格式、关联、索引等机械性工作
- 关键文件：规则/（4份治理规则）、工作流/（3份流程定义）、模板/（3份笔记模板）
