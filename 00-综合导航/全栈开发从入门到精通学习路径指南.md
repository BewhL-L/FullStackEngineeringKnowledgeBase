## 1. 计算机基础与开发环境

### 1.1 操作系统与命令行基础

> 🔍 **知识点深度解析**
>
> **作用**：操作系统是所有程序运行的载体，开发者必须理解进程、线程、文件系统、内存管理等基本概念，并熟练使用命令行完成文件操作、进程管理、环境配置等日常工作。Linux 是服务器主流操作系统，掌握 Linux 命令是部署和排查问题的基础。
>
> **原理**：操作系统通过内核管理硬件资源（CPU、内存、磁盘、网络），向上提供系统调用接口。进程是资源分配的最小单位，线程是 CPU 调度的最小单位。文件系统通过目录树组织文件，权限模型（读/写/执行）控制访问。命令行（Shell）是用户与内核交互的文本接口，通过解析命令调用对应程序。
>
> **用法要点**：① Windows 用 PowerShell，Linux/macOS 用 Bash/Zsh，核心命令通用；② 必学命令：cd/ls/pwd/mkdir/rm/cp/mv（文件操作）、cat/less/tail/grep（查看搜索）、ps/kill/top（进程管理）、chmod/chown（权限）、ssh/scp（远程）；③ 环境变量 PATH 决定命令查找路径，配置 JAVA_HOME/NODE_HOME 是开发环境基础；④ 学会看报错信息，命令行报错通常包含原因和解决方向；⑤ 推荐安装 Windows Terminal + WSL2（Windows 下运行 Linux），统一开发环境。

### 1.2 计算机网络基础（HTTP/TCP）

> 🔍 **知识点深度解析**
>
> **作用**：网络是前后端通信的基础，全栈开发者必须理解 HTTP 协议、TCP/IP 模型、常见状态码、请求响应结构，才能正确设计 API、排查跨域/接口报错等问题。
>
> **原理**：TCP/IP 四层模型（应用层→传输层→网络层→链路层），HTTP 工作在应用层，基于 TCP 传输层的可靠连接。TCP 三次握手建立连接（SYN→SYN+ACK→ACK），四次挥手断开连接。HTTP 请求由请求行（方法+URL+版本）、请求头（Header）、请求体（Body）组成；响应由状态行（状态码）、响应头、响应体组成。HTTPS 在 HTTP 与 TCP 之间加 TLS 层，通过非对称加密协商密钥、对称加密传输数据，保证机密性和完整性。
>
> **用法要点**：① 必记 HTTP 方法：GET（查）、POST（增）、PUT（改）、DELETE（删）、PATCH（部分改）；② 必记状态码：200成功、301永久重定向、302临时重定向、400参数错误、401未认证、403无权限、404不存在、500服务器错误、502网关错误、504超时；③ 常见请求头：Content-Type（application/json、multipart/form-data）、Authorization（Bearer Token）、Cookie；④ 跨域（CORS）由浏览器同源策略引起，后端配置 Access-Control-Allow-Origin 解决；⑤ 用 Chrome DevTools Network 面板抓包分析请求，是排查接口问题的核心技能；⑥ TCP 三次握手/四次挥手是面试高频考点，理解为什么需要三次（防止已失效连接请求到达服务端）、为什么四次（TCP 全双工，双方各自关闭）。

### 1.3 Git 版本控制

> 🔍 **知识点深度解析**
>
> **作用**：Git 是现代开发的标配版本控制工具，用于管理代码历史、团队协作、分支管理、代码回滚。不会 Git 无法参与任何团队项目。
>
> **原理**：Git 是分布式版本控制系统，每个开发者本地都有完整仓库副本。核心概念：工作区（Working Directory）→暂存区（Staging Area）→本地仓库（Local Repository）→远程仓库（Remote）。Git 通过 SHA-1 哈希标识每个提交（commit），形成有向无环图（DAG）的提交历史。分支本质是指向某个 commit 的可变指针，创建分支成本极低。
>
> **用法要点**：① 必学命令：git init/clone（初始化/克隆）、git add（暂存）、git commit（提交，-m 写信息）、git push/pull（推送/拉取）、git status/log（查看状态/历史）、git branch/checkout/switch（分支管理）、git merge/rebase（合并）、git reset/revert（回滚）；② commit message 规范：类型(scope): 描述，如 feat(user): 添加登录接口；③ 分支策略：main（生产）、develop（开发）、feature/xxx（功能）、hotfix/xxx（紧急修复）；④ .gitignore 忽略 node_modules、target、.env 等不需提交的文件；⑤ 解决冲突：打开冲突文件，手动选择保留内容，再 add + commit；⑥ 新手推荐先用 GUI 工具（SourceTree、GitKraken、IDE 内置 Git）熟悉流程，再过渡到命令行。

### 1.4 开发环境搭建

> 🔍 **知识点深度解析**
>
> **作用**：统一、稳定的开发环境是高效开发的前提。包括 JDK、Node.js、IDE、数据库、构建工具等的安装与配置。
>
> **原理**：JDK（Java Development Kit）包含 JRE（运行环境）+ 开发工具（javac 编译器、jar 打包等），JAVA_HOME 指向 JDK 安装目录，PATH 加入 bin 目录使命令全局可用。Node.js 是 JavaScript 运行时，npm/pnpm 是包管理器。IDE（集成开发环境）提供代码补全、调试、重构、版本控制等一体化能力。
>
> **用法要点**：① JDK 选 LTS 版本（Java 17 或 21），用 Oracle JDK 或 OpenJDK（Temurin/Adoptium）；② Node.js 选 LTS 版本，包管理器推荐 pnpm（速度快、节省磁盘）；③ 后端 IDE 用 IntelliJ IDEA（Community 免费版够用），前端用 VS Code（轻量、插件丰富）或 WebStorm；④ 数据库：MySQL 8.0 + Navicat/DBeaver（可视化工具），Redis 用 Windows 版或 Docker 运行；⑤ 环境变量配置后用 java -version、node -v、npm -v 验证；⑥ 推荐用 Docker 运行 MySQL/Redis 等服务，避免本地安装污染环境，且便于切换版本。

## 2. 前端基础：HTML/CSS/JavaScript

### 2.1 HTML5 语义化与结构

> 🔍 **知识点深度解析**
>
> **作用**：HTML（超文本标记语言）是网页的骨架，定义页面结构和内容。HTML5 引入语义化标签，让页面结构更清晰，利于 SEO 和无障碍访问。
>
> **原理**：HTML 由元素（Element）组成，元素通过标签（Tag）标记，如 `<p>段落</p>`。浏览器解析 HTML 构建 DOM 树（文档对象模型），每个元素是 DOM 树的一个节点。语义化标签（header/nav/main/article/section/aside/footer）用标签名表达内容含义，而非仅靠 div+class。
>
> **用法要点**：① 必学标签：结构（html/head/body/header/nav/main/section/article/aside/footer）、文本（h1-h6/p/span/strong/em）、列表（ul/ol/li/dl/dt/dd）、链接（a，href/target）、图片（img，src/alt/width）、表格（table/thead/tbody/tr/th/td）、表单（form/input/select/textarea/button/label）；② 语义化：header 页头、nav 导航、main 主内容、article 独立文章、section 章节、aside 侧边栏、footer 页脚；③ 表单 input type：text/password/email/number/date/checkbox/radio/file，配合 label 提升可用性；④ 块级元素（div/p/h1/ul）独占一行，行内元素（span/a/strong）不换行；⑤ HTML5 新特性：video/audio 媒体、canvas 绘图、localStorage/sessionStorage 本地存储、drag 拖放、geolocation 地理定位；⑥ 用 Emmet 缩写快速写 HTML（如 ul>li*3>a）。

### 2.2 CSS3 样式与布局

> 🔍 **知识点深度解析**
>
> **作用**：CSS（层叠样式表）控制网页的视觉表现，包括颜色、字体、间距、布局、动画。掌握 CSS 是写出美观页面的基础，Flexbox 和 Grid 是现代布局的核心。
>
> **原理**：CSS 通过选择器选中 HTML 元素，应用样式规则（属性:值）。浏览器根据 CSS 构建 CSSOM 树，与 DOM 树合并生成渲染树，然后布局（Layout）、绘制（Paint）、合成（Composite）显示页面。盒模型（Box Model）：内容（content）+内边距（padding）+边框（border）+外边距（margin），box-sizing: border-box 让 width 包含 padding 和 border（推荐全局设置）。
>
> **用法要点**：① 选择器：元素、类（.class）、ID（#id）、后代（div p）、子元素（div>p）、伪类（:hover/:focus/:nth-child）、伪元素（::before/::after）；② 布局核心：Flexbox（display:flex，justify-content 主轴对齐，align-items 交叉轴对齐，flex:1 占满剩余空间）——一维布局首选；Grid（display:grid，grid-template-columns/rows，gap）——二维布局首选；③ 定位：static（默认）、relative（相对自身）、absolute（相对最近定位祖先）、fixed（相对视口）、sticky（滚动吸附）；④ 响应式：媒体查询 @media (max-width:768px)、百分比、vw/vh、rem（相对根字体）；⑤ 动画：transition（过渡）、@keyframes + animation（关键帧动画）、transform（平移/旋转/缩放）；⑥ 优先级：!important > 行内样式 > ID > 类/伪类 > 元素，同优先级后写的覆盖先写的；⑦ 推荐学一个 CSS 预处理器（Sass/SCSS）：变量、嵌套、混合（mixin）、函数，提升编写效率。

### 2.3 JavaScript 核心（ES6+）

> 🔍 **知识点深度解析**
>
> **作用**：JavaScript 是前端唯一的编程语言（浏览器原生支持），负责页面交互逻辑、数据处理、DOM 操作、异步请求。ES6（ES2015）及后续版本引入大量新特性，是现代 JS 开发的基础。
>
> **原理**：JavaScript 是单线程、动态类型、解释型语言，基于事件循环（Event Loop）实现异步。JS 引擎（V8）执行流程：解析代码→生成 AST→编译为字节码/机器码→执行。执行上下文（Execution Context）包含变量环境、词法环境、this 绑定。作用域链决定变量查找顺序，闭包让函数记住并访问其词法作用域，即使函数在当前作用域之外执行。
>
> **用法要点**：① 变量：let（块级作用域）、const（常量，引用不可变），不要用 var（函数作用域、变量提升）；② 数据类型：基本类型（string/number/boolean/null/undefined/symbol/bigint）+ 引用类型（object/array/function），typeof 检测基本类型，Array.isArray 检测数组；③ 函数：箭头函数（()=>{}，无自己的 this，继承外层 this）、默认参数、剩余参数（...args）、解构赋值（const {a,b} = obj / const [x,y] = arr）；④ 数组方法：map（映射）、filter（过滤）、reduce（归约）、forEach（遍历）、find（查找）、some/every（判断）、sort（排序）——这些是函数式编程核心，必须熟练；⑤ 异步：回调函数→Promise（then/catch/finally）→async/await（语法糖，同步写法写异步），async 函数返回 Promise，await 等待 Promise resolve；⑥ DOM 操作：document.getElementById/querySelector 获取元素，addEventListener 绑定事件，innerHTML/textContent 修改内容，style/classList 修改样式；⑦ 事件循环：同步代码→微任务（Promise.then、queueMicrotask）→宏任务（setTimeout、setInterval、I/O），理解执行顺序是排查异步问题的基础；⑧ 模块化：ES Module（import/export）是标准，CommonJS（require/module.exports）用于 Node.js。

### 2.4 TypeScript 基础

> 🔍 **知识点深度解析**
>
> **作用**：TypeScript 是 JavaScript 的超集，添加了静态类型系统，在编译时捕获类型错误，提升代码可维护性和重构安全性。Vue3、React、Node.js 现代项目普遍使用 TS。
>
> **原理**：TypeScript 编译器（tsc）将 TS 代码编译为 JS 代码，类型信息在编译后擦除（不影响运行时）。类型检查发生在编译阶段，通过类型推导（Type Inference）自动推断变量类型，通过类型注解（Type Annotation）显式声明类型。接口（interface）和类型别名（type）定义对象结构，泛型（Generics）让类型可参数化，提升复用性。
>
> **用法要点**：① 基本类型：string、number、boolean、array（number[] 或 Array<number>）、tuple（[string, number]）、enum、any（不推荐，关闭类型检查）、unknown（安全的 any，需类型收窄）、void、never、null/undefined；② 接口 interface：定义对象形状，支持 extends 继承、可选属性（?）、只读属性（readonly）；③ 类型别名 type：定义联合类型（A | B）、交叉类型（A & B）、条件类型，type 比 interface 更灵活，interface 更适合定义对象且支持声明合并；④ 泛型：function identity<T>(arg: T): T，数组 Array<T>、Promise<T> 都是泛型；⑤ 类型收窄：typeof、instanceof、in、类型谓词（is）、联合类型判别（discriminated union）；⑥ 配置 tsconfig.json：target（编译目标 ES 版本）、strict（严格模式，推荐开启）、module（模块系统）、outDir（输出目录）；⑦ 在 Vue3 中用 <script setup lang="ts">，defineProps<Props>()、defineEmits<Emits>() 类型化组件通信。

## 3. 后端基础：Java 语言核心

### 3.1 Java 基础语法与面向对象

> 🔍 **知识点深度解析**
>
> **作用**：Java 是全栈后端的主流语言，语法严谨、生态成熟、跨平台。掌握 Java 基础语法和面向对象思想是学习 Spring 等框架的前提。
>
> **原理**：Java 源代码（.java）经 javac 编译为字节码（.class），由 JVM（Java 虚拟机）解释执行，实现「一次编写，到处运行」。JVM 包含类加载器、运行时数据区、执行引擎。面向对象三大特性：封装（隐藏内部细节，暴露接口）、继承（子类复用父类属性方法，extends）、多态（同一接口不同实现，方法重写+向上转型）。
>
> **用法要点**：① 数据类型：8 种基本类型（byte/short/int/long/float/double/char/boolean）+ 引用类型（类/接口/数组），基本类型有默认值，引用类型默认 null；② 运算符：算术（+ - * / %）、赋值（= += -=）、比较（== != > <）、逻辑（&& || !，短路）、位运算（& | ^ ~ << >> >>>）、三元（条件?值1:值2）；③ 流程控制：if-else、switch（Java 14+ 支持箭头表达式和 yield）、for/while/do-while、break/continue/return；④ 面向对象：类定义（class）、对象创建（new）、构造方法（与类同名，无返回值）、this（当前对象引用）、super（父类引用）、访问修饰符（public/protected/default/private）；⑤ 封装：属性 private，通过 getter/setter 访问，Lombok @Data 自动生成；⑥ 继承：extends 单继承，子类继承父类非 private 成员，方法重写（@Override）实现多态；⑦ 多态：父类引用指向子类对象（Animal a = new Dog()），调用重写方法时执行子类版本；⑧ static：静态成员属于类而非对象，通过类名访问，静态方法不能访问非静态成员；⑨ final：修饰变量不可变、方法不可重写、类不可继承。

### 3.2 集合框架

> 🔍 **知识点深度解析**
>
> **作用**：集合框架是 Java 最常用的数据结构库，提供 List（有序列表）、Set（无序不重复）、Map（键值对）、Queue（队列）等接口和实现，是日常开发的基础。
>
> **原理**：Collection 是集合根接口，List/Set/Queue 继承 Collection，Map 独立。ArrayList 基于动态数组实现，随机访问 O(1)，中间插入删除 O(n)；LinkedList 基于双向链表，插入删除 O(1)，随机访问 O(n)。HashSet 基于 HashMap（key 存元素，value 固定对象），去重依赖 hashCode + equals；HashMap 基于数组+链表+红黑树（Java 8+），默认容量 16，负载因子 0.75，链表长度超过 8 且数组长度≥64 时转红黑树。
>
> **用法要点**：① List：ArrayList（最常用，随机访问多）、LinkedList（频繁头尾插入删除）、Vector（线程安全，已过时）；② Set：HashSet（最常用，无序）、LinkedHashSet（有序，按插入顺序）、TreeSet（排序，元素需实现 Comparable）；③ Map：HashMap（最常用，无序，key 可为 null）、LinkedHashMap（有序）、TreeMap（排序）、ConcurrentHashMap（线程安全，并发场景）、Hashtable（线程安全，已过时）；④ Queue：LinkedList（普通队列）、ArrayDeque（双端队列，可作栈）、PriorityQueue（优先队列，默认小顶堆）；⑤ 遍历方式：for-i、for-each、Iterator（可安全删除）、forEach（Lambda）；⑥ 集合转数组：list.toArray(new String[0])；数组转集合：Arrays.asList（定长，不可增删）、new ArrayList<>(Arrays.asList(arr))；⑦ 集合判空：用 isEmpty() 而非 size()==0，先判 null 再判空（list != null && !list.isEmpty()）；⑧ 面试高频：HashMap 底层结构、put 流程、扩容机制、ConcurrentHashMap 线程安全原理（CAS+synchronized）。

### 3.3 异常处理

> 🔍 **知识点深度解析**
>
> **作用**：异常处理保证程序在出错时不会崩溃，并能给出有意义的错误信息。Java 异常体系是健壮性的基础。
>
> **原理**：Throwable 是异常根类，分为 Error（JVM 级错误，如 OutOfMemoryError，程序无法处理）和 Exception（程序可处理）。Exception 分为受检异常（Checked Exception，编译时必须处理，如 IOException、SQLException）和运行时异常（RuntimeException，编译不强制，如 NullPointerException、IllegalArgumentException）。try-catch-finally 捕获异常，try-with-resources 自动关闭实现 AutoCloseable 的资源。
>
> **用法要点**：① try-catch：try 中写可能出错的代码，catch 捕获特定异常，finally 无论是否异常都执行（释放资源）；② try-with-resources（Java 7+ 推荐）：try (Connection conn = ...) { ... }，自动关闭资源，替代 finally 手动关闭；③ 抛出异常：throw new RuntimeException("消息")（抛出异常对象），方法签名用 throws 声明可能抛出的受检异常；④ 自定义异常：继承 RuntimeException（运行时，推荐）或 Exception（受检），提供无参和带消息构造方法；⑤ 异常链：catch (Exception e) { throw new BusinessException("业务失败", e); }，保留原始异常栈；⑥ 不要捕获后不处理（空 catch 块），至少打印日志；⑦ 不要用异常控制流程（如用 InputMismatchException 判断输入是否数字）；⑧ 全局异常处理：Spring 中用 @RestControllerAdvice + @ExceptionHandler 统一捕获并返回标准错误响应。

### 3.4 常用类库与 Lambda/Stream

> 🔍 **知识点深度解析**
>
> **作用**：Java 标准库提供大量工具类，Lambda 和 Stream API 让代码更简洁、更函数式，是现代 Java 开发的必备技能。
>
> **原理**：Lambda 表达式是函数式接口（只有一个抽象方法的接口，@FunctionalInterface）的匿名实现，本质是语法糖，编译后生成 invokedynamic 指令。Stream API 用于操作集合，分为创建→中间操作（返回新 Stream，惰性求值）→终端操作（触发计算，返回结果或副作用）。中间操作包括 filter/map/sorted/distinct/limit，终端操作包括 collect/forEach/count/reduce/findFirst。
>
> **用法要点**：① 字符串：String 不可变（修改创建新对象），StringBuilder 可变非线程安全（单线程拼接），StringBuffer 可变线程安全（已少用）；字符串常量池减少重复创建；== 比较引用，equals 比较内容；② 包装类：Integer/Long 等，自动装箱（int→Integer）拆箱（Integer→int），Integer 缓存 -128~127（== 在此范围为 true，超出为 false，所以用 equals）；③ 日期时间：Java 8+ 用 LocalDate/LocalDateTime/Instant/Duration/Period，线程安全不可变，替代旧的 Date/Calendar；DateTimeFormatter 格式化；④ Optional：包装可能为 null 的值，避免空指针，ofNullable/ifPresent/orElse/orElseGet/map/filter，不要用 Optional 作为字段或方法参数；⑤ Lambda：(参数) -> { 方法体 }，单参数可省略括号，单语句可省略大括号和 return；⑥ Stream：list.stream().filter(x -> x > 0).map(x -> x * 2).collect(Collectors.toList())，常用收集器 toList/toSet/toMap/groupingBy/joining；⑦ 并行流：parallelStream() 利用 ForkJoinPool，适合 CPU 密集型、无状态、数据量大的场景，I/O 密集不适合。

## 4. 数据库基础：MySQL

### 4.1 SQL 语法与增删改查

> 🔍 **知识点深度解析**
>
> **作用**：SQL（结构化查询语言）是操作关系型数据库的标准语言，增删改查（CRUD）是后端开发的日常核心。
>
> **原理**：MySQL 是关系型数据库管理系统，数据存储在表（Table）中，表由行（Row/记录）和列（Column/字段）组成。SQL 分为 DDL（数据定义语言：CREATE/ALTER/DROP）、DML（数据操作语言：INSERT/UPDATE/DELETE）、DQL（数据查询语言：SELECT）、DCL（数据控制语言：GRANT/REVOKE）。查询执行流程：SQL 解析→优化器生成执行计划→存储引擎执行→返回结果。
>
> **用法要点**：① 查询：SELECT 字段 FROM 表 WHERE 条件 GROUP BY 分组 HAVING 分组后过滤 ORDER BY 排序 LIMIT 分页；② 条件：=、!=、>、<、BETWEEN...AND、IN(...)、LIKE（% 任意字符、_ 单个字符）、IS NULL/IS NOT NULL、AND/OR/NOT；③ 连接：INNER JOIN（内连接，只返回匹配行）、LEFT JOIN（左连接，左表全部+右表匹配）、RIGHT JOIN、子查询（IN/EXISTS/标量子查询）；④ 聚合函数：COUNT/SUM/AVG/MAX/MIN，配合 GROUP BY 使用，HAVING 过滤聚合结果；⑤ 插入：INSERT INTO 表(字段) VALUES(值)，批量插入 VALUES(...),(...)；⑥ 更新：UPDATE 表 SET 字段=值 WHERE 条件（必须加 WHERE，否则全表更新）；⑦ 删除：DELETE FROM 表 WHERE 条件（必须加 WHERE），TRUNCATE 清空表（不可回滚，更快）；⑧ 建表：CREATE TABLE 表名(字段名 类型 约束, PRIMARY KEY(id))，常用类型 INT/BIGINT/VARCHAR(n)/TEXT/DATE/DATETIME/DECIMAL(m,n)；⑨ 约束：PRIMARY KEY（主键，唯一非空）、UNIQUE（唯一）、NOT NULL（非空）、DEFAULT（默认值）、FOREIGN KEY（外键，实际开发少用物理外键，用逻辑关联）。

### 4.2 索引原理与优化

> 🔍 **知识点深度解析**
>
> **作用**：索引是提升查询性能的核心手段，相当于书的目录，让数据库快速定位数据，避免全表扫描。
>
> **原理**：MySQL InnoDB 存储引擎使用 B+ 树作为索引结构。B+ 树是平衡多路搜索树，非叶子节点只存索引键，叶子节点存全部数据并通过双向链表连接，范围查询效率高。聚簇索引（主键索引）的叶子节点存整行数据，二级索引（非主键）的叶子节点存主键值（回表查询）。最左前缀原则：联合索引 (a,b,c) 可用于 a、a,b、a,b,c 的查询，但不能用于 b 或 c 单独查询。
>
> **用法要点**：① 索引类型：主键索引（PRIMARY KEY）、唯一索引（UNIQUE）、普通索引（INDEX）、联合索引（多字段）、全文索引（FULLTEXT，少用）；② 创建索引：CREATE INDEX idx_name ON 表(字段)，联合索引字段顺序按区分度从高到低；③ 最左前缀：联合索引 (a,b,c)，查询 WHERE a=1 AND b=2 可用，WHERE b=2 不可用；④ 索引失效场景：函数操作索引列（WHERE YEAR(create_time)=2024）、隐式类型转换、LIKE 以 % 开头、OR 连接非索引列、!= / NOT IN / NOT EXISTS（部分情况）、索引列参与运算；⑤ EXPLAIN 分析执行计划：关注 type（const>ref>range>index>ALL，ALL 是全表扫描需优化）、key（实际使用索引）、rows（扫描行数）、Extra（Using filesort 需排序、Using temporary 用临时表，都需优化）；⑥ 慢查询优化：开启慢查询日志→找到慢 SQL→EXPLAIN 分析→加索引或改写 SQL；⑦ 不要过度索引：索引加速查询但减慢写入（增删改需维护索引），占磁盘空间；⑧ 覆盖索引：查询字段都在索引中，无需回表，性能更好（Extra 显示 Using index）。

### 4.3 事务与隔离级别

> 🔍 **知识点深度解析**
>
> **作用**：事务保证一组数据库操作要么全部成功、要么全部失败，是数据一致性的基础。隔离级别解决并发事务下的脏读、不可重复读、幻读问题。
>
> **原理**：事务 ACID 特性：原子性（Atomicity，不可分割）、一致性（Consistency，数据从一个一致状态到另一个）、隔离性（Isolation，并发事务互不干扰）、持久性（Durability，提交后永久保存）。InnoDB 通过 undo log 保证原子性（回滚）、redo log 保证持久性（崩溃恢复）、MVCC（多版本并发控制）+ 锁保证隔离性。隔离级别从低到高：读未提交（Read Uncommitted）、读已提交（Read Committed，Oracle 默认）、可重复读（Repeatable Read，MySQL 默认）、串行化（Serializable）。
>
> **用法要点**：① 事务命令：START TRANSACTION 或 BEGIN 开启，COMMIT 提交，ROLLBACK 回滚；② 并发问题：脏读（读到未提交数据）、不可重复读（同一事务两次读结果不同，其他事务修改并提交）、幻读（同一事务两次查询行数不同，其他事务插入/删除）；③ 隔离级别对比：读未提交（都可能）、读已提交（解决脏读）、可重复读（解决脏读+不可重复读，MySQL 通过 MVCC+间隙锁解决幻读）、串行化（全解决，性能最差）；④ MySQL 默认可重复读，一般不需要改；⑤ Spring 中用 @Transactional 声明事务，默认传播行为 REQUIRED（有事务加入，无则新建）；⑥ @Transactional 失效场景：非 public 方法、自调用（同类方法调用）、异常被 catch 未抛出、数据库引擎不支持事务（MyISAM）、rollbackFor 未配置（默认只回滚 RuntimeException）。

## 5. 框架入门：Vue3 与 Spring Boot

### 5.1 Vue3 基础入门

> 🔍 **知识点深度解析**
>
> **作用**：Vue3 是渐进式 JavaScript 框架，用于构建用户界面，是国内前端主流框架。掌握 Vue3 基础是前端开发的起点。
>
> **原理**：Vue3 采用 Composition API（组合式 API），通过 setup() 函数组织逻辑，响应式系统基于 Proxy（代理整个对象）实现，替代 Vue2 的 Object.defineProperty。核心流程：数据变更→Proxy 拦截 set→触发依赖更新→虚拟 DOM Diff→更新真实 DOM。单文件组件（.vue）包含 template（模板）、script（逻辑）、style（样式）三部分，由 Vite 编译。
>
> **用法要点**：① 创建项目：npm create vue@latest 或 pnpm create vue，选择 TypeScript、Vue Router、Pinia、ESLint；② 响应式：ref（基本类型，.value 访问）、reactive（对象类型，直接访问属性），模板中 ref 自动解包；③ 组件：defineProps 接收父组件数据，defineEmits 触发事件，defineExpose 暴露方法给父组件；④ 指令：v-bind（绑定属性，简写 :）、v-on（绑定事件，简写 @）、v-model（双向绑定）、v-if/v-else（条件渲染）、v-for（列表渲染，必须加 :key）、v-show（显示隐藏，display 切换）；⑤ 计算属性与侦听：computed（有缓存的派生状态）、watch（监听数据变化执行副作用）、watchEffect（自动收集依赖）；⑥ 生命周期：onMounted（挂载后，请求数据）、onUnmounted（卸载前，清理资源）；⑦ 路由：Vue Router 4，createRouter 创建，useRoute 获取当前路由，useRouter 编程式导航，路由懒加载 () => import()；⑧ 学习路径：先学 Options API 理解概念，再学 Composition API（项目推荐），<script setup> 是最简洁写法。

### 5.2 Spring Boot 入门

> 🔍 **知识点深度解析**
>
> **作用**：Spring Boot 是 Java 后端开发的事实标准，通过「约定优于配置」大幅简化 Spring 应用搭建，开箱即用，是全栈后端的核心框架。
>
> **原理**：Spring Boot 核心三大能力：自动配置（AutoConfiguration）、起步依赖（Starter）、内嵌服务器。自动配置通过 @SpringBootApplication（包含 @EnableAutoConfiguration）触发，SpringFactoriesLoader 加载 META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports 中的自动配置类，每个类用 @ConditionalOnClass/@ConditionalOnMissingBean 等条件注解判断是否生效。起步依赖是一组打包好的依赖描述符，parent POM 管理版本，避免冲突。内嵌 Tomcat 让应用打成可执行 JAR，java -jar 直接运行。
>
> **用法要点**：① 创建项目：Spring Initializr（start.spring.io）或 IDEA 新建 Spring Boot 项目，选 Spring Web、MyBatis Framework、MySQL Driver 等依赖；② 项目结构：src/main/java（代码，启动类在根包）、src/main/resources（配置 application.yml、静态资源）、src/test（测试）；③ 启动类：@SpringBootApplication 标注，main 方法调用 SpringApplication.run；④ RESTful API：@RestController（@Controller+@ResponseBody）、@RequestMapping/@GetMapping/@PostMapping/@PutMapping/@DeleteMapping、@PathVariable（路径参数）、@RequestParam（查询参数）、@RequestBody（请求体 JSON）；⑤ 配置文件：application.yml（推荐，层级清晰），server.port 改端口，spring.datasource 配数据库，自定义配置用 @Value 或 @ConfigurationProperties；⑥ 数据访问：整合 MyBatis-Plus（Mapper 继承 BaseMapper）或 Spring Data JPA，@MapperScan 扫描 Mapper；⑦ 统一返回：封装 Result<T>（code/message/data），全局异常处理 @RestControllerAdvice；⑧ 参数校验：spring-boot-starter-validation，@NotNull/@NotBlank/@Size 等注解，@Valid 触发校验；⑨ 学习路径：先写 CRUD 接口→整合数据库→事务管理→日志配置→打包部署。

### 5.3 前后端联调基础

> 🔍 **知识点深度解析**
>
> **作用**：前后端联调是全栈开发的核心环节，前端通过 HTTP 请求调用后端 API，完成数据交互。掌握联调流程和常见问题排查是必备能力。
>
> **原理**：前后端分离架构下，前端（Vue）和后端（Spring Boot）是独立项目，通过 RESTful API 通信。前端用 axios 发送 HTTP 请求（GET/POST/PUT/DELETE），后端 Controller 接收请求、处理业务、返回 JSON 数据。跨域（CORS）由浏览器同源策略（协议+域名+端口都相同才允许）引起，开发环境用 Vite 代理，生产环境用 Nginx 反向代理或后端配置 CORS。
>
> **用法要点**：① 前端请求：安装 axios，封装 request 实例（baseURL、超时、请求拦截器加 Token、响应拦截器处理错误和数据），api 目录按模块封装接口；② 跨域解决：开发环境 vite.config.ts 配置 server.proxy（/api 转发到 http://localhost:8080）；生产环境 Nginx 配置 location /api { proxy_pass http://backend:8080; }；或后端 @CrossOrigin 或全局 CORS 配置；③ 鉴权：登录成功后端返回 JWT Token，前端存 localStorage，请求拦截器 Authorization: Bearer <token>，后端拦截器校验 Token；④ 接口文档：后端用 Knife4j（Swagger 增强）或 Apifox 生成接口文档，前端按文档联调；⑤ 联调流程：先定义接口规范（URL、方法、参数、返回格式）→后端写接口→前端对接→联调测试→修复问题；⑥ 常见问题：404（URL 错或后端没启动）、400（参数格式错）、401（未登录或 Token 过期）、500（后端报错，看后端日志）、跨域报错（配置代理/CORS）、请求体为空（Content-Type 不对或后端没加 @RequestBody）；⑦ 调试工具：Chrome DevTools Network 看请求响应，Postman/Apifox 单独测后端接口，后端用 IDEA 断点调试。

## 6. 前端进阶：Vue3 深入与生态

### 6.1 Vue3 响应式原理与 Composition API 深入

> 🔍 **知识点深度解析**
>
> **作用**：深入理解 Vue3 响应式原理和 Composition API，是写出高性能、可维护 Vue 应用的关键，也是面试核心考点。
>
> **原理**：reactive(obj) 返回 Proxy 代理，拦截 get（track 收集依赖）、set（trigger 触发更新）、deleteProperty 等 13 种操作。ref(value) 内部创建 RefImpl 类实例，通过 get value()/set value() 拦截 .value 访问。依赖收集流程：组件渲染时访问响应式数据→触发 get→track 将当前 effect（组件更新函数）收集到该属性的依赖 Set 中；数据变更→触发 set→trigger 遍历依赖 Set 调用所有 effect→重新渲染组件。computed 内部有 dirty 标记，依赖变更时 dirty=true，首次访问计算并缓存，依赖不变直接返回缓存。
>
> **用法要点**：① ref vs reactive：基本类型用 ref，对象用 reactive；ref 在模板自动解包，JS 中用 .value；reactive 解构丢失响应式，用 toRefs 解构；② 组合函数（Composables）：逻辑复用的标准方式，替代 mixins，命名 useXxx，放在 composables/ 目录，返回响应式数据和方法，如 useFetch/useMouse/useDebounce；③ watch vs watchEffect：watch 监听特定数据源，可获取新旧值，可配置 immediate/deep；watchEffect 自动收集依赖，立即执行，不需要指定监听源；④ 性能优化：v-memo 缓存大列表子树、defineAsyncComponent 懒加载组件、keep-alive 缓存组件状态、markRaw/shallowRef 减少大对象响应式开销；⑤ 组件通信全方案：父子（props+emit）、跨层级（provide/inject）、全局（Pinia）、父访问子（ref+defineExpose）、v-model（props+emit 语法糖）；⑥ 深入学习：VueUse 库提供大量常用 composables，推荐学习源码理解最佳实践。

### 6.2 Pinia 状态管理

> 🔍 **知识点深度解析**
>
> **作用**：Pinia 是 Vue3 官方推荐的状态管理库，替代 Vuex，更简洁、TypeScript 友好，用于管理跨组件的全局状态（用户信息、购物车、主题等）。
>
> **原理**：defineStore(id, options) 创建 store，返回 useXxxStore 函数。首次调用时创建 store 实例（单例，全局唯一），后续调用返回同一实例。state 是响应式数据（内部用 reactive），getters 是计算属性（有缓存），actions 是方法（可同步/异步，直接修改 state，不需要 mutation）。Pinia 没有 mutations（Vuex 的 mutation 被移除），actions 可直接修改 state。storeToRefs 解构 state/getters 保持响应式，actions 可直接解构。
>
> **用法要点**：① 创建 store：defineStore('user', { state: () => ({...}), getters: {...}, actions: {...} })，或 Setup 风格 defineStore('user', () => { const count = ref(0); return { count } })；② 组件中使用：const store = useUserStore()，直接访问 store.xxx，解构 state 用 storeToRefs（const { userInfo } = storeToRefs(store)），方法直接解构（const { login } = store）；③ 持久化：pinia-plugin-persistedstate 插件，自动存 localStorage/ sessionStorage，配置 persist: true 或自定义 key/storage；④ 模块化：按功能分 store（user/cart/order/app），不要一个大 store；⑤ 跨 store 调用：在 action 中 import 其他 store 并调用；⑥ 与路由配合：路由守卫中用 store 判断登录状态，未登录跳转登录页；⑦ 从 Vuex 迁移：mutations 改为直接修改 state，getters 不变，actions 不变，mapState/mapGetters 改为 storeToRefs。

### 6.3 Element Plus 组件库实战

> 🔍 **知识点深度解析**
>
> **作用**：Element Plus 是 Vue3 生态最流行的企业级 UI 组件库，提供丰富的表单、表格、弹窗等组件，大幅提升中后台系统开发效率。
>
> **原理**：Element Plus 基于 Vue3 + TypeScript 开发，每个组件是独立的 Vue 组件，通过 props 接收配置、emit 触发事件。支持按需引入（unplugin-vue-components 自动导入），减小打包体积。主题定制通过 CSS 变量（--el-color-primary 等）实现，运行时可动态修改。
>
> **用法要点**：① 安装与引入：npm install element-plus，完整引入（main.ts 中 app.use(ElementPlus)）或按需引入（unplugin-auto-import + unplugin-vue-components，推荐）；② 表单组件：el-form（:model 绑定数据、:rules 校验规则、ref 调用方法）、el-form-item（prop 对应字段）、el-input/el-select/el-date-picker/el-radio/el-checkbox，校验用 formRef.validate()；③ 表格组件：el-table（:data 数据）、el-table-column（prop/label/width）、分页 el-pagination（current-page/page-size/total），自定义列用 slot，操作列放按钮；④ 弹窗组件：el-dialog（v-model 控制显示、title 标题）、el-message（轻提示）、el-notification（通知）、el-loading（加载）；⑤ 上传组件：el-upload（action 上传地址、:headers 加 Token、:on-success 回调、before-upload 校验）；⑥ 主题定制：CSS 变量覆盖 :root { --el-color-primary: #xxx }，或 element-plus/theme-chalk 源码修改；⑦ 封装思路：对常用组件二次封装（如 ProTable 封装表格+分页+搜索），减少重复代码；⑧ 注意：组件属性用 kebab-case 或 camelCase 均可，事件用 @event-name，方法通过 ref 调用。

### 6.4 Vite 工程化与构建优化

> 🔍 **知识点深度解析**
>
> **作用**：Vite 是 Vue3 官方推荐的构建工具，开发服务器基于原生 ESM 秒级启动，生产构建基于 Rollup。掌握 Vite 配置和构建优化是前端工程化的基础。
>
> **原理**：开发模式：Vite 用 esbuild 预构建依赖（node_modules 中第三方包，CommonJS 转 ESM，缓存到 node_modules/.vite），源码用浏览器原生 ESM（浏览器请求时按需编译，不打包整个项目），启动极快。HMR（热模块替换）只更新变更模块，不刷新页面。生产构建：用 Rollup 打包（Tree-shaking、代码分割、压缩），输出静态文件。插件机制基于 Rollup 插件 API，@vitejs/plugin-vue 处理 .vue 文件编译。
>
> **用法要点**：① 核心配置：vite.config.ts，plugins（vue()、自动导入等）、resolve.alias（@ 指向 src）、server（port、proxy 代理）、build（outDir、sourcemap、rollupOptions）；② 路径别名：resolve: { alias: { '@': resolve(__dirname, 'src') } }，配合 tsconfig.json 的 paths；③ 开发代理：server: { proxy: { '/api': { target: 'http://localhost:8080', changeOrigin: true, rewrite: (p) => p.replace(/^\/api/, '') } } }；④ 环境变量：.env.development（开发）、.env.production（生产），变量以 VITE_ 前缀暴露给客户端，import.meta.env.VITE_XXX 访问；⑤ 构建优化：build.rollupOptions.output.manualChunks 手动分包（将 vue、element-plus 等第三方库单独打包，利用浏览器缓存）；build.sourcemap 生产环境关闭；⑥ 插件生态：@vitejs/plugin-vue（Vue 支持）、unplugin-auto-import（自动导入 API）、unplugin-vue-components（自动导入组件）、vite-plugin-compression（gzip 压缩）、vite-plugin-imagemin（图片压缩）；⑦ 性能分析：rollup-plugin-visualizer 可视化分析打包体积，找出大依赖优化；⑧ 学习路径：基础配置→环境变量→代理→构建优化→插件开发（进阶）。

## 7. 后端进阶：Java 高级与 Spring 原理

### 7.1 并发编程

> 🔍 **知识点深度解析**
>
> **作用**：并发编程是 Java 高级核心，利用多线程提升程序吞吐量和响应速度，也是面试和实际开发的重难点。
>
> **原理**：进程是资源分配单位，线程是 CPU 调度单位，一个进程可包含多个线程共享堆内存和方法区，但每个线程有独立的虚拟机栈和程序计数器。Java 内存模型（JMM）定义线程与主内存的交互规则，三大特性：原子性（操作不可分割）、可见性（一个线程修改对其他线程可见）、有序性（指令不被重排序）。synchronized 通过对象监视器（Monitor）实现互斥，Java 6+ 有锁升级（偏向锁→轻量级锁→重量级锁）。volatile 保证可见性和有序性（禁止指令重排），不保证原子性。
>
> **用法要点**：① 线程创建：继承 Thread、实现 Runnable、实现 Callable（有返回值，Future 接收）、线程池（推荐，不要手动 new Thread）；② 线程状态：新建（NEW）、就绪（RUNNABLE）、运行（RUNNING）、阻塞（BLOCKED/WAITING/TIMED_WAITING）、终止（TERMINATED），理解状态转换；③ synchronized：修饰方法（实例方法锁 this、静态方法锁类对象）、修饰代码块（锁指定对象），可重入（同一线程可多次获取同一锁）；④ Lock 接口：ReentrantLock（可重入锁，支持公平/非公平、可中断、超时获取），用 try-finally 确保 unlock，Condition 实现线程间通信（await/signal/signalAll，替代 wait/notify）；⑤ 线程池：ThreadPoolExecutor 七大参数（corePoolSize 核心线程数、maximumPoolSize 最大线程数、keepAliveTime 空闲时间、unit 时间单位、workQueue 工作队列、threadFactory 线程工厂、handler 拒绝策略），任务流程：核心线程→队列→最大线程→拒绝策略；常用四种：FixedThreadPool、CachedThreadPool、SingleThreadExecutor、ScheduledThreadPool（但推荐手动创建 ThreadPoolExecutor，避免 OOM）；⑥ 并发工具：CountDownLatch（倒计时门闩，等待多个线程完成）、CyclicBarrier（循环栅栏，一组线程互相等待）、Semaphore（信号量，控制并发数）；⑦ 原子类：AtomicInteger/AtomicReference 等，基于 CAS（Compare-And-Swap，乐观锁）实现无锁原子操作；⑧ ThreadLocal：线程本地变量，每个线程独立副本，原理是 ThreadLocalMap（Thread 持有），key 为 ThreadLocal 弱引用，使用后必须 remove() 防止内存泄漏；⑨ 最佳实践：优先用线程池而非手动创建线程，优先用并发工具类而非 wait/notify，减小锁粒度，避免死锁（按固定顺序获取锁、设置超时）。

### 7.2 JVM 基础与内存模型

> 🔍 **知识点深度解析**
>
> **作用**：JVM（Java 虚拟机）是 Java 程序运行的环境，理解 JVM 内存结构、垃圾回收、类加载是排查内存泄漏、OOM、性能问题的基础。
>
> **原理**：JVM 运行时数据区：堆（Heap，所有线程共享，存对象实例，GC 主要区域）、方法区/元空间（Method Area/Metaspace，存类信息、常量、静态变量，JDK 8+ 用元空间在本地内存）、虚拟机栈（JVM Stack，线程私有，存栈帧：局部变量表、操作数栈、方法出口）、本地方法栈（Native Method Stack，native 方法）、程序计数器（Program Counter，线程私有，记录当前执行字节码行号）。垃圾回收：可达性分析算法（从 GC Roots 出发，不可达对象可回收），GC Roots 包括虚拟机栈引用的对象、方法区静态变量/常量引用的对象、本地方法栈引用的对象。
>
> **用法要点**：① 内存结构：堆分新生代（Eden + Survivor0 + Survivor1，比例 8:1:1）和老年代，新对象在 Eden，Minor GC 后存活到 Survivor，年龄到阈值（默认 15）晋升老年代；② GC 算法：标记-清除（产生碎片）、标记-复制（新生代用，无碎片但浪费空间）、标记-整理（老年代用，无碎片）；③ 垃圾收集器：Serial（串行，单核）、Parallel（并行，吞吐量优先）、CMS（并发标记清除，低延迟，已废弃）、G1（Region 分区，可预测停顿，JDK 9+ 默认）、ZGC（超低延迟，JDK 15+ 正式）；④ 类加载：加载→验证→准备→解析→初始化（五阶段），双亲委派模型（Bootstrap→Extension→Application，先让父类加载器加载，避免核心类被篡改），可打破（SPI、Tomcat）；⑤ 常用参数：-Xms（初始堆）、-Xmx（最大堆，生产设为相同避免动态扩缩）、-Xmn（新生代大小）、-XX:MetaspaceSize、-XX:+UseG1GC、-XX:+HeapDumpOnOutOfMemoryError（OOM 时 dump 堆）；⑥ 诊断工具：jps（查看 Java 进程）、jstat（GC 统计）、jmap（堆 dump）、jstack（线程栈，排查死锁）、Arthas（阿里开源，在线诊断）、VisualVM/MAT（堆转储分析）；⑦ 常见 OOM：堆 OOM（对象太多，调大堆或排查内存泄漏）、元空间 OOM（类太多，调大 MetaspaceSize）、栈溢出（递归太深，调大 -Xss）；⑧ 学习路径：内存结构→GC 算法/收集器→类加载→调优工具→实际排查。

### 7.3 Spring 核心原理（IoC/AOP）

> 🔍 **知识点深度解析**
>
> **作用**：Spring 是 Java 生态的基石，IoC（控制反转）和 AOP（面向切面编程）是两大核心，理解原理是用好 Spring、排查问题、扩展 Spring 的基础。
>
> **原理**：IoC（控制反转）：对象的创建和依赖管理由 Spring 容器负责，而非程序手动 new。DI（依赖注入）是 IoC 的实现方式，包括构造器注入（推荐，依赖不可变、循环依赖友好）、Setter 注入、字段注入（@Autowired，不推荐）。Bean 生命周期：实例化→属性填充→Aware 接口回调→BeanPostProcessor 前置处理→初始化（@PostConstruct/InitializingBean/init-method）→BeanPostProcessor 后置处理→使用→销毁（@PreDestroy/DisposableBean/destroy-method）。AOP：通过动态代理在方法前后织入增强逻辑，不修改原代码。JDK 动态代理（目标类实现接口，基于反射）、CGLIB 动态代理（目标类无接口，基于继承生成子类），Spring Boot 2.x 默认 CGLIB。
>
> **用法要点**：① 依赖注入：构造器注入（@Autowired 可省略，Spring 4.3+ 单构造器自动注入），字段注入用 @Autowired（required=false 允许为 null）或 @Resource（按名称注入，JDK 提供）；② 循环依赖：Spring 通过三级缓存解决单例 Bean 的循环依赖（singletonObjects 成品、earlySingletonObjects 早期半成品、singletonFactories 工厂），构造器注入无法解决循环依赖；③ Bean 作用域：singleton（默认，全局单例）、prototype（每次获取新建）、request/session（Web 环境）；④ AOP 概念：切面（Aspect，@Aspect）、切点（Pointcut，@Pointcut 表达式）、通知（Advice，@Before/@After/@AfterReturning/@AfterThrowing/@Around）、连接点（JoinPoint，被拦截的方法）；⑤ 切点表达式：execution(返回类型 包.类.方法(参数))，如 execution(* com.example.service..*.*(..)) 匹配 service 包所有类所有方法；⑥ @Around 最强大，可控制是否执行原方法、修改参数和返回值，用 ProceedingJoinPoint.proceed() 执行原方法；⑦ 事务管理：@Transactional 基于 AOP 实现，声明式事务，传播行为（REQUIRED/REQUIRES_NEW/NESTED 等），回滚规则（默认 RuntimeException，rollbackFor 指定异常）；⑧ 扩展点：BeanPostProcessor（Bean 前后处理）、BeanFactoryPostProcessor（Bean 定义加载后）、ApplicationContextAware（获取容器）、@EventListener（事件监听）。

### 7.4 常用设计模式

> 🔍 **知识点深度解析**
>
> **作用**：设计模式是前人总结的代码设计最佳实践，用于解决常见问题，提升代码可维护性、可扩展性、可复用性，也是面试高频考点。
>
> **原理**：设计模式分为三大类：创建型（对象创建方式）、结构型（类/对象组合方式）、行为型（对象间通信和职责分配）。设计模式遵循 SOLID 原则：单一职责（SRP）、开闭原则（OCP，对扩展开放对修改关闭）、里氏替换（LSP）、接口隔离（ISP）、依赖倒置（DIP，依赖抽象不依赖具体）。
>
> **用法要点**：① 创建型：单例模式（Singleton，全局唯一实例，饿汉/懒汉/双重检查/枚举，Spring Bean 默认单例）、工厂方法（Factory Method，定义创建对象接口，子类决定实例化哪个类）、抽象工厂（Abstract Factory，创建一族相关对象）、建造者（Builder，分步构建复杂对象，如 StringBuilder、Lombok @Builder）；② 结构型：代理模式（Proxy，控制对象访问，Spring AOP 动态代理）、装饰器（Decorator，动态添加功能，如 Java IO 流）、适配器（Adapter，接口转换，如 Spring MVC HandlerAdapter）、外观（Facade，提供统一入口，封装子系统复杂性）；③ 行为型：策略模式（Strategy，定义算法族，可互换，如支付方式）、模板方法（Template Method，定义算法骨架，子类实现步骤，如 Spring JdbcTemplate）、观察者（Observer，一对多通知，如 Spring 事件机制）、责任链（Chain of Responsibility，请求沿链传递，如 Servlet Filter、Spring Interceptor）；④ 学习方法：先理解每个模式的意图和适用场景，再看 JDK/Spring 中的实际应用，最后在项目中刻意使用；⑤ 不要为了用模式而用模式，简单问题简单实现，模式是工具不是目的；⑥ 推荐阅读《Head First 设计模式》入门，《设计模式之禅》深入。

## 8. 数据层进阶：Redis 与 MyBatis-Plus

### 8.1 Redis 缓存与数据结构

> 🔍 **知识点深度解析**
>
> **作用**：Redis 是基于内存的高性能键值数据库，常用于缓存、会话存储、排行榜、分布式锁、消息队列等，是提升系统性能的核心组件。
>
> **原理**：Redis 单线程模型（命令执行单线程，避免多线程竞争和上下文切换），基于内存操作，性能极高（QPS 10万+）。I/O 多路复用（epoll）处理网络连接，6.0+ 多线程只用于网络 IO，命令执行仍单线程。持久化：RDB（快照，定时保存内存数据到 dump.rdb，恢复快但可能丢数据）、AOF（追加文件，记录每条写命令，数据安全但文件大、恢复慢），可混合使用。过期策略：惰性删除（访问时检查过期）+ 定期删除（每隔一段时间抽查），内存满时触发淘汰策略（volatile-lru/allkeys-lru 等 8 种）。
>
> **用法要点**：① 数据结构：String（字符串/整数/浮点数，缓存、计数器、分布式锁 SETNX）、Hash（键值对集合，存对象）、List（双向链表，消息队列、最新列表）、Set（无序不重复集合，标签、共同好友）、ZSet（有序集合，按 score 排序，排行榜、延时队列）；② 缓存使用模式：Cache-Aside（旁路缓存，先查缓存没有查 DB 再写缓存，最常用）、Write-Through（写时同时写缓存和 DB）、Write-Behind（写时只写缓存，异步写 DB，性能高但可能丢）；③ 缓存三大问题：缓存穿透（查不存在的数据，布隆过滤器或缓存空值）、缓存击穿（热点 key 过期瞬间大量请求打 DB，互斥锁或永不过期）、缓存雪崩（大量 key 同时过期，过期时间加随机值、多级缓存）；④ 分布式锁：SET key value NX EX 30（原子加锁），释放用 Lua 脚本判断 value 再删（防止误删别人锁），Redisson 框架提供可重入分布式锁；⑤ 持久化配置：save 900 1（900秒内至少1次修改则 RDB）、appendonly yes（开启 AOF）、appendfsync everysec（每秒刷盘，折中）；⑥ 高可用：主从复制（读写分离）、哨兵（Sentinel，自动故障转移）、Cluster（集群，数据分片，横向扩展）；⑦ 常用命令：SET/GET/DEL/EXPIRE/TTL、HSET/HGET/HGETALL、LPUSH/RPOP/LRANGE、SADD/SMEMBERS/SISMEMBER、ZADD/ZRANGE/ZRANK；⑧ Java 客户端：Spring Data Redis（RedisTemplate）、Redisson（功能丰富，推荐）、Lettuce（Spring Boot 默认）。

### 8.2 MyBatis-Plus 持久层框架

> 🔍 **知识点深度解析**
>
> **作用**：MyBatis-Plus（MP）是 MyBatis 的增强工具，在 MyBatis 基础上只做增强不做改变，内置通用 CRUD、条件构造器、分页、代码生成器，大幅提升持久层开发效率。
>
> **原理**：MP 通过继承 BaseMapper<T> 接口，内置通用 CRUD 方法（insert/deleteById/updateById/selectById 等），无需编写 XML。启动时通过 MybatisDefaultParameterHandler 等扩展点注入通用 SQL。条件构造器（QueryWrapper/LambdaQueryWrapper）通过链式调用拼接 WHERE 条件，Lambda 版本支持方法引用（User::getName），编译时检查字段名，避免硬编码错误。分页插件（PaginationInnerInterceptor）通过拦截 SQL 自动添加 LIMIT 和 count 查询。
>
> **用法要点**：① 集成：引入 mybatis-plus-boot-starter，配置 MybatisPlusInterceptor 并添加 PaginationInnerInterceptor，@MapperScan 扫描 Mapper；② 实体类：@TableName 映射表名，@TableId(type=IdType.AUTO) 主键，@TableField 映射字段（exist=false 非表字段）、@TableLogic 逻辑删除、@TableField(fill=FieldFill.INSERT) 自动填充；③ BaseMapper：继承后直接用 insert/deleteById/updateById/selectById/selectList/selectPage，无需写 XML；④ 条件构造器：QueryWrapper<User> qw = new QueryWrapper<>(); qw.eq("name", "张三").gt("age", 18).orderByDesc("create_time"); LambdaQueryWrapper 用 User::getName 替代字段名字符串；⑤ 分页：Page<User> page = new Page<>(1, 10); userMapper.selectPage(page, qw); 返回 page.getRecords() 数据、page.getTotal() 总数；⑥ IService/ServiceImpl：通用 Service 层，内置 save/saveBatch/updateById/removeById/list/page 等，业务 Service 继承 ServiceImpl；⑦ 代码生成器：AutoGenerator 根据数据库表自动生成 Entity/Mapper/Service/Controller，大幅减少重复代码；⑧ 自定义 SQL：复杂查询仍可写 XML（resources/mapper/*.xml），MP 不影响原有 MyBatis 用法；⑨ 性能分析：p6spy 格式化打印 SQL（开发环境），生产用 Druid 监控慢 SQL；⑩ 注意：updateById 只更新非 null 字段（要更新为 null 需用 UpdateWrapper 的 set 方法），分页需配置插件否则不生效。

## 9. 全栈整合与工程化

### 9.1 项目工程化与规范

> 🔍 **知识点深度解析**
>
> **作用**：工程化是项目可维护、可协作、可扩展的基础，包括代码规范、目录结构、日志体系、单元测试、CI/CD 等，是从「能跑」到「可维护」的关键。
>
> **原理**：工程化通过标准化流程和工具，减少人为错误，提升团队协作效率。代码规范通过 Linter（ESLint/Checkstyle）在提交前检查，统一代码风格。日志通过 SLF4J 门面 + Logback 实现，分级输出便于排查。单元测试通过 JUnit + Mockito 验证代码逻辑正确性，保证重构安全。CI/CD 通过 Jenkins/GitHub Actions 自动化构建、测试、部署。
>
> **用法要点**：① 后端规范：阿里巴巴 Java 开发手册（强制遵循），Checkstyle/Spotless 插件自动格式化，Lombok 简化代码（@Data/@Slf4j/@Builder）；② 前端规范：ESLint + Prettier（代码格式化）、Stylelint（CSS）、Husky + lint-staged（git commit 前自动检查）、Commitlint（commit message 规范）；③ 日志体系：SLF4J 门面（org.slf4j.Logger），Logback 实现（Spring Boot 默认），配置 logback-spring.xml（控制台+文件，按天滚动，ERROR 单独文件），MDC 放 traceId 追踪请求链路；④ 日志级别：ERROR（错误，需关注）、WARN（警告，潜在问题）、INFO（关键信息，默认）、DEBUG（调试细节，开发用）、TRACE（更细）；生产环境 INFO，开发 DEBUG；⑤ 单元测试：JUnit 5（@Test/@BeforeEach/@AfterEach）、Mockito（@Mock 模拟依赖、when().thenReturn() 打桩、verify() 验证调用）、Spring Boot Test（@SpringBootTest 集成测试、@WebMvcTest 切片测试）；⑥ 测试覆盖率：JaCoCo 插件统计覆盖率，核心业务代码覆盖率目标 70%+；⑦ 前后端统一：统一响应格式 Result<T>（code/message/data）、统一错误码、统一时间格式（ISO 8601 或时间戳）、统一分页参数（pageNum/pageSize）；⑧ API 文档：Knife4j（Swagger 增强）或 Apifox，接口变更自动同步，前端按文档开发；⑨ 学习路径：代码规范→日志→单元测试→CI/CD→监控。

### 9.2 Docker 容器化部署

> 🔍 **知识点深度解析**
>
> **作用**：Docker 是容器化技术，将应用和依赖打包成镜像，在任何环境一致运行，解决「在我机器上能跑」的问题，是现代部署的基础。
>
> **原理**：Docker 基于 Linux 内核的 Namespace（资源隔离：PID/网络/挂载等）和 Cgroups（资源限制：CPU/内存）实现容器化。镜像（Image）是只读模板，由多层文件系统（UnionFS）组成，Dockerfile 定义构建步骤。容器（Container）是镜像的运行实例，可读写层在镜像之上。仓库（Registry）存储和分发镜像（Docker Hub、阿里云 ACR）。
>
> **用法要点**：① 核心概念：镜像（Image）、容器（Container）、仓库（Registry）、Dockerfile（构建脚本）、docker-compose（多容器编排）；② 常用命令：docker pull（拉镜像）、docker run（运行容器，-d 后台、-p 端口映射、-v 数据卷、--name 命名）、docker ps（查看运行容器）、docker exec -it（进入容器）、docker logs（查看日志）、docker stop/rm（停止/删除容器）、docker images（查看镜像）、docker rmi（删除镜像）；③ Dockerfile：FROM 基础镜像（openjdk:17-jdk-slim、node:18-alpine）、WORKDIR 工作目录、COPY 复制文件、RUN 执行命令（构建时）、EXPOSE 暴露端口、ENV 环境变量、ENTRYPOINT/CMD 启动命令；多阶段构建减小镜像体积；④ 数据卷：-v /host/path:/container/path 挂载，数据持久化（数据库、日志、配置文件）；⑤ 网络：bridge（默认，容器间通过 IP 通信）、host（共享主机网络）、自定义网络（容器名可 DNS 解析互通）；⑥ docker-compose：docker-compose.yml 定义多服务（app、mysql、redis、nginx），docker-compose up -d 一键启动，depends_on 控制启动顺序；⑦ Spring Boot 部署：Dockerfile 构建 JAR 镜像，docker run -p 8080:8080 -e SPRING_PROFILES_ACTIVE=prod myapp；⑧ Vue 部署：构建 dist 静态文件，用 nginx:alpine 镜像，COPY dist 到 /usr/share/nginx/html，配置 nginx.conf（SPA 路由 try_files、/api 反向代理）；⑨ 学习路径：安装 Docker→常用命令→Dockerfile→docker-compose→部署前后端项目→镜像优化（多阶段、alpine 基础镜像）。

## 10. 微服务架构

### 10.1 Spring Cloud 微服务体系

> 🔍 **知识点深度解析**
>
> **作用**：微服务架构将单体应用拆分为多个独立部署、独立开发的小服务，每个服务专注一个业务领域，通过轻量级协议（HTTP/RPC）通信。Spring Cloud 是微服务开发的一站式解决方案。
>
> **原理**：微服务核心问题：服务注册与发现（服务启动时注册到注册中心，消费方从注册中心获取服务列表）、负载均衡（消费方从多个实例中选择一个调用）、服务调用（声明式 HTTP 客户端）、熔断降级（服务故障时快速失败，避免级联故障）、API 网关（统一入口，路由/鉴权/限流）、配置中心（集中管理配置，动态刷新）、链路追踪（追踪请求在多个服务间的调用链）。
>
> **用法要点**：① 注册中心：Nacos（阿里开源，同时支持注册中心+配置中心，推荐）、Eureka（Netflix，已停更）、Consul；服务提供者启动时注册 IP+端口，消费者定时拉取服务列表缓存；② 负载均衡：Spring Cloud LoadBalancer（客户端负载均衡，替代 Ribbon），从服务列表中按策略（轮询/随机/加权）选择实例；③ 服务调用：OpenFeign（声明式 HTTP 客户端，写接口+注解，自动生成实现，整合负载均衡），@FeignClient(name="user-service")，方法上 @GetMapping("/user/{id}")；④ 熔断降级：Sentinel（阿里开源，推荐，支持流量控制、熔断降级、系统保护）、Resilience4j；配置降级规则（慢调用比例/异常比例/异常数），fallback 方法返回兜底数据；⑤ API 网关：Spring Cloud Gateway（基于 WebFlux 响应式，高性能），路由配置（uri predicates filters），全局过滤器实现鉴权、日志、限流；⑥ 配置中心：Nacos Config，bootstrap.yml 配置地址，Data ID 对应配置文件，@RefreshScope 动态刷新配置；⑦ 链路追踪：Sleuth（生成 traceId/spanId）+ Zipkin（收集展示调用链），或 SkyWalking（字节码增强，无侵入）；⑧ 学习路径：先理解微服务概念→注册中心+OpenFeign→网关→熔断→配置中心→链路追踪→完整微服务项目实战。

### 10.2 服务治理与网关

> 🔍 **知识点深度解析**
>
> **作用**：服务治理解决微服务架构下服务众多带来的管理问题，包括服务注册发现、负载均衡、熔断降级、限流、网关路由等，保证系统稳定运行。
>
> **原理**：API 网关是所有请求的统一入口，负责路由转发（根据 URL 路径转发到对应服务）、鉴权（校验 Token/权限）、限流（保护后端服务不被打垮）、日志（记录请求）、协议转换。网关基于过滤器链（Filter Chain）实现，请求经过一系列前置过滤器→转发到后端→后置过滤器处理响应。限流算法：计数器（固定窗口，有临界问题）、滑动窗口、漏桶（恒定速率流出）、令牌桶（恒定速率放令牌，允许突发）。
>
> **用法要点**：① Spring Cloud Gateway 配置：routes（id、uri: lb://service-name、predicates: Path=/api/user/**、filters: StripPrefix=1）；② 全局过滤器：GlobalFilter 接口，实现鉴权（从 Header 取 Token 校验）、日志（记录请求耗时）、限流（结合 Sentinel）；③ 限流：Sentinel Gateway 集成，按路由或 API 分组限流，令牌桶算法，配置 QPS 阈值；④ 熔断：Gateway 整合 Sentinel 或 Resilience4j，后端服务异常时返回降级响应；⑤ 跨域：网关层统一配置 CORS，避免每个服务单独配置；⑥ 服务间鉴权：网关校验用户 Token 后，将用户信息（userId）通过 Header 传递给下游服务，下游服务信任网关传入的用户信息（内网不直接暴露）；⑦ 灰度发布：网关按请求头/权重路由到不同版本服务，如 Header X-Version=v2 路由到 v2 版本；⑧ 网关选型：Spring Cloud Gateway（Spring 生态，响应式）、Kong（Nginx+Lua，高性能）、APISIX（国产，高性能）、Nginx（反向代理，简单场景）。

## 11. 分布式中间件

### 11.1 消息队列（RabbitMQ/Kafka）

> 🔍 **知识点深度解析**
>
> **作用**：消息队列（MQ）是分布式系统的核心组件，用于解耦、异步、削峰填谷。生产者发送消息到 MQ，消费者异步消费，提升系统吞吐量和可靠性。
>
> **原理**：消息队列核心模型：生产者（Producer）→Broker（消息服务器）→消费者（Consumer）。RabbitMQ 基于 AMQP 协议，模型：Exchange（交换机，接收生产者消息，按路由规则分发到 Queue）→Queue（队列，存储消息）→Consumer（消费）。Exchange 类型：direct（精确匹配 routingKey）、fanout（广播到所有绑定队列）、topic（通配符匹配）、headers（按 header 匹配）。Kafka 基于发布订阅，模型：Topic（主题，分区 Partition 并行）→Producer 发送到指定分区→Consumer Group 消费（一个分区只能被组内一个消费者消费），高吞吐、可持久化、支持回溯消费。
>
> **用法要点**：① 应用场景：异步处理（注册后异步发短信/邮件）、应用解耦（订单服务发消息，库存/积分服务各自消费）、削峰填谷（秒杀请求先入 MQ，消费者按能力消费）、最终一致性（分布式事务）；② RabbitMQ 核心：交换机+队列+绑定（Binding），生产者发消息到 Exchange 指定 routingKey，Exchange 按类型路由到 Queue，消费者监听 Queue；③ 消息可靠性：生产者确认（Publisher Confirm，消息到达 Broker 回调）、持久化（Exchange/Queue/Message 都持久化）、消费者手动 ACK（处理成功才确认，失败 requeue 或死信队列）；④ 死信队列（DLX）：消息被拒绝、过期、队列满时转发到死信交换机，用于处理失败消息；⑤ Kafka 核心：Topic 分区（Partition）提升并行度，副本（Replica）保证高可用，Producer 按 key 哈希选分区（同 key 同分区保证顺序），Consumer Group 消费（组内消费者数≤分区数）；⑥ Kafka 顺序性：同一分区内消息有序，跨分区无序，需要全局有序用单分区（牺牲并发）；⑦ 消息幂等：消费者可能重复消费（网络重试），业务层保证幂等（唯一 ID + 去重表、数据库唯一键、状态机）；⑧ 选型：RabbitMQ（功能丰富、延迟低、适合业务消息/延迟队列）、Kafka（高吞吐、适合日志/大数据/事件流）、RocketMQ（阿里开源，功能全面，适合电商金融）。

### 11.2 分布式事务

> 🔍 **知识点深度解析**
>
> **作用**：分布式事务解决微服务架构下一个业务操作涉及多个服务/数据库时的数据一致性问题，是分布式系统的核心难点。
>
> **原理**：CAP 定理：分布式系统无法同时满足一致性（Consistency）、可用性（Availability）、分区容错性（Partition tolerance），网络分区必然存在，所以只能在 CP 和 AP 间选择。BASE 理论：基本可用（Basically Available）、软状态（Soft State）、最终一致性（Eventually Consistent），是对 CAP 中 AP 的延伸，大多数互联网业务追求最终一致性而非强一致。分布式事务方案：2PC（两阶段提交，强一致，性能差，XA 协议）、TCC（Try-Confirm-Cancel，业务层面两阶段，性能好但侵入性强）、Saga（长事务，每个步骤有补偿操作，失败时反向补偿）、本地消息表（本地事务+消息表，定时重试，最终一致）、可靠消息最终一致性（MQ 事务消息）、最大努力通知。
>
> **用法要点**：① 2PC/XA：数据库层面支持，强一致，性能差（锁资源时间长），适合并发低、一致性要求极高的场景（金融转账）；② TCC：Try 预留资源（冻结库存）、Confirm 确认（扣减库存）、Cancel 取消（解冻库存），三个方法由业务实现，性能好但代码侵入性强，适合核心业务；③ Saga：每个服务提供正向操作和补偿操作，编排器按顺序调用，某步失败则反向调用已完成步骤的补偿，适合长流程业务（订单→支付→库存→物流）；④ 本地消息表：业务操作和写消息表在同一个本地事务，定时任务扫描消息表发送到 MQ，消费者消费，消费成功更新状态，失败重试，实现简单，最终一致，适合大多数场景；⑤ MQ 事务消息：RocketMQ 支持半消息（Half Message），生产者发送半消息→执行本地事务→提交/回滚消息→消费者消费，保证消息和本地事务的原子性；⑥ 最大努力通知：支付结果通知，支付服务多次回调商户，商户返回成功则停止，适合对一致性要求不高的场景；⑦ 选型原则：能不用分布式事务就不用（尽量单库事务），必须用时优先选最终一致性方案（本地消息表/MQ 事务消息），强一致场景用 TCC/XA；⑧ 框架：Seata（阿里开源，支持 AT/TCC/Saga/XA 模式，AT 模式无侵入，推荐入门）。

### 11.3 分布式锁与分库分表

> 🔍 **知识点深度解析**
>
> **作用**：分布式锁解决分布式系统下多个进程/机器互斥访问共享资源的问题；分库分表解决单库单表数据量过大导致的性能瓶颈。
>
> **原理**：分布式锁需满足：互斥性（同一时间只有一个客户端持有）、防死锁（持锁客户端崩溃后锁能自动释放）、可重入（同一客户端可多次获取）、高可用（锁服务本身不宕机）。Redis 分布式锁：SET key value NX EX seconds 原子加锁，value 设为唯一标识（UUID），释放用 Lua 脚本判断 value 相等再 DEL（防止误删）。Redisson 实现可重入锁（hash 结构存客户端ID+重入次数）、看门狗（自动续期）。ZooKeeper 分布式锁：临时顺序节点，最小节点获锁，监听前一个节点删除通知。
>
> **用法要点**：① Redis 分布式锁：SET lock:order:123 uuid NX EX 30，业务执行完 Lua 脚本释放；注意锁过期时间要大于业务执行时间，或用 Redisson 看门狗自动续期；② Redisson：RLock lock = redissonClient.getLock("key"); lock.lock(); try { ... } finally { lock.unlock(); }，支持可重入、公平锁、读写锁、联锁；③ 锁粒度：尽量减小锁范围和时间，只锁必要的共享资源，避免大锁；④ 分库分表原因：单表数据量超过千万（MySQL InnoDB B+ 树层级变深，查询变慢）、单库 QPS 过高、单库磁盘不足；⑤ 分库分表方式：垂直分库（按业务拆分，如用户库/订单库）、垂直分表（大字段拆到扩展表）、水平分库（同表数据按规则分到多个库）、水平分表（同库同表数据分到多个表）；⑥ 分片规则：范围分片（按时间/ID范围，易热点）、哈希分片（user_id % 分表数，均匀但范围查询麻烦）、一致性哈希（扩容迁移少）；⑦ 中间件：ShardingSphere（Apache 顶级项目，功能全面，推荐）、MyCat（代理模式，已少维护）；ShardingSphere-JDBC 客户端模式（应用层，无额外部署，推荐）、ShardingSphere-Proxy 代理模式（独立部署，对应用透明）；⑧ 分库分表难点：跨库 JOIN（数据冗余/应用层组装）、分布式事务（Seata）、排序分页（各库查询后归并）、全局唯一 ID（雪花算法 Snowflake、号段模式、UUID）；⑨ 注意：分库分表是最后手段，先优化 SQL+索引+读写分离+缓存，数据量确实到瓶颈再分。

### 12.1 Kubernetes 容器编排

> 🔍 **知识点深度解析**
>
> **作用**：Kubernetes（K8s）是容器编排平台，自动化部署、扩缩容、管理容器化应用，是云原生时代的操作系统，现代微服务部署的标准。
>
> **原理**：K8s 集群由 Master 节点（控制面）和 Worker 节点（工作节点）组成。Master 组件：API Server（统一入口，REST API）、etcd（集群状态存储，键值数据库）、Scheduler（调度 Pod 到节点）、Controller Manager（控制器，维护期望状态）。Worker 组件：kubelet（管理本节点 Pod）、kube-proxy（网络代理，Service 负载均衡）、容器运行时（Docker/containerd）。核心概念：Pod（最小调度单位，一个或多个容器共享网络和存储）、Deployment（管理 Pod 副本，声明式更新）、Service（Pod 访问入口，负载均衡，ClusterIP/NodePort/LoadBalancer）、Ingress（HTTP 路由入口）、Volume（存储）、ConfigMap/Secret（配置）。
>
> **用法要点**：① 核心资源：Pod（容器组，最小单位，一般不直接创建，用 Deployment 管理）、Deployment（声明副本数和更新策略，滚动更新）、Service（暴露 Pod，ClusterIP 集群内访问、NodePort 节点端口、LoadBalancer 云负载均衡）、Ingress（HTTP 路由，域名/路径转发到 Service，需要 Ingress Controller 如 Nginx Ingress）；② 存储：EmptyDir（临时存储，Pod 删除即失）、HostPath（挂载节点目录）、PV/PVC（持久卷/持久卷声明，解耦存储和使用）、StorageClass（动态供给 PV）；③ 配置：ConfigMap（普通配置，环境变量/挂载文件）、Secret（敏感信息，base64 编码，如密码/Token）；④ 调度：nodeSelector（节点选择）、亲和性（nodeAffinity/podAffinity，软硬亲和）、污点与容忍（Taint/Toleration，节点排斥 Pod）；⑤ 资源限制：resources.requests（请求资源，调度依据）、resources.limits（最大资源，超过限制 OOM）；⑥ HPA（自动扩缩容）：HorizontalPodAutoscaler，根据 CPU/内存/自定义指标自动调整 Pod 副本数；⑦ 健康检查：livenessProbe（存活探针，失败重启容器）、readinessProbe（就绪探针，失败从 Service 摘除）、startupProbe（启动探针，慢启动应用）；⑧ 常用命令：kubectl get pods/deploy/svc/ing、kubectl describe、kubectl logs、kubectl exec -it、kubectl apply -f、kubectl rollout status/undo；⑨ 学习路径：安装 minikube/kind 本地集群→核心资源→部署应用→Service/Ingress→存储配置→HPA/健康检查→生产集群（kubespray/kubeadm）。

### 12.2 Service Mesh 与可观测性

> 🔍 **知识点深度解析**
>
> **作用**：Service Mesh（服务网格）将服务间通信的治理能力（流量管理、安全、可观测性）从应用代码中剥离到 Sidecar 代理，让业务代码专注业务逻辑。可观测性（监控、日志、链路追踪）是分布式系统排障和优化的基础。
>
> **原理**：Service Mesh 架构：控制面（Control Plane，管理配置，如 Istiod）+ 数据面（Data Plane，Sidecar 代理，如 Envoy，与业务容器同 Pod）。所有进出业务容器的流量被 Sidecar 拦截（iptables 或 eBPF），Sidecar 负责服务发现、负载均衡、熔断、重试、mTLS 加密、遥测数据采集。业务代码无感知，不需要引入 SDK。
>
> **用法要点**：① Istio：最主流的 Service Mesh 实现，istioctl install 安装，自动注入 Sidecar（命名空间打 label istio-injection=enabled）；② 流量管理：VirtualService（路由规则，按权重/Header 路由，灰度发布）、DestinationRule（目标规则，定义 subset 版本、负载均衡策略、连接池）、Gateway（入口网关，替代 Ingress）；③ 灰度发布：DestinationRule 定义 v1/v2 subset，VirtualService 配置 weight 90/10，逐步调整流量；④ 安全：mTLS（服务间通信自动加密，PeerAuthentication 配置 STRICT 模式）、AuthorizationPolicy（授权策略，控制谁能调用谁）；⑤ 可观测性三大支柱：Metrics（指标，Prometheus 采集+Grafana 展示，如 QPS/延迟/错误率）、Logging（日志，ELK/Loki 收集分析）、Tracing（链路追踪，Jaeger/Zipkin/SkyWalking，追踪请求跨服务调用链）；⑥ Prometheus：时序数据库，pull 模式抓取 /metrics 端点，PromQL 查询，Alertmanager 告警；Grafana 可视化仪表盘；⑦ 日志方案：ELK（Elasticsearch+Logstash+Kibana）、EFK（Fluentd 替代 Logstash）、Loki（轻量，配合 Grafana）；应用日志输出到 stdout，由节点上的日志采集器收集；⑧ 链路追踪：OpenTelemetry（标准，统一 Trace/Metrics/Logs 采集）、Jaeger（CNCF 毕业项目）、SkyWalking（国产，无侵入，Java 生态友好）；traceId 贯穿整个请求链，span 表示一次调用；⑨ 学习路径：先理解 Service Mesh 概念→Istio 安装注入→流量管理灰度→安全 mTLS→可观测性三件套→生产实践。

## 13. 架构设计与性能调优

### 13.1 系统架构设计

> 🔍 **知识点深度解析**
>
> **作用**：架构设计是从业务需求出发，设计高可用、高性能、可扩展、可维护的系统方案，是高级开发者和架构师的核心能力。
>
> **原理**：架构设计核心原则：高内聚低耦合（模块内部紧密、模块之间松散）、单一职责（每个服务/模块只做一件事）、关注点分离（业务逻辑/数据存储/通信/运维分离）、无状态（服务不存会话状态，便于水平扩展，状态存外部存储）、可扩展（水平扩展加机器，垂直扩展加配置，优先水平）。高可用手段：冗余（多副本/多机房）、故障转移（自动切换）、降级（非核心功能关闭）、限流（保护系统）、熔断（防止级联故障）。
>
> **用法要点**：① 架构演进：单体架构（小团队快速启动）→垂直拆分（按业务拆模块）→微服务（服务独立部署）→服务网格（通信治理下沉）→Serverless（按需运行，免运维），根据团队和业务阶段选择，不要过度设计；② 高可用设计：服务无状态+多副本部署（K8s Deployment）、数据库主从复制+读写分离+故障转移（MHA/Orchestrator）、Redis 哨兵/集群、多可用区部署、异地多活（金融级）；③ 高性能设计：缓存（Redis 多级缓存：本地缓存 Caffeine+分布式缓存 Redis）、异步（MQ 削峰填谷）、并发（线程池/协程）、数据库优化（索引+分库分表+读写分离）、CDN（静态资源加速）、连接池（数据库/HTTP 连接复用）；④ 可扩展设计：水平扩展（无状态服务加机器）、数据分片（分库分表）、消息队列解耦、插件化架构；⑤ 常见架构模式：分层架构（表现层/业务层/数据层）、事件驱动架构（EDA，基于 MQ 事件）、CQRS（命令查询职责分离，读写分离到不同模型）、事件溯源（Event Sourcing，存事件而非状态）、六边形架构（端口与适配器，业务核心与外部隔离）；⑥ 技术选型：根据业务场景、团队熟悉度、社区生态、性能需求综合评估，不要盲目追新技术；成熟稳定优先（核心业务），新技术在非核心业务试点；⑦ 容量规划：预估 QPS/数据量/并发数，压测验证，预留 30%-50% 余量；⑧ 学习方法：研究大厂架构（阿里/美团/字节技术博客）、读架构相关书籍（《架构整洁之道》《设计数据密集型应用》DDIA）、参与开源项目、在项目中刻意练习架构设计。

### 13.2 性能调优实战

> 🔍 **知识点深度解析**
>
> **作用**：性能调优是在系统出现性能瓶颈时，通过分析定位和优化手段提升吞吐量、降低延迟，是高阶开发者的必备能力。
>
> **原理**：性能调优遵循「测量→定位→优化→验证」循环。先通过监控和压测发现瓶颈（CPU/内存/IO/网络），再用工具定位具体代码/SQL/配置，针对性优化，最后压测验证效果。性能指标：QPS（每秒查询数）、TPS（每秒事务数）、响应时间（RT，平均/P95/P99）、并发数、资源利用率（CPU/内存/磁盘 IO/网络）。
>
> **用法要点**：① JVM 调优：选择合适 GC 收集器（G1 通用、ZGC 低延迟），设置堆大小（-Xms=-Xmx，避免动态扩缩），新生代比例，避免 Full GC（频繁 Full GC 说明内存不足或内存泄漏）；用 jstat 看 GC 频率和耗时，Arthas 在线诊断，MAT 分析堆转储找内存泄漏；② MySQL 调优：索引优化（最左前缀、覆盖索引、避免索引失效）、SQL 优化（避免 SELECT *、大表 JOIN、深分页用游标）、配置优化（innodb_buffer_pool_size 设为物理内存 50%-70%、innodb_log_file_size、max_connections）、架构优化（读写分离、分库分表）；用 EXPLAIN 分析执行计划，慢查询日志定位慢 SQL；③ Redis 调优：合理使用数据结构、避免大 key（value 过大）、避免热 key（集中访问，本地缓存+多副本）、pipeline 批量操作、连接池优化、持久化策略（RDB+AOF 混合）、内存淘汰策略选择；用 redis-cli --latency 看延迟，slowlog 看慢命令；④ 前端性能优化：加载性能（代码分割懒加载、gzip 压缩、CDN、HTTP2、预加载 prefetch/preload）、渲染性能（虚拟滚动大列表、减少重排重绘、requestAnimationFrame、Web Worker 计算）、缓存（浏览器缓存 Cache-Control、Service Worker）；用 Lighthouse 跑分，Chrome Performance 面板分析；⑤ 系统级：CPU 密集型优化算法、增加 CPU；IO 密集型加缓存、异步化；网络优化减少请求数、压缩数据、就近接入；⑥ 压测工具：JMeter（功能全面）、Gatling（高性能，Scala 脚本）、wrk（HTTP 压测，轻量）、Locust（Python，分布式）；压测时逐步加压，找到拐点（QPS 上不去或 RT 飙升的点）；⑦ 调优原则：先优化业务逻辑和算法（收益最大），再优化框架和配置，最后加机器（水平扩展）；不要过早优化，先让系统跑起来再根据瓶颈优化；⑧ 建立性能基线：每次上线前压测，记录 QPS/RT，版本对比发现性能退化。

# 学习方法论与避坑指南

## 高效学习方法

1. **项目驱动学习**：不要只看视频/看书，每个知识点学完立刻写代码验证，用项目串联所有知识点。「看十遍不如写一遍」。
2. **费曼学习法**：学完一个知识点后，尝试用自己的话讲给别人听（或写技术博客），能讲清楚才是真懂了。
3. **刻意练习**：针对薄弱点（如算法、SQL 优化）集中练习，走出舒适区，而不是反复学已经掌握的内容。
4. **官方文档优先**：遇到问题先查官方文档，比博客更准确、更及时。Stack Overflow、GitHub Issues 也是好资源。
5. **建立知识体系**：用思维导图（XMind/幕布）整理知识点，建立关联，避免碎片化学习。
6. **定期复盘**：每周/每月回顾学了什么、做了什么、遇到什么问题，调整学习计划。
7. **交流分享**：加入技术社区（掘金、知乎、GitHub、微信群），和同行交流，参加技术分享。

## 常见避坑指南

| 坑 | 表现 | 正确做法 |
|----|------|---------|
| 只看不练 | 视频看了很多，代码写得少，遇到问题还是不会 | 每学一个知识点立刻写 Demo，用项目巩固 |
| 追求完美 | 想把所有细节搞懂再往下学，结果进度极慢 | 先会用，再深入原理，循序渐进，不要钻牛角尖 |
| 盲目追新 | 什么技术火就学什么，每个都浅尝辄止 | 先把主流技术（Vue3/Spring Boot/MySQL/Redis）学扎实，再按需扩展 |
| 复制粘贴 | 遇到问题直接复制 Stack Overflow 代码，不理解原理 | 理解代码为什么这样写，改成自己的，积累自己的代码库 |
| 忽视基础 | 直接学框架，Java/JS 基础不牢，遇到底层问题懵 | 基础是地基，框架是楼，地基不牢楼会塌，基础必须扎实 |
| 不做笔记 | 学过的东西很快忘，同一个问题反复查 | 写技术笔记/博客，整理自己的知识库，方便复习 |
| 不写注释 | 代码写完自己都看不懂，更别说别人 | 关键逻辑写注释，复杂算法写思路，好代码是自解释的 |
| 忽视英语 | 官方文档/报错信息看不懂，依赖翻译 | 技术英语词汇量不大，坚持读英文文档，慢慢就熟练了 |
