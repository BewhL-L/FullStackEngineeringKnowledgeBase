## 1. Spring Boot

### 1.1 概述

Spring Boot 是由 Pivotal 团队开发的基于 Spring 框架的快速开发脚手架，其核心设计理念是**"约定优于配置"（Convention over Configuration）**。它通过自动配置、起步依赖和内嵌服务器，极大简化了 Spring 应用的初始搭建和开发过程。

**核心定位**：
- 不是对 Spring 功能的增强，而是提供一种快速使用 Spring 的方式
- 整合了大量常用框架的默认配置，开箱即用
- 广泛应用于微服务架构，是 Spring Cloud 的基础

**版本演进**：

| 版本 | 发布年份 | 关键特性 |
|------|---------|---------|
| Spring Boot 1.x | 2014 | 初始版本，自动配置起步 |
| Spring Boot 2.x | 2018 | 基于 Spring 5，响应式 WebFlux，Micrometer 监控 |
| Spring Boot 3.x | 2022 | 基于 Spring 6，Jakarta EE 9+，Java 17+ 最低要求，AOT 编译 |

> 🔍 **知识点深度解析**
>
> **作用**：Spring Boot 是 Java 后端开发的事实标准，通过"约定优于配置"大幅降低 Spring 应用的搭建和开发成本。它不是新框架，而是 Spring 的快速开发脚手架，整合了自动配置、起步依赖、内嵌服务器三大核心能力。
>
> **原理**：自动配置通过 @EnableAutoConfiguration 触发，SpringFactoriesLoader 加载 META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports 中的自动配置类，每个自动配置类用 @ConditionalOnClass/@ConditionalOnMissingBean/@ConditionalOnProperty 等条件注解判断是否生效。起步依赖（Starter）是一组打包好的依赖描述符，parent POM 管理所有兼容版本，避免版本冲突。内嵌服务器（Tomcat/Jetty/Undertow）让应用打成可执行 JAR，java -jar 直接运行，不需要外部容器。
>
> **用法要点**：① 新项目用 Spring Boot 3.x（需 Java 17+，jakarta 包名）；② 用 start.spring.io 或 IDEA  Spring Initializr 快速创建项目；③ 依赖用 Starter（spring-boot-starter-web 等），不要手动找版本；④ 配置用 application.yml（层级清晰），多环境用 Profile；⑤ 排查自动配置用 --debug 看自动配置报告；⑥ 生产用 Actuator 监控（health/metrics/prometheus）；⑦ 面试常考：自动配置原理、Starter 原理、Bean 覆盖问题。

#### 1.2.1 自动配置（Auto-Configuration）

自动配置是 Spring Boot 最核心的特性。它通过 `@EnableAutoConfiguration` 注解触发，根据 classpath 中存在的依赖自动配置相应的 Bean。

**工作原理**：
1. 启动时通过 `SpringFactoriesLoader` 加载 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`
2. 逐个加载自动配置类（标注 `@AutoConfiguration`）
3. 通过条件注解 `@ConditionalOnClass`、`@ConditionalOnMissingBean`、`@ConditionalOnProperty` 等判断是否生效
4. 将符合条件的 Bean 注册到 IoC 容器

```java
// 典型的自动配置类
@AutoConfiguration
@ConditionalOnClass(DataSource.class)
@EnableConfigurationProperties(DataSourceProperties.class)
public class DataSourceAutoConfiguration {
    @Bean
    @ConditionalOnMissingBean
    public DataSource dataSource(DataSourceProperties properties) {
        return properties.initializeDataSourceBuilder().build();
    }
}
```

> 🔍 **知识点深度解析**
>
> **作用**：自动配置是 Spring Boot 的灵魂，根据 classpath 依赖自动装配 Bean，开发者不需要手动配置（如引入 web starter 自动配置 DispatcherServlet、Tomcat）。
>
> **原理**：@SpringBootApplication 包含 @EnableAutoConfiguration，后者导入 AutoConfigurationImportSelector，该类通过 SpringFactoriesLoader 加载 AutoConfiguration.imports 文件中的自动配置类全限定名。每个自动配置类用 @Conditional 系列注解做条件判断：@ConditionalOnClass（classpath 有某类才生效）、@ConditionalOnMissingBean（容器中没有该 Bean 才创建，用户自定义优先）、@ConditionalOnProperty（配置项满足才生效）。自动配置类按 @AutoConfigureBefore/@AutoConfigureAfter 排序。
>
> **用法要点**：① 自定义 Starter 时写自动配置类 + AutoConfiguration.imports；② 用户自定义 Bean 优先于自动配置（@ConditionalOnMissingBean）；③ 排查配置不生效率先用 --debug 看自动配置报告；④ Spring Boot 2.7+ 用 AutoConfiguration.imports（替代 spring.factories）；⑤ 自动配置类不要被组件扫描到（用 @AutoConfiguration 不是 @Configuration）；⑥ 面试必考点：自动配置原理、条件注解、Starter 自定义。

#### 1.2.2 起步依赖（Starter）

Starter 是一组方便的依赖描述符，将相关依赖打包在一起，避免手动管理大量依赖和版本冲突。

| Starter | 用途 |
|---------|------|
| spring-boot-starter-web | Web 开发（内嵌 Tomcat + Spring MVC） |
| spring-boot-starter-data-jpa | JPA 数据访问（Hibernate） |
| spring-boot-starter-data-redis | Redis 操作（Lettuce 默认） |
| spring-boot-starter-security | 安全认证授权 |
| spring-boot-starter-test | 测试（JUnit + Mockito + AssertJ） |
| spring-boot-starter-actuator | 生产监控 |
| mybatis-plus-boot-starter | MyBatis-Plus 整合 |

> 🔍 **知识点深度解析**
>
> **作用**：Starter 解决"依赖地狱"，将一组相关依赖打包（如 web starter 包含 spring-mvc、tomcat、jackson、validation），parent POM 管理所有版本，开发者不需要关心版本兼容。
>
> **原理**：Starter 本身是一个空 JAR（只有 pom.xml），通过依赖传递引入相关库。spring-boot-starter-parent 管理所有依赖版本（dependencyManagement），子项目继承后不需要写 version。自定义 Starter 命名规范：xxx-spring-boot-starter（第三方）或 spring-boot-starter-xxx（官方），包含自动配置类 + AutoConfiguration.imports。
>
> **用法要点**：① 用官方 Starter（spring-boot-starter-xxx），第三方用 xxx-spring-boot-starter；② 不要手动指定版本（parent 已管理，除非需要覆盖）；③ 自定义 Starter：自动配置类 + META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports；④ 排除冲突依赖：<exclusions> 排除；⑤ 注意 starter 传递依赖可能引入不需要的库（用 mvn dependency:tree 查看）。

### 1.3 常用用法

#### 1.3.1 快速创建项目

```xml
<!-- pom.xml 核心配置 -->
<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>3.2.0</version>
</parent>

<dependencies>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>
</dependencies>
```

```java
// 启动类
@SpringBootApplication
public class Application {
    public static void main(String[] args) {
        SpringApplication.run(Application.class, args);
    }
}
```

```java
// REST 控制器
@RestController
@RequestMapping("/api/users")
public class UserController {
    @GetMapping("/{id}")
    public User getUser(@PathVariable Long id) {
        return userService.findById(id);
    }
}
```

> 🔍 **知识点深度解析**
>
> **作用**：Spring Boot 项目标准结构：parent POM + Starter 依赖 + @SpringBootApplication 启动类 + 分层架构（controller/service/mapper/entity）。
>
> **原理**：@SpringBootApplication = @Configuration + @EnableAutoConfiguration + @ComponentScan。启动时 SpringApplication.run 创建 Spring 容器，执行 ApplicationRunner/CommandLineRunner，启动内嵌 Tomcat。@RestController = @Controller + @ResponseBody，返回值自动序列化为 JSON（Jackson）。@PathVariable 绑定 URL 路径变量。
>
> **用法要点**：① 启动类放在根包（com.example.app），组件扫描默认扫描该包及子包；② 分层：controller（接口）→ service（业务）→ mapper（数据）→ entity（实体）；③ 接口统一返回 Result<T>（code/message/data）；④ 全局异常处理 @RestControllerAdvice；⑤ 启动类不要放默认包（会扫描所有包，很慢）；⑥ 用 IDEA Spring Initializr 或 start.spring.io 创建。

#### 1.3.2 配置文件

**application.yml**（推荐，层级清晰）：

```yaml
server:
  port: 8080
spring:
  application:
    name: my-app
  datasource:
    url: jdbc:mysql://localhost:3306/mydb
    username: root
    password: ${DB_PASSWORD}
  profiles:
    active: dev
```

**多环境配置**：
- `application-dev.yml` — 开发环境
- `application-test.yml` — 测试环境
- `application-prod.yml` — 生产环境

通过 `spring.profiles.active=dev` 激活，或命令行 `--spring.profiles.active=prod`。

> 🔍 **知识点深度解析**
>
> **作用**：配置文件管理应用参数（端口、数据库、日志等），多环境 Profile 实现开发/测试/生产配置隔离。
>
> **原理**：Spring Boot 配置优先级（从高到低）：命令行参数 > 环境变量 > application-{profile}.yml > application.yml > 配置属性绑定默认值。${DB_PASSWORD} 引用环境变量（敏感配置不写在文件里）。Profile 激活后加载对应配置文件，覆盖默认配置。@Profile("dev") 注解让 Bean 只在指定环境生效。
>
> **用法要点**：① 用 yml 不用 properties（层级清晰，支持列表）；② 敏感配置用环境变量（${DB_PASSWORD}）或配置中心（Nacos）；③ 多环境用 Profile（dev/test/prod），启动时指定；④ 配置优先级：命令行 > 环境变量 > profile > 默认；⑤ 生产配置不要打包进代码（用环境变量或配置中心）；⑥ 配置项用 @ConfigurationProperties 绑定（类型安全）。

#### 1.3.3 配置属性绑定

```java
@ConfigurationProperties(prefix = "app")
@Component
@Data
public class AppProperties {
    private String name = "default";
    private int timeout = 30;
    private List<String> allowedOrigins = new ArrayList<>();
}
```

```yaml
app:
  name: 我的应用
  timeout: 60
  allowed-origins:
    - http://localhost:3000
    - https://example.com
```

> 🔍 **知识点深度解析**
>
> **作用**：@ConfigurationProperties 将配置文件属性绑定到 Java 对象（类型安全、支持校验、IDE 自动补全），比 @Value 更适合批量配置。
>
> **原理**：@EnableConfigurationProperties 或 @ConfigurationPropertiesScan 启用属性绑定，Spring Boot 通过反射将 yml 属性注入到对象字段（支持嵌套对象、List、Map）。prefix 指定配置前缀（app.name → name 字段）。支持 JSR-303 校验（@NotNull/@Min/@Email）。松绑定：app.allowed-origins → allowedOrigins（kebab-case 转 camelCase）。
>
> **用法要点**：① 批量配置用 @ConfigurationProperties（比 @Value 好）；② 加 @Validated + JSR-303 注解做配置校验；③ 加 spring-boot-configuration-processor 生成元数据（IDE 自动补全）；④ 用 @ConfigurationPropertiesScan 扫描（不需要 @Component）；⑤ 敏感配置不要绑定到对象日志中打印；⑥ 配置变更：@RefreshScope（Nacos 动态刷新）。

### 1.4 注意事项

1. **版本兼容**：Spring Boot 3.x 需要 Java 17+，且包名从 `javax.*` 迁移到 `jakarta.*`，升级时需注意
2. **自动配置排查**：启动时加 `--debug` 可查看自动配置报告，了解哪些配置生效/未生效及原因
3. **配置优先级**：命令行参数 > 环境变量 > application-{profile}.yml > application.yml，高优先级覆盖低优先级
4. **Bean 覆盖**：Spring Boot 2.1+ 默认禁止 Bean 覆盖，自定义 Bean 与自动配置冲突时报错，用 `@ConditionalOnMissingBean` 或 `spring.main.allow-bean-definition-overriding=true`
5. **热部署**：开发时使用 `spring-boot-devtools` 实现热重启，但生产环境必须排除
6. **打包方式**：默认打为可执行 JAR（`java -jar`），需 WAR 部署时改 `<packaging>war</packaging>` 并继承 `SpringBootServletInitializer`

> 💡 **深度讲解**：Spring Boot 的本质是"约定+自动配置+起步依赖"三位一体。自动配置的核心是条件注解驱动的按需装配——它不是魔法，而是在启动时扫描 classpath，根据你引入了哪些依赖来决定初始化哪些 Bean。比如引入了 `spring-boot-starter-web`，classpath 中有 `DispatcherServlet`，自动配置就会初始化 Spring MVC；引入了 `spring-boot-starter-data-redis`，就会自动配置 `RedisTemplate`。起步依赖则解决了"依赖地狱"——不需要自己找版本号，parent POM 已经管理好了所有兼容版本。理解了这两点，Spring Boot 的大部分"神奇"行为都能解释清楚。遇到配置不生效时，第一反应应该是看自动配置报告（`--debug`），而不是瞎猜。
>
> **📝 精简总结**：Spring Boot 以约定优于配置为核心，通过自动配置（条件注解驱动）+ 起步依赖（Starter 一站式依赖）+ 内嵌服务器实现快速开发；配置用 yml，多环境用 Profile，属性绑定用 `@ConfigurationProperties`；注意 3.x 需 Java 17+/jakarta 包名，Bean 覆盖默认禁用，排查用 `--debug` 看自动配置报告。

## 2. MyBatis-Plus

### 2.1 概述

MyBatis-Plus（简称 MP）是基于 MyBatis 的增强工具，在 MyBatis 基础上只做增强不做改变，为简化开发、提高效率而生。由苞米豆团队开发，是国内最流行的 MyBatis 增强框架。

**核心定位**：
- 内置通用 Mapper 和 Service，单表 CRUD 零 SQL
- 强大的条件构造器（QueryWrapper/LambdaQueryWrapper）
- 支持代码生成器、分页插件、逻辑删除、自动填充等
- 兼容原生 MyBatis，可平滑迁移

> 🔍 **知识点深度解析**
>
> **作用**：MyBatis-Plus 是 MyBatis 的增强版，内置通用 CRUD（单表零 SQL）、条件构造器、分页、逻辑删除、自动填充等，大幅减少重复代码。国内中后台项目标配。
>
> **原理**：MP 启动时扫描 @TableName 注解的实体类，通过 MyBatis 拦截器（Interceptor）在 SQL 执行前自动生成通用 SQL（insert/update/delete/selectById）。BaseMapper 接口提供 17 个通用方法，IService 提供更丰富的业务方法。条件构造器 QueryWrapper 用链式调用拼接 WHERE 条件，LambdaQueryWrapper 用方法引用（实体类::getXxx）避免硬编码字段名。分页插件 PaginationInnerInterceptor 拦截 SQL 自动加 LIMIT 和 COUNT 查询。
>
> **用法要点**：① 实体类加 @TableName/@TableId/@TableField；② Mapper 继承 BaseMapper<T>（自动获得 CRUD）；③ Service 继承 ServiceImpl<Mapper, T>；④ 复杂查询用 LambdaQueryWrapper（避免字段名硬编码）；⑤ 分页用 Page<T> + PaginationInnerInterceptor；⑥ 逻辑删除：@TableLogic + 全局配置；⑦ 自动填充：MetaObjectHandler（createTime/updateTime）；⑧ 代码生成器：AutoGenerator 生成 entity/mapper/service/controller。

### 2.2 核心特性

**通用 Mapper**：继承 BaseMapper 自动获得 insert/deleteById/updateById/selectById/selectList 等 17 个方法。

**条件构造器**：

```java
// Lambda 条件构造器（推荐，类型安全）
List<User> users = userMapper.selectList(
    new LambdaQueryWrapper<User>()
        .like(User::getName, "张")
        .ge(User::getAge, 18)
        .orderByDesc(User::getCreateTime)
);
```

**分页插件**：

```java
Page<User> page = new Page<>(1, 10);
Page<User> result = userMapper.selectPage(page, queryWrapper);
// result.getRecords() 当前页数据
// result.getTotal() 总条数
```

**其他特性**：逻辑删除（@TableLogic）、自动填充（MetaObjectHandler）、乐观锁（@Version）、代码生成器、多租户、动态表名。

> 🔍 **知识点深度解析**
>
> **作用**：MP 的核心特性让单表 CRUD 零 SQL，条件构造器类型安全，分页自动处理，逻辑删除/自动填充/乐观锁等常见需求内置支持。
>
> **原理**：通用 Mapper 通过 MyBatis 拦截器在启动时生成 SQL（insert 用所有非空字段，updateById 用主键更新）。条件构造器用 StringBuilder 拼接 SQL 片段（where/and/or/like/between），Lambda 版本通过序列化代理获取字段名（避免硬编码）。分页插件拦截 selectPage 方法，先查 COUNT 再查分页数据（LIMIT offset, size）。逻辑删除：查询自动加 deleted=0，删除变成 UPDATE deleted=1。自动填充：insert/update 时通过 MetaObjectHandler 自动设置 createTime/updateTime。
>
> **用法要点**：① 优先用 LambdaQueryWrapper（字段名变更编译报错）；② 分页必须配置 PaginationInnerInterceptor（否则不分页）；③ 逻辑删除：@TableLogic + global-config.db-config.logic-delete-field；④ 自动填充：实现 MetaObjectHandler，@TableField(fill=FieldFill.INSERT)；⑤ 乐观锁：@Version + OptimisticLockerInnerInterceptor；⑥ 复杂查询（多表/聚合）写 XML（MP 不替代 MyBatis）；⑦ 代码生成器生成基础代码，业务逻辑自己写。

### 2.3 常用用法

**标准三层结构**：

```java
// Entity
@Data
@TableName("user")
public class User {
    @TableId(type = IdType.AUTO)
    private Long id;
    private String name;
    private Integer age;
    @TableLogic
    private Integer deleted;
    @TableField(fill = FieldFill.INSERT)
    private LocalDateTime createTime;
}

// Mapper
public interface UserMapper extends BaseMapper<User> {}

// Service
public interface UserService extends IService<User> {}
@Service
public class UserServiceImpl extends ServiceImpl<UserMapper, User> implements UserService {}
```

**条件查询与分页**：

```java
Page<User> page = new Page<>(pageNum, pageSize);
LambdaQueryWrapper<User> wrapper = new LambdaQueryWrapper<User>()
    .like(StringUtils.hasText(name), User::getName, name)
    .ge(age != null, User::getAge, age)
    .orderByDesc(User::getCreateTime);
Page<User> result = userService.page(page, wrapper);
```

> 🔍 **知识点深度解析**
>
> **作用**：MP 标准用法：Entity（注解映射表）→ Mapper（继承 BaseMapper）→ Service（继承 ServiceImpl）→ Controller（调用 Service）。条件构造器支持条件参数（第一个 boolean 参数，true 才拼接条件）。
>
> **原理**：ServiceImpl 封装了 BaseMapper 的批量操作（saveBatch 用 JDBC 批量插入）。条件构造器的条件参数（boolean condition）实现动态 SQL（参数非空才加条件，替代 MyBatis 的 <if> 标签）。分页查询返回 Page 对象，包含 records（当前页数据）、total（总数）、current（当前页）、size（每页条数）。
>
> **用法要点**：① 条件参数：like(condition, column, val)，condition 为 true 才拼接（实现动态查询）；② 分页用 Page<T>，不要自己写 LIMIT；③ Service 层写业务逻辑，Controller 只做参数校验和调用；④ 批量操作用 saveBatch/updateBatchById（性能好）；⑤ 查询单条用 getOne（多条抛异常，用 false 参数不抛异常）；⑥ 复杂 SQL 写 XML（MP 不替代 MyBatis 的自定义 SQL）。

### 2.4 注意事项

1. **分页插件必须配置**：不配置 PaginationInnerInterceptor，selectPage 不会分页（返回全部数据）
2. **逻辑删除全局配置**：@TableLogic 配合 global-config，否则需要每个字段单独配置
3. **updateById 只更新非空字段**：null 字段不会更新，要更新为 null 用 UpdateWrapper 的 set 方法
4. **Lambda 构造器序列化**：LambdaQueryWrapper 用序列化代理获取字段名，实体类必须可序列化
5. **大字段性能**：查询大表时用 select 指定字段，避免 select *
6. **事务管理**：MP 的方法默认不在事务中，批量操作要加 @Transactional
7. **与 MyBatis 共存**：MP 不影响自定义 XML SQL，两者可混用

> 💡 **深度讲解**：MyBatis-Plus 的核心价值是"单表 CRUD 零 SQL"。它通过 MyBatis 拦截器在启动时为每个实体生成通用 SQL，配合条件构造器实现类型安全的动态查询。LambdaQueryWrapper 用方法引用替代字段名字符串，字段重命名时编译报错，比 XML 的 <if> 更安全。分页插件自动处理 COUNT 和 LIMIT，逻辑删除让删除变成更新（数据可恢复），自动填充统一处理 createTime/updateTime。但 MP 不是银弹——多表关联、复杂聚合查询还是要写 XML。最佳实践是：单表用 MP，复杂查询用 MyBatis XML，两者结合。
>
> **📝 精简总结**：MyBatis-Plus=MyBatis增强；核心=BaseMapper(通用CRUD)+LambdaQueryWrapper(类型安全条件)+PaginationInnerInterceptor(分页)；实体=@TableName/@TableId/@TableLogic/@TableField；用法=Entity→Mapper(继承BaseMapper)→Service(继承ServiceImpl)；注意=分页插件必配/updateById非空更新/复杂查询写XML。

## 3. MySQL

### 3.1 概述

MySQL 是最流行的开源关系型数据库，由瑞典 MySQL AB 公司开发，现属 Oracle。广泛应用于 Web 应用，是 LAMP/LNMP 架构的核心组件。InnoDB 是默认存储引擎（支持事务、行锁、外键）。

**核心特性**：
- ACID 事务支持（InnoDB）
- 多种存储引擎（InnoDB/MyISAM/Memory）
- 主从复制、读写分离
- 丰富的索引类型（B+树、哈希、全文）
- SQL 标准兼容，生态丰富

> 🔍 **知识点深度解析**
>
> **作用**：MySQL 是最流行的开源关系型数据库，中后台应用的数据存储标准。InnoDB 引擎支持事务、行锁、外键、MVCC，是默认引擎。
>
> **原理**：MySQL 架构：连接器（认证/连接管理）→ 查询缓存（8.0 移除）→ 分析器（词法/语法分析）→ 优化器（执行计划）→ 执行器（调用存储引擎）→ 存储引擎（InnoDB/MyISAM）。InnoDB 存储结构：表空间（ibd 文件）→ 段（数据段/索引段）→ 区（64页，1MB）→ 页（16KB，最小IO单位）→ 行。事务通过 redo log（持久性）+ undo log（回滚/MVCC）+ MVCC（多版本并发控制）实现 ACID。
>
> **用法要点**：① 用 InnoDB（支持事务/行锁，MyISAM 已不推荐）；② 字符集用 utf8mb4（支持 emoji）；③ 主键用自增 BIGINT（不要用 UUID，聚簇索引性能差）；④ 字段尽量 NOT NULL（NULL 影响索引和统计）；⑤ 用 DECIMAL 存金额（不要用 FLOAT/DOUBLE，精度丢失）；⑥ 时间用 DATETIME（范围大，TIMESTAMP 2038 问题）；⑦ 面试必考点：索引原理、事务隔离级别、MVCC、锁。

### 3.2 核心特性

**索引**：B+树索引（聚簇索引/二级索引）、覆盖索引、最左前缀原则、索引下推（ICP）。

**事务隔离级别**：
- 读未提交（Read Uncommitted）：可能脏读
- 读已提交（Read Committed）：解决脏读，可能不可重复读
- 可重复读（Repeatable Read，MySQL默认）：解决不可重复读，可能幻读（MVCC+间隙锁解决）
- 串行化（Serializable）：最高隔离，性能差

**锁机制**：行锁（共享锁/排他锁）、间隙锁（Gap Lock）、临键锁（Next-Key Lock）、表锁、意向锁。

> 🔍 **知识点深度解析**
>
> **作用**：索引提升查询速度（B+树 O(log n)），事务保证数据一致性，锁控制并发访问。三者是 MySQL 性能和正确性的核心。
>
> **原理**：InnoDB 索引是 B+树（叶子节点双向链表，非叶子节点只存键），聚簇索引叶子节点存完整行数据，二级索引叶子节点存主键值（回表查询）。覆盖索引：查询字段都在索引中，不需要回表。最左前缀：联合索引 (a,b,c) 可用于 a、a,b、a,b,c 查询。MVCC：每行有隐藏字段（trx_id 事务ID、roll_pointer 回滚指针），快照读通过 undo log 版本链 + ReadView 实现一致性视图，解决不可重复读。锁：行锁锁索引记录，间隙锁锁索引间隙（防止幻读），临键锁=行锁+间隙锁（左开右闭）。
>
> **用法要点**：① 高频查询字段建索引，低基数字段（性别）不要建；② 联合索引遵循最左前缀，等值在前范围在后；③ 用 EXPLAIN 看执行计划（type/key/rows/Extra）；④ 避免索引失效：函数/隐式类型转换/like '%xx'/OR 非索引字段；⑤ 默认隔离级别 RR（可重复读），一般不需要改；⑥ 死锁：固定加锁顺序、减少事务大小、用较低隔离级别；⑦ 大事务拆小事务（锁持有时间短）。

### 3.3 常用用法

**建表规范**：

```sql
CREATE TABLE `user` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键',
  `username` VARCHAR(50) NOT NULL COMMENT '用户名',
  `email` VARCHAR(100) DEFAULT NULL COMMENT '邮箱',
  `age` TINYINT UNSIGNED DEFAULT NULL COMMENT '年龄',
  `status` TINYINT NOT NULL DEFAULT 1 COMMENT '状态 1正常 0禁用',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `deleted` TINYINT NOT NULL DEFAULT 0 COMMENT '逻辑删除',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_username` (`username`),
  KEY `idx_status_create` (`status`, `create_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';
```

**查询优化**：

```sql
-- 避免 SELECT *，只查需要的字段
SELECT id, username, create_time FROM user WHERE status = 1;

-- 分页优化（深分页）
SELECT * FROM user WHERE id > (SELECT id FROM user ORDER BY id LIMIT 1000000, 1) LIMIT 10;
```

> 🔍 **知识点深度解析**
>
> **作用**：建表规范和查询优化是 MySQL 性能的基础。合理的表结构和索引设计避免后期性能问题。
>
> **原理**：自增主键保证聚簇索引顺序插入（性能好，页分裂少）。utf8mb4 支持 4 字节字符（emoji）。NOT NULL 字段节省空间（NULL 需要额外标记）且索引统计更准确。create_time/update_time 用 DEFAULT CURRENT_TIMESTAMP 和 ON UPDATE 自动维护。深分页 LIMIT 1000000,10 需要扫描 1000010 行，用子查询延迟关联（先查 id 再查数据）减少回表。
>
> **用法要点**：① 主键自增 BIGINT UNSIGNED；② 字段加 COMMENT（表注释）；③ 唯一索引 uk_前缀，普通索引 idx_前缀；④ 避免 SELECT *（只查需要的字段，可能覆盖索引）；⑤ 深分页用延迟关联或游标分页（WHERE id > lastId）；⑥ 大表加索引用 pt-online-schema-change（避免锁表）；⑦ 定期用 EXPLAIN 分析慢查询。

### 3.4 注意事项

1. **避免 SELECT ***：只查需要的字段，减少网络传输和内存，可能命中覆盖索引
2. **深分页优化**：LIMIT offset, size 在 offset 大时性能差，用延迟关联或游标分页
3. **索引失效场景**：函数操作、隐式类型转换、like '%xx'、OR 非索引字段、!= 操作
4. **事务大小**：大事务持有锁时间长，容易死锁和主从延迟，拆分为小事务
5. **字符集**：用 utf8mb4（不是 utf8，utf8 最多 3 字节不支持 emoji）
6. **连接数**：max_connections 合理设置，应用连接池总和不超过
7. **主从延迟**：读写分离时注意主从延迟，强一致读走主库

> 💡 **深度讲解**：MySQL 的核心是 InnoDB 引擎的 B+树索引 + MVCC + 锁机制。索引让查询从全表扫描 O(n) 降到 O(log n)，但索引不是越多越好（写操作要维护所有索引，占空间）。事务通过 redo log（崩溃恢复）+ undo log（回滚/MVCC）实现 ACID，默认 RR 隔离级别用 MVCC + 间隙锁解决幻读。性能优化三板斧：合理建索引（高频查询字段、联合索引最左前缀）、优化 SQL（避免索引失效、避免 SELECT *、深分页优化）、表结构设计（自增主键、NOT NULL、合适字段类型）。排查慢查询：开启 slow_query_log，用 EXPLAIN 看执行计划，看 type（ALL 全表扫描要优化）、key（实际用的索引）、rows（扫描行数）、Extra（Using filesort/Using temporary 要优化）。
>
> **📝 精简总结**：MySQL=开源关系型数据库(InnoDB)；核心=B+树索引(聚簇/二级/覆盖)+MVCC(undo log版本链)+锁(行锁/间隙锁/临键锁)；事务=ACID+4隔离级别(RR默认)；优化=合理索引+避免索引失效+EXPLAIN分析+深分页优化；注意=utf8mb4/自增主键/大事务拆分/主从延迟。

## 4. Redis

### 4.1 概述

Redis 是基于内存的键值对数据库，性能极高（QPS 10万+），支持丰富数据结构（String/Hash/List/Set/ZSet+Bitmap/HLL/Geo/Stream），支持持久化（RDB/AOF）和高可用（主从/哨兵/Cluster）。最常用作缓存、会话存储、排行榜、分布式锁。

> 🔍 **知识点深度解析**
>
> **作用**：Redis 是内存 KV 数据库，缓存是最主要用途（减轻数据库压力），也用于会话、排行榜、分布式锁、消息队列等。性能极高（单线程 10万 QPS）。
>
> **原理**：Redis 单线程模型（6.0 多线程 IO，命令执行仍单线程），基于内存操作+IO 多路复用（epoll）实现高性能。数据结构底层多种编码：String（int/embstr/raw SDS）、Hash（ziplist/hashtable）、List（quicklist）、Set（intset/hashtable）、ZSet（ziplist/skiplist+hashtable）。持久化：RDB（快照，bgsave fork 子进程）、AOF（写命令日志，everysec 刷盘）、混合持久化（4.0+）。过期策略：惰性删除+定期删除。内存淘汰：LRU/LFU。
>
> **用法要点**：① 缓存用 allkeys-lru/lfu 淘汰策略；② 基本类型用 String，对象用 Hash（字段可单独更新）；③ 排行榜用 ZSet，消息队列用 Stream（5.0+）；④ 分布式锁用 Redisson（可重入+看门狗续期）；⑤ 持久化用 AOF everysec + RDB 备份；⑥ 缓存三大问题：穿透（布隆+空值）、击穿（互斥锁+逻辑过期）、雪崩（TTL随机+高可用）；⑦ 高可用：中小规模哨兵，大规模 Cluster（16384槽）。

### 4.2 核心特性

**五大数据结构**：String（缓存/计数器/锁）、Hash（对象存储）、List（队列/最新列表）、Set（去重/集合运算）、ZSet（排行榜/延迟队列）。

**持久化**：RDB（快照，恢复快可能丢数据）、AOF（日志，数据安全文件大）、混合持久化（兼顾）。

**高可用**：主从复制（读写分离）、哨兵（自动故障转移）、Cluster（数据分片+高可用，16384哈希槽）。

> 🔍 **知识点深度解析**
>
> **作用**：丰富数据结构是 Redis 的核心优势（比 Memcached 只支持 String 强），不同场景选合适结构。持久化保证重启不丢数据，高可用保证服务不中断。
>
> **原理**：主从复制：全量复制（bgsave RDB + repl_backlog 积压命令）、增量复制（offset + repl_backlog）。哨兵：主观下线→客观下线（quorum）→选举领头哨兵→选最优从库提升。Cluster：16384 槽分配给主节点，key 槽位=CRC16(key)%16383，MOVED/ASK 重定向，Hash Tag 让相关 key 同槽。
>
> **用法要点**：① 数据结构选择：String 通用、Hash 存对象、List 队列、Set 去重/集合、ZSet 排序；② 持久化：AOF everysec（最多丢1秒）+ RDB 备份；③ 高可用：哨兵至少3节点，Cluster 至少3主3从；④ Cluster 多键操作用 Hash Tag；⑤ 不要用大 key（>10KB）和热 key（分片或本地缓存）；⑥ 不要用 KEYS *（阻塞），用 SCAN。

### 4.3 常用用法

**缓存模式（Cache Aside）**：

```java
// 读：先缓存后数据库
public User getUser(Long id) {
    String key = "user:" + id;
    User user = redisTemplate.opsForValue().get(key);
    if (user != null) return user;
    user = userMapper.selectById(id);
    if (user != null) {
        redisTemplate.opsForValue().set(key, user, 3600 + random(600), SECONDS);
    } else {
        redisTemplate.opsForValue().set(key, NULL_USER, 60, SECONDS); // 缓存空值
    }
    return user;
}
// 写：先更新数据库再删缓存
@Transactional
public void updateUser(User user) {
    userMapper.updateById(user);
    redisTemplate.delete("user:" + user.getId());
}
```

**分布式锁（Redisson）**：

```java
RLock lock = redissonClient.getLock("order:" + orderId);
try {
    boolean acquired = lock.tryLock(10, 30, TimeUnit.SECONDS);
    if (acquired) {
        // 业务逻辑
    }
} finally {
    if (lock.isHeldByCurrentThread()) lock.unlock();
}
```

> 🔍 **知识点深度解析**
>
> **作用**：Cache Aside 是最常用的缓存模式（读先缓存后DB，写先DB后删缓存），Redisson 分布式锁实现互斥（可重入+看门狗自动续期）。
>
> **原理**：Cache Aside：读缓存 miss 查 DB，查到写缓存（TTL 随机防雪崩），查不到缓存空值（防穿透）。写：先更新 DB 再删缓存（不是更新缓存，避免并发脏数据）。Redisson 锁：Hash 结构（field=线程标识，value=重入次数），加锁 Lua 脚本原子操作，看门狗每 10 秒检查续期到 30 秒（防止业务未完成锁过期），释放 Lua 脚本判断线程标识才删。
>
> **用法要点**：① 缓存用 Cache Aside（先DB后删缓存）；② TTL 加随机值防雪崩；③ 空值缓存短 TTL（60秒）防穿透；④ 分布式锁用 Redisson（不要自己实现）；⑤ 锁粒度小（锁业务ID不是锁全表）；⑥ 加锁失败有降级策略；⑦ 数据库唯一索引是最终兜底。

### 4.4 注意事项

1. **缓存和数据库一致性**：用 Cache Aside（先更新 DB 再删缓存），一致性要求高用延迟双删或 binlog 监听
2. **避免大 key/热 key**：大 key 阻塞网络和删除，热 key 单节点瓶颈（分片或本地缓存）
3. **不要用 KEYS ***：阻塞主线程，用 SCAN 迭代
4. **持久化 fork 阻塞**：大内存实例 bgsave fork 耗时，注意 maxmemory 设置
5. **内存淘汰策略**：缓存场景用 allkeys-lru/lfu，不要用默认 noeviction
6. **Cluster 多键操作**：跨槽不支持，用 Hash Tag 让相关 key 同槽
7. **不要用 Redis 存强一致数据**：缓存是最终一致，账户余额等用数据库

> 💡 **深度讲解**：Redis 的核心是"内存+丰富数据结构+单线程"。单线程避免了锁竞争，基于内存操作+IO 多路复用实现 10万+ QPS。数据结构底层用多种编码自动优化（小数据量 ziplist 省内存，大数据量转 hashtable/skiplist）。缓存是最主要用途，三大问题（穿透/击穿/雪崩）都有成熟解决方案。持久化用 AOF everysec（最多丢1秒）+ RDB 备份，高可用用哨兵（中小）或 Cluster（大规模，16384槽分片）。分布式锁用 Redisson（可重入+看门狗续期，不要自己用 SET NX 实现）。注意：Redis 是缓存不是数据库，不要存强一致数据（账户余额），不要用大 key/热 key，不要用 KEYS *。
>
> **📝 精简总结**：Redis=内存KV数据库；结构=String/Hash/List/Set/ZSet+Bitmap/HLL/Geo/Stream；持久化=RDB(快照)+AOF(日志)+混合；高可用=主从+哨兵(中小)/Cluster(16384槽)；缓存=Cache Aside(先DB后删缓存)，穿透(布隆+空值)/击穿(锁+逻辑过期)/雪崩(TTL随机)；锁=Redisson(可重入+看门狗)；注意=大key热key/不用KEYS*/不存强一致数据。

## 5. Vue3

### 5.1 概述

Vue3 是 Vue.js 的重大版本升级（2020年发布），用 TypeScript 重写，引入 Composition API、Proxy 响应式、Fragment、Teleport、Suspense 等新特性，性能和开发体验全面提升。是目前 Vue 的主力版本。

> 🔍 **知识点深度解析**
>
> **作用**：Vue3 是当前 Vue 主力版本，Composition API 解决了 Vue2 Options API 在复杂组件中逻辑分散、复用困难的问题，Proxy 响应式解决了 Vue2 新增属性/数组索引的局限性。
>
> **原理**：响应式用 Proxy（代理整个对象，拦截 get/set/deleteProperty 等13种操作），替代 Vue2 的 Object.defineProperty（只能拦截已有属性）。编译优化：静态提升（静态节点提到 render 外）、patchFlag（标记动态部分，Diff 只比较标记）、缓存事件处理函数、最长递增子序列（列表 Diff 减少 DOM 操作）。Composition API：setup() 中组织逻辑，组合函数（useXxx）替代 mixins 复用。
>
> **用法要点**：① 新项目用 Vue3 + <script setup>（最简洁）；② 基本类型用 ref（.value），对象用 reactive；③ 逻辑复用用 composables（useXxx），不用 mixins；④ 解构 reactive 用 toRefs（保持响应式）；⑤ 生命周期用 onMounted/onUnmounted（setup 中）；⑥ 性能：大列表 v-memo、组件懒加载、keep-alive；⑦ 生态：Vue Router 4、Pinia、Vite、Element Plus。

### 5.2 核心特性

**Composition API**：setup() 中用 ref/reactive/computed/watch 组织逻辑，可抽离为组合函数（composables）复用。

**Proxy 响应式**：代理整个对象，支持新增属性、数组索引变化，不需要 Vue2 的 $set。

**编译优化**：静态提升、patchFlag、缓存事件、最长递增子序列，性能比 Vue2 提升 1.3-2 倍。

**新组件**：Fragment（多根节点）、Teleport（内容渲染到其他位置）、Suspense（异步组件加载状态）。

> 🔍 **知识点深度解析**
>
> **作用**：Composition API 是 Vue3 核心升级（逻辑内聚、复用方便、TS 友好），Proxy 响应式解决 Vue2 局限，编译优化提升性能，新组件丰富开发能力。
>
> **原理**：ref 内部 RefImpl 类的 getter/setter 拦截 .value，reactive 返回 Proxy。依赖收集：get 时 track（收集当前 effect），set 时 trigger（执行依赖的 effect）。computed 有 dirty 标记（依赖变更时 dirty=true，访问时重新计算缓存）。组合函数就是普通函数（use 开头），内部用响应式 API，返回数据和方法，在 setup 中调用。
>
> **用法要点**：① <script setup> 是语法糖（自动暴露顶层变量，不需要 return）；② computed 有缓存（派生状态用 computed，不要用方法）；③ watch 监听特定数据，watchEffect 自动收集依赖；④ 组件通信：props+emit（父子）、provide/inject（跨层）、Pinia（全局）；⑤ 自定义组件 v-model：modelValue + update:modelValue；⑥ 清理副作用在 onUnmounted（定时器/事件监听）。

### 5.3 常用用法

```vue
<script setup>
import { ref, reactive, computed, onMounted } from 'vue'
import { useUserStore } from '@/stores/user'
import { storeToRefs } from 'pinia'

const count = ref(0)
const user = reactive({ name: '张三', age: 18 })
const doubleCount = computed(() => count.value * 2)

const userStore = useUserStore()
const { isLoggedIn } = storeToRefs(userStore)
const { login, logout } = userStore

const increment = () => count.value++

onMounted(() => {
  console.log('组件挂载')
})
</script>

<template>
  <div>
    <p>{{ count }} x 2 = {{ doubleCount }}</p>
    <p>{{ user.name }} - {{ user.age }}</p>
    <button @click="increment">+1</button>
  </div>
</template>
```

> 🔍 **知识点深度解析**
>
> **作用**：<script setup> 标准用法：ref/reactive 定义数据，computed 派生状态，onMounted 生命周期，Pinia 全局状态。模板中自动解包 ref（不需要 .value）。
>
> **原理**：<script setup> 编译时将顶层变量/导入暴露给模板（不需要 return）。ref 在模板中自动解包（{{ count }} 不是 {{ count.value }}）。storeToRefs 解构 Pinia 的 state/getters 保持响应式，actions 直接解构。
>
> **用法要点**：① <script setup> 中 defineProps/defineEmits/defineExpose 是编译器宏（不需要 import）；② props 只读（子组件不要修改，emit 事件）；③ 路由用 useRoute/useRouter；④ 表单 v-model 绑定；⑤ 列表渲染加 key（唯一稳定标识）；⑥ v-if 和 v-for 不要同时用（v-if 优先级高）。

### 5.4 注意事项

1. **ref 和 reactive**：基本类型用 ref（.value），对象用 reactive。解构 reactive 丢失响应式，用 toRefs
2. **不要滥用响应式**：不需要响应的大数据用 markRaw 或 shallowRef，减少开销
3. **列表 key**：用唯一稳定标识（id），不要用 index
4. **清理副作用**：onUnmounted 清除定时器、事件监听，防止内存泄漏
5. **Vue2 迁移**：用 @vue/compat 逐步迁移，注意移除的 API（filters/$on/$set）
6. **性能优化**：大列表 v-memo、组件懒加载（defineAsyncComponent）、keep-alive 缓存
7. **TypeScript**：用 <script setup lang="ts">，props/emit 用类型声明

> 💡 **深度讲解**：Vue3 的核心是 Composition API + Proxy 响应式 + 编译优化。Composition API 让逻辑按功能组织（而非按选项类型），组合函数（useXxx）替代 mixins 实现复用（来源清晰、无命名冲突、类型安全）。Proxy 响应式解决了 Vue2 Object.defineProperty 的局限（新增属性、数组索引、性能）。编译优化（静态提升/patchFlag/最长递增子序列）让 Vue3 比 Vue2 快 1.3-2 倍，打包体积更小（Tree-shaking）。新组件 Fragment（多根节点）、Teleport（弹窗渲染到 body）、Suspense（异步加载）提升开发体验。生态全面升级：Vue Router 4（createRouter）、Pinia（替代 Vuex）、Vite（秒级启动）、Element Plus。新项目直接用 Vue3 + <script setup> + TypeScript + Vite。
>
> **📝 精简总结**：Vue3=Composition API+Proxy响应式+编译优化；响应式=ref(.value)/reactive(Proxy)+computed(缓存)+watch；组件=defineProps/defineEmits+Fragment/Teleport/Suspense；复用=composables(useXxx)；生态=Vue Router4+Pinia+Vite+Element Plus；注意=解构响应式/key/清理副作用/性能优化。

## 7. Pinia

### 7.1 概述

Pinia 是 Vue 官方推荐的状态管理库（Vuex 继任者），2022年成为官方推荐，原生 TypeScript 支持，Composition API 风格，API 简洁（state/getters/actions，移除 mutations）。

> 🔍 **知识点深度解析**
>
> **作用**：Pinia 是 Vue3 官方状态管理（替代 Vuex），管理全局共享状态（用户信息、购物车、主题）。比 Vuex 简单（无 mutations、模块化天然、TS 友好）。
>
> **原理**：defineStore(id, setup) 创建 store 定义，useXxxStore() 获取单例实例（第一次调用时创建）。Setup Store 中 ref→state，computed→getters，函数→actions。store 本身是 reactive 包裹的响应式对象，直接修改 state 触发更新（不需要 mutations）。
>
> **用法要点**：① 用 Setup Store（Composition API 风格）；② 组件中 useXxxStore()，state/getters 用 storeToRefs 解构；③ 直接修改 state 或用 actions 封装；④ 持久化用 pinia-plugin-persistedstate；⑤ 按功能分 store（user/cart/app），不要一个大 store；⑥ 局部状态用 ref，不要都放 store。

### 7.2 核心特性

**三大核心**：State（响应式状态）、Getters（计算属性，有缓存）、Actions（业务方法，同步异步均可）。

**Setup Store**：Composition API 风格，用 ref/computed/function 定义，更灵活。

**无 mutations**：直接修改 state 或用 actions，不需要 Vuex 的 commit/mutation。

**DevTools 支持**：时间旅行调试、状态查看。

> 🔍 **知识点深度解析**
>
> **作用**：Pinia 的核心是 state/getters/actions 三元组，比 Vuex 少了 mutations（直接修改 state），更简单。Setup Store 用 Composition API 风格，可使用组合函数。
>
> **原理**：state 用 ref/reactive（响应式），getters 用 computed（有缓存，dirty 标记），actions 是普通函数（可 async/await，可调用其他 store）。storeToRefs 将 state/getters 转为 ref（解构保持响应式）。$patch 批量修改 state（减少更新次数），$reset 重置，$subscribe 监听变化。
>
> **用法要点**：① 派生状态用 getters（computed 缓存）；② 业务逻辑用 actions（可异步）；③ 批量修改用 $patch（对象或函数）；④ 跨 store 调用在 actions 中 useOtherStore()；⑤ 插件扩展（持久化、日志）；⑥ $onAction 监听 actions（错误处理、性能监控）。

### 7.3 常用用法

```javascript
// stores/user.js
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'

export const useUserStore = defineStore('user', () => {
  const token = ref(localStorage.getItem('token') || '')
  const userInfo = ref(null)
  
  const isLoggedIn = computed(() => !!token.value)
  
  async function login(credentials) {
    const res = await api.login(credentials)
    token.value = res.token
    userInfo.value = res.user
    localStorage.setItem('token', res.token)
  }
  
  function logout() {
    token.value = ''
    userInfo.value = null
    localStorage.removeItem('token')
  }
  
  return { token, userInfo, isLoggedIn, login, logout }
}, {
  persist: { paths: ['token'] }  // 只持久化 token
})
```

```vue
<!-- 组件中 -->
<script setup>
import { useUserStore } from '@/stores/user'
import { storeToRefs } from 'pinia'

const userStore = useUserStore()
const { isLoggedIn, userInfo } = storeToRefs(userStore)
const { login, logout } = userStore
</script>
```

> 🔍 **知识点深度解析**
>
> **作用**：用户认证 Store 是最常见的 Pinia 应用，管理 token/userInfo，提供 login/logout。持久化 token（刷新不丢失登录态），userInfo 每次启动重新获取。
>
> **原理**：token 初始化从 localStorage 读取（持久化），login 调用 API 保存 token 和用户信息，logout 清除。isLoggedIn 是 computed（基于 token）。persist.paths 只持久化 token（userInfo 不持久化，避免数据过期）。storeToRefs 解构保持响应式，actions 直接解构。
>
> **用法要点**：① token 持久化，userInfo 不持久化（每次启动重新获取）；② 路由守卫用 isLoggedIn 鉴权；③ 请求拦截器加 Authorization 头；④ 401 响应清除 token 跳转登录；⑤ 角色权限用 computed（isAdmin）；⑥ 登出清除所有状态和其他 store（如购物车）。

### 7.4 注意事项

1. **store 调用时机**：useXxxStore() 必须在 setup 中或之后调用（Pinia 安装后），不能在模块顶层
2. **解构响应式**：state/getters 用 storeToRefs 解构，普通解构丢失响应式。actions 可直接解构
3. **不要滥用**：组件局部状态用 ref/reactive，只有全局共享状态才放 Pinia
4. **持久化**：敏感数据（密码）不要存 localStorage，大数据不要持久化（5MB 限制）
5. **跨 store 调用**：在 action 中调用，避免循环依赖
6. **TypeScript**：Setup Store 类型自动推导，ref<T>() 指定类型
7. **从 Vuex 迁移**：mutations 移除（直接修改 state），modules 转为独立 store

> 💡 **深度讲解**：Pinia 是 Vue3 官方状态管理（替代 Vuex），核心简化是"移除 mutations"——Vuex 必须通过 mutations 修改 state（为了 DevTools 追踪），Pinia 直接修改 state 也能被 DevTools 追踪（通过 $patch 和直接赋值的拦截）。Setup Store 用 Composition API 风格（ref/computed/function），可使用组合函数，比 Options Store 更灵活。state/getters/actions 三元组：state 是响应式数据，getters 是计算属性（有缓存），actions 是业务方法（同步异步均可）。持久化用 pinia-plugin-persistedstate（自动存 localStorage）。典型应用：用户认证（token+登录登出）、购物车（商品+总价+增删改）、应用配置（主题+语言）。比 Vuex 优势：API 少、无 mutations、天然模块化（不需要命名空间）、TS 类型自动推导、打包体积小。新项目直接用 Pinia，不要用 Vuex。
>
> **📝 精简总结**：Pinia=Vue3状态管理(替代Vuex)；核心=state(ref)+getters(computed缓存)+actions(函数async)；定义=defineStore(id, setup)；使用=useXxxStore()+storeToRefs解构；修改=直接赋值/$patch；持久化=pinia-plugin-persistedstate；注意=setup后调用/storeToRefs/不滥用局部状态。
