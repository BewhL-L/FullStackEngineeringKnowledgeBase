# 📦 存量知识库迁移指南

> 本指南说明如何将现有的 60 份系统化知识文档平滑迁移、适配到自增长知识库体系。核心原则：不破坏现有内容，渐进式融合，双轨制运行。

---

## 1. 迁移策略：双轨制，不拆分

### 1.1 为什么不批量拆分现有文档

| 方案 | 成本 | 收益 | 风险 |
|------|------|------|------|
| 批量拆分为原子笔记 | 极高（60份×平均5000字） | 中（获得原子笔记） | 高（内容丢失、链接断裂、人工审核量大） |
| 保留现有文档 + 新增原子笔记 | 低 | 高（双轨互补） | 低（不破坏现有内容） |
| 按需提取概念卡片 | 中 | 高（精准提取常用概念） | 低（人工控制提取范围） |

**结论**：采用「保留现有文档 + 新增原子笔记 + 按需提取」的渐进式方案。

### 1.2 双轨制知识体系

```
┌──────────────────────────────────────────────────────────┐
│  轨道A：系统化文档（现有 60 份，保留不动）                  │
│  ─────────────────────────────────────                   │
│  特点：大而全、结构化、面试导向、速查手册                  │
│  用途：系统学习、面试复习、快速查阅某领域全貌              │
│  增长：低频更新，主要靠人工补充和修订                      │
│  位置：01~09 各分类目录下                                  │
├──────────────────────────────────────────────────────────┤
│  轨道B：原子化笔记（自增长，从 Inbox 生长）                │
│  ─────────────────────────────────────                   │
│  特点：一概念一笔记、自动关联、持续演化、随用随长          │
│  用途：深度理解、概念关联、知识图谱、灵感沉淀              │
│  增长：高频增长，LLM 自动处理 Inbox                        │
│  位置：01~09 各分类目录下（与系统化文档共存）              │
├──────────────────────────────────────────────────────────┤
│  连接层：MOC + 双向链接                                    │
│  ─────────────────────────────────────                   │
│  系统化文档中引用原子笔记，原子笔记中链接系统化文档        │
│  两者通过 MOC 和关系图谱形成统一的知识网络                 │
└──────────────────────────────────────────────────────────┘
```

## 2. 存量文档适配步骤

### 步骤1：补充元数据（批量，AI 执行）

为现有 60 份文档补充/完善 front matter：

```yaml
# 补充前（部分文档可能缺少）
---
title: Vue3 知识点系统梳理
tags: [Vue3, 前端]
---

# 补充后
---
title: Vue3 知识点系统梳理
tags: [前端, Vue3, 速查, 面试]
created: 2026-08-12
updated: 2026-08-13
source: 系统整理
type: 系统化文档
related:
  - [[Vue3 AI Agent前端集成知识点系统梳理_优化版]]
  - [[Vue3 AIGC前端应用知识点系统梳理_优化版]]
---
```

**补充内容**：
- `created` / `updated`：创建和更新日期
- `source`：标注为「系统整理」（区别于从 Inbox 生长的笔记）
- `type: 系统化文档`：标记文档类型
- `related`：列出同分类的相关文档
- 标签规范化：按「标签命名规范」调整（领域+技术+类型）

**执行方式**：
```
请为 01-前端开发/ 目录下所有知识文档补充 front matter：
1. 添加 created/updated 日期
2. 添加 source: 系统整理
3. 添加 type: 系统化文档
4. 规范化标签（按标签命名规范）
5. 添加 related 字段，列出同分类其他文档
6. 不修改正文内容
```

### 步骤2：添加返回导航（批量，AI 执行）

检查每份文档末尾是否有返回导航链接，缺失的补充：

```markdown
---

[[01-前端开发/MOC-前端开发|← 返回前端开发 MOC]] | [[Home|🏠 返回首页]]
```

### 步骤3：建立双向链接（渐进式，AI 辅助）

#### 3.1 系统化文档 → 原子笔记

当新增原子笔记时，在相关的系统化文档中添加链接：

```markdown
## 7. AI Agent 集成（新增章节）

相关原子笔记：
- [[Function Calling 工具调用]]
- [[RAG 检索增强生成]]
- [[Vercel AI SDK useChat 钩子]]
```

#### 3.2 原子笔记 → 系统化文档

原子笔记的「关联知识」部分链接到系统化文档：

```markdown
## 关联知识
- 上层聚合：[[Vue3 知识点系统梳理]]（Vue3 全景速查）
- 系统化文档：[[Vue3 AI Agent前端集成知识点系统梳理_优化版]]
```

#### 3.3 系统化文档之间的交叉链接

在系统化文档中添加指向其他分类系统化文档的链接：

```markdown
## 关联知识
- 后端对应：[[Java AI Agent开发知识点系统梳理_优化版]]
- 通用概念：[[AI Agent开发知识点系统梳理]]
```

### 步骤4：按需提取概念卡片（持续进行）

**不批量提取**，而是在以下场景提取：

| 场景 | 提取方式 |
|------|----------|
| 学习某概念时需要深入理解 | 从系统化文档中提取该概念，生成原子笔记 |
| 某个概念被多次引用 | 提取为独立笔记，建立入向链接 |
| 面试复习时需要重点突破 | 提取高频考点概念，生成面试导向笔记 |
| 写新项目需要参考 | 提取相关概念，生成实战型笔记 |

**提取指令模板**：
```
请从 [[Vue3 知识点系统梳理]] 中提取「Proxy 响应式原理」部分：
1. 生成原子化笔记 [[Vue3 Proxy 响应式原理]]
2. 保留原文内容，补充深入理解和代码示例
3. 添加关联链接（[[Vue3 知识点系统梳理]] [[Vue3+TypeScript核心]]）
4. 在原文档对应位置添加指向新笔记的链接
5. 原文档该部分内容保留，不删除
```

## 3. 迁移后的文档分类标识

为了在图谱和检索中区分两类文档，使用 `type` 字段和标签：

| 文档类型 | type 字段 | 标签特征 | 图谱表现 |
|----------|-----------|----------|----------|
| 系统化文档 | `type: 系统化文档` | 含 `#速查` 或 `#面试` | 大节点（字数多），按目录分色 |
| 原子化笔记 | `type: 原子化笔记` | 含 `#概念` 或 `#原理` | 小节点，按目录分色 |
| 概念卡片 | `type: 概念卡片` | 含 `#概念` + `#草稿` | 小节点，可能是孤儿（待补链） |
| MOC 索引 | （无 type） | 含 `#MOC` | 金色节点（tag:MOC 规则） |

**在 Dataview 中查询**：
```markdown
```dataview
TABLE type, tags, created
FROM "01-前端开发"
WHERE type = "系统化文档"
SORT created DESC
```
```

## 4. 迁移节奏建议

### 第一阶段：基础适配（1-2 天）

- [ ] 为所有现有文档补充 front matter（created/updated/source/type）
- [ ] 检查并补充返回导航链接
- [ ] 规范化所有文档的标签
- [ ] 创建 Inbox 目录和规则文件（已完成）

### 第二阶段：连接建立（1-2 周，随使用进行）

- [ ] 在各分类 MOC 中区分「系统化文档」和「原子化笔记」两个子分类
- [ ] 为高频引用的概念提取原子笔记（每周 3-5 个）
- [ ] 在系统化文档中添加指向原子笔记的链接
- [ ] 开始使用 Inbox 摄入新知识

### 第三阶段：体系融合（持续进行）

- [ ] 每周运行重构工作流，优化链接网络
- [ ] 每月审计 MOC 完整性
- [ ] 按需从系统化文档提取概念卡片
- [ ] 逐步形成「系统化文档做索引，原子笔记做深度」的知识网络

## 5. 迁移中的注意事项

### 5.1 不做的事

- ❌ 不批量拆分现有系统化文档
- ❌ 不删除现有文档的任何内容
- ❌ 不修改现有文档的正文结构（只补充元数据和链接）
- ❌ 不强行给所有概念都建原子笔记（按需提取）
- ❌ 不改变现有目录结构（01~09 分类保持不变）

### 5.2 要做的事

- ✅ 保留现有文档的完整性和原始内容
- ✅ 新摄入的知识严格按原子化规范处理
- ✅ 逐步建立系统化文档与原子笔记的双向链接
- ✅ 定期运行质量校验和重构工作流
- ✅ 在 MOC 中清晰区分两类文档

### 5.3 常见问题

**Q：现有文档和新原子笔记放在同一个目录下，会不会混乱？**

A：不会。通过 `type` 字段和标签区分，MOC 中分两个子分类展示。Obsidian 的图谱和搜索都支持按标签/类型筛选。

**Q：什么时候应该把系统化文档拆成原子笔记？**

A：当某份系统化文档的某个章节被频繁引用、需要独立更新、或内容已经远超其他章节时，才考虑提取。不做预防性拆分。

**Q：迁移期间 Inbox 怎么处理？**

A：立即开始使用 Inbox，新摄入的知识按原子化规范处理，与存量文档的适配并行进行，互不影响。

## 6. 迁移完成标准

当以下条件满足时，说明存量知识库已成功适配自增长体系：

- [ ] 所有现有文档有完整的 front matter（含 type 字段）
- [ ] 所有现有文档有返回导航链接
- [ ] 各分类 MOC 区分了系统化文档和原子化笔记
- [ ] 至少有 10 个从系统化文档中提取的原子笔记
- [ ] Inbox 正常运行，每周处理至少 1 次
- [ ] 周度重构工作流运行过至少 1 次
- [ ] 关系图谱中没有大面积孤儿节点（<5%）
