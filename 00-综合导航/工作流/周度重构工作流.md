# 🔄 周度重构工作流

> 定义每周对知识库进行健康度扫描和结构优化的流程。目标是保持知识库的原子化、关联性和时效性。

---

## 1. 触发时机

- **固定时间**：每周日晚上或周一早上
- **手动触发**：感觉知识库混乱、找不到东西时
- **增量触发**：Inbox 连续处理 2 周后，需要一次重构

---

## 2. 重构流程

```
┌─────────────────────────────────────────────────────────────┐
│  步骤1：全库健康度扫描                                        │
│  - 孤儿笔记（0入向0出向链接）                                 │
│  - 链接不足（<2个出向链接）                                   │
│  - 重复笔记（语义相似度>80%）                                 │
│  - 过大笔记（>3000字，可能需要拆分）                          │
│  - 过时风险（>6个月未更新 + 快速变化技术）                    │
│  - 格式问题（缺front matter/标签/返回导航）                   │
│  - Inbox 积压（>20条待处理）                                  │
│  输出：健康度报告 + 问题清单                                  │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  步骤2：生成重构方案                                          │
│  - 对每个问题给出具体操作建议                                 │
│  - 合并：列出重复笔记对 + 合并后的内容结构                    │
│  - 拆分：列出过大笔记 + 拆分后的子概念列表                    │
│  - 补链：列出孤儿笔记 + 建议关联的笔记                        │
│  - 更新：列出过时笔记 + 建议更新方向                          │
│  输出：重构方案（待人工确认）                                 │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  步骤3：人工确认（关键节点）                                  │
│  - AI 展示重构方案，按优先级排序                              │
│  - 用户选择：全部执行 / 部分执行 / 修改后执行 / 跳过          │
│  - 高风险操作（合并/拆分/删除）必须逐条确认                   │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  步骤4：执行重构                                              │
│  - 按确认后的方案执行                                         │
│  - 合并：将内容整合到主笔记，删除重复笔记，更新所有入向链接    │
│  - 拆分：生成子笔记，原笔记改为索引页指向子笔记                │
│  - 补链：为孤儿笔记添加双向链接                               │
│  - 更新：过时笔记标记 #过时 或补充新内容                      │
│  - 格式：批量修复格式问题                                     │
│  输出：执行日志                                               │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  步骤5：更新索引                                              │
│  - 更新受影响分类的 MOC                                       │
│  - 更新 Home.md 统计数据                                      │
│  - 更新学习路径（如有重大结构变化）                           │
│  输出：更新后的索引页                                         │
└─────────────────────────────────────────────────────────────┘
```

## 3. 各类问题的处理方法

### 3.1 孤儿笔记处理

**识别**：入向链接=0 且 出向链接=0

**处理方法**：
1. 判断笔记是否有价值 → 无价值则标记 #过时 或删除
2. 有价值则寻找关联：
   - 同分类中哪些笔记提到了这个概念？
   - 系统化文档中是否有相关章节？
   - 是否可以作为某篇笔记的「关联知识」？
3. 至少添加 2 个出向链接 + 1 个入向链接

**示例**：
```
孤儿笔记：[[Embedding 向量嵌入]]
处理：
- 出向链接：添加 [[RAG 检索增强生成]] [[VectorStore 向量存储]]
- 入向链接：在 [[RAG 检索增强生成]] 中添加 "前置知识：[[Embedding 向量嵌入]]"
- 在 [[Java AI Agent开发]] 中添加 "相关：[[Embedding 向量嵌入]]"
```

### 3.2 重复笔记合并

**识别**：语义相似度 > 80%，或标题高度相似

**处理方法**：
1. 确定主笔记（内容更完整、创建更早的）
2. 将次笔记的独有内容补充到主笔记
3. 更新所有指向次笔记的链接，改为指向主笔记
4. 次笔记标记 #过时 或删除（保留重定向说明）

**合并前必须人工确认**：
```
发现可能重复的笔记：
  A: [[Function Calling 工具调用]] (创建于2026-08-01, 1200字)
  B: [[Tool Use 工具使用]] (创建于2026-08-10, 800字)
相似度：87%

建议：以 A 为主笔记，合并 B 的内容
B 中独有的内容：
  - OpenAI 最新的 parallel_tool_calls 参数
  - 工具调用错误处理示例

确认合并吗？(Y/N)
```

### 3.3 过大笔记拆分

**识别**：字数 > 3000，或包含 3 个以上独立概念

**处理方法**：
1. 识别笔记中的独立子概念
2. 为每个子概念创建原子笔记
3. 原笔记保留总览和索引，指向各子笔记
4. 更新所有入向链接（可保留指向原笔记，或改为指向具体子笔记）

**拆分示例**：
```
过大笔记：[[前端工程化知识点系统梳理]] (8000字)

拆分为：
- [[Vite 构建工具]] (从原笔记提取 Vite 部分)
- [[ESLint 代码检查]] (提取 ESLint 部分)
- [[Husky Git钩子]] (提取 Husky 部分)
- [[CI-CD 持续集成]] (提取 CI/CD 部分)

原笔记改为：
  # 前端工程化（总览）
  > 前端工程化的核心概念和学习路径，详细内容见各子笔记。
  ## 子主题
  - [[Vite 构建工具]]
  - [[ESLint 代码检查]]
  - [[Husky Git钩子]]
  - [[CI-CD 持续集成]]
```

### 3.4 过时笔记处理

**识别**：
- 创建/更新时间 > 6 个月
- 涉及快速变化的技术（AI 框架、前端工具链等）
- 内容与当前版本不符

**处理方法**：
1. 标记 `#过时` 标签
2. 在笔记顶部添加提示：
   ```
   > ⚠️ 本文最后更新于 2026-02，部分内容可能已过时。
   > 最新信息请参考：[[更新后的笔记]] 或官方文档。
   ```
3. 如有更新版本，添加指向新版本的链接
4. 完全过时且无参考价值的，可删除（需人工确认）

## 4. 重构报告模板

```
🔄 周度重构报告 - 2026-W33 (2026-08-11 ~ 2026-08-17)

【健康度评分】78/100

【问题统计】
- 孤儿笔记：4篇
- 链接不足：7篇
- 可能重复：2组
- 过大笔记：1篇
- 过时风险：5篇
- 格式问题：3篇
- Inbox 积压：8篇

【已执行操作】
✅ 合并重复：[[Function Calling]] ← [[Tool Use]]
✅ 补链：为4篇孤儿笔记添加关联链接（共12个新链接）
✅ 格式修复：3篇笔记补充 front matter 和返回导航
✅ Inbox 处理：处理5篇待处理笔记，生成12篇原子笔记

【待人工确认】
⚠️ 拆分建议：[[前端工程化]] (8000字) → 拆分为4篇子笔记
⚠️ 过时更新：[[LangChain 概念]] 最后更新于2026-01，建议更新

【知识库变化】
- 笔记总数：60 → 72（+12，Inbox处理新增）
- 双向链接总数：342 → 378（+36）
- 孤儿笔记：12 → 8（-4）
```

## 5. 快捷指令

```
# 执行完整周度重构
执行周度重构，扫描全库并生成重构方案

# 只扫描不执行
扫描知识库健康度，生成报告，不执行任何修改

# 针对特定问题
找出所有孤儿笔记，给出补链建议
检查是否有重复笔记，列出相似度>80%的笔记对
找出所有>3000字的笔记，给出拆分建议
```
