# 🗺️ MOC 更新工作流

> 定义 MOC（内容地图）索引页的维护和更新流程。MOC 是知识库的导航枢纽，必须保持与实际文档的同步。

---

## 1. MOC 体系结构

```
Home.md（总入口）
  ├── MOC-综合导航.md（规则/模板/工作流/学习路径）
  ├── MOC-前端开发.md（12份文档）
  ├── MOC-后端开发.md（9份文档）
  ├── MOC-数据库与缓存.md（4份文档）
  ├── MOC-分布式与中间件.md（4份文档）
  ├── MOC-云原生与运维.md（5份文档）
  ├── MOC-计算机基础.md（4份文档）
  ├── MOC-通用工具.md（1份文档）
  ├── MOC-Python全栈.md（10份文档）
  ├── MOC-AI与效率工具.md（8份文档）
  └── MOC-项目实战.md（1份文档）
```

## 2. 触发更新的场景

| 场景 | 更新内容 | 执行者 |
|------|----------|--------|
| 新笔记归档 | 在对应分类 MOC 添加链接 | AI 自动 |
| 笔记删除/合并 | 从 MOC 移除或更新链接 | AI 自动 + 人工确认 |
| 笔记重命名 | 更新 MOC 中的链接显示名 | AI 自动 |
| 分类调整 | 移动笔记到其他分类的 MOC | 人工主导 |
| 月度审计 | 检查 MOC 完整性，补全缺失 | AI 扫描 + 人工确认 |
| 学习路径更新 | 更新 MOC 中的学习顺序 | 人工主导 |

## 4. 自动更新流程

### 4.1 新笔记归档时的 MOC 更新

```
触发：Inbox 处理工作流的步骤7（归档入库）

步骤：
1. 确定新笔记的分类目录（如 01-前端开发/）
2. 读取对应分类的 MOC 文件
3. 确定新笔记的子分类（如 AI Agent 与 AIGC）
4. 在对应子分类下添加新笔记链接
   格式：- [[路径/文件名|显示名]] — 一句话说明
5. 更新 MOC 顶部的文档统计数字（如有）
6. 保存 MOC
```

**添加链接的位置规则**：
- 优先放入最合适的子分类下
- 没有合适子分类时，新建子分类
- 同子分类内按创建时间倒序（新的在前）或按学习顺序排列

### 4.2 笔记删除/合并时的 MOC 更新

```
触发：周度重构工作流的步骤4（执行重构）

删除：
1. 从所有 MOC 中移除该笔记的链接
2. 检查是否有其他笔记引用它，更新入向链接

合并（A 合并到 B）：
1. 从 MOC 中移除 A 的链接
2. 检查 B 的链接说明是否需要更新（合并后内容更丰富）
3. 更新所有指向 A 的链接为指向 B
```

## 5. 月度 MOC 审计

每月1号执行，检查所有 MOC 的完整性：

### 5.1 审计检查项

```
1. 完整性检查
   - 扫描分类目录下所有 .md 文件（排除 MOC 本身）
   - 对比 MOC 中的链接列表
   - 找出 MOC 中缺失的文档
   - 找出 MOC 中链接到不存在文件的死链

2. 结构检查
   - MOC 是否包含标准结构（核心文档/知识关联/学习顺序/标签）
   - 子分类是否合理，是否有文档找不到归属
   - 学习顺序是否与当前文档匹配

3. 链接质量检查
   - 链接显示名是否准确
   - 一句话说明是否清晰
   - 是否有重复链接

4. 统计更新
   - 各分类文档数量是否准确
   - Home.md 中的总数是否准确
```

### 5.2 审计报告模板

```
🗺️ MOC 月度审计报告 - 2026-08

【完整性】
✅ MOC-前端开发：12篇文档全部收录，无死链
⚠️ MOC-后端开发：缺失1篇 [[Java AIGC应用开发]]
❌ MOC-AI与效率工具：2个死链（链接到已重命名的文件）

【结构问题】
- MOC-前端开发：子分类「AI Agent 与 AIGC」下有4篇，建议再细分
- MOC-综合导航：缺少「自增长知识库」子分类

【建议操作】
1. 为 MOC-后端开发 添加 [[Java AIGC应用开发]] 链接
2. 修复 MOC-AI与效率工具 的2个死链
3. 在 MOC-综合导航 中添加自增长知识库体系的链接
4. 更新 Home.md 统计数字（60篇 → 实际数量）
```

## 6. MOC 编写规范

### 6.1 链接格式

```markdown
✅ 标准格式：
- [[01-前端开发/Vue3 AI Agent前端集成知识点系统梳理_优化版|Vue3 AI Agent 前端集成]] — useChat、流式渲染、工具调用可视化

❌ 不规范：
- [[Vue3 AI Agent]] （缺少路径，可能重名）
- [[01-前端开发/xxx.md]] （带 .md 后缀，Obsidian 不需要）
- 链接无说明（只有标题，不知道内容是什么）
```

### 6.2 一句话说明写法

- 用「核心技术点 + 用途」的句式
- 不超过30字
- 突出该文档的独特价值

```
✅ 好的说明：
- Spring AI、LangChain4j、Function Calling、RAG、多Agent、可观测性
- LangChain.js、Vercel AI SDK、多Agent协作、模型路由、生产部署

❌ 不好的说明：
- 很详细的文档（无信息量）
- AI相关的东西（太模糊）
```

### 6.3 子分类命名

- 用名词短语，不用动词
- 4-8个字为宜
- 同一 MOC 内子分类粒度一致

```
✅ 好的子分类：
- 框架核心 / 状态管理 / UI组件库 / AI Agent 与 AIGC
- 语言基础 / 设计模式 / Spring 生态 / 持久层 / 并发编程

❌ 不好的子分类：
- 重要的（无意义）
- Vue3 相关的（太宽泛）
- 第一篇（按顺序而非按主题）
```
