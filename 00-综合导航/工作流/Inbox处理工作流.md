# 📥 Inbox 处理工作流

> 定义从 Inbox 原始笔记到归档原子化笔记的完整处理流程。AI 工具按此流程执行，人工在关键节点确认。

---

## 1. 触发条件

| 触发方式 | 时机 | 执行者 |
|----------|------|--------|
| 手动触发 | 随时，当 Inbox 有积累时 | 用户发起，AI 执行 |
| 每日定时 | 每天晚上/次日早上 | AI 自动（需配置） |
| 批量触发 | 周末集中处理 | AI 批量执行 |

**建议**：每天处理 1 次，保持 Inbox 不超过 20 条待处理。

---

## 2. 完整处理流程

```
┌─────────────────────────────────────────────────────────────┐
│  步骤1：读取待处理队列                                        │
│  - 扫描 Inbox/ 中 status: 待处理 的笔记                       │
│  - 按创建时间排序，优先处理最旧的                              │
│  - 输出：待处理清单                                           │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  步骤2：单篇笔记概念提取                                      │
│  - 读取原始笔记内容                                           │
│  - 识别核心概念（3-8个）                                      │
│  - 判断每个概念是否需要独立成笔记                             │
│  - 输出：概念列表 + 粒度判断                                  │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  步骤3：生成原子化笔记草稿                                    │
│  - 对每个概念按「原子化笔记模板」生成笔记                     │
│  - 自动填充 front matter（title/tags/created/source）        │
│  - 编写一句话定义、核心要点、深入理解                         │
│  - 存到 Inbox/_草稿/ 目录                                    │
│  - 输出：原子笔记草稿集合                                     │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  步骤4：关联建链                                              │
│  - 扫描新笔记之间的关联，添加双向链接                         │
│  - 扫描全库，为新笔记寻找入向链接（被已有笔记引用）           │
│  - 在「关联知识」部分标注关系类型                             │
│  - 输出：带完整链接的笔记                                     │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  步骤5：质量校验                                              │
│  - 按「质量校验规则」4个维度逐项检查                          │
│  - 自动修复格式和结构问题                                     │
│  - 必须项未通过 → 标记「需人工审核」                          │
│  - 可能重复 → 标记「待合并」                                  │
│  - 输出：校验报告                                             │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  步骤6：人工审核（关键节点）                                  │
│  - AI 展示：新笔记标题列表 + 校验报告 + 待确认项              │
│  - 用户审核：确认/修改/驳回                                  │
│  - 驳回的笔记退回草稿，修改后重新校验                         │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  步骤7：归档入库                                              │
│  - 根据标签和内容归类到 01~09 对应目录                        │
│  - 更新对应分类的 MOC（添加新笔记链接）                       │
│  - 原 Inbox 笔记 status 改为「已处理」                        │
│  - 在原笔记中添加「已归档到：[[笔记1]] [[笔记2]]」            │
│  - 输出：归档报告                                             │
└─────────────────────────────────────────────────────────────┘
```

## 3. 各步骤详细说明

### 3.1 步骤2：概念提取技巧

**提取方法**：
1. 通读原始笔记，标记所有名词短语（技术术语、概念名）
2. 对每个名词判断：这是一个独立概念吗？有深入展开的价值吗？
3. 合并相近概念，拆分复合概念
4. 输出最终概念列表

**概念提取示例**：

原始笔记：一篇关于 "Spring AI RAG 实战" 的博客

提取的概念：
```
1. RAG 检索增强生成（总览概念，必建）
2. 文档切分 TextSplitter（独立概念，有多种策略）
3. Embedding 向量嵌入（独立概念，RAG 的基础）
4. VectorStore 向量存储接口（独立概念，Spring AI 抽象）
5. 相似度检索 Top-K（独立概念，检索策略）
6. QuestionAnswerAdvisor（Spring AI 特定实现，可建）
```

### 3.2 步骤4：关联建链方法

**出向链接**（新笔记 → 已有笔记）：
- 新笔记中提到的已有概念 → 添加 `[[]]` 链接
- 前置知识、后续延伸、相似对比 → 在「关联知识」部分列出

**入向链接**（已有笔记 → 新笔记）：
- 扫描全库，找到提到新概念但未链接的笔记
- 在已有笔记中添加指向新笔记的链接
- 优先级：系统化文档 > 同分类笔记 > 其他分类笔记

**关联强度判断**：
- 强关联（直接引用、前置依赖）→ 必须建链
- 中关联（同领域、可对比）→ 建议建链
- 弱关联（间接相关）→ 可选建链

### 3.3 步骤6：人工审核要点

审核时重点检查：
1. **概念拆分是否合理**：有没有拆太细或太粗？
2. **内容准确性**：AI 生成的技术事实有没有错误？
3. **分类是否正确**：归档到哪个目录最合适？
4. **标签是否合适**：3-6个标签，领域+技术+类型
5. **关联是否充分**：至少2个出向链接，重要概念有入向链接

**快速审核技巧**：
- 只看标题和一句话定义，判断概念是否成立
- 快速浏览核心要点，判断内容是否准确
- 关联链接抽查2-3个，判断是否精准

## 4. 异常处理

| 异常情况 | 处理方式 |
|----------|----------|
| 原始笔记内容过少（<100字） | 不拆解，直接归档或标记「内容不足待补充」 |
| 原始笔记内容过多（>5000字） | 分批次处理，每次提取5-8个概念 |
| 概念与已有笔记高度重复 | 不新建，在已有笔记中补充内容，标记「已合并」 |
| 概念跨多个分类 | 选择最主要的分类归档，在其他分类 MOC 中添加交叉引用 |
| AI 无法判断概念粒度 | 标记「需人工审核」，列出拆分方案供选择 |
| 质量校验多次不通过 | 存入 Inbox/_草稿/，人工手动修改 |

```
- 处理原始笔记：3篇
- 生成原子笔记：8篇
- 归档成功：7篇
- 需人工审核：1篇
- 待合并：0篇

【归档清单】
- [[RAG 检索增强生成]] → 09-AI与效率工具/
- [[文档切分策略]] → 09-AI与效率工具/

...

【需人工审核】
- [[QuestionAnswerAdvisor 检索增强器]]：分类不确定（AI后端 or AI通用）

【关联建链统计】
- 新增出向链接：23个
- 新增入向链接：12个
- 更新已有笔记：5篇（添加了指向新笔记的链接）

【Inbox 状态】
- 待处理：5篇（处理前8篇）
- 已处理：3篇（本次）
```

## 6. 快捷指令

向 AI 工具发送以下指令即可触发：

```
# 处理全部待处理
处理 Inbox 中所有待处理笔记

# 处理指定数量
处理 Inbox 中最旧的 3 篇待处理笔记

# 处理单篇
处理 Inbox/2026-08-13-xxx.md 这篇笔记

# 只提取概念不归档
读取 Inbox/xxx.md，提取概念列表，先不生成笔记
```
