# 计算机网络分层模型速查

> **文档说明**：系统讲解计算机网络的分层模型，包括 OSI 七层模型与 TCP/IP 四层模型的对应关系、各层的核心功能、关键协议、常见设备、数据封装与解封装过程，以及 HTTP/HTTPS、TCP/UDP、IP、DNS 等核心协议的速查要点，含网络排障思路与常见面试题。
>
> **适用人群**：全栈开发工程师、后端开发工程师、需要理解网络基础的开发者
>
> **前置知识**：[[操作系统核心概念]]

## 一、概述

计算机网络采用**分层架构**，将复杂的网络通信问题分解为多个层次，每层负责特定功能，通过层间接口交互。分层的好处是：解耦、易于维护、可独立演进、标准化。

### 1. 两大模型对比

| 层级 | OSI 七层模型 | TCP/IP 四层模型 | 核心功能 | 典型协议 |
|------|-------------|----------------|---------|---------|
| 7 | 应用层（Application） | **应用层** | 为应用程序提供网络服务 | HTTP/HTTPS、FTP、SMTP、DNS、SSH、WebSocket |
| 6 | 表示层（Presentation） | 应用层 | 数据格式转换、加密解密、压缩 | SSL/TLS、ASCII、JPEG、JSON |
| 5 | 会话层（Session） | 应用层 | 建立、管理、终止会话 | RPC、NetBIOS、PPTP |
| 4 | 传输层（Transport） | **传输层** | 端到端通信、流量控制、差错恢复 | TCP、UDP |
| 3 | 网络层（Network） | **网络层** | 路由选择、逻辑寻址、分组转发 | IP、ICMP、ARP、OSPF、BGP |
| 2 | 数据链路层（Data Link） | **网络接口层** | 帧封装、物理寻址、介质访问控制 | Ethernet、Wi-Fi、PPP、MAC |
| 1 | 物理层（Physical） | 网络接口层 | 比特流传输、物理介质 | 网线、光纤、无线电、集线器 |

**记忆口诀（OSI 七层）**：
- 应表会传网数物（应用→表示→会话→传输→网络→数据链路→物理）
- All People Seem To Need Data Processing

### 2. 数据封装与解封装

```text
发送方（封装）：
应用层数据 → 加传输层头（端口）→ 段(Segment)
→ 加网络层头（IP）→ 包(Packet)
→ 加数据链路层头（MAC）+尾(FCS)→ 帧(Frame)
→ 转比特流 → 物理介质传输

接收方（解封装）：
物理层比特流 → 帧 → 去链路层头/尾 → 包
→ 去网络层头 → 段 → 去传输层头 → 应用层数据
```

| 层次 | 数据单元名称 | 封装信息 |
|------|------------|---------|
| 应用层 | 数据（Data） | 应用协议头 |
| 传输层 | 段（Segment） | 源端口、目的端口 |
| 网络层 | 包（Packet） | 源IP、目的IP |
| 数据链路层 | 帧（Frame） | 源MAC、目的MAC、FCS校验 |
| 物理层 | 比特（Bit） | 0/1 比特流 |

## 二、各层详解

### 1. 物理层（Physical Layer）

| 维度 | 说明 |
|------|------|
| **核心功能** | 在物理介质上传输原始比特流（0和1） |
| **关注问题** | 电压、频率、接口形状、介质类型、传输速率 |
| **典型设备** | 网线、光纤、集线器（Hub）、中继器、网卡物理部分 |
| **典型标准** | Ethernet（IEEE 802.3）、Wi-Fi（IEEE 802.11）、USB、HDMI |
| **传输介质** | 双绞线（CAT5e/CAT6）、光纤（单模/多模）、无线电、同轴电缆 |

**常见接口速率**：
| 标准 | 速率 | 介质 |
|------|------|------|
| 10BASE-T | 10 Mbps | 双绞线 |
| 100BASE-TX | 100 Mbps | 双绞线 |
| 1000BASE-T | 1 Gbps | 双绞线（CAT5e+） |
| 10GBASE-T | 10 Gbps | 双绞线（CAT6a+） |
| 100GBASE | 100 Gbps | 光纤 |

### 2. 数据链路层（Data Link Layer）

| 维度 | 说明 |
|------|------|
| **核心功能** | 将比特流组装成帧，进行物理寻址（MAC），介质访问控制，差错检测 |
| **关注问题** | 帧同步、MAC地址、冲突检测、差错检测（CRC/FCS） |
| **典型设备** | 交换机（Switch）、网桥、网卡（NIC） |
| **典型协议** | Ethernet、Wi-Fi（802.11）、PPP、HDLC、VLAN（802.1Q） |

**MAC 地址**：
- 48位（6字节），全球唯一
- 格式：`00:1A:2B:3C:4D:5E`（十六进制）
- 前24位：OUI（组织唯一标识符，厂商标识）
- 后24位：厂商分配的唯一序列号
- 广播地址：`FF:FF:FF:FF:FF:FF`

**交换机工作原理**：
- 学习：记录源MAC地址与端口的映射（MAC地址表）
- 转发：根据目的MAC地址查找端口，单播转发
- 泛洪：未知目的MAC时，向所有端口广播
- 老化：MAC地址表项超时后删除（默认300秒）

### 3. 网络层（Network Layer）

| 维度 | 说明 |
|------|------|
| **核心功能** | 逻辑寻址（IP）、路由选择、分组转发、拥塞控制 |
| **关注问题** | IP地址、子网划分、路由协议、ICMP差错报告 |
| **典型设备** | 路由器（Router）、三层交换机 |
| **典型协议** | IPv4、IPv6、ICMP、ARP、OSPF、BGP、RIP |

**IP 地址（IPv4）**：
- 32位（4字节），点分十进制表示：`192.168.1.1`
- 分为网络号 + 主机号
- 特殊地址：
  - `127.0.0.1`：回环地址（localhost）
  - `0.0.0.0`：所有网络接口
  - `255.255.255.255`：受限广播
  - `169.254.x.x`：APIPA（自动私有IP，DHCP失败时）

**私有 IP 地址段**：
| 类别 | 地址范围 | 数量 |
|------|---------|------|
| A类 | `10.0.0.0` - `10.255.255.255` | 1个A类网 |
| B类 | `172.16.0.0` - `172.31.255.255` | 16个B类网 |
| C类 | `192.168.0.0` - `192.168.255.255` | 256个C类网 |

**子网掩码与 CIDR**：
- 子网掩码：`255.255.255.0`（/24）
- CIDR 表示：`192.168.1.0/24`（前24位为网络号）
- 主机数 = 2^(32-前缀长度) - 2（减网络地址和广播地址）
- `/24`：254台主机；`/16`：65534台主机；`/30`：2台主机（点对点）

**ARP（地址解析协议）**：
- 功能：将 IP 地址解析为 MAC 地址
- 过程：广播 ARP 请求（谁是 192.168.1.1？）→ 目标单播 ARP 应答（我是，MAC是xx）
- 结果存在 ARP 缓存表中

**ICMP（Internet 控制报文协议）**：
- 功能：差错报告和网络诊断
- 常见类型：
  - Echo Request/Reply（ping，类型8/0）
  - Destination Unreachable（目标不可达，类型3）
  - Time Exceeded（超时，类型11，traceroute使用）
  - Redirect（重定向，类型5）

**路由协议分类**：
| 类型 | 协议 | 说明 |
|------|------|------|
| 内部网关协议（IGP） | OSPF | 链路状态协议，开放最短路径优先，大型网络 |
| | RIP | 距离矢量协议，跳数限制15跳，小型网络 |
| | IS-IS | 链路状态协议，运营商网络 |
| 外部网关协议（EGP） | BGP | 路径矢量协议，互联网AS间路由 |

### 4. 传输层（Transport Layer）

| 维度 | 说明 |
|------|------|
| **核心功能** | 端到端通信、端口寻址、可靠传输、流量控制、拥塞控制 |
| **关注问题** | 端口号、TCP三次握手/四次挥手、UDP、滑动窗口 |
| **典型设备** | 负载均衡器（四层）、防火墙 |
| **典型协议** | TCP、UDP |

**端口号**：
- 16位，范围 0-65535
- 分类：
  - 知名端口（0-1023）：系统保留，如 HTTP(80)、HTTPS(443)、SSH(22)
  - 注册端口（1024-49151）：应用程序注册使用
  - 动态/私有端口（49152-65535）：客户端临时使用

**常见端口速查**：
| 端口 | 协议 | 服务 |
|------|------|------|
| 20/21 | TCP | FTP（数据/控制） |
| 22 | TCP | SSH / SCP / SFTP |
| 23 | TCP | Telnet（不安全） |
| 25 | TCP | SMTP（发邮件） |
| 53 | TCP/UDP | DNS |
| 80 | TCP | HTTP |
| 110 | TCP | POP3（收邮件） |
| 143 | TCP | IMAP（收邮件） |
| 443 | TCP | HTTPS / SSL/TLS |
| 3306 | TCP | MySQL |
| 5432 | TCP | PostgreSQL |
| 6379 | TCP | Redis |
| 8080 | TCP | HTTP 代理/替代端口 |
| 9200 | TCP | Elasticsearch |
| 27017 | TCP | MongoDB |

**TCP vs UDP**：

| 维度 | TCP | UDP |
|------|-----|-----|
| **连接性** | 面向连接（三次握手） | 无连接 |
| **可靠性** | 可靠（确认、重传、排序） | 不可靠（不保证送达） |
| **顺序性** | 保证顺序 | 不保证顺序 |
| **流量控制** | 滑动窗口 | 无 |
| **拥塞控制** | 慢启动、拥塞避免 | 无 |
| **头部开销** | 20-60字节 | 8字节 |
| **速度** | 较慢 | 快 |
| **适用场景** | Web、邮件、文件传输、数据库 | 视频直播、DNS、游戏、VoIP |

**TCP 三次握手**：
```text
客户端 → 服务端：SYN（seq=x）          → 我要连接
服务端 → 客户端：SYN+ACK（seq=y, ack=x+1） → 同意连接
客户端 → 服务端：ACK（ack=y+1）         → 确认，连接建立
```
为什么是三次？防止已失效的连接请求突然又传到服务端，浪费资源。

**TCP 四次挥手**：
```text
客户端 → 服务端：FIN（seq=u）           → 我要断开
服务端 → 客户端：ACK（ack=u+1）         → 确认（可能还有数据要发）
服务端 → 客户端：FIN（seq=w）           → 我也断开
客户端 → 服务端：ACK（ack=w+1）         → 确认，等待2MSL后关闭
```
为什么是四次？TCP是全双工，双方需要分别关闭。

**TCP 状态机关键状态**：
| 状态 | 说明 |
|------|------|
| LISTEN | 监听连接请求 |
| SYN_SENT | 已发送SYN，等待确认 |
| SYN_RECV | 已收到SYN并发送SYN+ACK |
| ESTABLISHED | 连接已建立，数据传输中 |
| FIN_WAIT_1 | 已发送FIN，等待确认 |
| FIN_WAIT_2 | 收到FIN的ACK，等待对方FIN |
| TIME_WAIT | 收到FIN并发送ACK，等待2MSL |
| CLOSE_WAIT | 收到对方FIN，等待本地关闭 |
| LAST_ACK | 已发送FIN，等待最后的ACK |

### 5. 应用层（Application Layer）

| 维度 | 说明 |
|------|------|
| **核心功能** | 为应用程序提供网络服务接口，定义应用层协议 |
| **关注问题** | 应用协议、数据格式、认证授权 |
| **典型协议** | HTTP/HTTPS、DNS、FTP、SMTP/POP3/IMAP、SSH、WebSocket、gRPC |

**HTTP 方法**：
| 方法 | 说明 | 幂等 | 安全 |
|------|------|------|------|
| GET | 获取资源 | ✅ | ✅ |
| POST | 创建资源 | ❌ | ❌ |
| PUT | 全量更新资源 | ✅ | ❌ |
| PATCH | 部分更新资源 | ❌ | ❌ |
| DELETE | 删除资源 | ✅ | ❌ |
| HEAD | 获取响应头（无body） | ✅ | ✅ |
| OPTIONS | 获取支持的方法/CORS | ✅ | ✅ |

**HTTP 状态码**：
| 类别 | 说明 | 常见码 |
|------|------|--------|
| 1xx | 信息 | 100 Continue, 101 Switching Protocols |
| 2xx | 成功 | 200 OK, 201 Created, 204 No Content, 206 Partial Content |
| 3xx | 重定向 | 301 Moved Permanently, 302 Found, 304 Not Modified, 307 Temporary Redirect |
| 4xx | 客户端错误 | 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found, 405 Method Not Allowed, 429 Too Many Requests |
| 5xx | 服务端错误 | 500 Internal Server Error, 502 Bad Gateway, 503 Service Unavailable, 504 Gateway Timeout |

**DNS（域名系统）**：
- 功能：将域名解析为 IP 地址
- 端口：53（UDP为主，TCP用于区域传输和大响应）
- 解析过程：
  1. 浏览器缓存 → 系统缓存 → hosts文件
  2. 本地DNS服务器（递归查询）
  3. 根域名服务器 → 顶级域服务器（.com/.cn）→ 权威域名服务器
- 记录类型：
  - A：IPv4地址
  - AAAA：IPv6地址
  - CNAME：别名（指向另一个域名）
  - MX：邮件服务器
  - TXT：文本记录（SPF/DKIM验证）
  - NS：域名服务器

**HTTPS = HTTP + SSL/TLS**：
- 端口：443
- TLS 握手过程：
  1. 客户端发送 ClientHello（支持的加密套件、随机数）
  2. 服务端返回 ServerHello（选定加密套件、随机数）+ 数字证书
  3. 客户端验证证书，生成预主密钥，用服务端公钥加密发送
  4. 双方用预主密钥+随机数生成会话密钥
  5. 切换到加密通信
- 证书链：根CA → 中间CA → 服务器证书

## 三、网络排障思路

### 1. 分层排障法

从底层到上层逐层排查：

```text
物理层 → 网线是否插好？网卡灯是否亮？
数据链路层 → MAC地址是否正确？交换机端口是否UP？VLAN配置？
网络层 → IP地址/子网掩码/网关是否正确？能否ping通网关？
传输层 → 端口是否开放？防火墙是否放行？TCP连接能否建立？
应用层 → 服务是否正常？协议是否正确？认证是否通过？
```

### 2. 常用排障命令

| 命令 | 功能 | 示例 |
|------|------|------|
| `ping` | 测试网络连通性 | `ping google.com` |
| `traceroute`/`tracert` | 追踪路由路径 | `traceroute google.com` |
| `nslookup`/`dig` | DNS解析查询 | `nslookup google.com` |
| `ipconfig`/`ifconfig`/`ip addr` | 查看网络配置 | `ip addr` |
| `netstat`/`ss` | 查看网络连接和端口 | `ss -tlnp` |
| `curl` | 发送HTTP请求 | `curl -v https://api.example.com` |
| `telnet`/`nc` | 测试端口连通性 | `telnet 192.168.1.1 8080` |
| `tcpdump`/`wireshark` | 抓包分析 | `tcpdump -i eth0 port 80` |
| `arp -a` | 查看ARP缓存 | `arp -a` |
| `route`/`ip route` | 查看路由表 | `ip route` |

### 3. 常见问题排查

| 问题 | 排查步骤 |
|------|---------|
| 无法上网 | 1. ping 127.0.0.1（网卡）→ 2. ping 网关（局域网）→ 3. ping 8.8.8.8（外网）→ 4. ping 域名（DNS） |
| 端口无法连接 | 1. 服务是否启动 → 2. 防火墙是否放行 → 3. 监听地址是否为0.0.0.0 → 4. 网络是否可达 |
| DNS解析失败 | 1. 检查DNS服务器配置 → 2. nslookup测试 → 3. 检查hosts文件 → 4. 检查防火墙53端口 |
| HTTPS证书错误 | 1. 检查证书是否过期 → 2. 检查域名是否匹配 → 3. 检查证书链是否完整 → 4. 检查系统时间 |
| 连接超时 | 1. 网络是否可达 → 2. 防火墙是否丢包 → 3. 服务是否响应 → 4. 检查MTU/分片问题 |

## 四、常见面试题

| 问题 | 要点 |
|------|------|
| **TCP三次握手为什么不是两次？** | 防止已失效的连接请求到达服务端导致资源浪费；双方都需确认收发能力 |
| **TIME_WAIT状态为什么要等2MSL？** | 确保最后一个ACK能到达服务端；确保本次连接的所有报文在网络中消失 |
| **TCP和UDP的区别？** | 连接性、可靠性、顺序性、流量/拥塞控制、头部开销、速度、适用场景 |
| **HTTP和HTTPS的区别？** | 端口(80/443)、加密、证书、安全性、性能开销 |
| **GET和POST的区别？** | 语义(获取/创建)、幂等性、安全性、参数位置(URL/Body)、长度限制、缓存 |
| **DNS解析过程？** | 浏览器缓存→系统缓存→hosts→本地DNS→根→顶级域→权威服务器 |
| **输入URL到页面显示发生了什么？** | DNS解析→TCP连接→TLS握手→HTTP请求→服务端处理→HTTP响应→浏览器解析渲染→连接关闭 |
| **交换机和路由器的区别？** | 工作层次(数据链路/网络)、寻址(MAC/IP)、功能(局域网转发/跨网络路由) |
| **Cookie和Session的区别？** | 存储位置(客户端/服务端)、安全性、容量限制、跨域、性能 |
| **什么是跨域？如何解决？** | 浏览器同源策略限制；CORS、JSONP、代理、Nginx反向代理 |
