# 操作系统 - 进程与线程

> 进程与线程的核心概念、区别与联系、进程调度、同步互斥、死锁、并发编程基础。

## 概述

进程和线程是操作系统最核心的概念之一，是理解并发编程、性能优化和系统设计的基础。

**基本定义**：
- **进程（Process）**：程序的一次执行过程，是系统进行资源分配和调度的基本单位
- **线程（Thread）**：进程中的一个执行单元，是 CPU 调度和分派的基本单位
- **协程（Coroutine）**：用户态的轻量级线程，由程序自己调度，不需要内核参与

**进程 vs 线程 vs 协程**：

| 维度 | 进程 | 线程 | 协程 |
|------|------|------|------|
| 资源分配 | 拥有独立资源（内存、文件句柄等） | 共享进程资源 | 共享线程资源 |
| 调度单位 | 资源分配单位 | CPU调度单位 | 用户态调度 |
| 切换开销 | 大（需切换页表、刷新TLB） | 小（只需切换寄存器和栈） | 极小（用户态切换） |
| 通信方式 | IPC（管道、消息队列、共享内存） | 共享内存（需同步） | 共享内存（需同步） |
| 并发数 | 有限（几百个） | 较多（几千个） | 极多（几十万个） |
| 崩溃影响 | 进程崩溃不影响其他进程 | 线程崩溃可能导致整个进程崩溃 | 协程崩溃不影响其他协程 |

**为什么需要线程**：
- 进程间通信开销大，线程间共享内存，通信方便
- 进程切换开销大，线程切换开销小
- 多核CPU下，多线程可以真正并行执行
- 一个进程内的多个线程可以共享代码段、数据段、文件句柄等

## 原理

### 进程的状态与转换

```text
创建 → 就绪 ←→ 运行 → 终止
         ↑      ↓
         └── 阻塞 ←┘
```

- **创建态**：进程正在被创建
- **就绪态**：进程已获得除CPU外的所有资源，等待调度
- **运行态**：进程正在CPU上执行
- **阻塞态**：进程等待某事件（如IO、锁），暂时无法执行
- **终止态**：进程执行完毕或被终止

**状态转换**：
- 就绪 → 运行：调度程序选中该进程
- 运行 → 就绪：时间片用完，或被更高优先级进程抢占
- 运行 → 阻塞：等待IO、等待锁、等待信号
- 阻塞 → 就绪：等待的事件发生了

### 进程调度算法

| 算法 | 原理 | 优点 | 缺点 | 适用场景 |
|------|------|------|------|---------|
| FCFS（先来先服务） | 按到达顺序执行 | 简单公平 | 短作业等待时间长 | 批处理 |
| SJF（短作业优先） | 按执行时间最短优先 | 平均等待时间最短 | 长作业可能饥饿 | 批处理 |
| 时间片轮转 | 每个进程分配时间片，轮流执行 | 公平，响应快 | 上下文切换开销 | 分时系统 |
| 优先级调度 | 按优先级高低执行 | 重要任务优先 | 低优先级可能饥饿 | 实时系统 |
| 多级反馈队列 | 多个队列，优先级递减，时间片递增 | 兼顾长短作业，适应性强 | 实现复杂 | 通用系统 |

### 线程的实现方式

1. **用户级线程**：
   - 由用户空间的线程库管理，内核不知道线程存在
   - 优点：切换快，不需要内核干预，可自定义调度
   - 缺点：一个线程阻塞，整个进程阻塞；无法利用多核（内核只看到一个进程）

2. **内核级线程**：
   - 由内核管理，内核知道每个线程
   - 优点：一个线程阻塞不影响其他线程；可利用多核并行
   - 缺点：切换开销大（需要内核态切换）

3. **混合实现（两级线程模型）**：
   - 用户级线程映射到内核级线程（N:M映射）
   - 兼顾两者优点，如Go语言的goroutine

### 进程同步与互斥

**临界区**：访问共享资源的代码段，多个进程不能同时进入

**同步机制**：
1. **互斥锁（Mutex）**：保证同一时间只有一个线程进入临界区
2. **信号量（Semaphore）**：计数器，控制同时访问资源的线程数
   - 二元信号量（0/1）：相当于互斥锁
   - 计数信号量：允许多个线程同时访问
3. **条件变量（Condition）**：线程等待某个条件成立，通常与互斥锁配合
4. **管程（Monitor）**：封装共享数据和操作，保证同一时间只有一个进程在管程内
5. **读写锁（RWLock）**：读读共享，读写互斥，写写互斥

**经典同步问题**：
- **生产者-消费者问题**：生产者生产数据放入缓冲区，消费者从缓冲区取数据
- **读者-写者问题**：多个读者可以同时读，写者独占访问
- **哲学家进餐问题**：5个哲学家围坐，每人需要左右两根筷子才能吃饭

### 死锁

**死锁的四个必要条件**：
1. **互斥**：资源不能被多个进程同时持有
2. **持有并等待**：进程持有资源的同时等待其他资源
3. **不可剥夺**：资源不能被强制剥夺，只能主动释放
4. **循环等待**：进程间形成循环等待链

**死锁的处理策略**：
1. **预防死锁**：破坏四个必要条件之一（如有序资源分配破坏循环等待）
2. **避免死锁**：银行家算法，分配资源前检查是否安全
3. **检测死锁**：定期检测死锁，发现后恢复（终止进程、剥夺资源）
4. **忽略死锁**：假设死锁很少发生，不处理（如Windows、Linux）

## 实操

### 1. Java 线程创建与使用

```java
// 方式1：继承Thread类
class MyThread extends Thread {
    @Override
    public void run() {
        System.out.println("线程执行: " + Thread.currentThread().getName());
    }
}

// 方式2：实现Runnable接口（推荐）
class MyRunnable implements Runnable {
    @Override
    public void run() {
        System.out.println("线程执行: " + Thread.currentThread().getName());
    }
}

// 方式3：实现Callable接口（有返回值）
class MyCallable implements Callable<String> {
    @Override
    public String call() throws Exception {
        return "线程执行结果";
    }
}

// 使用
public class ThreadExample {
    public static void main(String[] args) throws Exception {
        // 方式1
        new MyThread().start();

        // 方式2
        new Thread(new MyRunnable()).start();

        // 方式3（有返回值）
        FutureTask<String> task = new FutureTask<>(new MyCallable());
        new Thread(task).start();
        System.out.println(task.get()); // 获取结果，阻塞等待

        // 方式4：Lambda
        new Thread(() -> System.out.println("Lambda线程")).start();

        // 方式5：线程池（推荐生产环境使用）
        ExecutorService pool = Executors.newFixedThreadPool(10);
        pool.submit(() -> System.out.println("线程池执行"));
        pool.shutdown();
    }
}
```

### 2. 线程同步（synchronized 和 Lock）

```java
// synchronized（隐式锁）
public class Counter {
    private int count = 0;

    // 方法锁
    public synchronized void increment() {
        count++;
    }

    // 代码块锁
    public void increment2() {
        synchronized (this) {
            count++;
        }
    }
}

// ReentrantLock（显式锁，更灵活）
public class CounterLock {
    private int count = 0;
    private final Lock lock = new ReentrantLock();

    public void increment() {
        lock.lock(); // 获取锁
        try {
            count++;
        } finally {
            lock.unlock(); // 释放锁（必须在finally中）
        }
    }

    // 尝试获取锁，带超时
    public boolean tryIncrement() {
        try {
            if (lock.tryLock(1, TimeUnit.SECONDS)) {
                try {
                    count++;
                    return true;
                } finally {
                    lock.unlock();
                }
            }
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
        return false;
    }
}
```

### 3. 线程池配置

```java
// 自定义线程池（生产环境推荐，不使用Executors）
public class ThreadPoolConfig {
    @Bean
    public ThreadPoolExecutor taskExecutor() {
        return new ThreadPoolExecutor(
            10,                          // 核心线程数
            20,                          // 最大线程数
            60,                          // 空闲线程存活时间
            TimeUnit.SECONDS,
            new LinkedBlockingQueue<>(1000),  // 任务队列
            new ThreadFactoryBuilder().setNameFormat("task-pool-%d").build(),
            new ThreadPoolExecutor.CallerRunsPolicy()  // 拒绝策略
        );
    }
}

// 线程池参数选择
// CPU密集型：核心线程数 = CPU核数 + 1
// IO密集型：核心线程数 = CPU核数 * 2 或 CPU核数 / (1 - 阻塞系数)
// 拒绝策略：
// - AbortPolicy：抛出异常（默认）
// - CallerRunsPolicy：调用者线程执行
// - DiscardPolicy：直接丢弃
// - DiscardOldestPolicy：丢弃最旧的任务
```

## 问题

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 死锁 | 四个必要条件同时满足 | 预防（破坏条件）/ 避免（银行家算法）/ 检测恢复 / 按顺序加锁 |
| 线程安全问题 | 多线程同时修改共享数据 | 加锁（synchronized/Lock）/ 原子类（AtomicInteger）/ 不可变对象 / ThreadLocal |
| 线程池队列满 | 任务太多，处理不过来 | 增大队列/线程数 / 优化任务处理速度 / 限流 / 合理的拒绝策略 |
| 上下文切换开销大 | 线程数太多，频繁切换 | 控制线程数（CPU核数相关）/ 减少锁竞争 / 使用协程 |
| 虚假唤醒 | 条件变量的wait可能被意外唤醒 | while循环检查条件，不用if |
| 活锁 | 线程都在响应对方，都不继续执行 | 加入随机延迟 / 打破交替响应模式 |
| 线程饥饿 | 低优先级线程一直得不到执行 | 公平锁 / 调整优先级 / 避免长时间持有锁 |
| 进程僵尸 | 子进程结束，父进程未回收 | 父进程调用wait/waitpid / 忽略SIGCHLD信号 |
