## 一、概述

**策略模式（Strategy Pattern）** 是一种行为型设计模式，它定义了一系列算法，将每个算法封装到独立的类中，使它们可以互相替换，让算法的变化独立于使用算法的客户端。

### 1. 核心思想

策略模式的核心是**将算法（策略）与使用算法的客户端分离**，通过组合而非继承来实现算法的灵活切换。

**解决的问题**：
- 一个类有多种行为，使用大量 `if-else`/`switch` 难以维护
- 需要在运行时动态切换算法
- 算法需要独立于客户端演化
- 避免继承导致的类爆炸

### 2. 生活中的类比

| 场景 | 策略 | 说明 |
|------|------|------|
| **出行方式** | 步行/骑车/开车/坐地铁/坐飞机 | 根据距离、时间、预算选择不同出行方式 |
| **支付方式** | 支付宝/微信/信用卡/现金 | 根据用户偏好选择支付方式 |
| **排序算法** | 快排/归并/堆排/冒泡 | 根据数据规模和特点选择排序算法 |
| **折扣策略** | 会员折扣/满减/优惠券/限时特价 | 根据用户类型和活动选择折扣方式 |
| **压缩算法** | ZIP/GZIP/TAR/7z | 根据需求选择压缩方式 |

### 3. 策略模式 vs if-else

**反例（大量 if-else）**：
```java
public class PaymentService {
    public void pay(String type, double amount) {
        if ("ALIPAY".equals(type)) {
            // 支付宝支付逻辑（50行代码）
            System.out.println("支付宝支付: " + amount);
        } else if ("WECHAT".equals(type)) {
            // 微信支付逻辑（50行代码）
            System.out.println("微信支付: " + amount);
        } else if ("CREDIT_CARD".equals(type)) {
            // 信用卡支付逻辑（50行代码）
            System.out.println("信用卡支付: " + amount);
        } else if ("APPLE_PAY".equals(type)) {
            // 新增支付方式需要修改这里，违反开闭原则
        }
        // 每新增一种支付方式，这个方法就越来越长
    }
}
```

**问题**：
- 方法越来越长，难以阅读和维护
- 新增支付方式需要修改已有代码（违反开闭原则）
- 不同支付逻辑耦合在一起，修改一个可能影响其他
- 无法在运行时动态切换
- 单元测试困难

**正例（策略模式）**：
```java
// 策略接口
public interface PaymentStrategy {
    void pay(double amount);
}

// 具体策略
public class AlipayStrategy implements PaymentStrategy {
    public void pay(double amount) {
        System.out.println("支付宝支付: " + amount);
    }
}

public class WechatStrategy implements PaymentStrategy {
    public void pay(double amount) {
        System.out.println("微信支付: " + amount);
    }
}

// 上下文（使用策略）
public class PaymentService {
    private PaymentStrategy strategy;

    public void setStrategy(PaymentStrategy strategy) {
        this.strategy = strategy;  // 运行时动态切换
    }

    public void pay(double amount) {
        strategy.pay(amount);  // 委托给策略
    }
}

// 使用
PaymentService service = new PaymentService();
service.setStrategy(new AlipayStrategy());
service.pay(100.0);  // 支付宝支付

service.setStrategy(new WechatStrategy());
service.pay(100.0);  // 微信支付

// 新增支付方式只需新增一个策略类，不需修改 PaymentService
```

## 二、UML 结构与角色

### 1. UML 类图

```text
┌─────────────────────────┐
│         Context         │
│  (PaymentService)       │
├─────────────────────────┤
│ - strategy: Strategy    │
├─────────────────────────┤
│ + setStrategy()         │
│ + execute()             │
└───────────┬─────────────┘
            │ 组合/委托
            ▼
┌─────────────────────────┐
│   <<interface>>         │
│        Strategy         │
│  (PaymentStrategy)      │
├─────────────────────────┤
│ + algorithmInterface()  │
└───────────┬─────────────┘
            │ 实现
     ┌──────┼──────┐
     ▼      ▼      ▼
┌────────┐┌────────┐┌────────┐
│Concrete││Concrete││Concrete│
│Strategy││Strategy││Strategy│
│   A    ││   B    ││   C    │
├────────┤├────────┤├────────┤
│+alg()  ││+alg()  ││+alg()  │
└────────┘└────────┘└────────┘
```

### 2. 角色说明

| 角色 | 说明 | 示例 |
|------|------|------|
| **Strategy（策略接口）** | 定义所有支持算法的公共接口 | `PaymentStrategy` |
| **ConcreteStrategy（具体策略）** | 实现策略接口，封装具体算法 | `AlipayStrategy`、`WechatStrategy` |
| **Context（上下文）** | 持有策略对象的引用，委托策略执行算法 | `PaymentService` |
| **Client（客户端）** | 创建具体策略对象，设置到上下文中 | 调用方 |

### 3. 协作流程

```text
Client → 创建 ConcreteStrategyA
Client → Context.setStrategy(ConcreteStrategyA)
Client → Context.execute()
Context → 委托给 Strategy.algorithmInterface()
ConcreteStrategyA → 执行具体算法
```

```java
// 策略接口
public interface PaymentStrategy {
    String getName();
    void pay(double amount);
    boolean supports(String type);
}

// 具体策略：支付宝
@Component
public class AlipayStrategy implements PaymentStrategy {
    @Override
    public String getName() { return "ALIPAY"; }

    @Override
    public void pay(double amount) {
        System.out.printf("支付宝支付 %.2f 元%n", amount);
        // 调用支付宝 API...
    }

    @Override
    public boolean supports(String type) {
        return "ALIPAY".equalsIgnoreCase(type);
    }
}

// 具体策略：微信支付
@Component
public class WechatStrategy implements PaymentStrategy {
    @Override
    public String getName() { return "WECHAT"; }

    @Override
    public void pay(double amount) {
        System.out.printf("微信支付 %.2f 元%n", amount);
        // 调用微信支付 API...
    }

    @Override
    public boolean supports(String type) {
        return "WECHAT".equalsIgnoreCase(type);
    }
}

// 具体策略：信用卡
@Component
public class CreditCardStrategy implements PaymentStrategy {
    @Override
    public String getName() { return "CREDIT_CARD"; }

    @Override
    public void pay(double amount) {
        System.out.printf("信用卡支付 %.2f 元%n", amount);
        // 调用信用卡 API...
    }

    @Override
    public boolean supports(String type) {
        return "CREDIT_CARD".equalsIgnoreCase(type);
    }
}

// 上下文（Spring 自动注入所有策略）
@Service
public class PaymentService {
    private final Map<String, PaymentStrategy> strategyMap;

    // Spring 自动注入所有 PaymentStrategy 实现
    public PaymentService(List<PaymentStrategy> strategies) {
        this.strategyMap = strategies.stream()
            .collect(Collectors.toMap(PaymentStrategy::getName, s -> s));
    }

    public void pay(String type, double amount) {
        PaymentStrategy strategy = strategyMap.get(type.toUpperCase());
        if (strategy == null) {
            throw new IllegalArgumentException("不支持的支付方式: " + type);
        }
        strategy.pay(amount);
    }
}

// 使用
@RestController
@RequestMapping("/payment")
public class PaymentController {
    @Autowired
    private PaymentService paymentService;

    @PostMapping("/pay")
    public void pay(@RequestParam String type, @RequestParam double amount) {
        paymentService.pay(type, amount);
    }
}
```

### 2. Python 实现（排序策略）

```python
from abc import ABC, abstractmethod
from typing import List

# 策略接口
class SortStrategy(ABC):
    @abstractmethod
    def sort(self, data: List[int]) -> List[int]:
        pass

    @abstractmethod
    def get_name(self) -> str:
        pass

# 具体策略：快速排序
class QuickSort(SortStrategy):
    def get_name(self) -> str:
        return "quick"

    def sort(self, data: List[int]) -> List[int]:
        if len(data) <= 1:
            return data
        pivot = data[len(data) // 2]
        left = [x for x in data if x < pivot]
        middle = [x for x in data if x == pivot]
        right = [x for x in data if x > pivot]
        return self.sort(left) + middle + self.sort(right)

# 具体策略：归并排序
class MergeSort(SortStrategy):
    def get_name(self) -> str:
        return "merge"

    def sort(self, data: List[int]) -> List[int]:
        if len(data) <= 1:
            return data
        mid = len(data) // 2
        left = self.sort(data[:mid])
        right = self.sort(data[mid:])
        return self._merge(left, right)

    def _merge(self, left, right):
        result = []
        i = j = 0
        while i < len(left) and j < len(right):
            if left[i] <= right[j]:
                result.append(left[i]); i += 1
            else:
                result.append(right[j]); j += 1
        result.extend(left[i:])
        result.extend(right[j:])
        return result

# 具体策略：内置排序（Timsort）
class BuiltinSort(SortStrategy):
    def get_name(self) -> str:
        return "builtin"

    def sort(self, data: List[int]) -> List[int]:
        return sorted(data)

# 上下文
class Sorter:
    def __init__(self):
        self._strategies = {}

    def register(self, strategy: SortStrategy):
        self._strategies[strategy.get_name()] = strategy

    def sort(self, data: List[int], strategy_name: str = "builtin") -> List[int]:
        strategy = self._strategies.get(strategy_name)
        if not strategy:
            raise ValueError(f"未知排序策略: {strategy_name}")
        return strategy.sort(data)

# 使用
sorter = Sorter()
sorter.register(QuickSort())
sorter.register(MergeSort())
sorter.register(BuiltinSort())

data = [3, 1, 4, 1, 5, 9, 2, 6]
print(sorter.sort(data, "quick"))    # 快速排序
print(sorter.sort(data, "merge"))    # 归并排序
print(sorter.sort(data, "builtin"))  # 内置排序
```

### 3. TypeScript 实现（折扣策略）

```typescript
// 策略接口
interface DiscountStrategy {
  calculate(originalPrice: number): number;
  getDescription(): string;
}

// 具体策略：无折扣
class NoDiscount implements DiscountStrategy {
  calculate(originalPrice: number): number {
    return originalPrice;
  }
  getDescription(): string {
    return "无折扣";
  }
}

// 具体策略：百分比折扣
class PercentageDiscount implements DiscountStrategy {
  constructor(private percentage: number) {}

  calculate(originalPrice: number): number {
    return originalPrice * (1 - this.percentage / 100);
  }
  getDescription(): string {
    return `${this.percentage}% 折扣`;
  }
}

// 具体策略：满减
class ThresholdDiscount implements DiscountStrategy {
  constructor(private threshold: number, private discount: number) {}

  calculate(originalPrice: number): number {
    if (originalPrice >= this.threshold) {
      return originalPrice - this.discount;
    }
    return originalPrice;
  }
  getDescription(): string {
    return `满${this.threshold}减${this.discount}`;
  }
}

// 具体策略：会员折扣
class MemberDiscount implements DiscountStrategy {
  constructor(private level: "normal" | "silver" | "gold" | "platinum") {}

  private getRate(): number {
    const rates = { normal: 1, silver: 0.95, gold: 0.9, platinum: 0.85 };
    return rates[this.level];
  }

  calculate(originalPrice: number): number {
    return originalPrice * this.getRate();
  }
  getDescription(): string {
    return `${this.level}会员 ${(1 - this.getRate()) * 100}%off`;
  }
}

// 上下文
class PriceCalculator {
  private strategy: DiscountStrategy;

  constructor(strategy: DiscountStrategy = new NoDiscount()) {
    this.strategy = strategy;
  }

  setStrategy(strategy: DiscountStrategy): void {
    this.strategy = strategy;
  }

  calculate(originalPrice: number): number {
    return this.strategy.calculate(originalPrice);
  }

  getDescription(): string {
    return this.strategy.getDescription();
  }
}

// 使用
const calculator = new PriceCalculator();

// 普通价格
calculator.setStrategy(new NoDiscount());
console.log(calculator.calculate(100), calculator.getDescription()); // 100 无折扣

// 会员折扣
calculator.setStrategy(new MemberDiscount("gold"));
console.log(calculator.calculate(100), calculator.getDescription()); // 90 gold会员 10%off

// 满减
calculator.setStrategy(new ThresholdDiscount(100, 20));
console.log(calculator.calculate(100), calculator.getDescription()); // 80 满100减20
```

## 四、策略模式的变体

### 1. 函数式策略（Java 8+ / Python / TS）

现代语言中，可以用函数/方法引用简化策略模式，不需要显式定义接口和实现类：

```java
// Java 8+：用 Function/Predicate 等函数式接口
public class PaymentService {
    private final Map<String, Consumer<Double>> strategies = new HashMap<>();

    public PaymentService() {
        strategies.put("ALIPAY", amount -> System.out.println("支付宝: " + amount));
        strategies.put("WECHAT", amount -> System.out.println("微信: " + amount));
    }

    public void pay(String type, double amount) {
        strategies.getOrDefault(type, a -> {
            throw new IllegalArgumentException("不支持: " + type);
        }).accept(amount);
    }
}
```

```python
# Python：用字典映射函数
strategies = {
    "quick": lambda data: quick_sort(data),

def sort_data(data, strategy="builtin"):
```

### 2. 策略枚举

用枚举实现策略，适合策略数量固定且较少的场景：

```java
public enum PaymentStrategy {
    ALIPAY {
        @Override
        public void pay(double amount) {
            System.out.println("支付宝支付: " + amount);
        }
    },
    WECHAT {
        @Override
        public void pay(double amount) {
            System.out.println("微信支付: " + amount);
        }
    },
    CREDIT_CARD {
        @Override
        public void pay(double amount) {
            System.out.println("信用卡支付: " + amount);
        }
    };

    public abstract void pay(double amount);

    // 工厂方法
    public static PaymentStrategy fromType(String type) {
        return PaymentStrategy.valueOf(type.toUpperCase());
    }
}

// 使用
PaymentStrategy.fromType("ALIPAY").pay(100.0);
```

### 3. 组合策略（Composite Strategy）

多个策略组合执行，如多重折扣叠加：

```java
public class CompositeDiscount implements DiscountStrategy {
    private final List<DiscountStrategy> strategies;

    public CompositeDiscount(DiscountStrategy... strategies) {
        this.strategies = Arrays.asList(strategies);
    }

    @Override
    public double calculate(double price) {
        double result = price;
        for (DiscountStrategy strategy : strategies) {
            result = strategy.calculate(result);  // 依次应用
        }
        return result;
    }
}

// 使用：会员折扣 + 满减 叠加
DiscountStrategy combined = new CompositeDiscount(
    new MemberDiscount("gold"),
    new ThresholdDiscount(100, 20)
);
double finalPrice = combined.calculate(200);  // 先9折=180，再满100减20=160
```

## 五、与其他模式的区别

### 1. 策略模式 vs 工厂模式

| 维度 | 策略模式 | 工厂模式 |
|------|---------|---------|
| **目的** | 封装算法，可互换 | 创建对象，隐藏创建逻辑 |
| **关注点** | 行为/算法的变化 | 对象创建的变化 |
| **返回值** | 执行算法的结果 | 创建的对象 |
| **使用时机** | 运行时切换算法 | 需要对象时 |
| **关系** | 策略对象由工厂创建 | 工厂可以创建策略对象 |

**两者经常配合使用**：工厂模式创建策略对象，策略模式执行算法。

### 2. 策略模式 vs 状态模式

| 维度 | 策略模式 | 状态模式 |
|------|---------|---------|
| **目的** | 封装可互换的算法 | 封装状态相关的行为 |
| **切换原因** | 客户端主动选择策略 | 对象状态变化自动切换 |
| **客户端感知** | 客户端知道所有策略 | 客户端不需要知道状态 |
| **状态持有** | 策略通常无状态 | 状态模式持有状态 |
| **切换频率** | 通常切换较少 | 状态可能频繁变化 |

### 3. 策略模式 vs 模板方法模式

| 维度 | 策略模式 | 模板方法模式 |
|------|---------|-------------|
| **实现方式** | 组合（委托） | 继承（重写） |
| **灵活性** | 运行时切换 | 编译时确定 |
| **代码复用** | 策略间无复用 | 基类复用公共逻辑 |
| **耦合度** | 低（策略独立） | 较高（子类依赖父类） |
| **适用场景** | 算法需动态切换 | 算法步骤固定，细节变化 |

## 六、适用场景与优缺点

### 1. 适用场景

- [ ] 一个类有多种行为，用 `if-else`/`switch` 维护困难
- [ ] 需要在运行时动态切换算法
- [ ] 算法需要独立于客户端演化和测试
- [ ] 多个类只有算法/行为不同，其他相同
- [ ] 需要隐藏算法的具体实现细节
- [ ] 客户需要知道不同策略的区别（如选择不同的支付方式）

### 2. 优点

| 优点 | 说明 |
|------|------|
| **开闭原则** | 新增策略不需修改已有代码 |
| **避免 if-else** | 消除大量条件判断，代码更清晰 |
| **可复用** | 策略可在不同上下文中复用 |
| **可测试** | 每个策略可独立单元测试 |
| **运行时切换** | 可动态切换算法 |
| **单一职责** | 每个策略只负责一个算法 |

### 3. 缺点

| 缺点 | 说明 |
|------|------|
| **类数量增加** | 每个策略一个类，可能导致类爆炸 |
| **客户端需了解策略** | 客户端需要知道不同策略的区别才能选择 |
| **增加复杂度** | 简单场景使用策略模式可能过度设计 |
| **策略间通信成本** | 策略间如果需要共享数据，需要额外处理 |

### 4. 何时不使用

- 算法只有一两种，且很少变化 → 直接用 if-else 更简单
- 策略逻辑非常简单（一行代码） → 用函数式接口/枚举更简洁
- 客户端不需要切换算法 → 不需要策略模式
- 项目很小，生命周期短 → 避免过度设计

## 七、Spring 中的策略模式

Spring 框架中大量使用策略模式：

| Spring 组件 | 策略接口 | 说明 |
|------------|---------|------|
| **资源加载** | `ResourceLoader` / `Resource` | 根据前缀选择不同资源加载策略（classpath:/file:/http:） |
| **视图解析** | `ViewResolver` | 不同视图解析策略（InternalResourceViewResolver/FreeMarkerViewResolver） |
| **异常解析** | `HandlerExceptionResolver` | 不同异常处理策略 |

| **事务管理** | `PlatformTransactionManager` | 不同事务管理策略（JDBC/JPA/Hibernate） |
| **属性解析** | `PropertySource` | 不同属性来源策略（系统环境/配置文件/命令行） |
