## 1. 操作系统

### 1.1 概述

操作系统管理硬件资源、为程序提供执行环境。核心职责：进程/线程管理、内存管理、文件系统、IO 与中断、提供系统调用。是连接应用与硬件的"内核"。

> 🔍 **知识点深度解析**
>
> **作用**：理解 OS 是理解并发、内存、IO 性能的根——JVM/K8s/数据库调优都建立在 OS 概念上。
>
> **原理**：内核态/用户态隔离保护硬件；进程是资源单位、线程是调度单位；虚拟内存用页表把虚拟地址映射到物理页，缺页时从磁盘换入；调度器按策略（CFS/RT）分配 CPU。
>
> **用法要点**：① 高并发程序受限于线程调度与上下文切换；② 内存用虚拟地址，OOM 多因 RSS 超 limit；③ 文件用 buffer/cache，free 看 available；④ IO 模型决定吞吐；⑤ 会看 top/ps/perf 排障。

### 1.2 核心特性

**进程线程**：PCB、上下文切换、协程（用户态轻量）。

**内存**：虚拟内存、分页、分段、缺页中断、页面置换（LRU）。

**并发原语**：锁、信号量、原子操作、CAS。

**IO 模型**：阻塞/非阻塞、多路复用（epoll）、异步 IO。

> 🔍 **知识点深度解析**
>
> **作用**：这些特性是"程序为什么有时慢/卡/崩"的答案集合。
>
> **原理**：上下文切换保存/恢复寄存器有开销，频繁切换浪费 CPU；虚拟内存让每个进程误以为独占全部内存；epoll 用红黑树+就绪链表管理海量连接，避免 select 的轮询；CAS 是无锁同步基础。
>
> **用法要点**：① 减少不必要锁降低切换；② 零拷贝（sendfile）省用户态拷贝；③ 协程（Go/Python asyncio）万级并发成本低；④ 页面置换抖动（thrashing）要加内存；⑤ IO 密集用多路复用。

### 1.3 常用用法

```bash
# 排障常用
top -H -p <pid>        # 看线程级 CPU
free -h                # 看内存(available 才是可用)
vmstat 1               # 看上下文切换(cs)/IO 等待(wa)
iostat -x 1            # 看磁盘 IO 利用率
```

```c
// 用 mmap 零拷贝读取大文件（示意）
void* p = mmap(NULL, size, PROT_READ, MAP_PRIVATE, fd, 0);
// 直接访问 p，无需 read 拷贝进用户缓冲
```

> 🔍 **知识点深度解析**
>
> **作用**：上述命令与 mmap 是 OS 层排障与优化手段。
>
> **原理**：`top -H` 显示线程；`free` 的 available 含可回收 cache；`vmstat` 的 cs 是上下文切换次数、wa 是 IO 等待；mmap 把文件映射进虚拟地址空间，读写走页错误按需加载，省一次拷贝。
>
> **用法要点**：① 先看 wa 判断是否 IO 瓶颈；② cs 过高查锁竞争；③ 大文件用 mmap/sendfile 零拷贝；④ available 比 free 更准；⑤ 结合 perf 火焰图定位热点。

### 1.4 注意事项

1. **上下文切换**：锁竞争激烈致切换暴涨，性能反降
2. **虚拟内存**：SWAP 频繁（thrashing）性能骤降，加内存/限 swap
3. **死锁**：锁顺序不一致易死锁，固定加锁顺序
4. **IO 阻塞**：同步阻塞拖垮吞吐，用多路复用/异步
5. **文件描述符**：连接数超 ulimit 报错，调内核参数

> 💡 **深度讲解**：操作系统是"资源调度器"。进程管资源、线程管调度，上下文切换有真实成本——高并发下锁竞争导致的频繁切换比计算本身更耗时。虚拟内存让程序脱离物理限制，但页面置换抖动（thrashing）会让系统瘫痪。IO 是性能分水岭：阻塞模型简单但吞吐低，epoll/IO 多路复用支撑十万级连接，异步 IO 进一步释放线程。排障要用对工具：top 看 CPU、free 看 available、vmstat 看切换与 IO 等待、iostat 看磁盘。零拷贝（mmap/sendfile）是高吞吐服务必学。

> 📝 **精简总结**：OS=资源管理(进程/内存/文件/IO)；进程=资源单位/线程=调度单位；内存=虚拟+分页+缺页；并发=锁/信号量/CAS；IO=阻塞/多路复用(epoll)/异步；注意=切换成本/ thrashing/死锁/ fd 限制。

## 2. 计算机网络

### 2.1 概述

网络让主机互联。分层模型：OSI 七层（理论）/ TCP/IP 四层（实践）。核心协议：IP（寻址）、TCP（可靠）、UDP（快）、HTTP（应用）、DNS（域名）、TLS（安全）。

> 🔍 **知识点深度解析**
>
> **作用**：网络是分布式系统的地基——每一次 API 调用都经过 TCP/HTTP/TLS。
>
> **原理**：TCP 三次握手建连、四次挥手断连，靠序列号+确认+滑动窗口+重传保证可靠有序；UDP 无连接无重传，低延迟；HTTP 是请求/响应文本协议，HTTPS=HTTP+TLS 加密；DNS 把域名解析为 IP。
>
> **用法要点**：① 可靠传输用 TCP，实时音视频用 UDP；② 性能看 RTT 与丢包；③ 长连接省握手开销；④ 抓包用 tcpdump/Wireshark；⑤ 跨域/CORS 是浏览器安全策略。

### 2.2 核心特性

**TCP**：三次握手、可靠传输、流量控制（滑动窗口）、拥塞控制、四次挥手。

**HTTP 演进**：1.1（队头阻塞/管线）、2（多路复用/二进制帧）、3（QUIC/基于 UDP）。

**安全**：HTTPS/TLS 握手、证书链、对称+非对称结合。

**其他**：DNS 解析、CDN、WebSocket（全双工）。

> 🔍 **知识点深度解析**
>
> **作用**：TCP 可靠 + HTTP 易用 + TLS 安全，构成 Web 三件套；HTTP/2、3 解决性能。
>
> **原理**：TCP 滑动窗口既做流量控制（对端缓冲）又参与拥塞控制（网络拥塞降窗）；HTTP/2 单连接多路复用流解决队头阻塞；HTTP/3 用 QUIC（UDP）避免 TCP 队头阻塞与握手 RTT；TLS 用非对称交换对称密钥，之后对称加密提速。
>
> **用法要点**：① 握手 RTT 影响首屏，用 TLS1.3（1-RTT）/0-RTT；② HTTP/2 需单域多路复用；③ 证书过期/链不全导致 HTTPS 失败；④ DNS 用 HTTPDNS 防劫持；⑤ WebSocket 用于实时双向。

### 2.3 常用用法

```bash
# 网络排障
curl -w "@curl_format.txt" -o /dev/null -s https://api.example.com  # 看各阶段耗时
tcpdump -i any -w cap.pcap port 443 &    # 抓包
ss -tnp | grep :8080                     # 看连接状态
```

```http
# 一次 HTTPS 请求关键头
GET /api/users HTTP/1.1
Host: api.example.com
Authorization: Bearer <token>
Accept: application/json
```

> 🔍 **知识点深度解析**
>
> **作用**：curl 计时与 tcpdump 抓包是定位"慢在哪/错在哪"的利器。
>
> **原理**：`-w` 输出 DNS/TCP/TLS/首字节(TTFB)各阶段耗时，定位瓶颈；`ss` 看连接为 ESTABLISHED/SYNN_SENT/TIME_WAIT；Authorization 头带令牌做鉴权。
>
> **用法要点**：① 慢先看 TTFB（后端）还是 download（网络）；② TIME_WAIT 多调 tcp_tw_reuse；③ 抓包分析握手与重传；④ 头字段规范（Authorization 非 Auth）。

### 2.4 注意事项

1. **队头阻塞**：HTTP/1.1 管线易阻塞，关键资源用 HTTP/2
2. **TIME_WAIT**：短连接多致端口耗尽，用长连接/复用
3. **TLS 成本**：握手有 RTT，用会话复用/TLS1.3
4. **CORS**：浏览器的跨域限制，后端需正确返回头
5. **证书**：过期/域名不匹配导致握手失败

> 💡 **深度讲解**：网络分层把复杂问题拆开——链路层管帧、网络层管寻址（IP）、传输层管可靠（TCP）/快（UDP）、应用层管语义（HTTP）。TCP 的可靠靠"序列号+确认+重传+窗口"，代价是握手 RTT 与队头阻塞。HTTP/2 用多路复用解决应用层队头阻塞，HTTP/3 用 QUIC（UDP）进一步消除传输层队头阻塞。HTTPS 用"非对称交换密钥 + 对称加密传输"兼顾安全与性能。排障工具链：curl 计时定位阶段、tcpdump/Wireshark 看包、ss 看连接状态。CORS 是浏览器同源策略的安全围栏，后端需显式放行。

> 📝 **精简总结**：网络=分层(TCP/IP)；TCP=握手/可靠/窗口/拥塞；HTTP=1.1队头阻塞→2多路复用→3 QUIC；HTTPS=非对称换密钥+对称加密；排障=curl计时/tcpdump/ss；注意=队头阻塞/TIME_WAIT/TLS成本/CORS/证书。

## 3. 计算机组成原理

### 3.1 概述

组成原理研究 CPU、存储、总线的硬件实现。核心：冯·诺依曼体系、指令集、CPU 流水线、存储层次（寄存器→Cache→内存→磁盘）、总线与 IO 接口。

> 🔍 **知识点深度解析**
>
> **作用**：理解硬件为何这样设计，才能解释"为什么 Cache 命中快、为什么内存比磁盘快万倍、为什么分支预测重要"。
>
> **原理**：冯·诺依曼"存储程序"——指令与数据同存内存，CPU 取指-译码-执行循环。CPU 五级流水线（IF/ID/EX/MEM/WB）提升吞吐，分支预测减少流水线停顿。存储层次用"局部性原理"用廉价大容量兜底高速小容量。
>
> **用法要点**：① 写缓存友好代码（顺序访问）提命中；② 关注 CPU 缓存行（false sharing）；③ 理解指令流水与分支预测；④ 内存带宽常是瓶颈；⑤ SIMD 加速批量计算。

### 3.2 核心特性

**存储层次**：寄存器(ns) → L1/L2/L3 Cache → 主存(DRAM) → SSD → HDD，速度递万倍、容量递千倍。

**CPU**：ALU、控制单元、寄存器、流水线、超标量、乱序执行。

**Cache**：映射（直接/组相联）、替换（LRU）、写策略（写回/写直达）、缓存一致性（MESI）。

> 🔍 **知识点深度解析**
>
> **作用**：存储层次是"用空间换时间"的硬件版；Cache 一致性是多核正确性的关键。
>
> **原理**：局部性（时间/空间）让 Cache 命中率高；组相联 Cache 提高灵活性；MESI 协议维护多核 Cache 行一致性（修改/独占/共享/无效）；false sharing 指多核改同缓存行不同字段互相失效。
>
> **用法要点**：① 顺序遍历数组提 Cache 命中；② 热点数据对齐缓存行避免 false sharing；③ 理解 CPU -bound vs IO-bound；④ NUMA 架构注意内存就近；⑤ 预取（prefetch）优化。

### 3.3 常用用法

```c
// 缓存友好：行优先遍历（示意）
for (int i = 0; i < N; i++)        // 外层行，连续访内存
  for (int j = 0; j < M; j++)
    sum += a[i][j];                 // 命中缓存行
// 反面：列优先跳行，缓存未命中多
```

```bash
# 看 CPU 缓存与拓扑
lscpu                          # 架构/核/缓存
perf stat -e cache-misses,cache-references ./app   # 缓存命中率
```

> 🔍 **知识点深度解析**
>
> **作用**：行优先遍历契合内存连续布局，Cache 命中高；perf 直接量化缓存行为。
>
> **原理**：C 数组行优先存储，`a[i][j]` 连续访问命中同一缓存行；列优先 `a[j][i]` 跨行跳，触发大量未命中。
>
> **用法要点**：① 热点循环改访问顺序；② 用 perf 看 cache-misses 定优化点；③ 大数组分块（blocking）适配 Cache；④ 结构体内存布局减 padding。

### 3.4 注意事项

1. **false sharing**：多核改同缓存行不同字段互相失效，用对齐/填充隔离
2. **分支预测**：随机分支误预测致流水线停顿，热路径减少
3. **内存墙**：CPU 快于内存，计算受带宽限制
4. **对齐**：结构体/ SIMD 需对齐否则降速
5. **小数宽**：寄存器→内存搬运有成本，热点少搬

> 💡 **深度讲解**：组成原理解释"为什么软件有快有慢"。核心是存储层次——寄存器到磁盘速度差百万倍，全靠"局部性原理"用 Cache 兜住。CPU 流水线让指令并行，但分支误预测会清空流水线（所以热路径要可预测）。多核下 MESI 协议保 Cache 一致，false sharing（多核改同缓存行）是隐形性能杀手。工程启示：写缓存友好代码（顺序访问、分块）、避免 false sharing、用 perf 量化缓存命中。AI 推理的 GPU 显存带宽瓶颈本质也是"内存墙"的延伸。

> 📝 **精简总结**：组成=冯诺依曼(存储程序)；存储层次=寄存器→Cache→内存→磁盘(速度差百万倍)；CPU=流水线/超标量/乱序；Cache=局部性/MESI/false sharing；注意=缓存友好/分支预测/内存墙/对齐。

## 4. 编译原理

### 4.1 概述

编译把高级语言翻译成机器码，流程：词法分析→语法分析→语义分析→中间代码→优化→目标代码。解释器逐行执行，JIT 混合二者。

> 🔍 **知识点深度解析**
>
> **作用**：懂编译才能懂"为什么语法报错在这里、为什么正则慢、为什么 JVM/JS 能快"。
>
> **原理**：词法分析用正则切 token；语法分析用上下文无关文法建 AST；语义分析做类型检查；中间表示（IR）便于优化（常量折叠、死代码消除）；JIT 在运行时把热点编译为机器码（如 JVM HotSpot、V8）。
>
> **用法要点**：① 语法错误看 AST 阶段提示；② 正则别写灾难性回溯；③ 理解 JVM/JS 的 JIT 优化热点；④ DSL 用解析器生成器（ANTLR）；⑤ 关注编译优化对调试的影响。

### 4.2 核心特性

**阶段**：词法（Lexer）→语法（Parser）→语义→IR→优化→CodeGen。

**优化**：常量折叠、公共子表达式、死代码消除、内联、循环展开。

**运行方式**：AOT（预先编译）、解释执行、JIT（运行时编译热点）。

> 🔍 **知识点深度解析**
>
> **作用**：分阶段让编译可维护；优化提升运行效率；运行方式决定启动与峰值性能。
>
> **原理**：CFG（控制流图）与 SSA（静态单赋值）是优化基础；JIT 用计数器识别热点（如方法调用 1 万次）触发 C1/C2 编译；V8 的 TurboFan、JVM 的 C2 做激进优化。
>
> **用法要点**：① 理解"热点才被编译"解释预热现象；② 内联减小调用开销但增代码体积；③ 逃逸分析助栈上分配/锁消除；④ 解释器启动快峰值低；⑤ 正则回溯爆炸要写非贪婪+锚点。

### 4.3 常用用法

```python
# 用 AST 做语法分析（Python ast 模块）
import ast
tree = ast.parse("x = 1 + 2")
print(ast.dump(tree))     # Module(body=[Assign(targets=[Name('x')], value=BinOp(Add, 1, 2))])

# 正则灾难性回溯示例（避免）
import re
# re.match(r"(a+)+$", "aaaaaaaaaaaaaaaaaaaaab")  # 可能极慢，避免嵌套量词
```

> 🔍 **知识点深度解析**
>
> **作用**：ast 模块让你程序化分析 Python 代码；正则回溯是性能与安全雷区。
>
> **原理**：`ast.parse` 产出 AST（抽象语法树）；正则 `(a+)+$` 在匹配失败时因嵌套量词产生指数级回溯（ReDoS）。
>
> **用法要点**：① 用 AST 写代码检查/转换工具；② 正则避免 `(x+)+` 嵌套量词；③ 用原子组/占有量词防回溯；④ 编译正则一次复用（`re.compile`）；⑤ AST 改写比字符串替换安全。

### 4.4 注意事项

1. **灾难性回溯**：正则嵌套量词致 ReDoS，谨慎写
2. **优化副作用**：激进优化可能改可观察行为，调试时关优化
3. **JIT 预热**：首请求慢因未编译，需预热
4. **类型擦除/推断**：编译期类型信息运行时可能不可用
5. **跨平台**：AOT 产物绑定平台，注意可移植

> 💡 **深度讲解**：编译原理是"高级语言为何能跑"的答案。流程词法→语法→语义→IR→优化→CodeGen 是通用范式，理解它就能看懂任何语言的报错位置。JIT（JVM HotSpot、V8）是工程精华——解释器快速启动，运行时把热点编译成高度优化的机器码，兼顾启动与峰值。两大坑：正则灾难性回溯（ReDoS，嵌套量词如 `(a+)+`）能拖垮服务；JIT 预热让首请求偏慢。写代码检查/DSL/转译器时，用 AST（如 Python ast、ANTLR）比正则字符串替换可靠得多。

> 📝 **精简总结**：编译=词法→语法→语义→IR→优化→CodeGen；运行=AOT/解释/JIT(热点编译)；优化=常量折叠/内联/死代码；注意=ReDoS回溯/JIT预热/类型擦除/跨平台。

## 5. 设计模式

### 5.1 概述

设计模式是经考验的面向对象设计套路，分创建型（单例/工厂/建造者）、结构型（适配器/装饰/代理）、行为型（策略/观察者/模板方法）。核心价值：解耦、复用、可扩展。

> 🔍 **知识点深度解析**
>
> **作用**：模式提供"命名即沟通"的设计词汇，避免重复造轮子，但滥用反成过度设计。
>
> **原理**：创建型封装对象创建过程（单例保证唯一、工厂隐藏具体类）；结构型组合对象成更大结构（装饰动态加职责、代理控制访问）；行为型职责分配与算法解耦（策略换算法、观察者解耦发布订阅）。
>
> **用法要点**：① 先理解问题再选模式；② 优先组合而非继承；③ 现代语言用依赖注入代替手写工厂/单例；④ 不要为用模式而用；⑤ 结合 SOLID 原则。

### 5.2 核心特性

**创建型**：单例、工厂方法、抽象工厂、建造者、原型。

**结构型**：适配器、装饰器、代理、桥接、组合、外观、享元。

**行为型**：策略、观察者、模板方法、命令、状态、责任链、迭代器。

**原则**：SOLID（单一/开闭/里氏/接口隔离/依赖倒置）。

> 🔍 **知识点深度解析**
>
> **作用**：三类模式覆盖"生对象/组结构/分行为"；SOLID 是评判设计好坏的尺。
>
> **原理**：装饰器用相同接口包裹对象层层加功能（如 Java IO）；观察者维护订阅列表通知变更；责任链把请求沿链传递直到处理；依赖倒置让高层依赖抽象而非具体。
>
> **用法要点**：① 装饰器优于继承扩展；② 观察者用于事件解耦；③ 策略用函数/lambda 现代写法；④ 单例用依赖注入容器管理；⑤ 开闭原则：对扩展开放对修改关闭。

### 5.3 常用用法

```python
# 策略模式（用函数实现，轻量）
def pay_by_alipay(amount): ...
def pay_by_wechat(amount): ...

STRATEGIES = {"alipay": pay_by_alipay, "wechat": pay_by_wechat}

def checkout(method, amount):
    return STRATEGIES[method](amount)      # 运行时切换算法

# 观察者模式（示意）
class Subject:
    def __init__(self): self._obs = []
    def attach(self, o): self._obs.append(o)
    def notify(self, e):
        for o in self._obs: o.update(e)
```

> 🔍 **知识点深度解析**
>
> **作用**：策略把"算法族"参数化，观察者把"发布-订阅"解耦，是现代语言极简实现。
>
> **原理**：`STRATEGIES` 字典映射名称到函数，调用处按名选算法，符合开闭原则；`Subject.notify` 遍历观察者推送事件，发布方不依赖具体订阅者。
>
> **用法要点**：① 策略优先用函数/lambda（Python/JS）；② 观察者注意内存泄漏（及时 detach）；③ 字典映射替代 if-else 分支；④ 事件驱动系统天然适配观察者。

### 5.4 注意事项

1. **过度设计**：简单 if-else 别硬套模式，先 YAGNI
2. **单例陷阱**：全局状态难测试，优先 DI 容器
3. **继承 vs 组合**：优先组合，避免继承爆炸
4. **性能**：装饰/代理链过长增加调用层次
5. **可测性**：紧耦合模式需配接口便于 mock

> 💡 **深度讲解**：设计模式是"可复用的设计词汇"，但金句是" don't overuse"。三层分类：创建型管"怎么造对象"（单例/工厂/建造者）、结构型管"怎么拼结构"（装饰/适配器/代理）、行为型管"怎么分职责"（策略/观察者/责任链）。现代语言下很多模式被语言特性简化——策略等于传函数、单例交给依赖注入容器、迭代器是语言内置。真正要内化的是 SOLID 原则：单一职责、开闭（对扩展开放）、里氏替换、接口隔离、依赖倒置。先有问题再找模式，别为模式而模式（YAGNI）。

> 📝 **精简总结**：模式=创建(单例/工厂)/结构(装饰/代理)/行为(策略/观察者)；原则=SOLID；价值=解耦复用可扩；注意=过度设计/单例全局态/优先组合/可测性。

## 6. 密码学与信息安全基础

### 6.1 概述

密码学保障机密性、完整性、认证、不可抵赖。对称加密（AES）快、非对称（RSA/ECC）解决密钥分发、哈希（SHA）做完整性、混合加密是 TLS 基础。

> 🔍 **知识点深度解析**
>
> **作用**：安全是上线底线——传输加密、口令存储、签名验签、Token 都依赖密码学。
>
> **原理**：对称加密同钥加解密（AES，分组+模式如 GCM）；非对称用公私钥对（RSA 加解密、ECC 更短密钥）；哈希单向不可逆（SHA-256），加盐防彩虹表；混合加密用 RSA 传 AES 会话密钥，之后 AES 加密数据。
>
> **用法要点**：① 口令用 bcrypt/scrypt/Argon2 慢哈希+盐；② 传输用 TLS（别自己实现）；③ 签名用非对称私钥；④ 随机数用密码学安全 RNG；⑤ 密钥管理（KMS）重于算法。

### 6.2 核心特性

**对称**：AES（GCM 模式带认证）、ChaCha20。

**非对称**：RSA（密钥交换/签名）、ECC（更短更强）、ECDSA/EdDSA。

**哈希**：SHA-256、SHA-3；HMAC（带密钥哈希）。

**协议**：TLS 1.3、JWT（签名令牌）、OAuth2（授权）。

> 🔍 **知识点深度解析**
>
> **作用**：不同原语组合成安全方案——AES 加密、RSA/ECC 交换与签名、SHA 验完整性、HMAC 防篡改。
>
> **原理**：GCM 同时提供加密与认证标签（防篡改）；ECC 用椭圆曲线，256 位等效 RSA 3072 位；HMAC 用密钥参与哈希防伪造；JWT 用签名（HS256 对称 / RS256 非对称）保证令牌未被改。
>
> **用法要点**：① AES 用 GCM 而非 ECB（ECB 泄露模式）；② 签名验证失败即拒绝；③ JWT 别存敏感信息（可被解码）；④ OAuth2 用授权码流+PKCE；⑤ 定期轮换密钥。

### 6.3 常用用法

```python
# 口令安全存储（bcrypt）
import bcrypt
pwd_hash = bcrypt.hashpw(b"user_password", bcrypt.gensalt(rounds=12))
assert bcrypt.checkpw(b"user_password", pwd_hash)

# HMAC 防篡改
import hmac, hashlib
sig = hmac.new(b"secret_key", b"data", hashlib.sha256).hexdigest()
```

```text
# JWT 结构：header.payload.signature（base64url 编码，签名防篡改）
eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiIxMjMifQ.SflKx...
```

> 🔍 **知识点深度解析**
>
> **作用**：bcrypt 慢哈希+盐抗暴力破解；HMAC 给数据加认证标签；JWT 三段式靠签名保完整。
>
> **原理**：bcrypt 故意慢（可调 rounds）且每口令随机盐，拖慢彩虹表/暴力；HMAC 密钥参与哈希，无密钥无法伪造；JWT 中间 payload 仅 base64 编码（可解码），签名段才保真。
>
> **用法要点**：① 口令永不存明文/可逆加密，用慢哈希；② HMAC 密钥保密；③ JWT payload 不存密码/密钥；④ 验签失败直接拒；⑤ 令牌设短过期+刷新。

### 6.4 注意事项

1. **别自研算法**：用成熟库（OpenSSL/NaCl），自研必错
2. **ECB 禁忌**：AES 绝不用 ECB 模式（泄露结构），用 GCM
3. **口令存储**：慢哈希+盐，不用 MD5/SHA 直接存
4. **随机数**：用 CSPRNG，禁伪随机（time/rand）
5. **密钥管理**：密钥泄露全盘崩，用 KMS/环境变量，定期轮换

> 💡 **深度讲解**：密码学四大目标——机密性（加密）、完整性（哈希/HMAC）、认证（签名/口令）、不可否认（签名）。工程铁律：**不要自己实现密码学**，用 OpenSSL/NaCl 等成熟库。对称 AES 负责加密数据（GCM 模式顺带认证），非对称 RSA/ECC 负责密钥交换与签名，二者在 TLS 中混合使用。口令绝不明文——用 bcrypt/scrypt/Argon2 慢哈希加盐。JWT 三段式中 payload 只是 base64（任何人可解码），靠签名段保证未被篡改，所以别往里塞敏感信息。密钥管理（KMS）比选算法更重要：密钥泄露等于没加密，务必环境变量/KMS 存储并定期轮换。

> 📝 **精简总结**：密码学=机密性/完整性/认证/不可否认；对称=AES(GCM)；非对称=RSA/ECC(交换+签名)；哈希=SHA/HMAC(验真)；口令=bcrypt+盐；铁律=不自研/不用ECB/密钥KMS管理。
