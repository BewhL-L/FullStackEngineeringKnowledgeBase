## 一、概述

**工厂模式（Factory Pattern）** 是最常用的创建型设计模式，它提供了一种创建对象的最佳方式，将对象的创建与使用分离，客户端不需要知道对象的具体创建逻辑，只需通过工厂获取对象。

工厂模式不是一个单一模式，而是一个**模式家族**，包括：
1. **简单工厂（Simple Factory）**：一个工厂类根据参数创建不同产品
2. **工厂方法（Factory Method）**：定义创建对象的接口，让子类决定实例化哪个类
3. **抽象工厂（Abstract Factory）**：创建一系列相关或相互依赖的对象家族

### 1. 核心思想

工厂模式的核心是**将对象的创建逻辑封装在工厂类中**，客户端通过工厂获取对象，而不是直接 `new` 对象。

**解决的问题**：
- 客户端直接 `new` 对象，导致耦合度高，更换实现需要修改客户端代码
- 对象创建逻辑复杂（需要初始化、配置、依赖注入），散落在各处难以维护
- 需要根据条件动态创建不同类型的对象
- 对象创建需要统一管理（如单例、池化、缓存）

### 2. 生活中的类比

| 场景 | 工厂 | 产品 |
|------|------|------|
| **汽车工厂** | 汽车制造厂 | 不同型号的汽车（轿车/SUV/卡车） |
| **咖啡店** | 咖啡吧台 | 不同种类的咖啡（美式/拿铁/卡布奇诺） |
| **物流公司** | 物流中心 | 不同运输方式（快递/空运/海运） |
| **手机工厂** | 手机代工厂 | 不同品牌的手机（苹果/华为/小米） |
| **数据库连接池** | 连接池工厂 | 不同数据库的连接（MySQL/PostgreSQL/Oracle） |

### 3. 直接 new vs 工厂模式

**反例（直接 new）**：
```java
public class NotificationService {
    public void sendNotification(String type, String message) {
        if ("EMAIL".equals(type)) {
            EmailSender sender = new EmailSender("smtp.example.com", 587);
            sender.setUsername("user");
            sender.setPassword("pass");
            sender.send(message);
        } else if ("SMS".equals(type)) {
            SmsSender sender = new SmsSender("api-key-xxx");
            sender.setProvider("twilio");
            sender.send(message);
        } else if ("PUSH".equals(type)) {
            PushSender sender = new PushSender("fcm-key-xxx");
            sender.send(message);
        }
        // 每新增一种通知方式，都要修改这里，且创建逻辑散落在各处
    }
}
```

**问题**：
- 创建逻辑（初始化、配置）散落在各处，重复代码
- 新增类型需要修改已有代码（违反开闭原则）
- 客户端依赖具体实现类，耦合度高
- 创建逻辑变化时需要修改多处
- 难以统一管理（如单例、缓存、日志）

**正例（工厂模式）**：
```java
// 产品接口
public interface NotificationSender {
    void send(String message);
}

// 具体产品
public class EmailSender implements NotificationSender { /* ... */ }
public class SmsSender implements NotificationSender { /* ... */ }
public class PushSender implements NotificationSender { /* ... */ }

// 工厂类（封装创建逻辑）
public class NotificationFactory {
    public static NotificationSender create(String type) {
        return switch (type.toUpperCase()) {
            case "EMAIL" -> new EmailSender("smtp.example.com", 587);
            case "SMS" -> new SmsSender("api-key-xxx");
            case "PUSH" -> new PushSender("fcm-key-xxx");
            default -> throw new IllegalArgumentException("不支持: " + type);
        };
    }
}

// 客户端（只需调用工厂，不关心创建细节）
public class NotificationService {
    public void sendNotification(String type, String message) {
        NotificationSender sender = NotificationFactory.create(type);
        sender.send(message);
    }
}
```

## 二、简单工厂（Simple Factory）

### 1. 定义

简单工厂（又称静态工厂）由一个工厂类根据传入的参数，动态决定创建哪个产品类的实例。它**不是 GoF 23 种设计模式之一**，但非常常用，是工厂方法的简化版。

### 2. UML 结构

```text
┌──────────────────────┐
│   SimpleFactory      │
│ (NotificationFactory)│
├──────────────────────┤
│ + create(type): Product│
└──────────┬───────────┘
           │ 创建
     ┌─────┼─────┐
     ▼     ▼     ▼
┌──────┐┌──────┐┌──────┐
│Product││Product││Product│
│  A   ││  B   ││  C   │
└──────┘└──────┘└──────┘
     ▲     ▲     ▲
     └─────┼─────┘
           │ 实现
    ┌──────────────┐
    │<<interface>> │
    │  Product     │
    └──────────────┘
```

### 3. Java 实现（日志记录器）

```java
// 产品接口
public interface Logger {
    void log(String message);
    void error(String message);
}

// 具体产品：控制台日志
public class ConsoleLogger implements Logger {
    @Override
    public void log(String message) {
        System.out.println("[LOG] " + message);
    }
    @Override
    public void error(String message) {
        System.err.println("[ERROR] " + message);
    }
}

// 具体产品：文件日志
public class FileLogger implements Logger {
    private final String filePath;
    public FileLogger(String filePath) {
        this.filePath = filePath;
    }
    @Override
    public void log(String message) {
        // 写入文件
    }
    @Override
    public void error(String message) {
        // 写入文件
    }
}

// 具体产品：数据库日志
public class DatabaseLogger implements Logger {
    private final DataSource dataSource;
    public DatabaseLogger(DataSource dataSource) {
        this.dataSource = dataSource;
    }
    @Override
    public void log(String message) {
        // 写入数据库
    }
    @Override
    public void error(String message) {
        // 写入数据库
    }
}

// 简单工厂
public class LoggerFactory {
    // 静态工厂方法
    public static Logger create(String type) {
        return switch (type.toUpperCase()) {
            case "CONSOLE" -> new ConsoleLogger();
            case "FILE" -> new FileLogger("/var/log/app.log");
            case "DATABASE" -> new DatabaseLogger(DataSourceConfig.getDataSource());
            default -> throw new IllegalArgumentException("不支持的日志类型: " + type);
        };
    }

    // 带参数的工厂方法
    public static Logger createFileLogger(String filePath) {
        return new FileLogger(filePath);
    }
}

// 使用
public class App {
    public static void main(String[] args) {
        Logger logger = LoggerFactory.create("CONSOLE");
        logger.log("应用启动");

        Logger fileLogger = LoggerFactory.createFileLogger("/custom/path.log");
        fileLogger.log("自定义路径日志");
    }
}
```

### 4. 优缺点

| 优点 | 缺点 |
|------|------|
| 封装创建逻辑，客户端不需关心细节 | 新增产品需修改工厂类（违反开闭原则） |
| 客户端不依赖具体产品类，降低耦合 | 工厂类职责过重，所有产品创建逻辑集中 |
| 实现简单，易于理解 | 不适合产品类型经常变化的场景 |
| 可集中管理对象创建（单例/缓存/池化） | |

## 三、工厂方法（Factory Method）

### 1. 定义

工厂方法模式定义了一个创建对象的接口，但让子类决定实例化哪一个类。工厂方法使一个类的实例化延迟到其子类。

**核心**：将工厂也抽象化，每个具体产品对应一个具体工厂，新增产品只需新增工厂，不需修改已有代码（符合开闭原则）。

### 2. UML 结构

```text
┌──────────────────────┐
│   <<abstract>>       │
│   Creator            │
│ (LoggerFactory)      │
├──────────────────────┤
│ + factoryMethod():   │
│   Product            │
└──────────┬───────────┘
           │ 继承
    ┌──────┼──────┐
    ▼      ▼      ▼
┌────────┐┌────────┐┌────────┐
│Concrete││Concrete││Concrete│
│Creator ││Creator ││Creator │
│   A    ││   B    ││   C    │
├────────┤├────────┤├────────┤
│+factory││+factory││+factory│
│Method()││Method()││Method()│
└───┬────┘└───┬────┘└───┬────┘
    │          │          │
    ▼          ▼          ▼
┌────────┐┌────────┐┌────────┐
│ProductA││ProductB││ProductC│
└───▲────┘└───▲────┘└───▲────┘
    │          │          │
    └──────────┼──────────┘
               │ 实现
        ┌──────────────┐
        │<<interface>> │
        │  Product     │
        └──────────────┘
```

### 3. Java 实现（数据库连接）

```java
// 产品接口
public interface Connection {
    void execute(String sql);
    void close();
}

// 具体产品：MySQL 连接
public class MySQLConnection implements Connection {
    private final String url;
    public MySQLConnection(String url) { this.url = url; }
    @Override
    public void execute(String sql) {
        System.out.println("MySQL 执行: " + sql);
    }
    @Override
    public void close() { /* 关闭连接 */ }
}

// 具体产品：PostgreSQL 连接
public class PostgreSQLConnection implements Connection {
    private final String url;
    public PostgreSQLConnection(String url) { this.url = url; }
    @Override
    public void execute(String sql) {
        System.out.println("PostgreSQL 执行: " + sql);
    }
    @Override
    public void close() { /* 关闭连接 */ }
}

// 抽象工厂
public abstract class ConnectionFactory {
    // 工厂方法（由子类实现）
    public abstract Connection createConnection();

    // 模板方法（公共逻辑）
    public Connection getConnection() {
        Connection conn = createConnection();
        // 公共初始化逻辑
        System.out.println("连接已创建");
        return conn;
    }
}

// 具体工厂：MySQL 工厂
public class MySQLConnectionFactory extends ConnectionFactory {
    @Override
    public Connection createConnection() {
        return new MySQLConnection("jdbc:mysql://localhost:3306/db");
    }
}

// 具体工厂：PostgreSQL 工厂
public class PostgreSQLConnectionFactory extends ConnectionFactory {
    @Override
    public Connection createConnection() {
        return new PostgreSQLConnection("jdbc:postgresql://localhost:5432/db");
    }
}

// 使用
public class App {
    public static void main(String[] args) {
        // 运行时决定使用哪个工厂
        ConnectionFactory factory = new MySQLConnectionFactory();
        Connection conn = factory.getConnection();
        conn.execute("SELECT * FROM users");
        conn.close();

        // 切换到 PostgreSQL，只需更换工厂
        factory = new PostgreSQLConnectionFactory();
        conn = factory.getConnection();
        conn.execute("SELECT * FROM users");
    }
}
```

### 4. 优缺点

| 优点 | 缺点 |
|------|------|
| 符合开闭原则，新增产品只需新增工厂 | 类数量增加，每个产品对应一个工厂 |
| 客户端不依赖具体产品类 | 增加了系统的抽象性和理解难度 |
| 工厂可包含公共逻辑（模板方法） | 简单场景可能过度设计 |
| 更符合单一职责原则 | |

## 四、抽象工厂（Abstract Factory）

### 1. 定义

抽象工厂模式提供一个接口，用于创建一系列相关或相互依赖的对象家族，而不需要指定它们的具体类。

**核心**：工厂方法创建单个产品，抽象工厂创建**产品家族**（一组相关产品）。

### 2. UML 结构

```text
┌──────────────────────────┐
│   <<interface>>          │
│   AbstractFactory        │
│ (GUIFactory)             │
├──────────────────────────┤
│ + createButton(): Button │
│ + createTextField(): TF  │
│ + createCheckbox(): CB   │
└────────────┬─────────────┘
             │ 实现
      ┌──────┴──────┐
      ▼             ▼
┌───────────┐ ┌───────────┐
│Concrete   │ │Concrete   │
│Factory A  │ │Factory B  │
│(Windows)  │ │(Mac)      │
├───────────┤ ├───────────┤
│+createBtn │ │+createBtn │
│+createTF  │ │+createTF  │
│+createCB  │ │+createCB  │
└─────┬─────┘ └─────┬─────┘
      │              │
      ▼              ▼
  产品家族A      产品家族B
(WinButton,    (MacButton,
 WinTextField,  MacTextField,
 WinCheckbox)   MacCheckbox)
```

### 3. Java 实现（跨平台 UI 组件）

```java
// 产品家族：按钮
public interface Button {
    void render();
    void onClick();
}

// 产品家族：文本框
public interface TextField {
    void render();
    String getText();
}

// 产品家族：复选框
public interface Checkbox {
    void render();
    boolean isChecked();
}

// Windows 风格产品
public class WindowsButton implements Button {
    public void render() { System.out.println("渲染 Windows 按钮"); }
    public void onClick() { System.out.println("Windows 按钮点击"); }
}
public class WindowsTextField implements TextField {
    public void render() { System.out.println("渲染 Windows 文本框"); }
    public String getText() { return "Windows text"; }
}
public class WindowsCheckbox implements Checkbox {
    public void render() { System.out.println("渲染 Windows 复选框"); }
    public boolean isChecked() { return false; }
}

// Mac 风格产品
public class MacButton implements Button {
    public void render() { System.out.println("渲染 Mac 按钮"); }
    public void onClick() { System.out.println("Mac 按钮点击"); }
}
public class MacTextField implements TextField {
    public void render() { System.out.println("渲染 Mac 文本框"); }
    public String getText() { return "Mac text"; }
}
public class MacCheckbox implements Checkbox {
    public void render() { System.out.println("渲染 Mac 复选框"); }
    public boolean isChecked() { return true; }
}

// 抽象工厂
public interface GUIFactory {
    Button createButton();
    TextField createTextField();
    Checkbox createCheckbox();
}

// 具体工厂：Windows 工厂
public class WindowsFactory implements GUIFactory {
    @Override
    public Button createButton() { return new WindowsButton(); }
    @Override
    public TextField createTextField() { return new WindowsTextField(); }
    @Override
    public Checkbox createCheckbox() { return new WindowsCheckbox(); }
}

// 具体工厂：Mac 工厂
public class MacFactory implements GUIFactory {
    @Override
    public Button createButton() { return new MacButton(); }
    @Override
    public TextField createTextField() { return new MacTextField(); }
    @Override
    public Checkbox createCheckbox() { return new MacCheckbox(); }
}

// 客户端（使用抽象工厂，不依赖具体产品）
public class Application {
    private final Button button;
    private final TextField textField;
    private final Checkbox checkbox;

    public Application(GUIFactory factory) {
        this.button = factory.createButton();
        this.textField = factory.createTextField();
        this.checkbox = factory.createCheckbox();
    }

    public void render() {
        button.render();
        textField.render();
        checkbox.render();
    }
}

// 使用
public class App {
    public static void main(String[] args) {
        // 根据操作系统选择工厂
        GUIFactory factory = System.getProperty("os.name").contains("Mac")
            ? new MacFactory()
            : new WindowsFactory();

        Application app = new Application(factory);
        app.render();
    }
}
```

### 4. 优缺点

| 优点 | 缺点 |
|------|------|
| 确保产品家族的一致性（同风格组件一起使用） | 产品家族固定，新增产品需修改抽象工厂接口 |
| 客户端不依赖具体产品类 | 类数量急剧增加（每个产品家族×每个产品） |
| 符合开闭原则（新增产品家族只需新增工厂） | 结构复杂，理解和维护成本高 |
| 隔离具体产品的创建 | 不适合产品类型经常变化的场景 |

## 五、三种工厂模式对比

| 维度 | 简单工厂 | 工厂方法 | 抽象工厂 |
|------|---------|---------|---------|
| **创建对象** | 单个产品 | 单个产品 | 产品家族（一组相关产品） |
| **工厂角色** | 具体工厂类 | 抽象工厂+具体工厂 | 抽象工厂+具体工厂 |
| **扩展性** | 差（新增产品改工厂） | 好（新增产品+工厂） | 好（新增家族+工厂） |
| **类数量** | 少 | 中 | 多 |
| **复杂度** | 低 | 中 | 高 |
| **适用场景** | 产品类型少且固定 | 产品类型经常变化 | 需要创建一组相关产品 |
| **GoF 模式** | ❌ 不是 | ✅ 是 | ✅ 是 |

**选择决策**：
```text
需要创建对象？
├─ 产品类型少且固定 → 简单工厂
├─ 产品类型经常变化 → 工厂方法
└─ 需要创建一组相关产品 → 抽象工厂
```

## 六、工厂模式的高级用法

### 1. 带缓存的工厂（对象池/单例）

```java
public class ConnectionFactory {
    private static final Map<String, Connection> cache = new ConcurrentHashMap<>();

    public static Connection getConnection(String type) {
        return cache.computeIfAbsent(type, k -> {
            // 创建逻辑只执行一次
            return switch (k) {
                case "MYSQL" -> new MySQLConnection("url");
                case "PG" -> new PostgreSQLConnection("url");
                default -> throw new IllegalArgumentException();
            };
        });
    }
}
```

### 2. 反射工厂（动态创建）

```java
public class ReflectionFactory {
    private static final Map<String, Class<? extends Product>> registry = new HashMap<>();

    static {
        registry.put("A", ProductA.class);
        registry.put("B", ProductB.class);
    }

    public static Product create(String type) {
        Class<? extends Product> clazz = registry.get(type);
        if (clazz == null) throw new IllegalArgumentException("未知类型: " + type);
        try {
            return clazz.getDeclaredConstructor().newInstance();
        } catch (Exception e) {
            throw new RuntimeException("创建失败", e);
        }
    }

    // 运行时注册新类型
    public static void register(String type, Class<? extends Product> clazz) {
        registry.put(type, clazz);
    }
}
```

### 3. 函数式工厂（Java 8+）

```java
public class FunctionalFactory {
    private static final Map<String, Supplier<Product>> suppliers = new HashMap<>();

    static {
        suppliers.put("A", ProductA::new);
        suppliers.put("B", ProductB::new);
        suppliers.put("C", () -> new ProductC("config"));
    }

    public static Product create(String type) {
        Supplier<Product> supplier = suppliers.get(type);
        if (supplier == null) throw new IllegalArgumentException();
        return supplier.get();
    }
}
```

### 4. Spring 中的工厂模式

| Spring 组件 | 说明 |
|------------|------|
| **BeanFactory** | Spring 最底层的工厂接口，负责创建和管理 Bean |
| **ApplicationContext** | BeanFactory 的子接口，功能更丰富 |
| **FactoryBean** | 自定义 Bean 创建逻辑的工厂接口 |
| **@Bean** | 注解方式声明工厂方法 |
| **ObjectFactory** | 延迟注入 Bean 的工厂 |
| **Provider** | JSR-330 标准的工厂接口 |

**FactoryBean 示例**：
```java
public class UserFactoryBean implements FactoryBean<User> {
    private String name;

    @Override
    public User getObject() {
        // 复杂的 User 创建逻辑
        User user = new User();
        user.setName(name);
        user.setCreatedAt(LocalDateTime.now());
        return user;
    }

    @Override
    public Class<?> getObjectType() {
        return User.class;
    }

    @Override
    public boolean isSingleton() {
        return true;
    }
}
```

## 七、与其他模式的区别

### 1. 工厂模式 vs 建造者模式

| 维度 | 工厂模式 | 建造者模式 |
|------|---------|-----------|
| **目的** | 创建不同类型的对象 | 创建复杂对象（多步骤构建） |
| **关注点** | 对象的类型选择 | 对象的构建过程 |
| **输入** | 类型参数 | 多个构建参数 |
| **输出** | 不同类型的对象 | 同一类型的不同配置 |
| **适用** | 创建简单/中等复杂度对象 | 创建复杂对象（很多可选参数） |

### 2. 工厂模式 vs 策略模式

| 维度 | 工厂模式 | 策略模式 |
|------|---------|---------|
| **目的** | 创建对象 | 封装算法/行为 |
| **关注点** | 对象创建 | 行为切换 |
| **返回值** | 创建的对象 | 算法执行结果 |
| **关系** | 工厂可以创建策略对象 | 策略由工厂创建 |
| **配合** | 经常配合使用 | 经常配合使用 |

### 3. 工厂模式 vs 单例模式

| 维度 | 工厂模式 | 单例模式 |
|------|---------|---------|
| **目的** | 封装对象创建 | 确保只有一个实例 |
| **关注点** | 创建逻辑 | 实例唯一性 |
| **关系** | 工厂可以创建单例对象 | 单例可以作为工厂 |

## 八、适用场景与优缺点总结

### 1. 适用场景

- [ ] 对象创建逻辑复杂，需要封装
- [ ] 需要根据条件动态创建不同类型的对象
- [ ] 客户端不应依赖具体产品类（解耦）
- [ ] 需要统一管理对象创建（单例/缓存/池化/日志）
- [ ] 对象创建需要依赖配置或外部资源
- [ ] 需要创建一组相关的产品（抽象工厂）

### 2. 优点

| 优点 | 说明 |
|------|------|
| **解耦** | 客户端不依赖具体产品类 |
| **封装创建逻辑** | 创建细节集中在工厂，易于维护 |
| **开闭原则** | 工厂方法/抽象工厂新增产品不需修改已有代码 |
| **统一管理** | 可集中处理单例、缓存、池化、日志 |
| **可测试** | 可 Mock 工厂，便于单元测试 |
| **符合依赖倒置** | 客户端依赖抽象（产品接口），不依赖具体实现 |

### 3. 缺点

| 缺点 | 说明 |
|------|------|
| **类爆炸** | 工厂方法/抽象工厂会增加大量类 |
| **复杂度增加** | 抽象层次增加，理解和维护成本上升 |
| **过度设计** | 简单场景使用工厂模式可能没必要 |
| **抽象工厂扩展难** | 新增产品类型需修改抽象工厂接口和所有实现 |

### 4. 何时不使用

- 对象创建非常简单（直接 `new` 即可）
- 产品类型只有一种，不会变化
- 项目很小，生命周期短
- 客户端需要知道创建细节（如调试场景）
