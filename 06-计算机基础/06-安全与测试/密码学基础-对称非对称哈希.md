## 一、概述

### 1. 密码学的目标

```text
密码学（Cryptography）的核心目标（CIA+）：
- 机密性（Confidentiality）：只有授权方能读取
- 完整性（Integrity）：数据未被篡改
- 认证性（Authentication）：身份可验证
- 不可否认性（Non-repudiation）：发送方不能否认
- 可用性（Availability）：服务可访问

三大基础工具：
1. 对称加密：解决机密性（加解密用同一密钥）
2. 非对称加密：解决密钥交换和身份（公钥私钥对）
3. 哈希函数：解决完整性（不可逆的指纹）
```

## 二、对称加密

### 1. 基本原理

```text
对称加密（Symmetric Encryption）：
- 加密和解密使用同一个密钥
- 速度快，适合大数据量
- 密钥分发是难题（如何安全地把密钥给对方）

加密：Ciphertext = Encrypt(Plaintext, Key)
解密：Plaintext = Decrypt(Ciphertext, Key)

分类：
- 分组密码（Block Cipher）：按固定块加密，如 AES
- 流密码（Stream Cipher）：逐字节/位加密，如 ChaCha20
```

### 2. AES（高级加密标准）

```text
AES（Advanced Encryption Standard）：
- 目前最主流的对称加密算法
- 密钥长度：128/192/256 位
- 分组大小：128 位（16 字节）
- 轮数：10/12/14 轮（对应密钥长度）
- 美国联邦政府标准

AES 工作模式：
- ECB：电子密码本（不安全，相同明文产生相同密文）
- CBC：密码分组链接（需要 IV，常用）
- CTR：计数器模式（可并行，推荐）
- GCM：Galois/Counter Mode（认证加密，推荐）
- CCM：CTR + CBC-MAC
```

```python
# Python AES 加密（cryptography 库）
from cryptography.fernet import Fernet
from cryptography.hazmat.primitives.ciphers import Cipher, algorithms, modes
from cryptography.hazmat.backends import default_backend
import os

# 简单用法（Fernet 封装了 AES-128-CBC + HMAC）
key = Fernet.generate_key()
cipher = Fernet(key)
token = cipher.encrypt(b"Secret message")
plaintext = cipher.decrypt(token)

# 原生 AES-GCM（推荐）
key = os.urandom(32)  # AES-256
nonce = os.urandom(12)  # GCM 推荐 12 字节
cipher = Cipher(algorithms.AES(key), modes.GCM(nonce), backend=default_backend())
encryptor = cipher.encryptor()
ciphertext = encryptor.update(b"Secret message") + encryptor.finalize()
tag = encryptor.tag  # 认证标签

# 解密
decryptor = Cipher(algorithms.AES(key), modes.GCM(nonce, tag), backend=default_backend()).decryptor()
plaintext = decryptor.update(ciphertext) + decryptor.finalize()
```

### 3. ChaCha20

```text
ChaCha20：
- 流密码，由 Daniel Bernstein 设计
- 密钥 256 位，nonce 96 位
- 纯软件实现，不需要硬件加速
- 在移动设备上比 AES 快
- TLS 1.3 支持的密码套件之一
- 常与 Poly1305 配合（ChaCha20-Poly1305）

适用场景：
- 移动设备（无 AES 硬件加速）
- 嵌入式系统
- TLS/HTTPS
```

### 4. 对称加密对比

| 算法 | 密钥长度 | 类型 | 速度 | 安全性 | 推荐 |
|------|---------|------|------|--------|------|
| **AES-256-GCM** | 256位 | 分组 | 快（硬件加速） | 高 | ✅ 首选 |
| **ChaCha20-Poly1305** | 256位 | 流 | 快（纯软件） | 高 | ✅ 移动/嵌入式 |
| **AES-128-CBC** | 128位 | 分组 | 快 | 中（需自己处理认证） | ⚠️ 旧系统 |
| **3DES** | 168位 | 分组 | 慢 | 低（已破解） | ❌ 不要用 |
| **DES** | 56位 | 分组 | 慢 | 极低（已破解） | ❌ 不要用 |
| **RC4** | 可变 | 流 | 快 | 低（已破解） | ❌ 不要用 |

## 三、非对称加密

### 1. 基本原理

```text
非对称加密（Asymmetric Encryption）：
- 密钥对：公钥（Public Key）+ 私钥（Private Key）
- 公钥加密，私钥解密
- 私钥签名，公钥验证
- 解决密钥分发问题
- 速度慢，不适合大数据量

典型用途：
- 密钥交换：用公钥加密对称密钥，发给对方
- 数字签名：私钥签名，公钥验证
- 身份认证：证明持有私钥
```

### 2. RSA

```text
RSA（Rivest-Shamir-Adleman）：
- 1977 年发明，最经典的非对称算法
- 基于大整数分解难题
- 密钥长度：2048/3072/4096 位
- 加密：c = m^e mod n
- 解密：m = c^d mod n
- 公钥 = (e, n)，私钥 = (d, n)

注意：
- RSA 加密有长度限制（不能加密比密钥长的数据）
- 实际用于加密对称密钥，不加密大数据
- RSA 签名常用 PSS 填充
```

```python
from cryptography.hazmat.primitives.asymmetric import rsa, padding
from cryptography.hazmat.primitives import hashes, serialization

# 生成密钥对
private_key = rsa.generate_private_key(
    public_exponent=65537,
    key_size=2048
)
public_key = private_key.public_key()

# 加密（OAEP 填充，推荐）
ciphertext = public_key.encrypt(
    b"Secret message",
    padding.OAEP(
        mgf=padding.MGF1(algorithm=hashes.SHA256()),
        algorithm=hashes.SHA256(),
        label=None
    )
)

# 解密
plaintext = private_key.decrypt(
    ciphertext,
    padding.OAEP(
        mgf=padding.MGF1(algorithm=hashes.SHA256()),
        algorithm=hashes.SHA256(),
        label=None
    )
)

# 数字签名
signature = private_key.sign(
    b"Message to sign",
    padding.PSS(mgf=padding.MGF1(hashes.SHA256()), salt_length=padding.PSS.MAX_LENGTH),
    hashes.SHA256()
)

# 验证签名
public_key.verify(
    signature,
    b"Message to sign",
    padding.PSS(mgf=padding.MGF1(hashes.SHA256()), salt_length=padding.PSS.MAX_LENGTH),
    hashes.SHA256()
)
```

### 3. ECC（椭圆曲线密码学）

```text
ECC（Elliptic Curve Cryptography）：
- 基于椭圆曲线离散对数难题
- 更短的密钥达到相同安全性
- 256 位 ECC ≈ 3072 位 RSA
- 计算更快，存储更小
- 适合移动设备和 IoT

常用曲线：
- P-256（secp256r1）：NIST 标准
- secp256k1：比特币使用
- Curve25519：现代推荐，性能好
- Ed25519：EdDSA 签名，推荐
```

```python
from cryptography.hazmat.primitives.asymmetric import ec
from cryptography.hazmat.primitives import hashes

# 生成 ECC 密钥对
private_key = ec.generate_private_key(ec.SECP256R1())
public_key = private_key.public_key()

# ECDSA 签名
signature = private_key.sign(
    b"Message to sign",
    ec.ECDSA(hashes.SHA256())
)

# 验证
public_key.verify(signature, b"Message to sign", ec.ECDSA(hashes.SHA256()))

# Ed25519（推荐的签名算法）
from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PrivateKey
private_key = Ed25519PrivateKey.generate()
signature = private_key.sign(b"Message")
public_key = private_key.public_key()
public_key.verify(signature, b"Message")
```

### 4. Diffie-Hellman 密钥交换

```text
DH（Diffie-Hellman）密钥交换：
- 双方在不安全信道上协商出共享密钥
- 不传输密钥本身
- 基于离散对数难题
- ECDH：椭圆曲线版本，更高效

过程：
1. 双方各自生成密钥对
2. 交换公钥
3. 各自用自己的私钥 + 对方公钥计算共享密钥
4. 结果相同（数学保证）
5. 用共享密钥作为对称加密密钥
```

### 5. 非对称算法对比

| 算法 | 密钥长度 | 速度 | 用途 | 推荐 |
|------|---------|------|------|------|
| **RSA-2048** | 2048位 | 慢 | 加密/签名 | ⚠️ 最低要求 |
| **RSA-3072** | 3072位 | 很慢 | 加密/签名 | ✅ 安全 |
| **ECDSA P-256** | 256位 | 中 | 签名 | ✅ 通用 |
| **Ed25519** | 256位 | 快 | 签名 | ✅ 推荐 |
| **ECDH P-256** | 256位 | 中 | 密钥交换 | ✅ 通用 |
| **X25519** | 256位 | 快 | 密钥交换 | ✅ 推荐 |

## 四、哈希函数

### 1. 基本原理

```text
哈希函数（Hash Function）：
- 将任意长度输入映射为固定长度输出
- 单向：无法从哈希值反推原文
- 抗碰撞：很难找到两个不同输入有相同哈希
- 雪崩效应：输入微小变化，输出完全不同

用途：
- 数据完整性校验
- 密码存储（加盐哈希）
- 数字签名（先哈希再签名）
- 区块链（工作量证明）
- 数据结构（哈希表、Merkle Tree）
```

### 2. 常见哈希算法

```text
MD5：
- 输出 128 位
- 已被破解，碰撞攻击可行
- 不要用于安全场景
- 可用于非安全的校验（如文件去重）

SHA-1：
- 输出 160 位
- 已被破解（SHAttered 攻击）
- 不要用于安全场景

SHA-2（SHA-256/SHA-512）：
- 输出 256/512 位
- 目前安全，主流选择
- SHA-256 是比特币使用的算法

SHA-3（Keccak）：
- 输出可变长度
- 最新标准，设计不同
- 安全性高
```

```python
import hashlib

# SHA-256
h = hashlib.sha256()
h.update(b"Hello, World!")
print(h.hexdigest())  # dffd6021bb2bd5b0af676290809ec3a53191dd81c7f70a4b28688a362182986f

# 快捷方式
hashlib.sha256(b"Hello").hexdigest()
hashlib.sha512(b"Hello").hexdigest()
hashlib.sha3_256(b"Hello").hexdigest()

# 大文件分块哈希
def hash_file(path, algorithm='sha256'):
    h = hashlib.new(algorithm)
    with open(path, 'rb') as f:
        while chunk := f.read(8192):
            h.update(chunk)
    return h.hexdigest()
```

### 3. 密码哈希（慢哈希）

```text
普通哈希不适合存密码：
- 太快，可暴力破解
- 彩虹表攻击

密码专用哈希（慢哈希）：
- bcrypt：加盐、可调工作因子
- scrypt：内存困难函数
- Argon2：最新，密码哈希竞赛冠军
- PBKDF2：标准，迭代多次

关键参数：
- salt：随机盐，防彩虹表
- cost/iterations：计算成本，防暴力破解
- 内存参数：防 GPU/ASIC 攻击
```

```python
import bcrypt
import hashlib

# bcrypt
password = b"mysecretpassword"
salt = bcrypt.gensalt(rounds=12)  # 工作因子 12
hashed = bcrypt.hashpw(password, salt)
# 验证
bcrypt.checkpw(password, hashed)  # True

# Argon2（推荐）
from argon2 import PasswordHasher
ph = PasswordHasher(time_cost=3, memory_cost=65536, parallelism=4)
hash = ph.hash("mysecretpassword")
ph.verify(hash, "mysecretpassword")

# PBKDF2（标准库）
salt = os.urandom(16)
key = hashlib.pbkdf2_hmac('sha256', password, salt, 100000)
```

### 4. 哈希算法对比

| 算法 | 输出 | 速度 | 安全性 | 用途 |
|------|------|------|--------|------|
| **MD5** | 128位 | 快 | 已破解 | 非安全校验 |
| **SHA-1** | 160位 | 快 | 已破解 | 旧系统兼容 |
| **SHA-256** | 256位 | 快 | 安全 | 通用、签名 |
| **SHA-512** | 512位 | 中 | 安全 | 高安全需求 |
| **SHA-3** | 可变 | 中 | 安全 | 新系统 |
| **bcrypt** | 60字符 | 慢 | 高 | 密码存储 |
| **Argon2** | 可变 | 可调 | 最高 | 密码存储（推荐） |

## 五、消息认证与数字签名

### 1. HMAC（哈希消息认证码）

```text
HMAC（Hash-based Message Authentication Code）：
- 用密钥 + 哈希函数生成认证码
- 验证消息完整性和来源
- 比单纯哈希多了密钥保护

公式：HMAC(K, m) = H((K' ⊕ opad) || H((K' ⊕ ipad) || m))

用途：
- API 请求签名（JWT 常用 HS256）
- Webhook 验证
- 消息完整性校验
```

```python
import hmac
import hashlib

# 生成 HMAC
key = b"secret-key"
message = b"GET /api/users"
signature = hmac.new(key, message, hashlib.sha256).hexdigest()

# 验证（用 compare_digest 防时序攻击）
received_sig = "..."
hmac.compare_digest(signature, received_sig)

# JWT HS256 就是 HMAC-SHA256
```

### 2. 数字签名

```text
数字签名（Digital Signature）：
- 私钥签名，公钥验证
- 提供认证性、完整性、不可否认性
- 过程：先哈希消息，再用私钥加密哈希

常用算法：
- RSA-PSS：RSA 签名
- ECDSA：椭圆曲线签名
- EdDSA（Ed25519）：现代推荐

与 HMAC 的区别：
- HMAC：对称密钥，双方都能生成，不能防否认
- 数字签名：非对称，只有私钥方能签名，可防否认
```

### 3. 混合加密（实际应用）

```text
实际系统中通常混合使用：

1. 生成随机对称密钥（AES 密钥）
2. 用对称密钥加密大数据（AES-GCM）
3. 用对方公钥加密对称密钥（RSA/ECDH）
4. 发送：加密的数据 + 加密的密钥
5. 接收方用私钥解密得到对称密钥
6. 用对称密钥解密数据

这就是 HTTPS、PGP、加密文件格式的通用模式。
```

## 六、PKI 与证书

### 1. PKI 体系

```text
PKI（Public Key Infrastructure）：
- 管理公钥和数字证书的体系
- 核心组件：CA（证书颁发机构）
- 证书 = 公钥 + 身份信息 + CA 签名

信任链：
1. 根 CA（Root CA）：自签名，浏览器内置信任
2. 中间 CA（Intermediate CA）：由根 CA 签名
3. 终端证书（End-entity）：由中间 CA 签名，用于网站/用户

验证过程：
- 浏览器验证网站证书的签名
- 用中间 CA 公钥验证
- 中间 CA 证书用根 CA 公钥验证
- 根 CA 内置在浏览器中，信任起点
```

### 2. 证书格式

```text
常见证书格式：
- PEM：Base64 编码，以 -----BEGIN 开头，常见 .pem/.crt/.cer
- DER：二进制格式，常见 .der/.cer
- PKCS#12：包含证书+私钥，密码保护，.p12/.pfx
- JKS：Java KeyStore，Java 专用

X.509 证书包含：
- 版本、序列号
- 签名算法
- 颁发者（Issuer）
- 有效期（Not Before/After）
- 主体（Subject）
- 公钥
- 扩展（SAN、用途等）
- CA 签名
```

```bash
# OpenSSL 常用命令
# 生成私钥
openssl genrsa -out private.key 2048

# 生成证书签名请求（CSR）
openssl req -new -key private.key -out request.csr

# 自签名证书
openssl req -x509 -newkey rsa:2048 -keyout key.pem -out cert.pem -days 365

# 查看证书信息
openssl x509 -in cert.pem -text -noout

# 证书格式转换
openssl x509 -in cert.pem -outform DER -out cert.der
```

## 七、实际应用

### 1. HTTPS / TLS

```text
TLS 握手过程（简化）：
1. 客户端发送支持的密码套件
2. 服务器返回证书 + 选定套件
3. 客户端验证证书
4. 密钥交换（ECDHE）：协商对称密钥
5. 双方用对称密钥加密通信

密码套件示例：
TLS_AES_256_GCM_SHA384
- 密钥交换：ECDHE（隐含）
- 认证：RSA/ECDSA（证书）
- 加密：AES-256-GCM
- 哈希：SHA-384
```

### 2. JWT

```json
JWT（JSON Web Token）结构：Header.Payload.Signature

Header：算法和类型
{ "alg": "HS256", "typ": "JWT" }

Payload：声明（用户信息、过期时间等）
{ "sub": "user123", "exp": 1700000000 }

Signature：HMAC 或非对称签名
HMACSHA256(base64(header) + "." + base64(payload), secret)

算法选择：
- HS256：HMAC-SHA256，对称密钥，简单
- RS256：RSA-SHA256，非对称，可分发公钥
- ES256：ECDSA-SHA256，更短的签名
```

## 八、最佳实践

### 1. 加密规范

- [ ] **用 AES-GCM 或 ChaCha20-Poly1305**：认证加密，不要用裸 AES-CBC
- [ ] **密钥长度足够**：AES-256、RSA-3072、ECC-256
- [ ] **每次加密用新 IV/nonce**：绝对不要重复使用 nonce
- [ ] **用密码哈希存密码**：bcrypt/Argon2，不要用 MD5/SHA
- [ ] **加盐**：每个密码用独立随机盐
- [ ] **HTTPS  everywhere**：所有通信加密
- [ ] **密钥管理**：用 KMS/Vault，不要硬编码

### 2. 签名和认证

- [ ] **用 Ed25519 做签名**：比 RSA 快、密钥短
- [ ] **HMAC 用 compare_digest**：防时序攻击
- [ ] **JWT 设置过期时间**：access token 短期，refresh token 长期
- [ ] **证书自动续期**：Let's Encrypt + certbot
- [ ] **验证证书链**：不要跳过证书验证

### 3. 避免的错误

- [ ] **不要自己实现加密算法**：用成熟库
- [ ] **不要用 ECB 模式**：相同明文产生相同密文
- [ ] **不要用 MD5/SHA-1 做安全哈希**：已破解
- [ ] **不要用明文存密码**：即使是内部系统
- [ ] **不要硬编码密钥**：用环境变量/KMS
- [ ] **不要重复使用 IV/nonce**：GCM 模式下重复 nonce 会泄露密钥
- [ ] **不要跳过证书验证**：生产环境禁用 verify=False

## 九、常见问题与排查

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| **AES 解密失败** | 密钥/IV 不对 / padding 错误 | 检查密钥长度、IV 一致性、填充模式 |
| **GCM 认证失败** | nonce 重复 / 数据被篡改 | 确保 nonce 唯一、检查密文完整性 |
| **RSA 加密报错** | 数据太长 / 填充不对 | RSA 只加密短数据（密钥），用 OAEP 填充 |
| **密码验证慢** | 工作因子太高 | 调整 bcrypt rounds/Argon2 参数 |
| **JWT 验证失败** | 密钥不对 / 过期 / 算法不匹配 | 检查 exp、alg、密钥 |
| **证书不受信任** | 自签名 / 过期 / 链不完整 | 用受信 CA、检查有效期、包含中间证书 |
| **HTTPS 握手失败** | 密码套件不兼容 / SNI | 升级 TLS 版本、配置 SNI |
| **HMAC 验证不一致** | 编码问题 / 密钥差异 | 统一 UTF-8、检查密钥 |
| **哈希碰撞** | 用了 MD5/SHA-1 | 改用 SHA-256/SHA-3 |
| **nonce 重复** | 随机数生成问题 / 计数器溢出 | 用 CSPRNG、计数器+随机组合 |
| **性能差** | 用了 RSA 加密大数据 | 混合加密：RSA 加密密钥，AES 加密数据 |
| **密钥泄露** | 硬编码 / 日志输出 | 用 KMS、检查日志、轮换密钥 |
| **前后端加密不一致** | 算法/模式/填充不同 | 统一参数、用标准库 |
| **移动端 AES 慢** | 无硬件加速 | 用 ChaCha20 |
| **签名验证失败** | 消息编码不同 / 换行符 | 统一序列化、canonical JSON |
