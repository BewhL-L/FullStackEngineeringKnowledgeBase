## 1. 复杂度分析

### 1.1 概述

复杂度衡量算法随输入规模增长的时间和空间消耗。时间复杂度用大 O 表示（渐进上界），空间复杂度衡量额外内存。是评估算法优劣的统一语言。

**常见量级**：O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!)。

> 🔍 **知识点深度解析**
>
> **作用**：复杂度让你在写代码前就能判断"数据量翻 10 倍会不会超时/爆内存"，是算法选型依据。
>
> **原理**：大 O 取最高阶且忽略常数——O(2n+3) 记为 O(n)；平均/最坏/最好情况分别评估；递归复杂度用主定理或递归树求解。
>
> **用法要点**：① 优先选低阶复杂度；② 常数在 n 小时可能主导（小数据朴素法更快）；③ 空间换时间（哈希缓存）；④ 递归留意栈深度（可能 O(n) 空间）；⑤ 面试常考复杂度推导。

### 1.2 核心特性

**时间**：最好/平均/最坏，关注最坏（保证上限）。

**空间**：额外空间（不含输入），含递归栈。

**权衡**：时间↔空间，读↔写。

> 🔍 **知识点深度解析**
>
> **作用**：分维度看复杂度避免片面优化——有时为降时间可接受升空间。
>
> **原理**：哈希表用 O(n) 空间换 O(1) 查找；归并排序 O(n) 空间换 O(n log n) 稳定；递归 DFS 空间=O(树高)。
>
> **用法要点**：① 最坏情况决定 SLA；② 内存受限场景牺牲时间保空间；③ 尾递归可优化为 O(1) 栈。

### 1.3 常用用法

```python
# 复杂度示例
def sum_arr(a):           # O(n) 时间, O(1) 空间
    s = 0
    for x in a: s += x
    return s

def bubble(a):            # O(n^2) 时间
    for i in range(len(a)):
        for j in range(len(a)-1-i):
            if a[j] > a[j+1]: a[j], a[j+1] = a[j+1], a[j]
```

> 🔍 **知识点深度解析**
>
> **作用**：代码即复杂度的直接体现——单层循环 O(n)，嵌套 O(n²)，二分 O(log n)。
>
> **原理**：循环次数与 n 的关系决定阶；`bubble` 内层随 i 减少但最坏仍约 n²/2 → O(n²)。
>
> **用法要点**：① 数循环层数初判；② 注意隐藏循环（如 `in` 在列表是 O(n)）；③ 递归用递推式。

### 1.4 注意事项

1. **常数陷阱**：O(n log n) 在 n 极小时可能慢于 O(n²)（插入排序实战快）
2. **最坏 vs 平均**：快排平均 O(n log n) 最坏 O(n²)，需随机化
3. **空间别忘**：递归/缓存可能使空间达标称数倍
4. **输入规模**：先估数据量再选算法，不要盲目上复杂结构

> 💡 **深度讲解**：复杂度是算法的"度量衡"。大 O 忽略常数看趋势——当 n 足够大，O(n log n) 一定赢 O(n²)。但工程里 n 小时常数重要（插入排序在小数组比快排快，故 introsort 混合）。空间换时间是永恒主题：哈希表用空间换 O(1) 查找。面试与刷题先想复杂度再写码，避免超时。

> 📝 **精简总结**：复杂度=大O渐进；量级 O(1)<log n<n<nlog n<n²<2ⁿ；时间看循环/递归，空间看缓存/栈；权衡=时间↔空间；注意=常数陷阱/最坏情况/空间别忘。

## 2. 线性结构：数组/链表/栈/队列

### 2.1 概述

数组是连续内存的定长/变长序列（随机访问 O(1)）；链表是离散节点通过指针相连（插入删除 O(1)，访问 O(n)）；栈是 LIFO（后进先出）；队列是 FIFO（先进先出）。

> 🔍 **知识点深度解析**
>
> **作用**：四者是所有复杂结构的基石，选错结构性能差十倍。
>
> **原理**：数组靠下标偏移直接计算地址故随机访问快，但中间插入需搬移；链表节点分散，插入只改指针但找位置要遍历；栈/队列是受限线性表，用数组或链表实现。
>
> **用法要点**：① 频繁随机访问用数组；② 频繁头插/删用链表；③ 括号匹配/撤销用栈；④ 缓冲/广度搜索用队列；⑤ 现代语言动态数组（list/ArrayList）已够用，少用裸链表。

### 2.2 核心特性

**数组**：连续、随机访问 O(1)、尾部增删 O(1)、中间 O(n)。

**链表**：单/双/循环，插入删 O(1)，访问 O(n)，有额外指针开销。

**栈**：push/pop/peek，LIFO；**队列**：enqueue/dequeue，FIFO，双端队列 Deque。

> 🔍 **知识点深度解析**
>
> **作用**：特性决定场景——数组查快改慢，链表改快查慢。
>
> **原理**：双链表节点含前驱后继指针，支持 O(1) 双向删；循环队列用首尾指针+取模避免搬移；Deque 两端皆可进出，是栈与队列的超集。
>
> **用法要点**：① LRU 缓存用哈希+双链表；② 队列用循环数组省搬移；③ 栈溢出注意深度递归；④ 链表判环用快慢指针。

### 2.3 常用用法

```python
# 用栈实现括号匹配
def valid(s):
    st, m = [], {')':'(', ']':'[', '}':'{'}
    for c in s:
        if c in m.values(): st.append(c)
        elif c in m:
            if not st or st.pop() != m[c]: return False
    return not st

# 用双端队列实现滑动窗口最大值（示意）
from collections import deque
```

> 🔍 **知识点深度解析**
>
> **作用**：括号匹配是栈的经典应用——遇左入栈、遇右比栈顶，体现 LIFO 与对称性。
>
> **原理**：遍历字符，左括号压栈，右括号弹栈比对；最终栈空则合法。复杂度 O(n) 时间 O(n) 空间。
>
> **用法要点**：① 栈适合"最近匹配"类问题；② 用哈希存配对省 if；③ 提前返回提速；④ Deque 实现单调队列解决窗口最值。

### 2.4 注意事项

1. **数组越界**：最易错，动态语言也需防空
2. **链表空指针**：删/反转前判空，避免 NPE
3. **栈溢出**：深度递归改迭代或用显式栈
4. **队列满**：有界队列需处理阻塞/丢弃
5. **选型**：读多写少用数组，写多用链表

> 💡 **深度讲解**：线性四件套是算法基本功。数组的随机访问是它最大的优势，所以排序、二分都依赖数组；链表的优势在插入删除不搬移，所以 LRU、邻接表用链表。栈（LIFO）解决"配对/撤销/递归"，队列（FIFO）解决"缓冲/层序遍历"。工程中动态数组（Python list / Java ArrayList）已封装扩容，绝大多数场景够用，裸链表主要用于特定数据结构（LRU、图邻接表）。

> 📝 **精简总结**：数组=连续随机访问O(1)改O(n)；链表=改O(1)查O(n)；栈=LIFO(括号/撤销)；队列=FIFO(缓冲/BFS)；Deque=双端；注意=越界/空指针/栈溢出/选型。

## 3. 哈希表

### 3.1 概述

哈希表通过哈希函数把键映射到桶，实现平均 O(1) 的增删查。是工程中最常用的数据结构（字典/Map/Set 底层）。

> 🔍 **知识点深度解析**
>
> **作用**：哈希表把"查找"从 O(n) 降到平均 O(1)，是缓存、索引、去重、计数、集合运算的基础。
>
> **原理**：哈希函数算键的散列值定位桶；冲突用链地址法（桶挂链表）或开放寻址（找下一个空桶）；负载因子超阈值触发扩容rehash。
>
> **用法要点**：① 键须实现良好 hashCode/equals；② 负载因子默认 0.75 触发扩容；③ 字符串/对象作键需不可变；④ 冲突多退化为链表（Java 8 转红黑树）；⑤ 需要有序用 TreeMap。

### 3.2 核心特性

**操作**：put/get/remove 平均 O(1)，最坏 O(n)（全冲突）。

**冲突解决**：链地址法、开放寻址（线性/二次探测）。

**扩展**：一致性哈希（分布式）、布隆过滤器（省空间判存在）。

> 🔍 **知识点深度解析**
>
> **作用**：冲突处理决定最坏性能；一致性哈希解决分布式扩缩容数据迁移；布隆过滤器极省空间判"可能存在"。
>
> **原理**：链地址法每个桶挂链表，冲突追加；开放寻址冲突时按步长找空位，删除用墓碑标记；一致性哈希把 key 与节点都哈希到环，仅影响相邻节点，迁移量小；布隆过滤器用多位比特置位，有误判无漏判。
>
> **用法要点**：① 分布式缓存用一致性哈希降迁移；② 缓存穿透用布隆过滤器拦不存在 key；③ 哈希函数要分散均匀；④ 扩容会短暂卡顿（rehash）。

### 3.3 常用用法

```python
# 计数与去重
from collections import Counter, defaultdict
cnt = Counter("abracadabra")          # {'a':5,'b':2,'r':2,'c':1,'d':1}
seen = set()
for x in arr:
    if x in seen: continue
    seen.add(x)                        # 去重 O(1)
# 分组
groups = defaultdict(list)
for u in users: groups[u.city].append(u)
```

> 🔍 **知识点深度解析**
>
> **作用**：Counter/defaultdict/set 是哈希表高频封装，覆盖计数、去重、分组。
>
> **原理**：`Counter` 底层是 dict 计数；`set` 去重靠哈希；`defaultdict` 访问缺失键自动建空容器。
>
> **用法要点**：① 计数/频次用 Counter；② 去重用 set（注意不可哈希类型不行）；③ 分组用 defaultdict(list)；④ 判存在比判不在可靠（布隆思想）。

### 3.4 注意事项

1. **键不可变**：可变对象改后 hashCode 变，找不到原值
2. **哈希冲突**：恶意构造冲突可打满某桶致 DoS，用随机化哈希
3. **扩容抖动**：rehash 耗时，预分配容量（如 HashMap 初始大小）
4. **遍历删除**：边遍历边删要用迭代器安全删除
5. **内存**：哈希表有负载与指针开销，极省内存场景慎用

> 💡 **深度讲解**：哈希表是"以空间换时间"的典范，平均 O(1) 查找让它无处不在。但三个坑必须记：键必须不可变（否则 hashCode 变后找不回）、冲突要处理好（Java 8 链表转红黑树防退化）、扩容 rehash 会卡顿（预分配容量）。分布式场景用一致性哈希把节点和 key 都哈希到环上，扩缩容只迁少量数据。判"不存在"比判"存在"可靠——布隆过滤器正是利用这点做缓存穿透防护。

> 📝 **精简总结**：哈希表=哈希函数映射+平均O(1)；冲突=链地址/开放寻址；扩展=一致性哈希(分布式)/布隆(判存在)；注意=键不可变/冲突DoS/扩容抖动/遍历删。

## 4. 树与二叉树

### 4.1 概述

树是分层非线性结构；二叉树每个节点最多两子。特殊形态：二叉搜索树（BST，左小右大）、平衡树（AVL/红黑树）、B+树（数据库索引）、 Trie（前缀树）。

> 🔍 **知识点深度解析**
>
> **作用**：树建模层级与有序关系——BST 支持有序查找，B+树支撑数据库索引，Trie 支撑前缀检索。
>
> **原理**：BST 中序遍历有序，查找/插删 O(h)（h 为树高）；失衡时 h→n 退化链表，故用平衡树保持 h=O(log n)；红黑树是近似平衡（旋转换色），Java TreeMap/HashMap 桶、C++ map 底层；B+树所有数据在叶子且链表相连，适合磁盘范围查询。
>
> **用法要点**：① 需要有序用 BST/TreeMap；② 数据库索引用 B+树；③ 前缀/自动补全用 Trie；④ 遍历递归要防深栈；⑤ 平衡靠旋转。

### 4.2 核心特性

**遍历**：前/中/后序（递归/迭代）、层序（BFS）。

**BST**：查找 O(log n) 平均，依赖平衡。

**平衡树**：AVL（严格）、红黑树（工程常用）、B+树（磁盘）。

**Trie**：前缀共享，字符串检索 O(L)。

> 🔍 **知识点深度解析**
>
> **作用**：遍历是树操作基础；平衡保证性能；Trie 是字符串专属高效结构。
>
> **原理**：中序遍历 BST 得升序；层序用队列；红黑树五条性质保证最长路径≤2倍最短；B+树非叶只存键、叶存数据且链式，范围扫描只需走链表；Trie 每个节点代表一个字符前缀，公共前缀共享路径。
>
> **用法要点**：① 验证 BST 用中序是否递增；② 层序用队列；③ 范围查询用 B+树；④ 输入法/路由用 Trie；⑤ 递归遍历注意终止条件。

### 4.3 常用用法

```python
# 二叉树最大深度（递归）
def max_depth(node):
    if not node: return 0
    return 1 + max(max_depth(node.left), max_depth(node.right))

# 中序遍历（迭代）
def inorder(root):
    res, st, cur = [], [], root
    while cur or st:
        while cur: st.append(cur); cur = cur.left
        cur = st.pop(); res.append(cur.val); cur = cur.right
    return res
```

> 🔍 **知识点深度解析**
>
> **作用**：深度与遍历是树题两板斧；递归直观、迭代防栈溢出。
>
> **原理**：`max_depth` 后序思想，左右子树最大深度+1；迭代中序用栈模拟"一路左压栈→弹栈访问→转向右"的回溯。
>
> **用法要点**：① 树高/对称/路径和常用递归；② 深树用迭代避免栈溢出；③ 层序配 (node, depth) 记录层级；④ 构造类用前+中序还原。

### 4.4 注意事项

1. **失衡**：普通 BST 可能退化成链表，用平衡树
2. **空指针**：遍历/操作前判空
3. **栈深度**：递归深度=O(树高)，极深树改迭代
4. **B+树 vs B树**：索引用 B+（叶链表利于范围）
5. **Trie 内存**：字符分叉多占内存，可用压缩 Trie

> 💡 **深度讲解**：树把"有序"和"层级"统一表达。BST 提供 O(log n) 有序操作，但输入有序会退化成链表——所以数据库和语言标准库都用自平衡树（红黑树）或 B+树。B+树是磁盘友好的王者：非叶只导航、叶全连成链，范围查询与全表扫描极快，这是 MySQL/PG 索引默认结构。Trie 把字符串前缀共享，是搜索联想、路由匹配的高效解。树遍历（前中后序+层序）是几乎所有树题的基础，递归写起来美，极深树要改迭代防栈溢出。

> 📝 **精简总结**：树=分层结构；BST=左小右大O(log n)怕失衡；平衡=AVL/红黑/B+树；Trie=前缀共享O(L)；遍历=前中后序+层序；注意=失衡/空指针/栈深度/B+树范围优势。

## 5. 堆与优先队列

### 5.1 概述

堆是满足"父节点与子节点有序"的完全二叉树，分大顶堆（父≥子）与小顶堆（父≤子）。优先队列用堆实现，取极值 O(1)、插入删除 O(log n)。

> 🔍 **知识点深度解析**
>
> **作用**：堆在"不断取最大/最小"场景无可替代——TopK、调度、中位数、Dijkstra。
>
> **原理**：完全二叉树用数组存储（i 的左孩子 2i+1、右 2i+2）；插入沉底后上浮（sift-up），取顶后末位补顶并下沉（sift-down）维持堆性质。
>
> **用法要点**：① TopK 用大小为 K 的小顶堆；② 中位数用大顶+小顶双堆；③ 调度用优先队列；④ Python heapq 默认小顶堆；⑤ 堆排不稳定且非原地友好。

### 5.2 核心特性

**操作**：push/pop/top O(log n)，建堆 O(n)。

**应用**：TopK、合并 K 个有序链表、Dijkstra 最短路、定时任务。

**双堆**：大顶+小顶维护动态中位数。

> 🔍 **知识点深度解析**
>
> **作用**：堆把"取极值"从 O(n) 降到 O(log n)，且建堆只需 O(n)（自底向上调整）。
>
> **原理**：Floyd 建堆从最后一个非叶自底向上 sift-down，总比较 O(n)；TopK 维护 K 大小堆，新元素比堆顶大才入堆弹顶，保住最大 K 个。
>
> **用法要点**：① 流式 TopK 用固定大小堆；② 合并 K 链表每次弹最小；③ 优先队列按 (优先级, 序号) 防比较歧义；④ heapq 取负实现大顶。

### 5.3 常用用法

```python
import heapq
# TopK 最大元素
def topk(nums, k):
    heap = []
    for x in nums:
        heapq.heappush(heap, x)
        if len(heap) > k: heapq.heappop(heap)   # 保留最大的 k 个
    return sorted(heap, reverse=True)

# 合并 K 个有序链表（堆存 (值, 链表索引, 节点)）
```

> 🔍 **知识点深度解析**
>
> **作用**：TopK 用最小堆只保 K 个，空间 O(K) 优于全排序 O(n log n)。
>
> **原理**：小顶堆堆顶是当前最小，超过 K 就弹最小，最终剩最大的 K 个；`heapq` 默认小顶，故 TopK 最大直接用。
>
> **用法要点**：① 求最大 K 用小顶堆（反直觉但正确）；② 合并链表堆元素带链表索引避免节点不可比；③ 优先队列存元组保证可比。

### 5.4 注意事项

1. **默认小顶**：heapq/ PriorityQueue 默认最小，要大顶取负
2. **元素可比**：堆中元素需可比较，对象实现 __lt__
3. **动态更新**：堆不支持高效随机改值，需惰性删除
4. **稳定性**：堆排序/堆本身不稳定
5. **TopK 边界**：k>n 或空输入需处理

> 💡 **深度讲解**：堆是"动态极值"专家。它最经典的应用是 TopK——维护一个大小为 K 的小顶堆，新元素比堆顶大才入堆，最终堆里就是最大的 K 个，空间 O(K)。动态中位数用"大顶堆（左半）+ 小顶堆（右半）"两堆平衡。Dijkstra、定时器、合并 K 个有序序列都用优先队列。注意 heapq 默认小顶堆，要大顶就存负数；堆中元素必须可比较，自定义对象实现比较方法。堆不支持高效随机更新值——改值通常用"惰性删除"（标记旧值失效，弹到再跳过）。

> 📝 **精简总结**：堆=完全二叉树(大/小顶)；操作=push/pop/top O(log n)，建堆O(n)；应用=TopK/合并K链表/Dijkstra/中位数(双堆)；注意=默认小顶/元素可比/惰性删除/不稳定。

## 6. 图

### 6.1 概述

图由顶点和边组成，建模任意关系（社交、网络、依赖）。表示：邻接矩阵（O(V²) 查边快）、邻接表（O(V+E) 省空间）。遍历：BFS（层序/最短路）、DFS（连通/环）。

> 🔍 **知识点深度解析**
>
> **作用**：图建模"多对多"关系，是所有网络型问题的语言。
>
> **原理**：邻接矩阵用 V×V 数组，查边 O(1) 但占 O(V²)；邻接表用每个顶点的边链表，省空间、遍历邻边快。BFS 用队列逐层扩展，首次到目标即最短路（无权）；DFS 用栈/递归深入，适合连通分量与环检测。
>
> **用法要点**：① 边密用矩阵，边疏用邻接表；② 无权最短路用 BFS；③ 拓扑排序检测 DAG 依赖；④ 判环用三色标记/并查集；⑤ 强连通分量用 Tarjan/Kosaraju。

### 6.2 核心特性

**存储**：邻接矩阵、邻接表、边列表。

**遍历**：BFS（队列）、DFS（栈/递归）。

**算法**：最短路（Dijkstra/A*）、最小生成树（Prim/Kruskal）、拓扑排序、并查集。

> 🔍 **知识点深度解析**
>
> **作用**：不同存储与算法解决不同图问题——最短路、连通、依赖序。
>
> **原理**：Dijkstra 用优先队列每次松弛距离最小顶点（非负权）；A* 加启发式 h 加速；Prim 从点扩、Kruskal 从边并（并查集判环）求 MST；拓扑排序对入度为 0 的点依次出队。
>
> **用法要点**：① 非负权最短路 Dijkstra；② 含负权用 Bellman-Ford/SPFA；③ MST 边少用 Kruskal；④ 依赖编译用拓扑排序；⑤ 并查集处理动态连通。

### 6.3 常用用法

```python
# BFS 无权最短路
from collections import deque
def bfs(n, adj, start):
    dist = [-1]*n; dist[start]=0; q=deque([start])
    while q:
        u=q.popleft()
        for v in adj[u]:
            if dist[v]==-1: dist[v]=dist[u]+1; q.append(v)
    return dist
```

> 🔍 **知识点深度解析**
>
> **作用**：BFS 是"无权图最短路 + 层序遍历"标准解，首次访问即最短。
>
> **原理**：队列保证先访问近点，`dist` 初 -1 兼作 visited，入队即标记防重复。
>
> **用法要点**：① dist=-1 兼做访问标记；② 加权图换 Dijkstra；③ 记录前驱可还原路径；④ 环图必须判已访问防死循环。

### 6.4 注意事项

1. **表示选型**：边疏（E≪V²）用邻接表省内存
2. **负权边**：Dijkstra 失效，用 Bellman-Ford
3. **环检测**：DFS 需三色标记，否则误判
4. **大图**：顶点多内存敏感，注意结构开销
5. **连通性**：非连通图需遍历所有分量

> 💡 **深度讲解**：图是关系型问题的通用语言。邻接表（省空间）和邻接矩阵（查边快）是两大存储，边稀疏一律邻接表。遍历上 BFS 求无权最短路、DFS 探连通与环。加权最短路用 Dijkstra（非负权）或 Bellman-Ford（含负权），最小生成树用 Kruskal（并查集）或 Prim，依赖顺序用拓扑排序。并查集（Union-Find）是处理"动态连通/环检测"的利器，近乎 O(1)。注意 Dijkstra 遇负权会错，必须换算法。

> 📝 **精简总结**：图=顶点+边；存储=邻接表(疏)/邻接矩阵(密)；遍历=BFS(最短路)/DFS(连通环)；算法=Dijkstra(非负权)/Kruskal(MST)/拓扑排序/并查集；注意=负权/环检测/表示选型。

## 7. 排序算法

### 7.1 概述

排序把序列按序排列。主流：快速排序（平均 O(n log n)，原地）、归并（稳定，需额外空间）、堆排（O(n log n)）、插入（小数据快）、计数/桶/基数（非比较，线性）。

> 🔍 **知识点深度解析**
>
> **作用**：排序是预处理（二分、去重、分组）的前置，库函数通常用混合排序（introsort）。
>
> **原理**：快排选基准分区，递归处理两侧，平均 O(n log n)，最坏（已序）O(n²) 需随机化/三数取中；归并二分后合并两有序段，稳定但 O(n) 空间；堆排建堆后反复取顶 O(n log n)；插入在近乎有序时接近 O(n)。
>
> **用法要点**：① 默认用语言内置排序（已优化）；② 近乎有序用插入/内置混合；③ 稳定需求用归并；④ 对象多键用稳定排序+元组；⑤ 海量外排用归并。

### 7.2 核心特性

| 算法 | 平均 | 最坏 | 空间 | 稳定 |
|------|------|------|------|------|
| 快排 | O(n log n) | O(n²) | O(log n) | 否 |
| 归并 | O(n log n) | O(n log n) | O(n) | 是 |
| 堆排 | O(n log n) | O(n log n) | O(1) | 否 |
| 插入 | O(n²) | O(n²) | O(1) | 是 |
| 计数 | O(n+k) | O(n+k) | O(k) | 是 |

> 🔍 **知识点深度解析**
>
> **作用**：表格是选型速查——稳定/空间/最坏各有权衡。
>
> **原理**：比较排序下界 O(n log n)，非比较排序（计数/桶/基数）在键值范围有限时可 O(n)；快排最坏靠随机化避免；归并稳定但吃空间。
>
> **用法要点**：① 通用选快排/内置；② 稳定+不差空间选归并；③ 内存极紧选堆排；④ 整数小范围用计数；⑤ 字符串用基数（按位）。

### 7.3 常用用法

```python
# 快排（随机化基准）
import random
def quicksort(a, l=0, r=None):
    if r is None: r = len(a)-1
    if l >= r: return
    p = random.randint(l, r); a[p], a[r] = a[r], a[p]
    i = l
    for j in range(l, r):
        if a[j] < a[r]: a[i], a[j] = a[j], a[i]; i += 1
    a[i], a[r] = a[r], a[i]
    quicksort(a, l, i-1); quicksort(a, i+1, r)
```

> 🔍 **知识点深度解析**
>
> **作用**：随机化快排把最坏概率降到极低，是实践最快的通用排序。
>
> **原理**：随机选基准放末位，单指针 i 维护"小于区"，遍历把小的换到左侧，最后基准归位，递归两侧。
>
> **用法要点**：① 随机基准防有序退化；② 小数组可切插入排序（introsort 思路）；③ 迭代版省递归栈；④ 重复多可用三路快排（< = >）。

### 7.4 注意事项

1. **快排最坏**：未随机化遇有序 O(n²)，必随机化/三数取中
2. **稳定性**：需要保留相等元素原序用归并/插入/计数
3. **递归深度**：快排递归 O(log n)，极端仍可能深，用尾递归/堆
4. **非比较局限**：计数/基数仅适用有限范围键值
5. **库函数优先**：手写易错，生产用内置 sort

> 💡 **深度讲解**：排序看似基础却处处用。比较排序理论下界 O(n log n)，快排平均最快但最坏 O(n²)——所以工业实现（如 C++ introsort、Python Timsort）都混合优化：快排 + 小数组切插入 + 退化时转堆排。稳定排序（归并/插入/计数）在"多键排序保留原序"时必需。非比较排序（计数/桶/基数）在整数或定长字符串上可线性时间，但受键值范围限制。结论：99% 场景直接调语言内置排序，理解原理用于选错时排查。

> 📝 **精简总结**：排序=比较(O(nlogn))/非比较(线性)；快排=平均最快需随机化；归并=稳定吃空间；堆排=原地不稳；插入=小数据快；注意=最坏退化/稳定性/库函数优先。

## 8. 查找算法

### 8.1 概述

查找定位目标。无序用线性 O(n)；有序用二分 O(log n)；二叉搜索树 O(log n)；哈希 O(1) 平均。二分是面试最高频。

> 🔍 **知识点深度解析**
>
> **作用**：查找是检索基础，二分把有序查找从 O(n) 降到 O(log n)。
>
> **原理**：二分维护 [lo,hi]，每次取中点比较收缩一半；关键是边界与循环不变量（如"答案在 [lo,hi]"）防死循环与漏解。BST 查找沿大小方向下行。
>
> **用法要点**：① 先确认有序再二分；② 用 mid=lo+(hi-lo)//2 防溢出；③ 二分答案（对单调性函数求边界）；④ 旋转数组/峰值用变种二分；⑤ 哈希查找优先于二分（若只需存在性）。

### 8.2 核心特性

**二分**：精确查找、左/右边界、二分答案。

**树查找**：BST、B+树（范围）。

**哈希查找**：平均 O(1)。

> 🔍 **知识点深度解析**
>
> **作用**：二分家族覆盖"找值/找边界/找最优"，是优化暴力枚举的核心手段。
>
> **原理**：找左边界用 `while lo<hi: mid=(lo+hi)//2; if ok(mid): hi=mid else lo=mid+1`；二分答案对"可行解单调"的问题（如最少天数运货）直接搜答案。
>
> **用法要点**：① 写清循环不变量；② 边界题确认返回 lo/hi；③ 二分答案需验证函数单调；④ 浮点二分设精度退出。

### 8.3 常用用法

```python
# 二分查找（左闭右闭）
def binary_search(a, x):
    lo, hi = 0, len(a)-1
    while lo <= hi:
        mid = lo + (hi-lo)//2
        if a[mid] == x: return mid
        elif a[mid] < x: lo = mid+1
        else: hi = mid-1
    return -1

# 二分答案：最小满足能力的天数
def min_days(weights, cap):
    def ok(d):
        cur, need = 0, 1
        for w in weights:
            if cur + w > cap: need += 1; cur = 0
            cur += w
        return need <= d
    lo, hi = max(weights), sum(weights)
    while lo < hi:
        mid = (lo+hi)//2
        if ok(mid): hi = mid
        else: lo = mid+1
    return lo
```

> 🔍 **知识点深度解析**
>
> **作用**：精确二分与"二分答案"是两类——前者找下标，后者在可行域上搜最小/最大满足条件的值。
>
> **原理**：`binary_search` 标准左闭右闭；`min_days` 中 `ok(cap)` 判断容量 cap 能否 d 天运完，因"容量越大天数越少"单调，故可对容量二分。
>
> **用法要点**：① 左闭右闭用 `<=`，更新 ±1；② 二分答案验证函数必须单调；③ mid 防溢出；④ 返回 lo（收敛点）。

### 8.4 注意事项

1. **前提有序**：未排序二分结果错误
2. **边界死循环**：循环条件与更新不一致易死循环
3. **溢出**：mid 用 `lo+(hi-lo)//2`
4. **重复元素**：找边界需明确返回最左/最右
5. **浮点**：用精度（如 1e-6）退出防无限

> 💡 **深度讲解**：查找里二分性价比最高——有序即 O(log n)。它有两大家族：精确查找（找下标）和二分答案（对单调可行性函数搜最优值，如"运货最少天数""最小满足速度"）。后者是优化暴力枚举的利器，关键写对验证函数 `ok(x)` 的单调性。三大易错点：必须有序、边界条件防死循环、mid 用 `lo+(hi-lo)//2` 防溢出。重复元素要明确定义返回最左还是最右边界。

> 📝 **精简总结**：查找=线性O(n)/二分O(log n)/哈希O(1)；二分=精确+边界+答案；核心=有序前提+循环不变量+mid防溢出；注意=死循环/重复边界/浮点精度。

## 9. 动态规划与贪心

### 9.1 概述

动态规划（DP）把问题拆为重叠子问题，用状态转移+记忆化求解最优；贪心每步取局部最优，要求问题具贪心选择性质。DP 适用"最优子结构+重叠子问题"。

> 🔍 **知识点深度解析**
>
> **作用**：DP 解决最优化（最长/最小/最多），贪心在满足条件时更简单更快。
>
> **原理**：DP 定义 dp[i] 表示以 i 为结尾/到第 i 步的最优值，转移由子问题组合；自底向上填表或自顶向下记忆化（memo）。贪心证明局部最优导致全局最优才可用（如活动选择、霍夫曼编码）。
>
> **用法要点**：① 先找状态与转移；② 一维/二维 dp 视依赖；③ 空间可滚动数组压缩；④ 例题：背包、最长递增子序列、编辑距离、最长公共子序列；⑤ 能贪心就别 DP（更简单）。

### 9.2 核心特性

**DP 要素**：状态定义、转移方程、初始化、遍历顺序。

**经典模型**：0/1 背包、LIS、LCS、编辑距离、股票买卖、区间 DP。

**贪心**：活动选择、霍夫曼、贪心调度。

> 🔍 **知识点深度解析**
>
> **作用**：四要素是写 DP 的套路；经典模型可套用。
>
> **原理**：0/1 背包 `dp[i][w]=max(dp[i-1][w], dp[i-1][w-v]+val)` 选/不选第 i 件；LIS 用 `dp[i]=max(dp[j]+1) for j<i and a[j]<a[i]`；编辑距离二维 dp 三来源（增/删/改）。
>
> **用法要点**：① 背包空间可压成一维倒序；② LIS 可结合二分 O(n log n)；③ 区间 DP 枚举长度；④ 贪心先证性质再写；⑤ 记忆化注意递归基。

### 9.3 常用用法

```python
# 0/1 背包（一维优化）
def knapsack(vals, vols, C):
    dp = [0]*(C+1)
    for v, w in zip(vals, vols):
        for c in range(C, w-1, -1):       # 倒序防重复选
            dp[c] = max(dp[c], dp[c-w]+v)
    return dp[C]

# 最长递增子序列（二分 O(n log n)）
import bisect
def lis(a):
    tail = []
    for x in a:
        i = bisect.bisect_left(tail, x)
        tail[i:i+1] = [x]
    return len(tail)
```

> 🔍 **知识点深度解析**
>
> **作用**：背包是 DP 模板题；LIS 展示"dp+二分"提速。
>
> **原理**：一维背包倒序更新保证每件最多选一次；LIS 用 `tail` 维护最小结尾序列，二分定位插入位保持递增，长度即答案。
>
> **用法要点**：① 背包倒序防重复；② LIS 二分版 `tail` 非真实子序列但长度对；③ 状态定义清晰优先于优化；④ 边界 dp 初始化。

### 9.4 注意事项

1. **子问题重叠**：无重叠用分治/回溯即可，不必 DP
2. **状态定义**：定义错全盘错，先想"dp[i] 表示什么"
3. **遍历顺序**：依赖未算完就错，注意初始化与方向
4. **贪心正确性**：未经证明的贪心常错，优先 DP 兜底
5. **空间**：高维 dp 注意内存，滚动数组压缩

> 💡 **深度讲解**：DP 是算法面试的"分水岭"。核心是两步——定义状态（dp[i] 表示什么）和写转移方程（怎么由子问题来）。经典模型（背包、LIS、LCS、编辑距离）几乎覆盖所有变体，背熟套路即可套。空间能用滚动数组压缩（背包一维倒序）。贪心更优雅但必须证明"局部最优→全局最优"，否则用 DP 兜底更稳。一个实用心法：当问题问"最大/最小/最多/是否可行"且能拆重叠子问题，大概率是 DP。

> 📝 **精简总结**：DP=状态+转移+记忆化；要素=定义/转移/初始化/顺序；模型=背包/LIS/LCS/编辑距离；贪心=局部最优需证明；注意=状态定义/遍历顺序/贪心正确性/空间压缩。

## 10. 字符串匹配

### 10.1 概述

字符串匹配在文本中找模式。暴力 O(nm)；KMP 用失效函数（next 数组）避免回溯文本 O(n+m)；BM/KR 为其他优化；AC 自动机多模式匹配。

> 🔍 **知识点深度解析**
>
> **作用**：匹配是搜索、过滤、生物信息的基础；KMP 在模式重复度高时显著快于暴力。
>
> **原理**：KMP 预处理模式得 next[i]（最长真前缀=后缀），匹配失配时模式右移 next[j] 而非文本回退，文本指针不回溯，故 O(n+m)；next 数组用双指针自匹配求出。
>
> **用法要点**：① 单模式高频匹配用 KMP；② 多模式（敏感词）用 AC 自动机；③ 简单场景用语言内置 find/index；④ Rabin-Karp 用哈希滚动匹配；⑤ 正则适合复杂模式但不保证线性。

### 10.2 核心特性

**算法**：暴力（O(nm)）、KMP（O(n+m)）、BM（坏字符+好后缀）、Rabin-Karp（哈希）、AC 自动机（多模式）。

**应用**：搜索引擎、敏感词过滤、代码高亮、DNA 匹配。

> 🔍 **知识点深度解析**
>
> **作用**：不同算法在单/多模式、最坏保障、实现复杂度上权衡。
>
> **原理**：BM 从右向左比，坏字符规则跳过更多；Rabin-Karp 用滚动哈希，相等再逐字符验防碰撞；AC 自动机是 Trie+失败指针，一次扫描匹配所有模式。
>
> **用法要点**：① 单模式 KMP/BM；② 多模式 AC 自动机；③ 滚动哈希注意模溢出；④ 工程直接用内置/正则，算法用于理解底层。

### 10.3 常用用法

```python
# KMP next 数组 + 匹配（示意）
def kmp(text, pat):
    n, m = len(text), len(pat)
    nxt = [0]*m
    j = 0
    for i in range(1, m):                 # 自匹配求 next
        while j and pat[i] != pat[j]: j = nxt[j-1]
        if pat[i] == pat[j]: j += 1
        nxt[i] = j
    j = 0
    for i in range(n):                    # 匹配，文本不回退
        while j and text[i] != pat[j]: j = nxt[j-1]
        if text[i] == pat[j]: j += 1
        if j == m: return i-m+1           # 命中
    return -1
```

> 🔍 **知识点深度解析**
>
> **作用**：KMP 把"失配后文本回退"改成"模式按 next 右移"，文本指针只前进。
>
> **原理**：`nxt[i]` 是 pat[0..i] 最长相等前后缀长；匹配时失配 `j=nxt[j-1]` 跳到可对齐位置；`j==m` 表示整模式匹配完。
>
> **用法要点**：① next 求法即"模式自己匹配自己"；② 文本指针 i 单调不减；③ 返回首个命中位置；④ 多命中循环继续。

### 10.4 注意事项

1. **暴力够用**：偶发短匹配用内置 find 更简单
2. **next 含义**：前缀=后缀理解错 next 全错
3. **多模式**：敏感词过滤用 AC 自动机而非多次 KMP
4. **哈希碰撞**：Rabin-Karp 需二次验证
5. **Unicode**：中文/emoji 按码点，注意长度

> 💡 **深度讲解**：字符串匹配从暴力 O(nm) 起步，KMP 通过"失效函数"（next 数组）让文本指针不回退，达到 O(n+m)，核心技巧是"模式自己匹配自己"求出最长相等前后缀。多模式匹配（如敏感词过滤）用 AC 自动机一次扫描命中所有模式，远快于多次 KMP。Rabin-Karp 用滚动哈希适合"多模式或近似匹配"。工程上大多数匹配直接用语言内置 `find`/`index` 或正则，掌握 KMP/AC 是为了理解底层与应对特定性能场景。

> 📝 **精简总结**：匹配=暴力O(nm)/KMP O(n+m)/AC(多模式)；KMP=next失效函数(文本不回退)；多模式=AC自动机；注意=暴力够用/next含义/哈希碰撞/Unicode。
